# 04 · 多用户与内核集成

> 决策依据：#9/#33（多用户/全登录服务）、#17（DB 档案为权威注入内核）、#21（Controller 为基座+workspace 桥接）、#22（能力全套暴露）、#23（内建工具+run_steps 映射）、#35/#51/#53（白名单/全量边界/单入口）、#52（按需召回）、#55/#56（扩展资产与权限作用域）、#57（planner 审查者）、#38（双模型）、#24（搜索切换）、#43/#44（首管理员/建用户）。
> 本文档是全改造技术风险最高处（00 §六 R1）；M1 的多实例 spike 必须先于一切内核修改完成。

## 一、分层：用户装配层

```
cmd/deep-tutor（进程入口）
  └── internal/web                 # 用户装配层（新增包，唯一多用户感知处）
        ├── bootstrap              # 进程级：DB/迁移/密钥/全局扩展资产/事件总线
        ├── auth                   # JWT/PAT/首管理员/中间件
        ├── assemble               # per-user 装配：从 DB 档案+全局资产构造 build.Options
        ├── pool                   # Controller/tutor.Service 实例池（per user/thread）
        ├── api                    # /api v2 路由族
        ├── shim                   # v1 兼容层
        └── events                 # 全局事件流（#60）
              ↓ 只经 boot.Build / control.Controller 公开面
        internal/assembly/boot …   # Reasonix 内核（零多用户感知）
```

铁律：`internal/web` 之外任何内核包不出现 user 概念；用户差异全部体现在装配参数（路径 root、provider 解析器、policy、扩展快照）。这是 00 §三分层原则的落地，也让上游内核 diff 未来仍可人工对照（R10）。

## 二、进程级 bootstrap

1. 启动序列：加载配置（环境变量+`data/` 探测）→ SQL 连接+迁移 → 主密钥 → 全局扩展资产装载（插件包安装态、admin 技能/MCP 清单——**只读快照**，#55）→ 事件总线 → HTTP mux（/api → auth → 路由族；shim 挂载）→ 监听 41173。
2. 零用户时：GET / 返回初始化页提示（#43）；`deep-tutor admin create` CLI 等价通道。
3. 关停：Controller 池 drain（运行中轮完成或超时→interrupted 落账，语义同旧崩溃恢复）→ DB checkpoint。

## 三、per-user 装配（assemble）

对每个用户首次触达时构建（缓存于 pool）：

| build.Options 输入 | 来源 | 说明 |
|---|---|---|
| 路径族（SessionDir/CheckpointDir/MemoryDir…） | data/users/<uid>/kernel/… | per-user state root（#31，02 §五） |
| ProviderResolver | users 的 provider_profiles → 运行时 provider 实例 | **动态注册表**：每用户一个 provider.Resolver 实例（DB 档案→kind 工厂），不碰内核全局 init 注册表；默认模型=用户 active 档案；planner_model 同理解析（#38） |
| Policy（权限） | 全局底线规则 ∩ 用户收紧规则 | 见 §七（#56） |
| 工具注册表 | 内建白名单（#35）+ 全局扩展资产只读（#55） | 学习域白名单集：read_file/glob/grep/ls/web_fetch/websearch/recall/memory/remember/forget/todo_write/ask + 领域工具（note_create/note_draft/plan_draft/kb_search 等自定义注册，语义=旧 12 工具的学习域子集+#23 内建化）；管理员开全量=全集+bash/write/edit/subagent/MCP/技能；CUA 独立开关默认关（#51） |
| Skills/Plugins/MCP | 全局安装态只读投影 | 用户不可装（#55）；admin 变更→所有用户实例 runtimeGeneration 升级（drain 旧代，对齐内核 PublishGate 机制） |
| Hooks | 服务管理员配置文件启用 | Web UI 不暴露（01 §二） |
| Sink | web 事件适配器 | 内核类型化事件→(a) run SSE 流 (b) run_steps 审计落账 (c) 全局事件流桥接 |

**装配产物**：`*build.Result`（Controller+tutor.Service 绑定该用户）。缓存键=user_id；Controller 细分到 thread（§五）。

## 四、内核多实例化改造清单（M1 spike 产出后回填，先列已知项）

| 全局态（上游基线；吸收后为 `internal/` 同构实现） | 问题 | 改造方向 |
|---|---|---|
| provider kind 注册表（init 全局） | kind 工厂是全局的——**这没问题**：工厂无状态，per-user 的是实例 | 保持全局工厂；Resolver per-user |
| tool 内建注册表（init 全局） | 同上，注册表共享、run 时按 Options 组装 | 保持（内核已按 run 组装） |
| tutor.Service 进程级单例（serve 层） | per-user Service | 池化（§三）；原单例代码删除 |
| 技能全局目录/插件包安装态 | 单 root 假设 | 全局共享只读 + per-user skills 目录预留（#55 默认禁用） |
| MCP host / 扩展 dispatcher | 单进程实例 | 全局一套（admin 管理），多用户共享；会话级并发按内核既有 per-server concurrency |
| usage catalog / historycatalog（SQLite 目录） | 单用户假设 | **不复用**：用量走 SQL 台账（#19）；会话历史检索=threads 索引+内核会话文件 |
| environment/启动摘要注入 | 进程级缓存 | per-user 首装配时生成，装配后字节稳定（缓存稳定约束） |
| serve 的 auth gate（token/password/none） | 与多用户 JWT 并存 | /api 走 internal/web/auth；内核原生路由仅 loopback/内部（不对外承诺，03 §一） |

> spike 方法：grep 在树内核代码（`internal/assembly/boot.Build` 全部调用方与 Options 字段来源；`REF/` 仅为本地对照副本，不作为检索源）；对每个字段标注 P(进程)/U(用户)/T(线程)；输出矩阵贴回本节。**发现无法参数化的深水点立即记录并评估**（可能需要小改内核——允许，#30 自由修改，但要独立 commit+DEEPTUTOR.md 登记）。

## 五、Controller 池与 Chat 桥接（#21/#53）

- **粒度**：thread → Controller 实例（1:1 内核会话）；user → tutor.Service 实例。池：惰性创建+空闲回收（30min 无活动且无运行轮→持久化会话后释放；运行轮持有强引用）。
- **一轮 Chat**：POST /runs → pool 取/建 Controller → Send(text) → 内核跑轮（工具经白名单注册表）→ Sink 事件转发 SSE + run_steps 落账 + usage 即时落 api_usage（预算判定在计量后，超限中断=旧语义）→ 终态更新 runs。
- **审批桥**：工具 Ask → `approval_request` 事件（run 流+全局流）→ POST /runs/{id}/approve-tool → Controller.Approve；ApprovalTimeout 默认 10min 超时=fail-closed deny。
- **workspace 三段生命周期映射**（#21）：
  - scratch：per-thread 工作区目录（data/users/<uid>/workspaces/<thread>/），工具写文件限于此（CapabilityGrant.WritePaths 强制）；
  - committed：轮次正常结束=内核 checkpoint 锚定该轮 + artifacts 行登记 draft→committed；
  - promoted：POST /runs/{id}/approve（或 promote 工具提案触发 awaiting_approval 自动暂停）→ 复制进领域存储（plans/materials/notes）→ artifacts.promoted。
- **Rewind**：内核 PrepareRewind/CommitRewind 两阶段直通 /api/threads/{id}/rewind（03 §二）；覆盖缺口（bash 副作用等）在 UI 呈现 Coverage 状态（内核语义）。
- **记忆（#52）**：默认关闭 Reasonix 每轮自动召回（Context Engine 配置项 off）；recall/memory 工具读 SQL memories 表（内核 MemoryStore 接口的 SQL 实现——文件态唯一例外，02 §三）；thread/user 两级 scope。
- **单入口动态工具面（#53）**：同一对话页，工具集由 (用户角色 × 配置) 决定；前端经 GET /api/tools 感知当前面，审批/全量提示随之。

## 六、生成域：tutor.Service 复用与 planner 审查者（#3/#57）

- Service 保留 REF 先例结构：8 工具流水线、feedbackTargets 重跑、refusal code、日预算（改读 SQL 台账）。存储注入 SQL Store（02 §四）。
- **planner 审查者**（#38/#57）：在 `validate_plan`（规则五维）之后追加 host 步骤 `planner_review`：
  1. 输入=候选 plan + 用户 intent + 规则校验报告；planner 模型（用户档案 planner_model，未配置则跳过本步）独立会话评审；
  2. 输出=结构化 findings[]（target: knowledge_map|stages|schedule，severity，suggestion）；
  3. findings 非空 → 并入 feedbackTargets 反馈循环（与规则失败同路径重跑，预算 ≤2 轮共享）；全空 → 放行；
  4. SSE：`review_started/review_done`（03 §五；shim 吞掉）；findings 计入 plan.meta 与 api_usage（feature=planner_review）。
  5. planner 不可用（未配置/预算尽）→ 跳过并 warn，不阻塞交付（降级语义对齐流水线既有 repaired 模式）。

## 七、权限作用域合并（#55/#56）

- 规则求值保持内核纯函数 Policy 语义（deny>ask>allow；动态 bash 强制 ask）。
- **作用域合并**：有效规则 = 全局底线（admin 维护，存 DB settings 表）与用户规则（user_prefs）**同 target 取更严者**：任一 deny→deny；否则任一 ask→ask；否则 allow。fallback 由用户审批档位（默认 ask）决定，但全局底线可将 fallback 提升为 ask/deny。
- 沙箱配置：全局一份（admin）；Windows 无 OS 沙箱事实在设置页常显（#36 跟随原生：enforce 则 bash fail-closed）。

## 八、搜索与 Web（#24）

- Searcher 接口双实现：Reasonix websearch（web_search_model+共享凭据+SSRF+相关性门）与 Bing（凭据来自 credentials 表，Go 重实现旧 Bing 调用+SSRF 防护）；用户 prefs.websearch_provider 切换；开销统一落 api_usage 计日预算。

## 九、用量/预算/配额（#19）

- 计量点：(a) Chat 轮次 Sink usage 事件 (b) 生成流水线各 LLM 工具 (c) quiz/materials/slides/kb_chat 独立端点 (d) planner_review——全部即时落 api_usage（防成本黑洞，note/05 原则）。
- 计价：Reasonix pricing.CurrentRate（#20）+ 用户覆盖（settings）→ occurrence 双区估值（02 §三）。
- 配额：进程级信号量（生成全局 8/用户 1；chat 全局 8/线程 1；LLM 16）→ 409/503 语义同 v1（03 §六-4）。

## 十、Studio / CLI / TUI / ACP 的登录（#33）

- 全部客户端经 /api 登录（JWT/PAT）；Studio webview 存 JWT 于安全存储；CLI `deep-tutor login`（终端凭据→JWT 存 0600 配置）+ `--token` PAT 直用；ACP/remotehost 通道同 token。
- 内核原生 serve 路由（/events、/providers 等）在主二进制内仅绑定 loopback 且要求进程内签发的会话票据——不对外（03 §一）；Studio 的 /tutor/* 面板路由挂同一认证中间件（admin/用户角色区分）。
