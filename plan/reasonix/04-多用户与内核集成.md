# 04 · 多用户与内核集成

> 决策依据：#9/#33（多用户/全登录服务）、#17（DB 档案为权威注入内核）、#21（Controller 为基座+workspace 桥接）、#22（能力全套暴露）、#23（内建工具+run_steps 映射）、#35/#51/#53（白名单/全量边界/单入口）、#52（按需召回）、#55/#56（扩展资产与权限作用域）、#57（planner 审查者）、#38（双模型）、#24（搜索切换）、#43/#44（首管理员/建用户）。
> 本文档是全改造技术风险最高处（00 §六 R1）；M1 的多实例 spike 必须先于一切内核修改完成。

## 一、分层：用户装配层

```
cmd/deep-tutor（进程入口）
  └── internal/web                 # 用户装配层（新增包，唯一多用户感知处）
        ├── bootstrap              # 进程级：DB/迁移/密钥/全局扩展资产/事件总线
        ├── auth                   # JWT/PAT/首管理员/中间件
        ├── assemble               # per-user 装配：从 DB 档案+全局资产构造 build.Options
        ├── pool                   # Controller/tutor.Service 实例池（per user/thread）
        ├── api                    # /api v2 路由族
        ├── shim                   # v1 兼容层
        └── events                 # 全局事件流（#60）
              ↓ 只经 boot.Build / control.Controller 公开面
        internal/assembly/boot …   # Reasonix 内核（零多用户感知）
```

铁律：`internal/web` 之外任何内核包不出现 user 概念；用户差异全部体现在装配参数（路径 root、provider 解析器、policy、扩展快照）。这是 00 §三分层原则的落地，也让上游内核 diff 未来仍可人工对照（R10）。

## 二、进程级 bootstrap

1. 启动序列：加载配置（环境变量+`data/` 探测）→ SQL 连接+迁移 → 主密钥 → 全局扩展资产装载（插件包安装态、admin 技能/MCP 清单——**只读快照**，#55）→ 事件总线 → HTTP mux（/api → auth → 路由族；shim 挂载）→ 监听 41173。
2. 零用户时：GET / 返回初始化页提示（#43）；`deep-tutor admin create` CLI 等价通道。
3. 关停：Controller 池 drain（运行中轮完成或超时→interrupted 落账，语义同旧崩溃恢复）→ DB checkpoint。

## 三、per-user 装配（assemble）

对每个用户首次触达时构建（缓存于 pool）：

| build.Options 输入 | 来源 | 说明 |
|---|---|---|
| 路径族（SessionDir/CheckpointDir/MemoryDir…） | data/users/<uid>/kernel/… | per-user state root（#31，02 §五） |
| ProviderResolver | users 的 provider_profiles → 运行时 provider 实例 | **动态注册表**：每用户一个 provider.Resolver 实例（DB 档案→kind 工厂），不碰内核全局 init 注册表；默认模型=用户 active 档案；planner_model 同理解析（#38） |
| Policy（权限） | 全局底线规则 ∩ 用户收紧规则 | 见 §七（#56） |
| 工具注册表 | 内建白名单（#35）+ 全局扩展资产只读（#55） | 学习域白名单集：read_file/glob/grep/ls/web_fetch/websearch/recall/memory/remember/forget/todo_write/ask + 领域工具（note_create/note_draft/plan_draft/kb_search 等自定义注册，语义=旧 12 工具的学习域子集+#23 内建化）；管理员开全量=全集+bash/write/edit/subagent/MCP/技能；CUA 独立开关默认关（#51） |
| Skills/Plugins/MCP | 全局安装态只读投影 | 用户不可装（#55）；admin 变更→所有用户实例 runtimeGeneration 升级（drain 旧代，对齐内核 PublishGate 机制） |
| Hooks | 服务管理员配置文件启用 | Web UI 不暴露（01 §二） |
| Sink | web 事件适配器 | 内核类型化事件→(a) run SSE 流 (b) run_steps 审计落账 (c) 全局事件流桥接 |

**装配产物**：`*build.Result`（Controller+tutor.Service 绑定该用户）。缓存键=user_id；Controller 细分到 thread（§五）。

### 4.5 深水点清单与处置决定

> 深水点 = **装配层改填值解决不了**的点。分三类：**K**=必须改内核（#30 允许，独立 commit + `DEEPTUTOR.md` 登记）；**W**=`internal/web` 装配层承担；**D**=明确不改（设计取舍，写进 §一 铁律的例外清单）。

| # | 深水点 | 类别 | 处置决定 |

### 4.6 对阶段① M2/M3 的硬约束（spike 结论）

1. **`internal/web` 之外的任何内核包不出现 user 概念**（§一 铁律）——spike 复核后这条**依然成立**，但要补一条例外说明：**K 类深水点（#1 `#2` `#26` `#27`）改的是「绑定来源」，不是「用户概念」**——内核拿到的仍是 `Roots`/`Home` 这类**存储绑定**，不是 user id。user id 只存在于 `internal/web`。
2. **装配层必须设 `Options.Home`**；`control.Controller` 已能按同一绑定读 home（✅ iter 404 已落地：`controllerDeps.roots` + `control.Options.Roots` + `Controller.Roots()`，且 `Rebuild` 让替换件继承 stated home）——余下要做的是让装配层**真的填上** `Options.Home`，否则「按用户分流」仍只停留在能力层。
3. **内核已有缝够用，不需要为多用户改内核结构**：per-build 注入面已有 `ProviderResolver` `SharedHost` `BalanceStore` `TaskStore` `Stderr` `CleanupPendingReconciler` `ApprovalTimeout` `EffortOverride` `PermissionAllow` `AdditionalDirs` `Home` `GlobalSecrets`；per-space 面已有 `SetTutorSpaceResolver`/`SetTutorSpaceService`；存储绑定面已有 `config.Roots`/`RootsForHome`。**真正要改内核的是剩余 182 处调用点改走 build 的 Roots**（control 的 42 处 ✅ iter 404 已完成），以及 K 类的 4 处（`Home` 贯通 ✅ / `Controller` 加 Roots ✅ / `healthyConfig` 按 home ✅ iter 406 / `secrets` 安全底线 ✅ iter 407）。
4. **服务进程的启动环境是契约**：`DEEPTUTOR_STATE_HOME`/`DEEPTUTOR_CACHE_HOME` 一旦存在就会钉死 state/cache 根（见 4.4 第 18 条），per-user 分流失效——`internal/web` 启动时必须显式校验并拒绝/告警。
5. **`internal/web` 尚不存在**（本仓当前状态：`internal/web` 目录不存在）。M2/M3 落地前，**Go 侧 tutor 面仍是单用户本地空间，不得作为多用户服务对外承诺**（与 iter 401 的遗留项一致）。
6. **扩展资产是全局的，会话设置是用户的——两者不可混用同一个绑定**（iter 405 的订正）：MCP/技能/插件包按决策 #55 由管理员装、全员可用，其**声明与启用态都在全局**；会话自身的设置随 per-user home 走。控制器因此：MCP 的安装/删除走**进程绑定**，设置读写走**会话绑定**。**装配层还欠一件事**：把全局安装态**只读投影**进每个用户，否则 per-user 会话看不到全局 MCP 清单（深水点 #33）。

## 五、Controller 池与 Chat 桥接（#21/#53）
