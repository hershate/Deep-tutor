# 02 · 数据层设计

> 决策依据：#13/#31（领域 SQL + 内核文件态按用户分 root）、#32（SQLite 预留 PG）、#48（sqlc）、#46（语义等价自由设计）、#15（新迁移机制）、#16（data/ 目录）、#14（全新开始）、#19（SQL 台账+三层防线）、#20（Reasonix 费率表）、#21（threads/runs/steps/memory 概念重建）、#52（按需召回）。
> 语义基准：note/02（26 表）、note/03（流水线持久化语义）、R-Tutor `internal/runtime/tutor/{types,store}.go`。

## 一、总原则

1. **两制并存**：领域数据（产品语义）全 SQL；内核文件态（Reasonix 自身的会话 transcript/checkpoint/记忆 facts）保留文件形态，按用户分 root。界线判据：**表里有的=要跨特性查询/聚合/归属隔离的；文件里有的=内核自己读写闭环的**。
2. **大内容不进库**：沿用 Deep-tutor 哲学——原件/解析文本/导出产物/工作区文件在文件系统，DB 存路径与元数据（note/02 存储哲学）。
3. **语义等价、结构自由**（#46）：表名/字段可重设计，但 note/01–11 中的行为语义（状态机、预算口径、审计完整性）逐条可对拍。
4. **方言抽象从第一天**（#32）：所有 SQL 经 sqlc 生成；`store.Tx` 层隔离 SQLite/PG 差异（占位符、upsert、时间类型）；禁止业务层裸拼方言 SQL。

## 二、技术栈

| 组件 | 选型 | 说明 |
|---|---|---|
| 引擎 | SQLite（WAL、busy_timeout、foreign_keys=ON）默认；PG 预留 | DSN：`data/deep-tutor.db`；PG 经配置项启用 |
| 访问层 | **sqlc**（#48） | `internal/web/store/`：queries.sql + schema.sql → 生成代码；每域一个 query 文件 |
| 迁移 | golang-migrate 兼容的自研轻量 runner（#15"建新机制"） | `migrations/NNNN_*.sql` 顺序执行 + `schema_migrations` 表；启动时自动 up（沿用 Deep-tutor 启动迁移习惯）；**不实现旧库代际探测**（#14 全新开始） |
| 加密 | 凭据加密存储 | provider api_key、PAT hash、Bing key：服务级主密钥（env `DEEPTUTOR_SECRET`，缺省首次生成写 data/secret.key 0600）；密钥加密（AES-GCM）；PAT 只存 hash |

## 四、tutor.Service 存储改写（#13）

- R-Tutor `store.go` 的 JSON 文件读写全部替换为 `internal/web/store` 的 sqlc 实现：Service 保持 transport 无关（#3），构造注入 `Store` 接口（原 `*Store` 结构体改为接口，方法集=现 JSON 操作面）。
- 数据落点变化：`<state root>/tutor/…` JSON → SQL 表 + `data/users/<uid>/materials|exports/…` 文件（大内容）。
- 等价测试基准（R6）：note/03 的流水线语义 + R-Tutor pipeline 测试逐条迁移对拍（tool_start 事件序列、feedbackTargets 重跑、降级 default_data、budget/refusal code）。

## 五、data/ 目录总图（#16/#31）

```
data/
├── deep-tutor.db            # SQLite（领域 SQL；PG 模式下仅迁移台账）
├── secret.key               # 服务主密钥（0600，首次生成）
├── users/<uid>/
│   ├── kernel/              # 内核文件态（per-user state root，#31）
│   │   ├── sessions/…       # Controller 会话 JSONL + 分支 + 子代理记录
│   │   ├── checkpoints/…    # rewind 快照
│   │   ├── memory/…         # 记忆 facts（若未走 SQL 例外）/ MEMORY 索引
│   │   ├── skills/          # 用户级技能（受 #55 限制：默认仅 admin 装全局）
│   │   └── settings.json    # 内核级用户设置（hooks 等服务端配置）
│   ├── materials/<sid>/     # 会话材料原件/解析文本（originals/parsed）
│   ├── exports/…            # 导出产物
│   └── workspaces/<thread_id>/<run_id>/   # Chat 工作区（scratch→committed→promoted）
├── plugins/                 # 插件包安装态（全局 admin #55：plugin-packages.json + 包目录）
├── mcp/…                    # MCP 凭据/状态（全局）
└── backups/                 # 备份产物
```

- 内核 per-user root 的注入点：boot.Build Options 的路径参数全部指向 `data/users/<uid>/kernel/`（04 §四）。
- 全局态（插件包安装态、MCP、全局技能目录）在 data/ 顶层共享，只读挂载给各用户实例（#55）。

## 六、备份/恢复

- 保留全量备份能力（语义重设计）：SQL 全量导出（按域 JSON envelope）+ 用户 kernel/materials 文件树打包 zip；导入=追加式+KB 内容去重（对齐 Deep-tutor 旧行为，阶段① M5 范围）。
- 备份不含凭据明文（密文+独立密钥说明）。

## 七、并发与预算口径

- 写并发：SQLite WAL + busy_timeout 10s；写事务短小；M4 验收含 ≥5 并发生成压测（R5）。
- 预算三层防线（#19）：会话预算（BudgetTracker 语义，默认 $1）、日预算（api_usage 当日本地时区求和，默认 $10，超限 402 + refusal code）、重生成上限（version>2 → 429）。
- 成本计量落账原则不变："异常/取消/超时路径已烧的 token 必须落 api_usage"（note/05 落账原则逐条对拍）。
