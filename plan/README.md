# 原生功能验证契约

本文只定义当前验收方式，不记录实施进度。项目现状通过 git commit description 追溯。

## 验收基线

功能范围与交互以 [`note/14-Tauri原生后端覆盖清单.md`](../note/14-Tauri原生后端覆盖清单.md) 为准。每个功能必须由 `desktop/src-tauri/src/backend/` 的真实命令提供结果，前端不得用静态数据、计时器或成功通知代替。

## 无界面检查

```bash
make lint
make test
make check
make build
```

- `make lint`：Rust 格式、TypeScript 与 Vite 生产构建。
- `make test`：完整 Rust 测试，真实 SQLite、MockRuntime、临时文件与本机回环协议服务，串行执行。
- `make check`：上述检查全部通过。
- `make build`：生成 Tauri 2 NSIS 安装包，最终文件统一输出到根目录 `dist/` 并校验复制哈希，不运行安装器或打开应用。配置测试锁定 `DeepTutor` 的安装目录、开始菜单目录和安装包名称均为 ASCII，同时保持应用标识与学习数据位置不变。

不得通过前台窗口、对话框、键鼠注入或截屏进行自动测试。

## 功能证据

- 写入：验证真实命令、数据库、文件和权限边界，失败不产生伪造成功或部分提交。
- 实时：验证事件持久化、Last-Event-ID 续接、终态顺序、取消恢复与结果重放。
- 外部：验证实际协议请求、错误分类、用量、超时和敏感信息排除；测试服务不冒充真实供应商验收。
- 文件：验证路径约束、类型签名、哈希、大小/数量/压缩比限制、备份 ID 映射和原子写入。
- 页面：验证真实命令返回与持久化状态，不只验证组件渲染。

## 独立验收

真实供应商、真实媒体编码播放、静默安装/运行/卸载和交互操作分别在对应环境验收。缺少这些证据时必须明确保留边界，不得将构建成功、协议夹具或单元测试写成全部环境已经通过。

原生安装验证使用独立绝对数据目录：`DEEPTUTOR_VERIFY_DATA_DIR=F:/TEMP/deeptutor/<独立目录> <安装后的可执行文件> --verify-native`。该入口清空窗口配置，完成真实业务装配和 SQLite 初始化后退出事件循环，不打开界面或事件驱动测试窗口。

默认目录创建、自定义目录持久化、无效路径与损坏配置使用纯目录决策和临时文件测试。MockRuntime 必须执行真实的初始化、目录修改、重试与恢复命令，验证切换只在下次启动生效且不搬移或删除旧数据。主窗口始终显示，启动错误页与设置页共用目录面板；目录选择器和立即重启只由用户主动操作，自动测试不调用真实窗口或对话框。

性能回归必须验证未变化的 schema 不重复迁移、结构漂移仍修复、账户连接复用且没有锁重入。材料队列验证单工作线程、排队取消、停止后不自动续跑、恢复后继续，以及接续时不提前显示空闲。

## 清理契约

被原生实现替代的旧路径与模拟分支应删除，不并存两套产品实现。旧服务端、旧前端、启动脚本、历史方案和进度日志不恢复。许可证、上游披露、当前决策和验证文档保留且与代码一致。
