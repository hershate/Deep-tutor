# Self-Study Guide

> 资产状态：历史 Claude Code 方法论。当前不注册斜杠命令或关键词触发，不执行 Read/Write/WebSearch，也不创建 `study-materials/` 目录。
> 本文件经 `include_str!` 嵌入二进制，仅通过插件面板读取。

## 当前原生对应关系

| 历史方法 | 当前实现 |
|---|---|
| 解析大纲与依赖 | `learning/pipeline.rs` 的目标输入、知识图谱和渐进阶段 |
| 拆分学习单元 | 图谱节点与 `learning_lecture_units`；节点预计 5–600 分钟 |
| 编写自学材料 | `learning/lecture.rs` 逐单元生成并持久化讲义 |
| 练习与检查理解 | `practice/` 的 choice、fill、short、essay 和考试 |
| 复习节点 | `review/` 的到期排程和四档反馈 |
| 补充资源 | `web/` 的 DuckDuckGo 检索和实际正文抓取 |
| 保存与分享 | SQLite、原生导出、全量备份和只读分享 |

当前 `LectureContent` 的结构为：

```text
{
  title, overview,
  sections: [{ heading, content }],
  examples: [{ title, content }],
  checkpoints: [{ question, answer }],
  citations
}
```

讲义按方案、阶段和版本保存。无资料方案可生成通用讲义，但引用必须为空；有资料时引用必须是连续原文。外部资源检索失败只记录真实警告，不伪造链接或引用。

## 历史方法论

以下步骤描述资产来源，不是当前应用的自动执行流程。

### 1. 解析输入

- 读取课程大纲、知识点列表或课程提纲，识别章节、层级和前置依赖。
- 输入缺少学习领域、目标或知识点时先补充信息，不猜测主题。
- 依赖不明确时可以提出结构化顺序，但不得虚构用户未提供的事实。

### 2. 拆分单元

- 历史建议单元体量为 30–60 分钟，每单元设置 2–4 个可检查的学习目标。
- 按依赖排列单元，标注前置知识。
- 主题超过 10 个时先按模块分组，再划分单元；当前实现改为按图谱节点和阶段组织。

### 3. 检索资料

- 历史方法要求每个核心概念检索教程、官方文档或实践指南，并记录标题、摘要和 URL。
- 无结果或结果不相关时不得强行引用。
- 当前实现只采纳实际抓取成功的网页，检索不可用不妨碍无资料通用内容生成。

### 4. 编写材料

历史单元模板包含 YAML 元数据、概述、核心概念、示例、基础练习、可选进阶练习、检查理解、总结和扩展阅读：

```yaml
---
unit: "单元编号及名称"
prerequisites: ["前置知识"]
objectives: ["学完后能够……"]
estimated_time: "预估学习时间"
---
```

- 概念解释、示例和练习必须围绕同一学习目标。
- 每单元至少 2 个基础练习；内容不足时不填充空节。
- 历史单文件超过 500 行时拆分或精简；当前讲义以结构化字段和单元持久化，不使用该文件阈值。

### 5. 生成索引与计划

历史输出包含 `index.md`、单元导航、依赖路线、学习目标、预计时间和每 3–4 个单元一次的复习建议。当前由学习计划、讲义目录和复习日历承担这些功能，不生成该索引文件。

### 6. 报告结果

历史报告包含单元数量、保存路径、学习顺序、总预计时间和使用建议。当前界面以真实方案、讲义、练习和复习状态展示结果，不报告未创建的文件。

## 历史输出边界

旧 `self-study-guide/study-materials/`、`01-单元名称.md`、模块目录、斜杠命令和触发词不属于当前产品。历史 `references/` 与 `study-materials/` 从未随本仓库资产分发。
