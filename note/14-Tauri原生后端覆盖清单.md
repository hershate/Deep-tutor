# Tauri 原生后端功能与验收清单

目标：`REF/frontend/app` 中的所有交互都由原生后端提供真实结果，
不以 `setTimeout`、本地假数据或界面提示冒充后端能力。

## 一、目标架构

- **进程内后端**：`desktop/src-tauri/src/backend/`。Tauri commands 提供请求/响应，
  Tauri events 提供实时输出，不恢复独立 Web 服务。
- **持久化**：应用数据目录中的 SQLite。结构化状态、任务执行记录和事件 outbox
  均持久化；大文件与材料原件放应用数据目录的文件区。
- **实时协议**：后端事件带单调递增 id，前端按 Last-Event-ID 续接；
  终态先落盘再发送，断线不重复执行、不重复计费。
- **密钥**：API Key 经一次性表单进入系统密钥库；数据库、WebView 持久化、
  日志、导出和同步载荷均不保存明文。
- **外部能力**：模型协议、网页抓取、WebDAV/S3 由后端实际执行；
  未配置或不可用时返回明确错误，不生成模拟成功结果。
- **冗余清理**：Python/Reasonix 旧后端已删除；不以“清理”为名留下无实现功能，
  也不恢复已删除的旧产品路径。

## 三、验收要求

1. 命令测试覆盖真实读写、输入拒绝、迁移和失败回滚。
2. 前端调用真实命令，不以本地状态或通知冒充后端成功。
3. 实时事件具有持久化 id，断线只续接不重复执行；终态先落盘再发送。
4. 真实 Tauri 安装包内验证跨页、重启恢复、任务输出、备份与卸载。
5. 外部依赖测试使用明确的测试服务，不把模拟服务结果当作真实供应商验收。
6. 每个切片完成时删除对应模拟分支；最终扫描不得保留 `setTimeout` 模拟、
   假“连接成功”或未经后端产生的“已完成”。

验收方式与无界面检查见 [`plan/README.md`](../plan/README.md)。
实际完成情况和验证证据只记录在 git commit description，不在本文维护状态栏。
