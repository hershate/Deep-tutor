## 5. skills 目录与工具绑定

`skills/` 8 个目录，每个含 `README.md` + `SKILL.md`（`ppt-slide-builder` 另含 `references/` 与 `templates/`）。加载器 `load_skills`（skills/loader.py:33-49）扫描 `<skill-name>/SKILL.md`，取 frontmatter `name:`（缺失回退目录名）作为注册表键，值为剥 frontmatter 后的正文；单文件失败跳过 + 告警，**永不抛异常**；正文超 `_MAX_BODY_CHARS`=64,000 截断（iter 369）。

## 6. 工具执行统一语义（loop.py，详见 [03](03-生成流水线.md) §3）

```
run_tool = 取消检查 → LLM/Python 分流 →
  [LLM] system(skill→inline→default) + user(args+upstream 清洗) →
        瞬态退避重试 → JSON 提取 + pydantic 校验 → 失败修复重试≤3 →
        post_process → ok | repaired（有 default_data）/ error（无）
  [Python] asyncio.wait_for(func, timeouts.parse=900s)
→ metadata(duration/tokens/cost/model/provider) → ToolOutput
```

### 7.2 ToolOutput 信封（tools.go:53-89）

```go
type CallStatus string
const ( CallOK = "ok"; CallDegraded = "degraded"; CallError = "error" )

type ToolOutput struct {
    Status   CallStatus `json:"status"`
    Degraded string     `json:"degraded,omitempty"`
    Data     any        `json:"data,omitempty"`
    Error    string     `json:"error,omitempty"`
    Meta     toolMeta   `json:"meta"`
}
```

与 v1 的对应：

| 语义 | v1 | Go |
|---|---|---|
| 成功 | `status="ok"` | `Status=CallOK` |
| 降级 | `status="repaired"` + `errors[{code,message}]` | `Status=CallDegraded` + `Degraded` 原因串（**无错误码/错误列表结构**） |
| 失败 | `status="error"` + `errors[{code,message}]` | `Status=CallError` + `Error` 单串（`errIdentity`，tools.go:84-89） |
| 元数据 | `metadata{tokens_in,tokens_out,cache_read,cache_write,cost,duration_ms,model,provider}` | `toolMeta{duration_ms,tokens,cost,model,degraded}`（llm.go:192-198）：**tokens 为输入+输出合计**，无 cache 分项、无 provider 归属 |

### 7.5 provider 接口与注入方式（internal/runtime/tutor/llm.go）

`LLM` 接口（llm.go:16-19）：

```go
type LLM interface {
    Name() string
    Stream(ctx context.Context, req provider.Request) (<-chan provider.Chunk, error)
}
```

由 `provider.Provider`（`internal/contract/provider/provider.go:530-537`，同名同签名）满足。`ErrNoLLM`（llm.go:23）标记「未配置模型」，流水线降级而非臆造。

调用链：`runLLM`（llm.go:55-96）把 `llmCall{System, User, MaxTokens}` 组装为 `provider.Request`（system + user 两条消息），消费 `provider.Chunk` 流（`ChunkText` 累积文本，`ChunkUsage` 累加 4 类 token，`ChunkError` 返回错误），`ctx.Done()` 兜底取消。**瞬态重试在 provider 适配器层**，`runJSONTool` 只处理形状修复（llm.go:46-48）。

结构化调用器 `jsonTool[T]`（llm.go:123-129）：字段 `System / User(func) / Decode / Verified / Default`。`runJSONTool`（llm.go:136-181）执行修复循环——`attempt <= repairAttempts`（=3，共 4 次尝试），解码或校验失败把错误原文回灌给模型；耗尽后有 `Default` 返回默认并标 `degraded="schema_violation"`，否则返回错误；无 provider 时有 `Default` 返回默认并标 `degraded="no_llm_provider"`。

注入链路（`internal/frontend/serve/tutor.go`）：

| 注入项 | 方式 | 行号 |
|---|---|---|
| Provider | `ServiceOptions.Provider: tutorProviderFromConfig`——每次 run 时 `config.Load()` → `ResolveStartupChatModel` → `ResolveModel` → `provider.New(...)`，返回的 provider 包成 `tutor.LLM` | tutor.go:59 / 141-159 |
| Pricer | `ServiceOptions.Pricer: tutorPricerFromConfig()`——用 chat 同一套费率卡（`RateCardForModel` + `pricing.OriginalCostAmount`）换算成本 | tutor.go:60 / 70-96 |
| Searcher | `ServiceOptions.Searcher: tutorSearcherFromConfig()`——`&tutor.WebSearcher{SearchModel: boot.NewWebSearchModel(cfg, ...), Provider: tutorProviderFromConfig}`，走 Reasonix 统一检索选模 | tutor.go:61 / 103-114 |
| 日预算 | `ServiceOptions.DailyBudget: tutorDailyBudgetFromEnv()`——读 `TUTOR_DAILY_BUDGET`，默认 10.0，≤0 关闭 | tutor.go:62 / 118-128 |
| Store | `tutor.OpenStore(config.TutorDir())`——按 root 缓存单例 `tutorShared[root]`，一个进程一份 Service | tutor.go:45-65 |
| 宿主覆盖 | `Server.SetTutorService(svc)`——桌面端或测试可自带 Service | tutor.go:130-136 |
