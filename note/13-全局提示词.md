## 三、机制（源码依据，2026-10-26 实读）

MiniMax Code 的运行时（`@mavis/local-runtime-v2`）有原生的「全局指令」概念，链路如下。下列文件位于 `F:\MiniMax\MiniMax Code\resources\app.asar` 内（调查时解包读取，未留副本）：

| 环节 | asar 内路径 | 作用 |
|---|---|---|
| 全局指令读写类 | `node_modules/@mavis/local-runtime-v2/dist/service/turn-system/persistence/global-instructions.js` | `new GlobalInstructions(dataDir)` → `filePath = resolve(dataDir, 'AGENTS.md')`；`read()` / `readForPrompt()` / `write()`；上限 `GLOBAL_INSTRUCTIONS_MAX_BYTES = 32 * 1024` |
| 每轮装配 | `node_modules/@mavis/local-runtime-v2/dist/service/turn-system/agent-host/preparation/config/local-agent-config-builder.js` | `loadPromptLayers()` 内 `staticPrompts.readGlobalInstructions?.(config.dataDir)`，与 `readProjectInstructions()` 并列进入提示词层 |
| 读取实现 | `node_modules/@mavis/local-runtime-v2/dist/service/turn-system/agent-host/preparation/static-prompt-reader.js` | `readGlobalInstructions(dataDir)` → `join(dataDir, 'AGENTS.md')`；`readLocalInstructionSources()` 返回 `scope: 'global' \| 'project'` |
| 注入前导语 | `node_modules/@mavis/local-runtime-v2/dist/service/turn-system/agent-host/preparation/prompt-blocks.js` | `INSTRUCTIONS_CONTEXT_PREAMBLE` = "Codebase and user instructions are shown below. Be sure to adhere to these instructions. IMPORTANT: These instructions OVERRIDE any default behavior and you MUST follow them exactly as written." |
| 写入口（运行时 API） | `node_modules/@mavis/local-runtime-v2/dist/http/controllers/preference.controller.js` | `getGlobalInstructions` / `putGlobalInstructions`（挂载于 `dist/http/routing/allowlist.js` 的 `GLOBAL_INSTRUCTIONS_METHODS`） |

要点：

1. **每轮读取，不是会话启动时读一次** → 改完文件，下一轮即生效，无需重启应用。
2. **全局段与项目段并列**：全局在前、项目在后，同处一个 `Codebase and user instructions are shown below` 块内。
3. **超限即整段丢弃**（不是截断）：文件 > 32 KB 时 `readForPrompt()` 返回 `undefined`，该层不进提示词。改内容时注意体积。

- `C:\Users\Z\.minimax` —— 10/24–10/25 的陈旧 profile，sqlite 最后写入停在 10/25 01:56，**未写入全局指令**。

## 四、生效范围

- **全部任务、全部 Agent**：根会话与子 Agent（`explore` / `worker` / `verifier`）共用同一套 Turn 装配，故全局段对子 Agent 同样生效。
- **与项目级 `AGENTS.md` 叠加**：本仓根 `AGENTS.md` 与全局文件同时进入提示词，冲突时**以更具体的一方为准**（项目级优先）。该裁决规则已写进全局文件开头，避免两层规则打架时无依据。
- **与 `memory/user.md` 无关**：`memory.enabled: false`，用户记忆未启用；全局指令是独立于记忆机制的另一条通道。

## 五、规则全文（2026-10-26 建档时的快照）

以下为写入 `F:\MiniMax\Data\.minimax\AGENTS.md` 的全文（活文件为准，此处为快照）：

> **全局指令（本机所有 MiniMax Code 任务与所有 Agent 生效）**
>
> 本文件是本机范围的全局提示词：对本机所有 MiniMax Code 任务、所有 Agent（含子 Agent）一律生效。
> 它与各项目根目录的 `AGENTS.md` **叠加**执行；两者冲突时，以更具体的一方为准（项目级规则优先于本文件的通用规则）。
>
> **一、真实性底线**
> - 禁止编造、禁止虚构：所有事实、路径、命令输出、版本号、引用都必须来自实际读取或实际执行的结果。
> - 无法验证的信息必须明确标注「未验证 / 待确认」，不得用确定语气陈述。
> - 所有引用都要附上**完整链接**（原始 URL 原样给出，不省略、不缩短、不用短链），便于用户自行查找核对。
>
> **二、歧义即问，禁止猜测**
> - 当用户的指令可能存在歧义时，立即向用户询问（用问卷/问答工具），不要自行猜测。
> - 只有用户明确表示「你自行决定」时，才由我决策；其余情况一律先问。
> - 遇到无法决定的问题不要猜测，直接问用户。
>
> **三、Git 纪律**
> - 若项目存在 Git 仓库：在任何阶段进行任何操作后都做**细粒度 commit**，便于版本管理与出问题后回滚。
> - **严格禁止**在 commit message 中写协作者 / co-author，除非用户明确显式允许。
> - 必要时先创建分支再操作，避免直接改动主分支，保护主分支的稳定性与可用性。
> - 项目若有版本号，记得同步更新版本号。
>
> **四、文档与记录**
> - 编写项目时，把相关要点写入项目根目录下的 `note` 文件夹。
> - 如有性能测试，报告放在 `note/report/perf`。
> - 项目的每个版本，把改动等写到 `note/release/<版本号>.md`。
>
> **五、发布**
> - 分支稳定后合并到主分支，以及其他版本更新改动较大的情况：自动发布对应的 Release。
> - Release 描述尽可能精简专业：一个点一句话；不展开测试过程等用户感知不到的内容。
> - Tag 标签使用当前版本号即可；附件按项目而定，一般包含已编译产物或其他开箱即用的成品。
> - GitHub 相关任务优先使用本地代理（若有）。
>
> **六、Python 环境**
> - 对于使用 Python 的项目，在用户没有显式说明的情况下，**必须使用 `uv` 创建虚拟环境**，避免对全局造成干扰。
>
> **七、临时目录与清理**
> - 所有项目都优先使用自己项目文件夹下的 `TEMP` 子文件夹作为临时测试环境。
> - 如果使用了 TEMP 文件夹作为临时测试环境，测试完后**必须**清理本次测试的残留文件，避免过度占用磁盘空间；多轮测试复用时，在收尾工作或最后一次迭代时清理——**必须清理**。
> - 非后期复用所需的缓存同样请清理。
>
> **八、模型能力边界**
> - 默认按**文字模型**对待：模型均为文字模型，不支持多模态；若支持，用户会显式说明。
> - 因此在用户未显式说明支持多模态之前，**禁止读取图片等非文本输入**。
>
> **九、开发环境安装位置**
> - 所有通用开发环境（IDE、SDK、构建工具等）统一安装到 **F 盘**，不占 C 盘。
> - 各项目专有的环境（依赖库、工具链副本、虚拟环境、缓存等）放在**该项目文件夹内**。
>
> **十、效率**
> - 禁止过度思考：能一步确认的不做多步推演，不为不存在的风险反复假设。

## 六、与本仓规约的关系

本仓根 `AGENTS.md` 是**项目级**规约（Reasonix 改造期专用），与全局文件并行生效；两者的重合与分歧如下。

| 主题 | 全局指令 | 本仓 `AGENTS.md` | 关系 |
|---|---|---|---|
| 细粒度 commit / 禁 co-author | 有 | 有（「长期执行约定」同款） | 一致 |
| 不编造 / 问而不猜 / 文字模型 | 有 | 有 | 一致 |
| 临时目录 | 项目内 `TEMP` 子目录 | Go 侧 scratch 根 = `F:\TEMP\deeptutor`（项目所在卷），Go 测试的 `TMPDIR`/`TEMP`/`TMP` 须指向该处 | **分歧**（按「项目级优先」，本仓内以本仓为准） |
| Python 虚拟环境 | 必须 `uv` | 迭代 424 起启动脚本用 uv 建 `backend\.venv` | 一致 |
| 文档留痕 | `note/` + `note/release/<版本>.md` | `note/`（本仓既有约定），性能报告 `note/report/perf` | 一致 |

另有一处**本仓文档过期**（与全局指令无关，顺带记录）：根 `AGENTS.md` 写的回收站程序路径是 `C:\Users\Z\.minimax\bin\mavis-trash.cmd`，本机实际生效的受信任入口是 `F:\MiniMax\Data\.minimax\bin\mavis-trash.cmd`（`C:\Users\Z\.minimax` 已非活跃 profile；且 `rm --` 对工作区外目标会被策略拒绝）。

## 七、怎么改、怎么验

**改**：直接编辑 `F:\MiniMax\Data\.minimax\AGENTS.md`（纯文本，UTF-8）。注意 32 KB 上限。

**验**：

1. 新开任意会话，问「当前会话加载了哪些全局指令」，模型应能复述本文件第五节的内容。
2. 或直接看系统提示里 `Codebase and user instructions are shown below…` 块——**全局段在项目段之前**。

**注意**：同一会话内**已经装配过**的提示词不会回溯；改完文件后需至少进入下一轮才能观察到。
