# 87 号：样式可访问性与文案问题集（第三十一轮·横切审计）

审计基线：`f0d7e54a`。范围：styles.css（1868 行）全文 + 24 个 tsx 内联样式 + Rust 侧用户可见错误串。对比度按 oklch→sRGB→WCAG 相对亮度公式实算（正常文字 ≥4.5:1，大字/非文本 ≥3:1，焦点圈 WCAG 2.2 Focus Appearance ≥3:1）。共 13 条：P3×6、信息×7。未重复 82#8/82#9 与 74 批已修项。

## P3

### 87#1 亮色主题全局焦点圈对比度 1.05–1.31:1，键盘焦点近乎不可见

- 位置：`desktop/src/styles.css:31`（`--accent-bright: var(--lime-400)`）与 `:83`（`button/a/input/...:focus-visible { outline: 3px solid var(--accent-bright) }`）。
- 传递链条：①亮色主题下焦点圈用 lime-400（高亮度黄绿）；②与 paper-50 底比 1.25:1、纯白 1.31:1、accent-soft 底 1.05:1、surface-soft 1.13:1——全部远低于 WCAG 2.2 焦点外观 3:1 要求；③键盘用户 Tab 导航时无法定位焦点位置。暗色主题 13.79:1 正常。
- 影响范围：覆盖面最大的一条——亮色下**所有**可交互元素的键盘焦点圈失效。74 批修了「焦点圈禁」（焦点不逃逸），但圈本身颜色在亮色下不可见。
- 修复方向：亮色 outline 改 `var(--accent)`（实测 6.5:1）或 `--accent-strong`；或保留 lime 但外圈加深色 second outline。

### 87#2 `.hint-box` 练习提示文字 2.11:1

- 位置：`styles.css:597`（`background: oklch(0.95 0.035 95); color: var(--warning)`）；使用 `pages/Practice.tsx:253`、`components/SubjectivePractice.tsx:144`。
- 传递链条：amber-500（L0.73）作 13px 正文色于浅琥珀底 → 2.11:1（需 4.5:1）。暗色覆盖（:598 换深底）7.68:1 通过。亮色下点「只给一点提示」看到的提示文字严重发虚。
- 修复方向：亮色文字改深琥珀（badge-amber 字色 `oklch(0.43 0.09 65)` = 6.75:1 同族先例），灯泡图标可保留亮琥珀。

### 87#3 `--warning` 亮色作正文文字系统性欠对比（4 处共因）

- 位置与实测（均亮色不达标、暗色正常）：
  - `styles.css:1110` `.capacity-warning` 12px on surface = **2.34:1**（Plan.tsx:189、PlanGenerator.tsx:315 两处 warnings/fixes、SharedPlan.tsx:56）
  - `styles.css:623` `.mistake-count` 24px/700 on surface = **2.44:1**（大字需 3:1）（Practice.tsx:264 错题次数）
  - `styles.css:673` `.review-grade .grade-hard` 12px/700 on surface-raised = **2.44:1**（Review.tsx:160「困难」档）
  - `styles.css:603` `.answer-feedback.is-wrong > div` 15px 标题 on surface-soft = **2.11:1**（Practice.tsx:254「回答错误…」、SubjectivePractice.tsx:146、ExamWorkspace.tsx:205）
- 共因：amber-500 亮度只适配深底，亮色缺文字级深琥珀。同因图标（`streak-panel svg`、`maintenance-warning svg` 约 2.2–2.4:1，非文本需 3:1）。
- 修复方向：新增 `--warning-strong`（≈L0.45）供亮色文字使用，一次收敛全部四处+图标。

### 87#4 导出回执警示文字 1.95:1（全站最低）

- 位置：`styles.css:1307/1310`（`.export-receipt { background: var(--accent-soft) }` + `.export-warning { color: var(--warning) }`）；使用 `components/ExportCenter.tsx:121`（`role="alert"`）。

- 修复方向：亮色改深琥珀或深红（74#15 badge-red 深红 `oklch(0.42 0.16 25)` 可复用）。

### 87#5 备份回执内嵌 form-error 4.41:1（差一线）

### 87#6 学习热力图 has-record 格子聚焦态不可辨

### 87#10 同一「记忆卡」概念四种叫法

- `pages/Review.tsx` 全页「记忆卡」（主称呼）；`pages/Dashboard.tsx:49`「{n} 张**卡片**等待复习」；`components/BackupPanel.tsx:12` `review_cards: '复习卡'`；`components/ExportCenter.tsx:22`「复习**卡片**」/`:14`「卡片库」。备份预演与导出中心里的叫法与复习页对不上号，用户难确认是同一批数据。

### 87#11 「方案」/「计划」双词并行，Dashboard 一屏内切换

- `pages/Dashboard.tsx:47` 同一 hero 卡内 ProgressRing 标「**方案**生成进度」、按钮写「查看学习**计划**」；导航与页名「学习计划」（App.tsx:45、Plan.tsx:182），页面内实体全称「方案」（Plan.tsx:188）；Reports tab「按方案」。看似有语义分工（方案=AI 实体/计划=排期页面），但同屏互换指同一物，新用户需自行推断。
- 修复方向：明确分工后单点收口（如 Dashboard 统一「方案」，或页名改「学习方案与排期」）。
