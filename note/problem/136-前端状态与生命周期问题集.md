### 136#2 八处 listen 订阅 promise 链无 .catch——与全仓其余 13 处口径不一致

- 位置：`AgentTaskCenter.tsx:58-65`、`ExportCenter.tsx:69-78`、`MaintenancePanel.tsx:31-34`、`SharePlanDialog.tsx:46-48`、`KnowledgeMap.tsx:88-94`、`PlanGenerator.tsx:137-169`、`ProviderHub.tsx:149-164`、`StudyRoom.tsx:161-181`。
- 传递链条：①`listen()`（@tauri-apps/api/event）在事件插件初始化失败等罕见情形 reject；②这八处的订阅链无 .catch——reject 变 unhandled promise rejection（仅控制台噪音）；③该组件的事件驱动刷新静默失效——无错误横幅、无 toast；④其余 13 处订阅均有 catch 会提示——同一底层故障在不同组件呈现两种口径。
- 影响范围：受影响=事件系统整体故障的罕见情形（八处组件静默失效+控制台噪音）；不受影响=正常运行与该故障下的其余 13 处（有提示）；损害性质=防御与一致性缺口。
- 修复方向：统一补 `.catch(reportBackendError)`（纯指示类可静默注释 catch）。

### 136#4 ErrorBoundary 仅 main.tsx 顶层一个——页面级渲染异常整应用替换

- 位置：`desktop/src/main.tsx:10-40`（全仓唯一 ErrorBoundary，包住整个 `<App/>`；注释自述「信息项 14」已知设计）；懒加载页（App.tsx:37-42 六页）只包 Suspense 无独立 boundary。
- 传递链条：①任一页面/组件 render 抛错（数据形状 bug）或懒加载 chunk 加载失败；②顶层 boundary 捕获——React 卸载整棵树并执行全部 effect cleanup；③侧栏、导航、其余页面、所有未持久化本地 UI 状态（社区回复草稿、快速记录半填内容、答题草稿的组件内副本）全部丢失；④只剩错误页+`window.location.reload()`——本来只坏一页变成整应用不可用。附带核实：MODAL_STACK/overflowLocks/FOCUS_CONTAINMENT_STACK 在该路径不泄漏（整树卸载 cleanup 正常执行，「弹层栈卡死」场景在当前结构下不可达）。
- 影响范围：受影响=遭遇前端渲染 bug 的用户（故障从一页放大到全应用+状态清场）；不受影响=正常路径与弹层栈卫生；损害性质=故障放大与状态丢失（已知设计的代价面）。
- 修复方向：renderPage() 外层加页面级 boundary，兜底「本页加载失败+返回+重试」，保住侧栏与其余状态。

### 136#5 会中事件驱动 sync 的非 database_busy 瞬时错误直接整应用切错误页

- 位置：`desktop/src/backend/useBackendState.ts:249-256`（requestSync 的 `sync().catch(fail)`）与 `:170-177`（fail 兜底分支 `setStartupError; setReady(false)`）→ `App.tsx:436-438`（整树替换错误页）。
- 传递链条：①应用正常运行（ready=true）期间某事件/窗口聚焦触发 requestSync；②getAppState 失败且错误码不是 database_busy（该类已被 24#1 分支五次静默重试吸收）、不是认证码、不是 startup_not_ready——如 io_error/internal；③fail 的兜底分支不区分启动期/会中期——setStartupError 并清 ready；④App 整树切换「本地数据或实时连接打开失败」错误页——所有页面卸载、本地 UI 状态丢失，恢复依赖 111#5 的 3s 轮询或下一事件成功（几秒级闪断）。
- 影响范围：受影响=会中一次非归类瞬时读错误的用户（概率低——SQLite 争用已归一为 database_busy）；不受影响=启动期失败（本应错误页）与 database_busy 路径；损害性质=一次坏读撕裂整个 UI 而非保留快照降级。
- 修复方向：fail 区分启动期/会中期——会中期保留快照仅报横幅，连续 N 次失败才落错误页。

### 136#6 只读分享页按 Ctrl+K 写入 modal 状态——返回应用后搜索弹层凭空打开
