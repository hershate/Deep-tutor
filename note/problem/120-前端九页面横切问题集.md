### 120#1 Plan「按强度保存排期」与「替代安排」两入口绕过确认层直发不可撤销的全量重排——危险操作确认双标准

- 位置：`desktop/src/pages/Plan.tsx:193`（工具栏 `onClick={() => void changeIntensity(overview?.intensity ?? '标准')}`）、`:215`（替代安排行 `onClick={() => { setAlternativesOpen(false); void changeIntensity(item.intensity) }}`）；对照 :191 segmented 走 `setIntensityTarget` → :216 ConfirmDialog（「会以该强度重新保存全部方案任务的时长与日期，手动调整过的排期也会被覆盖；此操作不可撤销」）。
- 传递链条：①segmented 强度按钮经确认层（43#5 专门修的口径）；②工具栏按钮与替代安排行对同一个 planningBackend.applyIntensity 直接执行；③后端 apply_intensity（planning/mod.rs:374-422）重写 preferences 并整包重排 tasks；④用户在「预览」性质的替代安排弹窗点一行，手动排期即刻被覆盖，无确认无撤销——确认层文案还反过来指引「可点查看替代安排预览」。
- 影响范围：所有手动调过任务日期/时长的用户；破坏性等同 segmented 路径。
- 修复方向：两入口改 `setIntensityTarget(强度)` 复用 :216 确认层。

### 120#2 PlanGenerator 生成完成后退回「实时生成」步骤即无法回到「确认方案」——采用/局部重生成/导出/分享全部不可达

- 位置：`desktop/src/pages/PlanGenerator.tsx:312`（stepper `disabled={index > step}`——回退到 2 后第 3 步禁用）+ `:324`（step 2 控制区对 done/degraded 渲染 null——既无取消也无恢复也无「查看结果」）。
- 传递链条：①方案 done/degraded，用户在第 3 步「确认方案」（采用/导出/分享入口全在此）；②点 stepper「实时生成」（2<3 允许）回 step=2；③「确认方案」按钮因 index>step 禁用，step 2 控制区为 null；④回第 3 步的唯一途径是等下一个 plan.* 事件（:151 `if (next.result) setStep(3)`）或在历史下拉切到另一个方案再切回（select 选中当前项不触发 onChange）——只有一个方案时被迫走「新建方案→重新生成」。
- 影响范围：所有生成完成后误点回退的用户；采用/局部重生成/导出/分享不可达。
- 修复方向：step 2 在 plan.result 存在且非 running 时补「查看方案结果 → setStep(3)」按钮；或 stepper 允许前进到已有 result 的步骤。

### 120#3 PlanGenerator 生成页宣称「重新读取不会重复执行已完成请求」却无任何重读入口——事件停滞即卡态且无自愈

### 120#4 ExportCenter 打开时方案列表读取失败只有横幅无重试——需方案的 8 个格式按钮全禁用，恢复只能关窗重开

### 120#5 全局搜索结果点击不定位命中项；知识节点结果跳「学习空间」与结果标注的知识地图割裂——图标/副标题与落点不符

- 位置：`desktop/src/App.tsx:369-377`（openSearchResult：planId+stageId 命中 → 跳 study；否则只 navigate(result.page) 不定位）；后端实证（engagement/mod.rs:403-502）：note/material→library、task→plan、project→projects，planId/stageId 全 None；**node 结果 page='map' 且 planId+stageId 均 Some**。
- 传递链条：①搜「条件概率」命中知识节点（图标+副标题「知识节点 · 掌握度 X%」）；②Enter/点击 → planId&&stageId 命中 → 跳学习空间讲义页而非结果标注的知识地图，无任何「将进入学习空间」提示；③其余 kind 落到容器页但完全不定位/不高亮命中项——多方案时点旧方案结果落在当前方案的 Plan 页，需二次人工查找。

### 120#6 ProgressBar 原语默认 aria-label 硬编码「完成 X%」——非完成度语义的消费方（token 预算/步数）读屏全部失真

- 位置：`desktop/src/components/UI.tsx:65`（`aria-label={label || `完成 ${clamped}%`}`）。
- 传递链条：①AgentCenter:136（会话输出预算）、:143（本次运行步数，tone=blue）等未传 label；②读屏播报「完成 75%」；③实际语义是 token 预算占用/步数进度；④同类还有 AgentTaskCenter:79 对 failed 任务的进度条——Dashboard/Plan 等完成度场景恰好成立属侥幸。
- 影响范围：所有省略 label 的消费页（至少三处语义错位）；读屏用户。
- 修复方向：去掉兜底文案——label 必填（tsc 强制），或无 label 时不渲染 aria-label 文本由消费方提供语义命名；错位消费点补 label。
