## P3

### 20#1 Library 的取消竞态守卫放在了不会返回该错误的函数上

- 位置：`desktop/src/pages/Library.tsx:153`（startParse，带守卫）、`Library.tsx:161`（cancelParse，无守卫）
- 证据：`isCancelRace` 名单含 `no_active_job`（`desktop/src/backend/client.ts:440-441`，A-9 注明
  是"资料解析任务取消的竞态码"）；后端 `materials/mod.rs:1060` 附近在解析恰已结束时取消
  会返回 `no_active_job`。现在 `startParse`（enqueue 不会返回该码）有
  `if (!isCancelRace(error))` 守卫，`cancelParse` 反而直接 `reportBackendError(error)`。
- 影响：解析任务恰在点击"请求取消"瞬间结束时，用户看到真错误 toast（实际任务已正常结束）。
- 修复方向：守卫移到（或同时加到）cancelParse。

### 20#2 添加任务科目回退可超后端上限；多处输入框缺 clampToBytes

- 位置：`desktop/src/pages/Plan.tsx:112`（subject 回退）、`Plan.tsx:174`（任务弹窗 title/subject 无钳制）、`desktop/src/components/TutorPanel.tsx:46`、`desktop/src/pages/AgentCenter.tsx:110`（消息输入无钳制）
- 证据：
  ```ts
  // Plan.tsx:112 —— 科目留空时回退 plan.goal（弹窗内钳制 200B）或兜底文案
  subject: subject.trim() || plan?.goal || '综合学习'
  ```
  后端 `store.rs:887` `text(object, "subject", 100, false)` 限 100 字节；goal 长于
  100B 且科目留空时保存必被拒。任务名称（title 上限 500B）、导师/Agent 消息输入
  （后端 32000B）均无前端钳制，超限只能靠 toast 兜底。对照同弹窗时长字段已做
  `Math.min(10080, Math.max(1, ...))` 钳制（Plan.tsx:110 注释）。
- 影响：长输入整单被拒后输入丢失；与 limits.ts"输入侧与后端同一度量"的口径不齐。
- 修复方向：回退值截断至 100B；列出的输入框补 clampToBytes。

### 20#3 社区预约的两个入口守卫不一致（侧栏无禁用，靠后端报错兜底）

- 位置：主列表 `desktop/src/pages/Community.tsx:131`（disabled + title 提示）；侧栏 `Community.tsx:132`（直接调用）
- 证据：主列表按钮 `disabled={!groupJoined && !room.reserved}` 且 title="先加入关联小组才能预约"；
  侧栏"预约学习提醒"按钮 `onClick={() => void reserve(upcoming.id, upcoming.reserved)}` 无任何守卫。
  **主审复核备注**：初审代理曾断言"后端也不校验成员"，经复核不实——后端
  `community/mod.rs:815-821` 校验 `community_group_members` 并返回 `group_not_joined`
  （"请先加入关联小组，再预约"），无越权风险，仅为 UI 一致性问题。
- 影响：侧栏点击会得到错误 toast，而主列表同样操作是禁用+悬停提示，体验不一致。
- 修复方向：侧栏复用 groupJoined 判定禁用。

### 20#4 考试/社区时长与熔断参数输入无代码内钳制，仅靠 min/max 属性

- 位置：`desktop/src/components/ExamWorkspace.tsx:172,175`（timeLimitMinutes 1..240 / passScorePercent 1..100）、`desktop/src/pages/Community.tsx:136`（roomMinutes 10..240）、`desktop/src/components/ProviderRouting.tsx:75-78`（熔断参数）
- 证据：`<input type="number" min={1} max={240} ... onChange={... Number(event.target.value)}` ——
  键入越界值直接提交，由后端（practice/mod.rs:557-569、community/mod.rs:729、
  routing.rs:352-355）拒绝并 toast 兜底。对照 PlanGenerator.tsx:280 在 onChange 内
  钳制，惯例不一致。
- 影响：越界输入整单被拒、表单内容丢失；交互标准不齐。
- 修复方向：对齐 PlanGenerator 的 onChange 钳制惯例。

### 20#5 破坏性操作缺少确认对话框（与 Settings 既有防误触标准不齐）

- 位置（单击即执行、不可恢复）：

  - `desktop/src/pages/Review.tsx:136`（删除记忆卡）
  - `desktop/src/components/WikiPanel.tsx:137`（清空问答历史）
  - `desktop/src/pages/Integrations.tsx:91`（卸载插件，级联删除投递历史）
  - `desktop/src/pages/ProviderHub.tsx:379`（删除供应商档案+系统密钥库凭据）
  - `desktop/src/components/SharePlanDialog.tsx:111`（撤销分享，令牌失效）
  - `desktop/src/pages/Community.tsx:131`（取消安排，连带取消全部预约）
- 证据：以上按钮均直接 `void fn(...)` 执行。对照：Settings 清除数据（setResetOpen

- 修复方向：统一补确认对话框（至少覆盖删除资料/卸载插件/删除档案/撤销分享）。

### 20#6 Integrations 命名空间展示列表缺 maintenance，与后端白名单 15 项不符

### 20#7 Practice 收藏无 busy 守卫，快速双击触发两次 toggle 与两次详情拉取

- 位置：`desktop/src/pages/Practice.tsx:133-141`
- 证据：`bookmark` 无 busy 判定；`notify(question.bookmarked ? ...)` 使用请求前闭包值，
  双击时第二条提示文案与最终状态相反；`detail!.set.id` 为非空断言。
- 影响：观感抖动+提示文案短暂错误；无数据损坏（两次 toggle 幂等抵消风险除外）。
- 修复方向：加 busy 守卫，notify 基于刷新后的状态。

### 20#8 知识地图渲染对悬空边/缺位置节点使用非空断言，异常数据将抛错

- 位置：`desktop/src/pages/KnowledgeMap.tsx:123-124`
- 证据：`const a = positions.get(edge.from)!; const b = positions.get(edge.to)!` 及
  `mastery! >= 80`。若后端图数据出现悬空边或节点缺位，渲染直接崩溃
  （有 main.tsx ErrorBoundary 兜底，不至于白屏无出口）。
- 影响：低概率渲染崩溃；防御性缺口。
- 修复方向：`get(...)?.` + 跳过缺失项。

### 20#9 全局搜索结果 "↵" 提示无对应键盘处理

### 20#10 周历事件 React key 可碰撞（同日同名的无 taskId 事件）

- 位置：`desktop/src/pages/Plan.tsx:160`
- 证据：`key={event.taskId ?? event.title}`——里程碑等无 taskId 的条目若同日同名，
  key 重复触发 React 警告并可能渲染异常。
- 修复方向：key 加 index 或 `${event.kind}-${event.title}-${index}`。

### 20#11 Settings 免打扰时段仅 2 个预设，存量任意值时下拉框显示为空
