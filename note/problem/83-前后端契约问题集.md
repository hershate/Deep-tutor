## P3

### 83#1 `tool_active` 竞态码未收录前端 isCancelRace 表，恢复运行被误报为失败

- 位置：后端 `desktop/src-tauri/src/backend/agent/tools.rs:465`（返回码 `tool_active`，语义「相同工具调用已登记但未完成，未重复产生副作用」）↔ 前端 `desktop/src/backend/client.ts:483-514`（`isCancelRace` 码表无此码）、`desktop/src/backend/useAgent.ts:220`（resume 失败路径直接 `setError` 弹横幅）。
- 传递链条：①agent run 在工具执行中崩溃/中断，且 56#5 的 run 收口（`agent/mod.rs:1241` 将 running 态工具行随 interrupted 翻转）未覆盖该行时，工具登记残留 `active`；②用户点「继续运行」→ `resume_agent_run` 重放命中 `tool_active` 返回 Err；③前端码表不识别 → 走错误分支弹横幅——但操作本身幂等安全（副作用未重复），属伪错误。
- 影响范围：中断恢复场景偶发误报「运行失败」，用户可能误以为数据损坏而放弃恢复。
- 修复方向：`isCancelRace` 码表补 `tool_active`（注释口径同 29#2 的 `run_active`），命中时静默重试或提示「上次工具仍在收尾，请稍候再试」。

### 83#4 孤儿事件（发了无专门细分监听）

### 83#5 AgentTaskCenter 监听的 endsWith 过滤不含 approval/memory/artifact 类事件

- 位置：`desktop/src/components/AgentTaskCenter.tsx:46-47`（仅 started/completed/failed/cancelled/interrupted/degraded 结尾时刷新列表）。
- 传递链条：①后端发出 `agent.approval_requested`/`memory_changed`/`artifact_committed` 事件 → ②本组件 kind.endsWith 过滤不匹配这些后缀，列表不即时刷新 → ③approval 由 `useAgent.ts:158-169` 的 sessionId 分支即时处理（审批弹层不受影响），任务中心列表最终靠全局快照兜底更新。
- 影响范围：任务中心列表对审批/记忆/制品事件的刷新滞后于其他事件（秒级差）；无数据丢失、契约未破裂。知悉即可。

## 核对通过的关键结论（供修复轮免复查）

- save_draft（expected_revision）、replace_collection（WriteReceipt）、reveal_path、import_webpage、维护三命令、reset_application、备份三命令：两侧签名、返回结构、全部调用点（含 Library.tsx 对轻量回执 `versions.drafts` 的消费）均已改齐。

- 事件终态顺序：全部 emit 在 commit 后；前端终态消费均为「收到事件→拉取命令」模式，无先发后落盘违规。
