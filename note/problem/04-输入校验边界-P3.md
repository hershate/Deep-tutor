# P3 输入校验边界问题（10 项）

"UI 允许提交但后端必拒"或"UI 未提供防护导致后端报错"类问题。
共性根因之一：前端 `maxLength` 按 UTF-16 字符计，后端按 UTF-8 字节校验——
汉字占 3 字节，中文实际可用长度仅为界面显示的约 1/3。

## 1. [系统性] 前端按字符数限制、后端按字节校验，中文输入可达后端必拒值（多处）
- 前端（字符数）：`Plan.tsx:169` 目标 maxLength=200；`PlanGenerator.tsx:267` goal/level
  maxLength=1000、milestone=1000、`:261` 资料标题 200、正文 `slice(0,500000)` 字符；
  `StudyRoom.tsx:222` 批注 100000；`App.tsx:287` 全局搜索无限制；
  `SecurityPanel.tsx:100/101` 显示名称 80/令牌用途 60；
  `components/ReportViews.tsx` 打卡笔记无上限。
- 后端（UTF-8 字节）：`planning/mod.rs:445`（goal≤200B）、`learning/mod.rs:283-313`
  （goal/level/milestone≤1000B）、`materials/mod.rs:612/618`（标题 200B/正文 500KB）、
  `learning/knowledge.rs:295`（批注≤100KB）、`engagement/mod.rs:352-356`（搜索>200B 报错）、
  `security/mod.rs:921/1070`（名称 80B/60B）、`reports/mod.rs:895-901`（打卡笔记≤4000B）。
- 影响：Plan 目标 >66 汉字、名称 >26 汉字等保存必报错，界面允许的长度约为后端 3 倍；
  PlanGenerator 文本资料页虽有"按 UTF-8 字节上限校验"提示，但计数器显示"x / 500,000 字符"仍误导。
- 传递链条：触发（在输入框粘贴超过后端字节限值约 1/3 长度的中文，如 Plan 目标 67 汉字=201B、显示名称 27 汉字、令牌用途 21 汉字）→ 根因（前端 maxLength/slice 按 UTF-16 字符计：`Plan.tsx:169` 等；后端 `.len()` 按 UTF-8 字节判：`planning/mod.rs:445` goal.len()>200 等，同一限值两种度量）→ 传导（文本原样经 client.ts invoke 直达 Tauri command，后端校验第一步即返回 invalid_* 错误，不落库）→ 症状（点保存/搜索后弹报错提示，长文本整体作废需手动删减）。
- 影响范围：功能面：计划页 update_goal、方案生成、资料导入、批注、全局搜索、建用户/建 PAT、打卡笔记等约 10 组命令；触发条件：默认配置即命中，仅需中文输入超过字节限值的 1/3 长度，无其他前置；受损面：可用性——合法长度的中文被整体拒绝，输入白费。

## 2. WikiPanel 提问与检索输入无长度上限，超限后白填
- 前端：`WikiPanel.tsx:127` 提问 textarea 无 maxLength、`:119` 检索 input 无 maxLength。
- 后端：`knowledge/mod.rs:461-465`（问题 1–8000 字节）、`:345-350`（检索词 1–200 字节）。
- 影响：粘贴长问题（约 2600 汉字）或长检索词（约 66 汉字）提交必报错，长文本作废。
- 传递链条：触发（用户在问答框粘贴 2667+ 汉字问题，或在检索框输入 67+ 汉字检索词）→ 根因（`WikiPanel.tsx:127` 提问 textarea 与 `:119` 检索 input 均无 maxLength，前端不截断不计数）→ 传导（ask/search 将原文 invoke 至 `knowledge/mod.rs:461` question.len()>8000、`:345` query.len()>200，直接返回 invalid_knowledge_question/invalid_search_query）→ 症状（点提问/检索立即报错，已输入长文作废，无任何字数提示）。
- 影响范围：功能面：WikiPanel 的 ask 与 search 两条命令；触发条件：默认配置即命中，仅取决于输入长度（问题 >8000B、检索词 >200B）；受损面：可用性——超限输入被拒且无前置计数，无数据损坏。

## 3. WikiPanel 资料勾选无 8 份上限、允许勾选未解析资料，与文案不符
- 前端：`WikiPanel.tsx:118` 所有资料可勾选（含解析中的），无上限；侧栏文案
  "仅使用选中的已解析资料"；`:127` 提交只要求非空。
- 后端：`knowledge/mod.rs:200-210` scope 1–8 份、`:214-222` 每份必须有解析文本。
- 影响：勾选 9+ 份或含任一未解析资料时报错，文案暗示自动过滤实际整体拒绝。
- 传递链条：触发（用户在引用范围侧栏勾选第 9 份资料，或勾选任一"解析中/未解析"资料后点提问）→ 根因（`WikiPanel.tsx:118` checkbox 对全部 resources 开放、selected 数组无上限，文案"仅使用选中的已解析资料"只是提示不执行过滤）→ 传导（`:127` 提交仅要求 selected 非空，material_ids 原样传后端，`knowledge/mod.rs:201-209` ids.len()>8 报 invalid_knowledge_scope、`:214-222` detail.text 为空报 material_not_parsed）→ 症状（点提问立即整体报错，不会自动剔除超量或未解析资料）。
- 影响范围：功能面：WikiPanel ask 命令及引用范围勾选交互；触发条件：默认配置即命中——勾选 ≥9 份或任选一份未完成解析的资料即可；受损面：可用性——文案与行为不符导致问答无法发起，需用户自行猜因。

## 4. UsagePanel 费率与预算输入无前端拦截，负数/超限提交必拒
- 前端：`UsagePanel.tsx:83/84`——费率仅 `min="0" step="any"` 无 max，HTML min 不阻止键入
  负数；`:46-54` `Number(inputRate)` 直连提交。
- 后端：`providers/usage.rs:217-227`（费率有限、非负、≤1,000,000）、`:167-176`（预算非负）。
- 影响：键入负数或超百万费率保存必报 toast；与 SecurityPanel 配额的完整前端禁用风格不一致。
- 传递链条：触发（用户在费率框键入负数或 >1,000,000 的数值，或在预算框键入负数后点保存）→ 根因（`UsagePanel.tsx:83/84` input 仅 min="0" step="any" 无 max，HTML min 不拦截键入，onChange 原样存值）→ 传导（`:46-54` saveRate 用 `Number(inputRate)` 直连 upsertRate、saveBudget 同理，后端 `providers/usage.rs:217-227` 判费率有限/非负/≤1,000,000、`:167-176` 判预算非负有限，返回 invalid_usage_rate/invalid_usage_settings）→ 症状（点保存后 toast 报错，费率或预算设置未生效）。
- 影响范围：功能面：用量页 upsert_rate 与 save_settings 两条命令；触发条件：默认配置即命中，仅需键入越界数值；受损面：费用控制配置保存失败（预算防线不生效），但不产生错误计费，无数据损坏。

## 5. 社区全部表单缺少长度/时间防护
- 前端：`Community.tsx:125` 帖标题/正文无 maxLength、`:119` 回复无、`:126` 小组名称/主题无、
  `:127` 开始时间无 min（可选过去）、`:117` 搜索框无长度限制且每击键触发请求（`:40`）。
- 后端：`community/mod.rs:358`（标题≤200B/正文≤20000B）、`:417`（回复≤10000B）、
  `:567-575`（名称≤100B/主题≤1000B/时间≤100B）、`:688-694`（开始须晚于当前）、
  `:324`（搜索≤200B）。
- 影响：较长中文内容提交只收到报错 toast，无前置计数；过去时间同样报错。
- 传递链条：触发（撰写帖标题 >67 汉字/正文 >6666 汉字、回复 >3333 汉字、小组名 >33 汉字/主题 >333 汉字，或将开始时间选为过去）→ 根因（`Community.tsx:125/119/126` 各 input/textarea 无 maxLength、`:127` datetime-local 无 min，提交仅做非空检查）→ 传导（createPost/reply/createGroup/createRoom 原样 invoke，后端 `community/mod.rs:358/417/567-575` 按 UTF-8 字节判长报错、`:688-694` start≤now 报 invalid_room_time）→ 症状（点保存收到报错 toast，长文作废；`community/mod.rs:324` 另使 67+ 汉字搜索词报 invalid_search_query）。
- 影响范围：功能面：社区页 create_post/reply/create_group/create_room 及 overview（搜索）五条命令，搜索每击键即触发请求（`Community.tsx:40` 依赖 query）；触发条件：默认配置即命中，仅需超限中文或过去时间；受损面：可用性——内容整体被拒且无计数提示，长文白写。

## 6. 记忆卡编辑器无长度限制

- 后端：`review/mod.rs:181-195`——正面≤8000B、背面≤20000B、标签≤100B。
- 影响：粘贴长内容保存被拒，仅报错无字数提示（约 2666 汉字触顶）。
- 传递链条：触发（在记忆卡编辑器粘贴正面 >2666 汉字、背面 >6666 汉字或标签 >33 汉字后点保存）→ 根因（`Review.tsx:130` front/back/tag 三个输入均无 maxLength）→ 传导（`:77` save 仅校验 front/back 非空即 create/update，后端 `review/mod.rs:181-195` validate_scope 按 UTF-8 字节判 8000/20000/100，返回 invalid_card_content/invalid_card_tag）→ 症状（保存被拒弹报错，无字数提示，粘贴内容作废）。
- 影响范围：功能面：复习页记忆卡 create/update 两条命令；触发条件：默认配置即命中，仅需粘贴超限内容；受损面：可用性——长内容卡片无法创建，无数据损坏。

## 8. 打卡日期不受 84 天窗口约束：窗口外日期"保存成功"但无处显示，未来日期报错
- 前端：`ReportViews.tsx:35`——日期 input 无 min/max，仅校验非空与分钟 1–1440。
- 后端：`reports/mod.rs:890-892` 仅拒绝未来日期；`:826-831` 日历/热力图/统计仅统计
  最近 84 天的 `study_checkins`。
- 影响：85 天前打卡提示已保存但热力图/统计全部不可见；选未来日期报 `future_checkin`。
- 传递链条：触发（用户在打卡弹窗把学习日期改为 85 天前或更早，或选未来日期）→ 根因（`ReportViews.tsx:35` 日期 input 无 min/max，disabled 仅校验非空与分钟 1–1440）→ 传导（saveCheckin 直达 `reports/mod.rs:888-893` 仅拒未来日期，窗口外过去日期通过并写入 study_checkins；而 `:826-831` get_calendar 仅按 `(0..84)` 天窗口查询）→ 症状（远期日期提示保存成功但热力图/统计/最近打卡均不含该记录，数据"消失"；未来日期报错）。
- 影响范围：功能面：报告页 save_checkin 命令与 get_calendar（热力图、连续记录、打卡率、最近打卡）读取；触发条件：默认配置即命中，仅需手选 84 天窗口外日期；受损面：数据正确性——记录已落库却不可见，用户误以为丢失可反复补录。

## 9. 资料导入对话框允许多选无上限，后端单次最多 32 个文件整批拒绝
- 前端：`client.ts:337-339` `multiple: true` 无数量约束；`Library.tsx:118` 全部路径一次性提交。
- 后端：`materials/commands.rs:19-25`——`paths.len() > 32` 整批拒绝 `too_many_files`。
- 影响：一次选 33+ 文件整批失败，需分批重选，无预检提示。
- 传递链条：触发（用户在导入对话框一次框选 33 个及以上文件并确认）→ 根因（`client.ts:337-339` 对话框 options `multiple: true` 且无数量限制）→ 传导（`Library.tsx:118` 将全部非 zip 路径一次性传 import_material_files，`materials/commands.rs:19-25` paths.len()>32 直接返回 too_many_files，不处理任何文件）→ 症状（点选择后整批报错，已选文件全部作废，需手动分批重选）。
- 影响范围：功能面：资料库 import_material_files 命令（zip 走 import_material_archive 不受 32 上限约束）；触发条件：默认配置即命中，仅需单次选择 >32 个文件；受损面：可用性——批量导入整批失败且无预检，无数据损坏。

## 10. 模拟考试 UI 选项 5/10/20 题 ⊂ 后端 1..=20（UI 更严，无损害）
- 前端：`Practice.tsx` 考试题数仅 5/10/20 三档。
- 后端：`practice/exams.rs` 允许 1..=20。
- 影响：无用户损害；记录在案供对照（非缺陷，UI 收紧属有意设计时可忽略）。
- 复核修正：模拟考试 5/10/20 三档 select 实际位于 `desktop/src/components/ExamWorkspace.tsx:166`；`pages/Practice.tsx:210` 是针对练习，提供 1/5/10/20 四档。1..=20 的题数校验在 `practice/mod.rs:478`（generate 内），`practice/exams.rs` 无题数校验。原结论不变：UI 两处选项均为后端 1..=20 的子集。
- 传递链条：触发（用户在模拟考试配置弹窗从题目数量下拉选择 5/10/20 任一档）→ 根因（`ExamWorkspace.tsx:166` select 仅渲染 `[5, 10, 20]` 三档；后端 `practice/mod.rs:478` 允许 1..=20）→ 传导（count 随 generate 输入传后端，恒在合法区间，invalid_question_count 校验必过）→ 症状（无任何报错，仅用户无法经 UI 选 1 或 6–19 等题数）。
- 影响范围：功能面：模拟考试与针对练习的生成命令（practice generate）；触发条件：任何配置下均不触发错误，只限制可选题数；受损面：无——纯 UI 收紧，可用性与数据均不受损。
