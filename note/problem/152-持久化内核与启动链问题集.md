## P2

### 152#1 user1 整库迁移两段 rename 主文件先行——第二次 rename 失败后迁移被跳过，静默丢失仅存 WAL 的提交

- 位置：`desktop/src-tauri/src/backend/store.rs:347-360`（`for suffix in ["", "-wal"]`
  按主文件 → `-wal` 顺序 rename，127#8 设计意图是复制 `-wal` 保住
  checkpoint 与 BEGIN 之间只落 WAL 的提交）；失败收尾 `:363-367`
  （`copy_result` Err 只 `remove_file(&staged)`——主文件已改名，删除落空）；
  跳过判定 `:283`（下次打开按 `!path.exists()` 决定是否重做迁移）。
- 传递链条：①user1 首迁执行，staged 主文件 rename 到
  `users/1/deep-tutor.db` 成功；②第二次 rename（`-wal`）失败——目标被
  占用/杀软锁定/IO 错误，或进程恰在两次 rename 之间崩溃（毫秒级窗口）；
 ③`path` 已存在但缺少 WAL 帧——127#8 要保住的提交不在主文件里；
  ④下次打开（含本次 assemble 失败后的自动 retry）`path.exists()` 为真
  → 迁移整段跳过 → 直接打开丢提交的库，且 `:369-374` 的
  checkpoint(TRUNCATE) 折叠永不执行。附带：残留的
  `*.migration-tmp`/`*.migration-tmp-wal`（`:320-325`）无任何清扫路径
  （`sweep_pointer_tmps` 只管指针 tmp），永久滞留。
- 影响范围：受影响=user1 整库迁移（单用户工作区首迁）失败/崩溃路径上的
  数据完整性；新建库与稳态打开不受影响。损害性质=静默丢提交（数据损失，
  窗口窄但不可逆）。
- 修复方向：先 rename `-wal` 再 rename 主文件（主文件未落位时
  `path.exists()`=false，下次打开自然重做迁移），或改目录级原子切换；
  补 `*.migration-tmp*` 的打开期清扫。

## 待核

### 152#3 retry_storage_initialization 守卫到 running 置位的竞态窗

- `startup.rs:579-595` 守卫在 async 命令线程执行，`running=true` 在
  `:597-601` spawn_blocking 闭包内才置位——两次并发 retry 都可通过守卫
  → 双路 assemble 并发（双重 Store::at_user 迁移、BackendState 互相替换、
  12 域 recover 交错）。对照冷启动 `initialize_background`（:406-408）
  在调用线程同步置位无此窗。需核 UI 双击禁用时序是否足以关窗。

### 152#4 retry 重解析出的新 root 不回写 StartupState——data_root 陈旧

- `startup.rs:306-318` `prepare()` 仅在 State 缺失时注册；`:587-588`
  retry 重新解析 configured_directory。外部修改指针文件 + retry 组合下
  assemble 用新 root 建库，而 `data_root()`（导出路径遏制 08#2 与
  reveal_path 使用）与 overview `dataRoot` 仍指旧目录直到重启。低频
  （进程内改指针被 pending 守卫拦截）。

### 152#5 next_free_id 的 +1ms 基数仍留 1ms 邻接撞号窗

- `store.rs:1093-1094` floor=now+1ms × 前端 `ids.ts localId()=Date.now()`
  ——后端 T 时刻分配 T+1、前端 T+1 时刻生成 T+1 同值。31#58 前移只消除
  同毫秒。兜底 duplicate_id 拒绝整次保存存在，用户看到无上下文的
  「记录标识不能重复」。毫秒级巧合，概率极低。

### 152#6 备份导入静默丢弃 preferences——「恢复到已初始化工作区」永不恢复偏好

- `backup/transfer.rs:1195-1201`：preferences 仅在目标库无 `current` 行时
  导入；而 `store.rs:554-571` bootstrap 对每个新工作区播种
  `preferences/current` → 正常恢复场景（恢复到已初始化的工作区）主题/
  时长/免打扰等偏好恒不恢复。若产品语义是「当前偏好优先」则正确——
  需核对意图（tests 未见 preferences 恢复断言）。

### 152#7 备份导入是「配额与插入同事务」不变式的最大例外 + 长事务

- `backup/transfer.rs:1599-1640`：单 IMMEDIATE 事务内 prepare_ids +
  stage_files + import_rows + install_files（**文件 IO 在写锁内**），
  materials/notes/threads 不走 `ensure_quota_in_tx`（全后端 9 个配额
  调用点均同事务，唯备份导入旁路）。GB 级导入期间并发写命令 10s
  busy_timeout 耗尽 → database_busy。配额行随备份导入（archive.rs:427-435）
  是否属「自恢复」语义需确认；共享/敌意备份推高配额计数是否接受亦需定夺。

### 152#8 store_busy 未入前端 03#6 静默口径
