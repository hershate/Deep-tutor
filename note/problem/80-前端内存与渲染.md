# 80 · 前端内存与渲染性能（第二十八轮·WebView 侧专项）

> 审计范围：长列表/直播累积/监听/定时器/大 JSON/媒体/重渲染链/WebView 存储。
> 73 号审 Rust 主线程，本轮为 WebView 内的对侧面。主审已抽验 K-15 属实。

## P3

### 80#1（=K-14/K-15）全仓快照管道：每事件簇整包 get_app_state + 写路径全集合往返——规模×频率乘积最大

- 位置：`backend/useBackendState.ts:59/:185-197`（事件→120ms 尾沿去抖→全量快照）；后端 `store.rs:525-553`（app_state 无条件返回 tasks+notes+resources+projects 全量）；`client.ts:358`（replaceCollection 上传整个 value 且返回整个 AppSnapshot）。
- 传递链条：① 任何 provider.chat_delta（不分归属）都计入事件簇 ② 簇间隙一次 get_app_state：500 笔记×50KB 均值 ≈25MB 级字符串三份拷贝（Rust serde+IPC+JS parse）③ 勾选一个任务 = 上传 10,000 条 tasks → 下载全快照 → 写事件再触发一次全快照（写放大 ×2）。
- 影响范围：事件密集期（讲义生成/Agent 运行/流式回答）WebView 主线程周期性长任务；集合越大每次交互越重。
- 修复方向：app_state 支持命名空间过滤/增量；写路径返回轻量回执（事件已带状态变更信号）。

### 80#2（=K-7/K-8/K-18）流式直播每 150ms 全量重建 + 整页 reconcile——O(n²) 家族

- 位置：后端 `providers/mod.rs:967-988`（getProviderChat 对非终态请求全扫 chat_delta events 逐条 push_str 重建）；前端 8 个直播消费点各 150ms 拉一次全量累积文本（deltaThrottle 已把每 delta 一次压到每 150ms，但每次拉取仍是全量）；页面级 state（setLiveRequest/setGenerationOutput）每 tick 触发整页 reconcile——Practice 整页（含错题本）、StudyRoom 整页（含全部 ReactMarkdown）。
- 传递链条：16K token 回答 ≈ 数百 delta 行——第 k 次拉取扫 k 行传 k 段文本，全程 O(n²) SQL 扫描/IPC/字符串分配；ReactMarkdown 无 memo 使 parse 成本乘进每次 tick。
- 影响范围：所有长回答期间的界面流畅度；同时是 73 号 Rust 主线程占用的前端放大器。
- 修复方向：后端 chat 表保存增量游标（lastEventId 起）；直播组件隔离（FocusLayer 14#10 同款）+ ReactMarkdown memo。

### 80#3（=K-1/K-2）无界渲染两处：Plan 待排期任务（上限 10,000）与练习错题本（后端无 LIMIT）

- 位置：`Plan.tsx:195`（unscheduled.map，后端 planning/mod.rs:233-265 无 LIMIT）；`Practice.tsx:256`（mistakes.map，practice/mod.rs:1307 无 LIMIT）。
- 传递链条：任务 10,000 配额 × 每条 3 DOM+控件 ≈3 万节点；错题每答错一行永不清理。对照 Dashboard slice(0,100)、练习历史 LIMIT 50 均有界。
- 修复方向：后端 LIMIT+分页或前端 slice+提示。

### 80#4（=K-9/K-10）笔记编辑器击键级全文 Markdown/KaTeX 重解析 + Wiki 引用弹窗全文 span 化

- 位置：`Library.tsx:299`（ReactMarkdown 内联在每击键 re-render 的 Modal，正文上限 1MB，预览无防抖——草稿保存有 350ms 防抖但渲染没有）；`WikiPanel.tsx:159`（MB 级解析文本按引用 split 成千上万 span 全进 DOM，getMaterial 亦全量文本 IPC）。
- 影响范围：长笔记编辑每击键可感卡顿；点开引用即卡顿数秒。
- 修复方向：预览渲染防抖（350ms 同款）；引用弹窗只渲染 quote 邻域窗口。

### 80#5（=K-3/K-4/K-6）搜索与列表渲染三处

- `Library.tsx:70`（每击键对全部笔记 title+excerpt+content 拼接+lowercase——500×50KB≈每击键 25MB 分配，社区帖搜索有 250ms 去抖此处没有）；`Community.tsx:153-155`（500 帖全渲染、回复无上限、每 community.* 事件全量重拉含 getCollection('projects') ≤10,000 条）；`AgentTaskCenter.tsx:24-32`（refresh 对每方案每 stage 逐一 getLecture 全量讲义 JSON 仅为进度数字，300ms 窗口重跑）。
- 修复方向：笔记搜索去抖+索引字段；社区分页；任务中心改轻量进度端点。

### 80#6（=K-17）MediaPlayer 整文件累积进 WebView 内存

- 位置：`MediaPlayer.tsx:23-40`（chunk 循环累积 parts 再 Blob）——1GB 视频 = 1GB JS 堆+Blob 双份峰值；分块 IPC（256KB）本是 46#2 设计，但终点仍是整文件。修复：媒体协议/流式 <video src> 或仅元数据+按需范围加载。

### 80#7a 插件事件列表「加载更早」追加后全量重渲染

- 位置：`pages/Integrations.tsx` 插件事件区（append 后整列表重渲染）。
- 传递链条：① 点「加载更早」→ 事件数组追加 ② 列表无 memo/分窗，旧行全部重新 reconcile ③ 但每行仅一段纯 code 文本、无 Markdown——实际开销轻。
- 影响范围：长事件列表下的追加卡顿（轻）；可 memo 行组件收尾。

### 80#7b（=K-11）Integrations 事件刷新无节流——全仓唯一漏配页

- 位置：`pages/Integrations.tsx`（plugin.* 事件监听直接 refresh，无 deltaThrottle/尾沿合并）。
- 传递链条：① 插件投递密集期（批量测试/重载）每事件一次全量重拉 ② 其余 8 页直播消费点均有 150ms 节流口径 ③ 事件风暴时 Integrations 页拉取次数无上限。
- 影响范围：插件密集期的 IPC 放大；补同款节流即修。

### 80#7c（=K-12）TutorPanel+AgentCenter 并行时 useAgent 双实例重复拉取

- 位置：`useAgent` hook 的两个挂载实例（App 同时挂 TutorPanel 与 AgentCenter 时各一）；后端 getAgentSession 含全部 artifacts content_json 无 LIMIT。
- 传递链条：① 两面板同屏 ② 各自 useAgent 独立 getAgentSession 全量拉取（同一份数据 ×2，含全部讲义 JSON）③ 无实例间共享/去重。
- 影响范围：双面板并行时的 IPC 与解析双倍；大数据量会话下叠加 80#1 快照管道。

### 80#7d（=K-13）useAgent 搜索语料随每事件 O(全部会话文本) 重建

- 位置：`useAgent.ts`（每事件后重建搜索语料索引，遍历全部会话文本）。
- 传递链条：① 任一 agent 事件到达 ② 语料重建对全部会话全文做拼接/小写化 ③ 长会话历史下每事件一次 O(全文) 分配——与 80#5 笔记搜索同族（社区帖搜索有 250ms 去抖，此处无）。
- 影响范围：agent 运行期 WebView 内存分配放大；可惰性/去抖构建。

### 80#7e（=K-16）窗口隐藏后 30/60s 轮询不停

- 位置：App 层通知/用量轮询 interval（30s 与 60s 两档）。
- 传递链条：① 用户最小化/切走窗口（WebView 隐藏）② 轮询 interval 照常 fire → 后端查询 + IPC 空转 ③ WebView 不可见期间结果无人消费。
- 影响范围：后台空转的 IPC/CPU 噪声；可监听可见性暂停。

### 80#7f listLearningPlans 8 处无缓存多点拉取

- 位置：8 个消费点各自调 listLearningPlans（含复习评分路径——打一次分也拉全套 100 份方案含 result_json）。
- 传递链条：① 各页/各操作独立全量拉取 ② 无前端缓存或事件失效机制——同屏多组件即多次同数据拉取 ③ 复习评分这种单一动作也附带全套方案解析。
- 影响范围：方案集合较大时的重复解析；与 80#1 写放大叠加。可收敛为单一 hook + 事件失效缓存。
