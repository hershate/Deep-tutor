## 用户点名项结论（专项核实，均无问题）

- **「点击打开工作区（在资源管理器中显示）是否会弹出任务管理器式的选择」→ 不会**。
  唯一文件定位通道 `reveal_path`（backend/commands.rs:47-64，白名单=数据根或本进程
  24h 内导出回执）→ opener 2.7.2 的 Windows 实现（reveal_item_in_dir.rs:110-170）为
  进程内 COM 调用 `CoInitialize`+`ILCreateFromPathW`+`SHOpenFolderAndSelectItems`，
  仅打开资源管理器并选中目标；全仓（Rust+TS）不存在以文件为目标的默认打开调用，
  故不存在触发 Windows「你要如何打开这个文件」选择器的路径。
- **「点击各种按钮是否会弹出命令行窗口哪怕一瞬间」→ 不会**。四条 OS 通道全部无控制台：
  reveal=COM（同上）；openUrl=`ShellExecuteExW`（open 5.4.5 windows.rs:292-319，
  shellexecute-on-windows feature；其 fallback commands() 链即使走到也全带
  CREATE_NO_WINDOW，windows.rs:8,75-87）；文件对话框=rfd win_cid COM IFileDialog
  （dialog_ffi.rs:61-68）；后端零 `Command::new`，且 main.rs:1 `windows_subsystem = "windows"`。
- reveal 失败（路径不存在/断连网络盘/白名单拒绝）→ 后端中文类型化错误，三处前端入口
  均有可见展示，无英文原文、无静默失败、无系统弹窗（文案精度问题见 134#5）。

## P3

### 134#1 ExportCenter：取消保存对话框连带清掉上一次成功导出的回执与定位入口

- 位置：`desktop/src/components/ExportCenter.tsx:107-109`（`run()` 开头即 `setDone(null); setDonePath('')`，早于 `saveMaterialFile`；取消 `if (!destination) return` 在其后）。
- 传递链条：①导出 Markdown 成功——回执区「已写入 N 字节 · SHA-256…」+「在资源管理器中显示」按钮；②点 PDF 卡片；③原生保存对话框弹出；④点取消——回执区与 reveal 按钮整体消失，尽管上次导出的文件仍在、后端 reveal 回执（24h TTL）也仍允许定位。对照 BackupPanel.tsx:21-35 取消时保留旧回执，同仓行为不一致。
- 影响范围：受影响=导出中心连续导出场景（刚导出的文件失去应用内定位入口）；不受影响=数据与后端回执登记；纯可用性损失。
- 修复方向：`setDone/setDonePath` 清空移到「用户确认了保存路径」之后（`if (!destination) return` 之前不清），与 BackupPanel 对齐。

### 134#2 toast 自动消失时长固定，与文案长度无关——长统计 3.2 秒即逝

- 位置：`desktop/src/App.tsx:169-173`（`toast.tone === 'error' ? 5200 : 3200` 固定毫秒，32#15 独立计时已修但时长口径未动）；长文案样本 BackupPanel.tsx:31-33（含缺失/漂移计数的成功提示可超 60 字）、Library.tsx:399（多文件失败明细）。
- 传递链条：①全量备份完成（有 N 个文件被跳过）→ ②toast 弹出 60+ 字统计 → ③中文阅读约 5-8 字/秒，读完需 8-12 秒 → ④3.2 秒自动消失且无历史回看入口，用户读到一半即丢。
- 影响范围：受影响=所有长文案 notify 消费方；不受影响=短文案；损害为「知情」丢失而非数据。
- 修复方向：时长按字数自适应（如 `Math.min(10000, 2000 + 字数×120ms)`）或悬停暂停计时。

### 134#3 openExternalUrl 失败文案与真实原因不符——合法 https 被指「不支持」

- 位置：`desktop/src/backend/shell.ts:11-14`（catch 后无条件抛 `open_url_failed`「无法打开链接：仅支持安全的 https 地址，由系统浏览器处理。」，91#1 引入）。
- 传递链条：①用户点预设「查看官方接入文档」（ProviderHub.tsx:424，URL 本就是 https）或讲义内 https 链接（UI.tsx:32）；②系统无 https 关联浏览器/被组策略禁——`ShellExecuteExW` 失败；③③文案说「仅支持安全的 https 地址」——用户手里正是合法 https，被引向错误的自查方向。
- 影响范围：受影响=无默认浏览器/组策略受限环境的链接打开失败（罕见）；不受影响=scope 拒绝场景（文案正确）；误导性自救指引。
- 修复方向：按失败来源分流——scope 拒绝保持现文案；OS 打开失败改提示「系统未设置默认浏览器或打开被系统拒绝」（真实 error 已在 console，可按 code 区分）。

### 134#4 ProviderHub 供应商编辑器无未保存守卫——误触遮罩/Esc 即丢整表单（含 API Key 长文本）

- 位置：`desktop/src/pages/ProviderHub.tsx:421`（`<Modal ... onClose={() => setEditorOpen(false)}>` 无 dirty 判断）+ `:194-216`（`openAdd` 置 `emptyForm`、`openEdit` 重置 form）；UI.tsx Modal 遮罩 mousedown 与 Esc 均触发 onClose。

### 134#5 DataDirectoryPanel reveal 失败文案把所有原因都指向「重试初始化」

### 134#6 禁用按钮的解释仅靠 title——键盘/读屏不可达

- 位置：`desktop/src/components/DataDirectoryPanel.tsx:98`（disabled 态说明「数据目录尚未创建，请先重试初始化」仅 `title` 属性）。
- 传递链条：①数据目录未就绪时按钮置 disabled 并挂 title 说明；②title 仅鼠标悬停可见；③disabled 按钮不可聚焦——键盘导航与读屏用户永远触发不了 title、拿不到禁用原因；④旁路信息可推断（Badge「需要处理」+错误横幅+重试按钮），62#8 注释自述该设计针对「直点必败」场景——防误点有效，解释可达性不全。
- 影响范围：受影响=键盘/读屏用户对禁用原因的知情（可及性缺口）；不受影响=鼠标用户（悬停即见）与防误点效果；损害性质=可及性缺口，无功能损失。
- 修复方向：disabled 说明改由相邻可见文本/aria-describedby 承载。

### 134#7 Library 草稿「离开确认」不覆盖应用内导航，由自动保存兜底

- 位置：`desktop/src/pages/Library.tsx:145-148`（仅 `beforeunload` 守卫窗口关闭）。
- 传递链条：①笔记编辑器只在窗口关闭前弹确认（beforeunload）；②SPA 内 hash 导航离开页面时组件连 Modal 一起卸载——无确认直接走；③未保存改动依赖 350ms 草稿自动保存+重开恢复（draftRestored 提示）兜底；④数据基本不丢，但最近 350ms 窗口内的输入可能丢失，且「离开确认」模型在 SPA 导航路径缺位——用户无感知切换。
- 影响范围：受影响=SPA 内导航离开且最近一小段未自动保存的编辑（最坏丢 <350ms 输入）；不受影响=窗口关闭路径（有确认）与已自动保存内容；损害性质=防丢模型不完整，自动保存大幅兜底。
- 修复方向： SPA 导航离开前补脏检查（或接受自动保存兜底并在注释明示口径）。

### 134#8 状态信息用错误通道播报

- 位置：`desktop/src/components/MaintenancePanel.tsx:77-78` 与 `desktop/src/pages/Library.tsx:418`（保存进行中关闭弹窗时经 `backend-error` 事件播「正在等待…请稍候」）。
- 传递链条：①保存进行中用户关闭弹窗；②组件用 backend-error 事件向全局通知层发「正在等待…请稍候」类状态信息；③App.tsx:157 把 backend-error 渲染为红色 `role=alert` 错误 toast；④状态信息以错误样式与错误语义（读屏播报 error）呈现——用户以为保存出错了。
- 影响范围：受影响=保存中途关弹窗的少见场景（误导性红色提示）；不受影响=正常保存完成路径；损害性质=反馈通道语义错位。
- 修复方向：状态类信息走独立 notice 通道（非 error tone、非 role=alert）。

### 134#9 Practice cancel 无 busy 守卫，与同页范式不一致

- 位置：`desktop/src/pages/Practice.tsx:137-144`（该页少数无 busy 守卫的写操作）。
- 传递链条：①用户快速双击「取消生成」；②第二次点击发出第二个 cancel IPC（无 busy 守卫拦）；③后端任务已因第一次取消进入终态——第二次返回 `no_active_generation`；④isCancelRace 静默兜底（client.ts:512-554）——行为最终正确，但与同页 20#7/32#10 显式 busy 范式不一致，多耗一次 IPC。
- 影响范围：受影响=快速双击场景（一次多余 IPC，被静默消化）；不受影响=功能正确性与单次点击；损害性质=范式不一致。
- 修复方向：cancel 按钮补 busy 守卫对齐同页范式（或注释说明依赖 isCancelRace 的取舍）。

### 134#11 保存对话框覆盖确认依赖 Win32 默认选项——需实机验收一次

- 位置：rfd 0.17.2 win_cid 保存对话框从不调用 `SetOptions`（dialog_ffi.rs:163-173/301-312）；首过滤器扩展名自动补全（:175-181）同源。
- 传递链条：①应用全部「另存为」走 rfd 的 IFileSaveDialog COM 封装；②rfd 不显式设置选项——覆盖确认依赖 Win32 文档声明的默认项含 `FOS_OVERWRITEPROMPT`；③若该默认假设在某 Windows 版本/环境下不成立——同名保存将静默覆盖既有文件；④扩展名自动补全同理依赖默认行为。只读审计无法实机验收。
- 影响范围：受影响=「保存到已存在文件名」路径（若默认项不含提示则静默覆盖——数据覆盖风险待排除）；不受影响=新文件名保存的全部路径；损害性质=依赖平台默认行为的未验证假设。
