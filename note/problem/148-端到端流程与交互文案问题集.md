## P3

### 148#1 知舟导师空态文案未提「须先采用方案」，无方案用户发送后才撞错误

- 位置：`desktop/src/components/TutorPanel.tsx:56`（空态文案
  「请描述你想理解的内容。发送后，……没有模型档案时，会明确返回配置错误。」
  ——只提模型档案缺失这一种失败）；`:63` 三个建议快捷按钮
  （解释当前内容/只给一点提示/检查我的理解）直接 `submit(...)`。
- 传递链条：①新用户未采用任何方案时打开导师抽屉（顶栏「问知舟」入口无
  前置守卫）；②`useAgent.send`（`desktop/src/backend/useAgent.ts:210-231`）
  无活动会话时自动 `createSession`；③后端 `agent/mod.rs:362-381` 要求
  plan 已采用——无已采用方案报 `workspace_unavailable`「请先采用一个学习
  方案，再创建 Agent 会话」；④错误以红色横幅出现在输入之后，而空态文案
  与建议按钮均未提示该前提，快捷按钮一键即撞墙。
- 影响范围：受影响=未采用方案用户的导师使用体验（初次使用即遇到）；
  不受影响=已采用方案用户。损害性质=前置条件不可发现 + 文案与失败面
  不符（空态只列了两种失败之一）。
- 修复方向：无已采用方案时空态文案明示「需先采用学习方案」并禁用建议
  按钮（或点击后引导跳转方案生成）。

### 148#2 deferred（统一反馈/考试）模式客观题提交后本人作答从界面消失

- 位置：`desktop/src-tauri/src/backend/practice/mod.rs:1243-1270`
  （`detail()` 仅 `status == "completed" || feedback_mode == "immediate"`
  时返回 done 答案，deferred 进行中客观题答案不返回——主观题经
  `subjective::pending_answers` 返回本人作答）；前端
  `desktop/src/components/ExamWorkspace.tsx:218-219`（fill/short/essay
  输入框依赖 `recorded && typeof answer?.response === 'string'` 回显）
  与 `desktop/src/components/SubjectivePractice.tsx:156`。
- 传递链条：①模拟考试（强制 deferred）或统一反馈练习中提交客观题；
  ②`ExamWorkspace.tsx:148` `setSelected(null); setDraft('')`；③回看该题
  时 `answer === undefined`（客观题 done 行不在返回集），输入框显示为空
  的禁用框——考生无法确认自己的作答已保存。144#3 的回显修复只在
  immediate/已交卷路径生效。
- 影响范围：受影响=deferred 模式的考试与练习回看；不受影响=判分、遮蔽
  对错逻辑（遮蔽对错是设计意图，本人原文被隐藏不是）。损害性质=行为
  不一致 + 用户无法确认已保存。
- 修复方向：后端在 deferred 进行中对本人 `response_json` 单独返回
  （不返回 score/correct/feedback），或前端保留本地已提交草稿回显。

### 148#3 导出中心「当前单元讲义」允许选择未采用方案，选中即死路

### 148#4 列表 key 使用展示文本，模型产出重复文本时 React key 冲突

- 位置：`desktop/src/pages/Practice.tsx:241+257`（nodeIds 映射为节点
  **标题**后 `<Badge key={node}>{node}</Badge>`——后端 `validate.rs`
  只校验节点 id 唯一，不校验标题唯一）；`desktop/src/pages/Projects.tsx:197`
  （`feedback.suggestions.map(suggestion => <li key={suggestion}>)`——
  后端 `projects/mod.rs:386-391` 对建议文本只校验非空/长度，不查重）。
- 传递链条：①模型生成同名知识节点标题（映射到同一题）或重复建议文本；
  ②React 同列表 key 冲突；③渲染警告与潜在的列表项错位/状态串扰。
  全仓其余列表均以 id 为 key，仅这两处以文本为 key。
- 影响范围：受影响=重复文本下的练习题节点徽章与项目建议列表渲染。
  损害性质=数据驱动的渲染不稳定。

### 148#5 方案生成要求至少 1 份已解析资料——设计确认（非私自改必选）

- 位置：前端 `desktop/src/pages/PlanGenerator.tsx:178`
  （`ready = selected.length > 0 && …`，步骤 0「继续澄清目标」按钮
  `disabled={!ready}`）；后端
  `desktop/src-tauri/src/backend/learning/mod.rs:312-317`
  （`invalid_materials`「每个方案须选择 1 到 8 份已解析资料」）。
- 核对结论：REF 原设计（`REF/frontend/app/src/pages/PlanGenerator.tsx:74`
  「继续澄清目标」`disabled={!sources.some(s => s.status === '已解析')}`）
  同样要求至少 1 份已解析资料；当前实现前后端口径一致、错误文案明确。
  「纯新手不上传材料就无法制定学习计划」属实但为**沿袭原设计**——材料
  是知识图谱/引用链的数据源，无材料的方案无从生成引用。最轻入口是
  「纯文本」粘贴（无需文件）。
- 影响范围：备查。若产品层面希望支持「零材料生成」，属新需求而非缺陷。

### 148#6 AI 问答绑定关系——设计确认

- 位置：Agent/导师链路 `agent/mod.rs:362-381`（会话必须挂**已采用**方案，
  无 planId 时自动取任一已采用方案，否则 `workspace_unavailable`）；
  Wiki 问答链路 `knowledge/mod.rs:203-213+512-526`（绑**资料**而非方案：
  1-8 份已解析资料，与计划无关）。
- 核对结论：「AI 问答一定绑定学习计划」对知舟导师/Agent 工作台成立
  （硬绑定已采用方案）；对 KB/Wiki 问答不成立（绑资料）。两条链路边界
  清晰、均为有意设计（Agent 工作区/记忆/产物都按方案组织）。残余缺口
  见 148#1（前置条件不可发现）。

### 148#7 plan.status='degraded' 两页术语不一致

- 位置：`desktop/src/pages/PlanGenerator.tsx:28`（`degraded: '降级交付'`）
  vs `desktop/src/pages/Plan.tsx:122/192`（经 `statusName`，
  `desktop/src/status.ts:14` `degraded: '部分完成'`）。
- 传递链条：同一方案在生成页显示「降级交付」、在学习计划页显示
  「部分完成」——「部分完成」易误读为生成中断，与「带警告交付」语义
  有出入。损害性质=同状态跨页术语漂移。
- 修复方向：统一为「降级交付」（与 result-banner 的「存在需要复核的
  降级项」文案呼应），status.ts 的 degraded 释义单列。

### 148#8 未配置模型供应商时方案生成页无前置提示

- 位置：`desktop/src/pages/PlanGenerator.tsx` 全文（步骤 0/1 无供应商
  状态读取与提示）；后端报错点
  `providers/routing.rs:476-478`（`provider_not_configured`「请先配置并
  选择模型供应商」）。
- 传递链条：①新用户未在模型接入中心配置任何档案即进入方案生成；
  ②完成资料导入与目标填写后才在点击「开始生成方案」时收到配置错误；
  ③错误文案本身明确（有指引），但前置成本已付出（导入资料、填表）。
- 影响范围：受影响=初次使用且跳过模型配置的用户。损害性质=引导缺位
  （非功能缺陷）。
- 修复方向：步骤 1 侧栏或页首在无可用供应商时给出「先配置模型」提示
  与跳转链接。

### 148#9 语言偏好 en-US 时 document.lang 指向英文但界面全中文
