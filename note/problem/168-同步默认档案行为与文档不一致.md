# 168：同步默认档案行为与文档不一致

## 现象与触发条件

本地已有默认供应商，执行 WebDAV/S3 配置恢复，远端配置携带另一个有效 `activeProvider`。实际恢复会切换到远端默认档案；文档却笼统声明新增或导入不覆盖已有默认项。

## 传递链条

1. `desktop/src-tauri/src/backend/providers/sync_config.rs:315-450` 执行同步配置导入。
2. `:434-445` 对远端 `active_provider` 映射后的档案无条件调用 `set_active`。
3. `desktop/src-tauri/src/backend/providers/mod.rs:697-720` 更新 `provider_meta.active_provider` 并发送 `provider.active_changed`。
4. 后续未指定显式任务路由的模型请求因此使用远端默认档案。
5. `desktop/README.md` 与 `note/产品与技术决策.md` 当前将“不覆盖”范围写成“导入或新增”，与实际同步恢复冲突。

## 影响范围

影响同步恢复后的默认上游与现行使用说明。普通 JSON 追加导入没有远端 active 恢复步骤，只经首个档案自动补默认项；它与同步恢复不是同一行为。无需改变远端显式默认档案的恢复语义，应缩窄文档范围。

## 修复验收

文档分别说明：新增与普通追加导入保留已有选择；WebDAV/S3 恢复采用远端有效默认档案。模型实际调用链与界面说明一致。
