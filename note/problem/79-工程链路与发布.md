## 中

### 79#1（=J-1）安装包 SHA-256 只算不发布——用户无法校验分发物完整性

- 位置：`desktop/scripts/tauri.mjs:34-38` + `.github/workflows/ci.yml:55-60`。
- 传递链条：① tauri build 成功 → 复制安装包到 dist/ → 计算 source/destination 两次 SHA-256 仅自比对 ② 摘要比对后丢弃——不打印、不落 `.sha256`、CI artifact 只传 `dist/*.exe` ③ 终端用户（尤其 GitHub artifact 下载者）无法做完整性校验；哈希逻辑只覆盖「同机复制」这一最无风险环节。
- 影响范围：所有分发安装包的接收者。
- 修复方向：摘要写入 `dist/<name>.sha256` 随 artifact 上传并打印。

### 79#2（=J-2）collect-licenses 在 node_modules 整体缺失时静默成功——缺整族许可的安装包照常产出

- 位置：`scripts/collect-licenses.mjs:105-150/:252-255`。
- 传递链条：① node_modules 不存在（路径漂移/依赖未装）→ npm 段整体跳过（npmMissing=0、无披露）② 只要 cargo 侧有收录 → `copied>0` → exit 0 ③ 「零收录即失败」守卫只在两侧同时为零时触发；NOTICE 第 23 行「npm 依赖许可随包分发」的承诺被架空。
- 影响范围：合规安装包可能在管线失效时照常产出。
- 修复方向：node_modules 缺失按 npm 侧管线失败（exit 1）或清单显式披露。

### 79#3（=J-3）许可收集不递归嵌套 node_modules——嵌套运行时依赖静默缺失（连「缺失」都不计）

- 位置：`collect-licenses.mjs:108-149`（仅扫顶层含 @scope 一层；runtimeFilter 的嵌套名生成后从未被主扫描使用）。
- 传递链条：npm 因版本冲突未提升的嵌套包（node_modules/x/node_modules/y）不收录不计 missing——同依赖双版本进 vite 产物时嵌套副本许可缺失且清单无感知。peerDeps 与 overrides（katex 实测按实际树收录）当前无恙。
- 修复方向：扫描递归一层嵌套 node_modules 或按 lock 实际树枚举。

## 低

### 79#4（=J-4）tauri.mjs bundle 路径硬编码 + 构建失败不清理 dist 旧包

- `tauri.mjs:25`（`target/release/bundle/nsis` 硬编码——`--target <triple>`/`--debug` 时路径实为 target/<triple>/…，会误报找不到安装包）；构建失败早退不清理 dist，同版本旧 exe 残留可被误当新产物（本地 dist 已堆积 1.0.0→1.1.2 共 9 个历史包，均正确忽略未入库）。修复：按 target 推导路径；复制前清理同版本旧文件。

### 79#5（=J-6）verify-native 协议未接入 CI——安装包层回归只能人工验收

- main.rs 的 `--verify-native`（0/2 契约完整、绕过单实例、DEEPTUTOR_VERIFY_DATA_DIR 绝对路径强制）全仓无 CI/脚本调用；CI 产出的 NSIS 从未被安装或执行验证即上传。修复：CI 加一步解包后对 exe 跑 verify-native 断言 exit 0。

### 79#6（=J-11）rust-toolchain profile="minimal" 不含 rustfmt——新机首跑 make lint 即挂

- `rust-toolchain.toml:4` minimal（rustc/cargo/stdlib）→ 新机 rustup 自动装 1.99.1 无 rustfmt → `cargo fmt` 报组件缺失。本机能跑是因 F 盘工具链手工补装过；CI 能跑是 dtolnay action 默认 profile 含 rustfmt——两侧机制不同。修复：toml 加 `components = ["rustfmt"]` 或 profile="default"。

### 79#7（=J-8）Node 无本地钉扎；本地 gnu vs CI msvc 双环境缝隙

- CI node-version "24" 但无 engines/.nvmrc；AGENTS 声明本地 1.99.1-gnu、CI windows-latest 默认 MSVC host——fmt/test 语义一致但链接器/运行时行为与产物二进制不同，问题可能在另一侧才复现。修复：package.json 加 engines；发布产物以哪侧为准需定口径。

### 79#8（=J-9）CI 内联复制 make 目标 + 前端双重构建

- ci.yml:39-54 手写四步与 Makefile 逐字一致（已核对）但两处需人工同步；「Frontend build」步骤 + tauri build 的 beforeBuildCommand 在 CI 跑两遍前端构建。修复：CI 调 make check（或抽公共脚本）。

### 79#9（=J-5）release profile 全默认——二进制带符号、体积偏大

- Cargo.toml 无 [profile.release]——strip=none/lto=false 默认；NSIS 比 strip+lto 方案更大且符号随分发物外泄（逆向面）。dev-dependencies 隔离已核实无误。

### 79#10（=J-7/J-10/J-12~14 合并）边角

- tsconfig include 仅 src——vite.config.ts 不在类型检查内（当前无恙）；Makefile Windows SHELL 探测硬编码盘符、失败时错误晦涩（常规路径已核实可用）；check-versions 白名单缺 Cargo.lock 工作区包版本（暴露更慢但不漏网）；pre-push hook 依赖 AGENTS 的环境导出，GUI 客户端推送会因 dlltool 缺失失败（建议 hook 头注释说明前置）；CI actions 按 tag 未 SHA 钉扎（供应链可选项）。
