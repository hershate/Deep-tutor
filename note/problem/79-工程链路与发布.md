## 中

### 79#1（=J-1）安装包 SHA-256 只算不发布——用户无法校验分发物完整性

- 位置：`desktop/scripts/tauri.mjs:34-38` + `.github/workflows/ci.yml:55-60`。
- 传递链条：① tauri build 成功 → 复制安装包到 dist/ → 计算 source/destination 两次 SHA-256 仅自比对 ② 摘要比对后丢弃——不打印、不落 `.sha256`、CI artifact 只传 `dist/*.exe` ③ 终端用户（尤其 GitHub artifact 下载者）无法做完整性校验；哈希逻辑只覆盖「同机复制」这一最无风险环节。
- 影响范围：所有分发安装包的接收者。
- 修复方向：摘要写入 `dist/<name>.sha256` 随 artifact 上传并打印。

### 79#2（=J-2）collect-licenses 在 node_modules 整体缺失时静默成功——缺整族许可的安装包照常产出

- 位置：`scripts/collect-licenses.mjs:105-150/:252-255`。
- 传递链条：① node_modules 不存在（路径漂移/依赖未装）→ npm 段整体跳过（npmMissing=0、无披露）② 只要 cargo 侧有收录 → `copied>0` → exit 0 ③ 「零收录即失败」守卫只在两侧同时为零时触发；NOTICE 第 23 行「npm 依赖许可随包分发」的承诺被架空。
- 影响范围：合规安装包可能在管线失效时照常产出。
- 修复方向：node_modules 缺失按 npm 侧管线失败（exit 1）或清单显式披露。

### 79#3（=J-3）许可收集不递归嵌套 node_modules——嵌套运行时依赖静默缺失（连「缺失」都不计）

- 位置：`collect-licenses.mjs:108-149`（仅扫顶层含 @scope 一层；runtimeFilter 的嵌套名生成后从未被主扫描使用）。
- 传递链条：npm 因版本冲突未提升的嵌套包（node_modules/x/node_modules/y）不收录不计 missing——同依赖双版本进 vite 产物时嵌套副本许可缺失且清单无感知。peerDeps 与 overrides（katex 实测按实际树收录）当前无恙。
- 修复方向：扫描递归一层嵌套 node_modules 或按 lock 实际树枚举。

## 低

### 79#4（=J-4）tauri.mjs bundle 路径硬编码 + 构建失败不清理 dist 旧包

- 位置：`desktop/scripts/tauri.mjs:25`（`target/release/bundle/nsis` 硬编码）+ 构建失败早退分支。
- 传递链条：① 用 `--target <triple>` 或 `--debug` 构建 ② 实际产物在 `target/<triple>/…/nsis`，脚本仍去硬编码路径找 ③ 误报「找不到安装包」；另一路径——构建失败早退不清 dist → 同版本旧 exe 残留可被误当新产物（本地 dist 已堆 1.0.0→1.1.2 共 9 个历史包，均正确 gitignore 未入库）。
- 影响范围：非默认构建参数时的误报；本地 dist 卫生。修复：按 target 推导路径；复制前清理同版本旧文件。

### 79#5（=J-6）verify-native 协议未接入 CI——安装包层回归只能人工验收

- 位置：`main.rs` 的 `--verify-native` 入口（0/2 契约完整、绕过单实例、DEEPTUTOR_VERIFY_DATA_DIR 绝对路径强制）；`.github/workflows/ci.yml` 无任何调用。
- 传递链条：① CI 构建 NSIS → 直接上传 artifact ② 产出的安装包从未被安装或执行验证 ③ 打包配置/资源缺失类回归只能靠人工装包发现——协议夹具与构建成功不能替代安装包层验收（AGENTS 已声明此边界）。
- 影响范围：发布链路最后一环的人工依赖。修复：CI 加一步解包后对 exe 跑 verify-native 断言 exit 0。

### 79#6（=J-11）rust-toolchain profile="minimal" 不含 rustfmt——新机首跑 make lint 即挂

- 位置：`rust-toolchain.toml:4`（profile="minimal" = rustc/cargo/stdlib）。
- 传递链条：① 新机 clone → rustup 按 toml 自动装 1.99.1 minimal（无 rustfmt 组件）② 首跑 make lint/make check → `cargo fmt` 报组件缺失即挂 ③ 本机能跑靠 F 盘工具链手工补装、CI 能跑靠 dtolnay action 默认 profile 含 rustfmt——两侧机制各自兜底，第三个环境（贡献者/新机）必挂。
- 影响范围：新环境上手成本。修复：toml 加 `components = ["rustfmt"]`。

### 79#7（=J-8）Node 无本地钉扎；本地 gnu vs CI msvc 双环境缝隙

- 位置：ci.yml `node-version "24"`（浮动 minor）；仓库无 engines/.nvmrc；AGENTS 声明本地 1.99.1-gnu，CI windows-latest 默认 MSVC host。
- 传递链条：① Node 大版本外无钉扎——本地与 CI minor 可漂移 ② Rust 侧本地 gnu、CI msvc：fmt/test 语义一致，但链接器与运行时不同、产物二进制不同 ③ 同一 bug 可能在另一侧才复现；发布产物以哪侧为准无口径。
- 影响范围：双环境缝隙下的「我这能跑」偏差。修复：package.json 加 engines；发布产物定侧。

### 79#8（=J-9）CI 内联复制 make 目标 + 前端双重构建

- 位置：`ci.yml:39-54`（手写四步，已核对与 Makefile 逐字一致）；「Frontend build」步骤 + tauri build 的 beforeBuildCommand。
- 传递链条：① Makefile 改动需人工同步 CI 内联副本——两处漂移风险 ② CI 先显式跑一遍前端构建、tauri build 的 beforeBuildCommand 再跑一遍——每次 CI 双倍前端构建时长。
- 影响范围：维护双份；CI 时长浪费。修复：CI 调 make check（或抽公共脚本）。

### 79#9（=J-5）release profile 全默认——二进制带符号、体积偏大

- 位置：`desktop/src-tauri/Cargo.toml`（无 [profile.release] 段）。
- 传递链条：① cargo 默认 strip=none/lto=false ② NSIS 内二进制带完整符号、体积偏大 ③ 符号随公开分发物外泄（降低逆向成本）；对照 strip+lto 方案可显著缩包。
- 影响范围：安装包体积与逆向面。dev-dependencies 隔离已核实无误。

### 79#10（=J-7/J-10/J-12~14 合并）边角五项

- **79#10a tsconfig 覆盖缺口**（J-12）：`tsconfig.json` include 仅 src——`vite.config.ts` 不在 tsc 类型检查内。链条：vite.config 出类型错误 → tsc 不报、仅在构建器加载时暴露（当前无恙）。影响：类型门禁盲区。
- **79#10b Makefile SHELL 探测**（J-13）：Windows 分支硬编码盘符探测，失败时报错晦涩（常规路径已核实可用）。链条：非标准 Git Bash 安装位 → 探测落空 → 用户看到的是晦涩的 shell 错误而非「请设 SHELL=…」。
- **79#10c check-versions 白名单缺口**（J-14）：白名单不含 Cargo.lock 工作区包版本——版本漂移要等 cargo check 才暴露（更慢但不漏网）。链条：改版本漏 Cargo.toml → check-versions 过 → cargo --locked 编译时才失败。
- **79#10d pre-push hook 环境依赖**（J-7）：hook 内跑 fmt/test 依赖 AGENTS 声明的 dlltool PATH 导出——GUI 客户端（无该导出）推送会因 dlltool 缺失失败，报错不指向原因。链条：hook 头无前置说明 → GUI 推送失败 → 用户需查文档才知道要导出 winlibs PATH。建议 hook 头注释说明。
- **79#10e CI actions 未 SHA 钉扎**（J-10）：actions 按可变 tag 引用（如 dtolnay/rust-toolchain@stable）——上游 tag 被移动即引入供应链变化。链条：CI 凭 contents:read 最小权限缓解，但引用本身可变。属可选项加固。
