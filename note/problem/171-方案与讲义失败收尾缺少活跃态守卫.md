# 171：方案与讲义失败收尾缺少活跃态守卫

## 现象与触发条件

方案或讲义已进入 done/degraded/interrupted 等终态后，旧工作线程的迟到失败收尾仍可改写主行并发送失败事件。恢复与仍存活任务交叠、重复失败收尾是触发条件。

## 传递链条

1. `desktop/src-tauri/src/backend/learning/mod.rs:801-826` 的 `fail_plan` 按 id 无条件 UPDATE，无状态条件。
2. 同文件 `:829-881` 的 `complete_plan` 已有终态检查；`:984-1038` 的 `recover` 只更新 running/cancelling，说明终态不能被旧任务覆盖是既有约束。
3. `desktop/src-tauri/src/backend/learning/lecture.rs:770-797` 的 `fail_lecture` 虽在 SQL 写 running/cancelling，但不检查影响行数，始终写入并发送 lecture.failed/cancelled。
4. 前端 `PlanGenerator`、`StudyRoom` 依据这些事件刷新，过期失败事件会制造错误提示和错误的状态顺序；方案主行还可能实际回退到 failed。

## 影响范围

影响方案生成、讲义生成、启动/备份恢复与停机超时后的交叠路径。正常单次生成不触发；取消、恢复和真实终态的持久化约束会被破坏。

## 修复验收

两处失败收尾只在主行仍活跃时更新；未更新时不写事件、不发送。已 done/degraded/interrupted 的记录经过迟到失败调用后保持原状态，outbox 不增加终态事件。
