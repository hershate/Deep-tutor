## P3

### 115#1 Community 初载失败永久转圈、groups 页签全空白——无错误态无重试

- 位置：`desktop/src/pages/Community.tsx:59`（`void refresh().catch(reportBackendError)`——catch 只派发 5 秒 toast，`data` 恒 null）；`:164`（`{!data && <div className="page-loading" role="status">…正在读取真实讨论…</div>}`——失败态复用加载态，永久转圈）；`:165`（groups 页签 `data?.groups.map` 直接空渲染，连加载指示都没有）。
- 传递链条：①进入学习社区，`communityBackend.overview` 或 `getCollection('projects')` 拒绝 → ②仅 5 秒 toast，data 恒 null → ③讨论页签永久「正在读取真实讨论…」转圈；groups 页签一片空白；④无任何重试入口，恢复仅靠用户无从得知的隐性路径（切页签等待 community.* 事件）。对照同库既有标准：Review.tsx:157（loadError+重试横幅）、Reports.tsx:91。
- 影响范围：社区首载故障的用户被卡死在假加载态。
- 修复方向：加 loadError 状态，失败渲染错误横幅+重试（对齐 Review.tsx:157）；groups 页签补 data 为 null 时的加载/错误两态。

### 115#2 UsagePanel 预算输入受控值即时转 Number——小数点被吃、预算防线被静默放大

- 位置：`desktop/src/components/UsagePanel.tsx:106`（`<input type="number" … value={sessionUsd} onChange={event => setSessionUsd(Number(event.target.value))} />`，dailyUsd 同款；`saveBudget`（:73-83 一带）无本地校验直接提交）。
- 传递链条：①用户想把会话预算从 1 改成 1.5，键入「.」→ ②浏览器对 type=number 的坏输入态报 value 为 "1"/""，`Number()` 归一为 1 或 0，受控 value 立即回写——小数点被吃或整框归零 → ③再键「5」得到「15」→ ④点「保存原生预算」直接提交，15 USD 落库——预算是「达到后不再发起新请求」的防线语义，被静默放大 10 倍，不盯输入过程不会发现。对照同文件 :105 的费率输入用字符串 state（inputRate/outputRate）无此问题。
- 影响范围：所有调整预算为小数的用户；金额防线语义受损。
- 修复方向：预算改字符串草稿 + 失焦/提交时解析（对齐同文件费率输入模式）。

### 115#3 Settings 学习档案加载失败时三个区块静默缺失——SectionHeader 还在，像「功能本来就没有」

- 位置：`desktop/src/pages/Settings.tsx:68`（`void load().catch(reportBackendError)`）、`:129`（`{profile && <>…}` 个人学习档案整块）、`:130`（`{profile && <label>默认讲解方式…}`）、`:131`（`{profile && <label>免打扰时段…}`）。
- 传递链条：①进入设置页，`engagementBackend.profile()` 失败（或未返回）→ ②仅 5 秒 toast（或无感）→ ③「个人学习档案」区块只剩标题空白、「导师行为」缺讲解方式下拉、「通知与专注」缺免打扰下拉——分区标题照常渲染，视觉上是「本来就没这些功能」；④无重试，恢复仅靠 session_started/preferences 事件或重进页面。
- 影响范围：档案加载失败场景的设置主功能缺失且不可发现恢复路径。
- 修复方向：profile 为 null 时区分加载中/失败两态，失败给横幅+重试（对齐 StudyRoom.tsx:275）。

### 115#4 预约提醒 toast 不受免打扰时段约束——「不主动弹出提醒」承诺被唯一主动弹窗通道绕过

- 位置：`desktop/src/App.tsx:220-229`（claim 轮询 `due.length` 非零即 `notify("预约「X」即将开始")`，不读任何 suppressed 状态）；后端已算好该字段：`engagement/mod.rs:756`（`suppressed: quiet(&preferences, …)`）；承诺文案 `App.tsx:454`（「当前处于免打扰时段；通知仍保留在中心，不主动弹出提醒。」）。
- 传递链条：①用户处于免打扰时段；②60s claim 轮询/visibilitychange 恢复触发领取；③App 的 claim effect 无条件弹 toast；④终态：免打扰期间仍被主动打断——与通知中心文案、设置页「免打扰时段」语义直接矛盾。`suppressed` 全前端仅 454 行作说明文字，无行为消费。
- 影响范围：所有开启免打扰的用户在预约到期时。
- 修复方向：claim effect 读取最新 `notifications.suppressed`（或单独调判定），suppressed 时跳过 toast、只落通知中心。

### 115#5 SubjectivePractice 作答 textarea 无可访问名称——读屏用户在核心作答路径失去上下文

- 位置：`desktop/src/components/SubjectivePractice.tsx:143`（`<textarea rows={…} value={…} onChange={…} disabled={recorded || busy} placeholder="先组织自己的回答…" />`——无 label 关联无 aria-label；placeholder 不构成可访问名且输入即消失）。
- 传递链条：①读屏用户 Tab 进入作答框 → ②读屏只播报「编辑框」或空名 → ③不知道这是「简答/论述作答」框。对照同型控件：ExamWorkspace.tsx:201 有 `aria-label={…作答：…}`、WikiPanel.tsx:158 有 `aria-label="向知识库提问"`、Community 回复框有 `aria-label={回复帖子：…}`——主观题作答是本组件核心路径，唯一漏网。
- 影响范围：读屏用户的主观题练习核心交互。
- 修复方向：补 `aria-label={`作答：${question.prompt}`}`（对齐 ExamWorkspace）。

### 115#7 UsagePanel / Integrations 首载成功后，事件驱动的刷新失败完全静默——页面停留旧数据零提示

- 位置：`UsagePanel.tsx:39`（catch 只 setError+toast）与 `:100`（`if (!data && error)`——error 仅在无 data 时渲染）；`Integrations.tsx:18-23`（catch 只 setLoadError，连 toast 都没有）与 `:115-117/:123/:130`（loadPending 仅 data 为空时渲染）。

### 115#8 Community busy 在途期间 accept/toggleGroup/reserve 按钮可点但静默无反应

- 位置：`Community.tsx:163`（`<button onClick={() => void accept(item.id, !item.accepted)}>` 无 disabled，同行 like/bookmark 有 `disabled={busy}`）、`:165`（加入/退出小组 Button）、`:166-167`（预约提醒/取消预约 Button，仅按小组加入态禁用）。

### 115#14 MediaPlayer onError 后未清 url——损坏的播放器元素与错误框+「重试读取」并存

- 位置：`MediaPlayer.tsx:50`（unsupported 只 setError）、`:55-57`（`{url && mime.startsWith('video/') && <video … onError={unsupported} …/>}`——url 保留，损坏的 video/audio/img 与 form-error 同屏）。
