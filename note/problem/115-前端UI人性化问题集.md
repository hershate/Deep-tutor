### 115#1 Community 初载失败永久转圈、groups 页签全空白——无错误态无重试

- 位置：`desktop/src/pages/Community.tsx:59`（`void refresh().catch(reportBackendError)`——catch 只派发 5 秒 toast，`data` 恒 null）；`:164`（`{!data && <div className="page-loading" role="status">…正在读取真实讨论…</div>}`——失败态复用加载态，永久转圈）；`:165`（groups 页签 `data?.groups.map` 直接空渲染，连加载指示都没有）。
- 传递链条：①进入学习社区，`communityBackend.overview` 或 `getCollection('projects')` 拒绝 → ②仅 5 秒 toast，data 恒 null → ③讨论页签永久「正在读取真实讨论…」转圈；groups 页签一片空白；④无任何重试入口，恢复仅靠用户无从得知的隐性路径（切页签等待 community.* 事件）。对照同库既有标准：Review.tsx:157（loadError+重试横幅）、Reports.tsx:91。
- 影响范围：社区首载故障的用户被卡死在假加载态。
- 修复方向：加 loadError 状态，失败渲染错误横幅+重试（对齐 Review.tsx:157）；groups 页签补 data 为 null 时的加载/错误两态。

### 115#2 UsagePanel 预算输入受控值即时转 Number——小数点被吃、预算防线被静默放大

- 位置：`desktop/src/components/UsagePanel.tsx:106`（`<input type="number" … value={sessionUsd} onChange={event => setSessionUsd(Number(event.target.value))} />`，dailyUsd 同款；`saveBudget`（:73-83 一带）无本地校验直接提交）。
- 传递链条：①用户想把会话预算从 1 改成 1.5，键入「.」→ ②浏览器对 type=number 的坏输入态报 value 为 "1"/""，`Number()` 归一为 1 或 0，受控 value 立即回写——小数点被吃或整框归零 → ③再键「5」得到「15」→ ④点「保存原生预算」直接提交，15 USD 落库——预算是「达到后不再发起新请求」的防线语义，被静默放大 10 倍，不盯输入过程不会发现。对照同文件 :105 的费率输入用字符串 state（inputRate/outputRate）无此问题。
- 影响范围：所有调整预算为小数的用户；金额防线语义受损。
- 修复方向：预算改字符串草稿 + 失焦/提交时解析（对齐同文件费率输入模式）。

### 115#6 WikiPanel 初载失败显示假空态「尚无问答历史」——文案断言与事实不符

- 位置：`desktop/src/components/WikiPanel.tsx:38`（`void refresh().catch(reportBackendError)`）与 `:159`（`{!sessions.length && <p className="form-help">尚无问答历史；提问后会保存在本地。</p>}`）。

### 115#7 UsagePanel / Integrations 首载成功后，事件驱动的刷新失败完全静默——页面停留旧数据零提示
