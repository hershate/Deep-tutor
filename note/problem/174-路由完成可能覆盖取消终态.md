# 174：路由完成可能覆盖取消终态

## 现象与触发条件

路由上游已成功返回，用户在路由 `finish` 提交前取消。路由行已处于 cancelling，但完成路径仍可写入 done，并发送 route_completed。

## 传递链条

1. `desktop/src-tauri/src/backend/providers/routing.rs:1317-1376` 的取消将 running 改为 cancelling 并保存取消标志。
2. `:880-909` 的 `finish` 直接按 `result.status` 更新，没有读取当前状态或限制 WHERE 活跃态。
3. 同一函数始终把事件写成 `provider.route_completed`，即使结果状态为 cancelled。
4. `:1278-1280` 随后把原 result 返回给调用方，导致数据库、事件和返回值可能不一致。

## 影响范围

影响路由模式的模型请求、Agent、方案、讲义、练习和 Wiki 的取消边界。已产生的输出与用量应保留，但取消后不得显示为正常完成。直连与聚合不使用路由故障转移，仍由同一 finish 处理终态。

## 修复验收

cancelling 加迟到完成时，路由终态为 cancelled，事件为 route_cancelled，返回对象状态一致；已有终态不被改写或重复通知。已有取消与故障转移测试必须通过。
