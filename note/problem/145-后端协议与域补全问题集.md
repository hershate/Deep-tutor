### 145#1 Gemini Native 协议工具调用条目无上限，故障/恶意端点可无界膨胀内存并无限滞留 worker（55#1 三协议防线缺口）

- 位置：`desktop/src-tauri/src/backend/providers/gemini.rs:244-257`（
  `output.tool_calls.insert(tool_index, …)` 后 `tool_index += 1`，无上限检查）。
  对照其余三协议同根防线：`openai.rs:19`（`MAX_TOOL_CALL_ENTRIES: usize = 256`）+
  `openai.rs:1152-1157`、`anthropic.rs:183-186`、`responses.rs:188-193`（均
  `index >= 上限 → invalid_tool_call/invalid_response` 错误），openai 路径 55#1
  注释自述目的：「distinct index 无上限时畸形流可用极小事件让 BTreeMap 无限
  增长直至 EOF」。
- 传递链条：①用户自配 Gemini 兼容端点（自定义 base_url，协议 Gemini Native）
  故障或被劫持；②端点持续发送每行含多个 functionCall 的 SSE 事件——id 缺省时
  本地生成（gemini.rs:238-243）、args 取 {}，单条目约 40 字节，绕过 25#17 的
  256KB 单参数上限（只约束 arguments 累计），行级 64KB 上限内可塞约 1800 个
  最小调用；③每次 insert 计入 produced_bytes()（openai.rs:1009-1019 含
  tool_calls 规模），protocol.rs:364-375 的「零产出累计 1MB」空闲预算随之恒归
  零，行级 64KB 与空闲 1MB 上限全部失效；chunk_timeout（默认 120s）只约束单
  chunk 间隔——持续发送的流永不触发任何终止条件，tool_calls BTreeMap 无界
  增长、worker 线程无限滞留（取消入口仍可用：protocol.rs:315-320 每 100ms 检查）。
- 影响范围：受影响=Gemini Native 协议下长时间保持连接的故障/恶意端点流
  （1Mbps 持续一小时约膨胀数百 MB 内存）；不受影响=官方 Gemini 端点与 OpenAI
  Chat / OpenAI Responses / Anthropic Messages 三协议（上限在码）。损害性质=
  资源卫生（内存无界+worker 滞留），无数据损害。
- 修复方向：与三协议同口径——`tool_index >= openai::MAX_TOOL_CALL_ENTRIES` 时
  返回 `output.error("invalid_tool_call", "工具调用数量超出上限")`。

### 145#2 practice generate/resume 的域内 active Mutex 覆盖整个 IMMEDIATE 事务——141#1 同型未列入的两个入口（并案补全）

- 位置：`desktop/src-tauri/src/backend/practice/mod.rs:692-731`（generate：
  `active.lock()` 在 :692-695、store() 与 IMMEDIATE 事务 :696-730、drop 在
  :731）；`practice/mod.rs:1752-1806`（resume 同型）。与 141#1 的三个入口
  （agent send/resume、practice subjective submit）同锁同型——整个
  HashMap<i64, Arc<AtomicBool>> 的域锁，非按 id 分锁。
- 传递链条：与 141#1 完全同型——①备份导入/维护 vacuum 持全局 store 互斥锁与
  库写锁期间，用户调用 generate_practice_set 或失败后 resume_practice_set
  （同步命令，主线程执行）；②先取 state.active，随后开 IMMEDIATE 事务——事务
  在 busy_timeout 上等待最长 10 秒，期间 active 锁不释放；③并发窗口内
  cancel_practice_generation（mod.rs:1609-1615）与登出/切换停机集合的
  practice::stop（mod.rs:1653-1659）在同一把 HashMap 锁上排队，主线程冻结面=
  锁等待+事务时长。141#1 修复方向只提「practice subjective submit 同型一并
  收口」，generate/resume 两个主入口未列入，本轮全文深读补全。
- 影响范围：受影响=长写事务进行中同时发起练习生成/恢复并尝试取消/登出的并发
  窗口；不受影响=常态单命令场景（锁窗口毫秒级）。损害性质=主线程冻结面+
  取消入口延迟，非数据损坏（锁释放后取消仍生效）。
- 修复方向：对齐 learning/lecture.rs:302-313 的 register 模式——锁内只做运行中
  检查与登记，IMMEDIATE 事务移出锁窗口，commit/launch 失败补偿移除登记；与
  141#1 收口一并实施。
