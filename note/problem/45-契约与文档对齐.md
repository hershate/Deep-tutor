## 信息性

### 45#1 四条无调用方的命令与两条死封装——37#5 改造后的残留

- 位置与链条：
  - `events_since`（注册 `main.rs:96`，实现 `backend/commands.rs:112-115`）：38#2 删除前端翻页后全仓无 UI 调用方；但 commands/web/projects/export/notes 等模块的 IPC 级测试以它作事件断言通道（16-19 轮 README 已注记为**有意保留**）。
  - `fetch_webpage`（`main.rs:159`，`web/commands.rs:9-12`）：`web.ts:5-6` 有文档豁免注记（21#3），`import_webpage` 在 Rust 内部直调 `fetch()`，命令无前端调用方。
  - `export_practice_mistakes`（`practice/commands.rs:76-79`）+ 死封装 `src/backend/practice.ts:115`：37#5 后 UI 走 `exportMistakesFile`（`Practice.tsx:160-162`）。
  - `export_usage_csv`（`providers/commands.rs:245-248`）+ 死封装 `src/backend/usage.ts:16`：UI 走 `exportCsvFile`（`UsagePanel.tsx:83-85`）。
- **影响范围**：纯死代码，无运行时影响。注意 `Practice.tsx:157` 的组件本地函数也叫 `exportMistakes`（走新命令）而 `practice.ts:115` 的同名包装走旧命令——同名不同物，读代码时易混淆。清理方向：删两条死封装；两个旧导出命令若确认无其他消费方（测试）可一并下线。

### 45#2 三处 serde_json::Value 上的 TS 类型断言——键名经核对与后端实际写入一致

- 位置：`desktop/src/backend/client.ts:120-125`（`LearningPlan.artifacts`）、`:82-90`（`LearningResult.resources`）、`:304`（`AgentArtifact.content`）。
- **传递链条**：① 后端生成/写入（`learning/mod.rs:712` 以 `$.step{index}` 写 artifacts；`pipeline.rs:126-130` 写 `items/externalSearch`；讲义 JSON 存 agent 产物）→ ② Rust 侧类型为 `serde_json::Value`（无编译期键约束）→ ③ IPC 序列化原样透传 → ④ 前端 TS 断言为具体结构并直接取键——**若后端改键名，编译期不报错、运行时取到 undefined**。
- **影响范围**：当前无任何用户可见影响（本轮逐键核对写入侧与断言侧一致）；风险是前瞻性的——三处是全仓仅有的「类型系统不设防」边界，后端重构改键时最易静默断链。受影响人群=未来改 learning/agent JSON 结构的开发者与随之受害的用户；不受影响=当前版本全部功能。信息级：建议给三处加运行时键存在性断言或后端 typed struct。

### 45#3 DESIGN.md「表面圆角 9–18px」与 styles.css 少量 8px 小件不符

- 位置：`desktop/DESIGN.md:27`（区间下限 9px）；`desktop/src/styles.css:88/360/401/482`（`.skip-link`/`.calendar-event`/`.lesson-list > button`/`.note-context` 为 8px）。
- **传递链条**：① 开发者按 DESIGN.md 区间书写新组件圆角 → ② 与既有 8px 小件并排（如同页面的日历事件与表面卡片）→ ③ 视觉上 1px 差异肉眼难辨——规范与实现间的漂移只影响设计审查一致性，不影响用户操作。
- **影响范围**：仅设计规范维护者；主表面（.surface 16px、note-card 13px、term-grid 9px）均在区间内且文档同段本有弹性口径（「不要求全部取 4/8 倍数」），属边界情况。用户零感知。修复方向（可选）：文档区间改 8–18px 或小件升 9px。

### 45#4 仓库根空壳 backend/ 目录残留

- 位置：仓库根 `backend/`（仅含被 .gitignore:15 忽略的 `.pytest_cache`；`git ls-files backend` 无输出）；README.md:70 声明 Python 后端已删除。
- **传递链条**：① 历史某次运行 pytest 在根 backend/ 留下缓存 → ② Python 后端删除时只清了 git 跟踪文件 → ③ 未跟踪的 `.pytest_cache` 残留至今 → ④ 对新读者造成「是否还有 Python 后端」的瞬时困惑（README 已澄清）。

## 正向结论（两轴全对齐的明细）

- **命令轴**：前端调用 189 个应用命令全部在 main.rs 注册（191/191 定义=注册，含 4 个 `#[tauri::command(async)]`）；参数键名经 Tauri 2 默认 camelCase 转换逐条对齐（约 20 组带参命令）；Option/null/undefined 语义（缺键→None）全部命中。
- **事件轴**：全仓唯一 emit 点 `backend/commands.rs:22-26` 单通道 `backend://event`；信封 4 字段（id/kind/payload/createdAt）与 TS 一致；前端消费的约 15 组 payload 字段（provider.route_attempt 8 字段、chat_delta 的 reasoning:bool、agent.* 的 runId/sessionId、state.changed 的 namespace、plan.*/study./material.*/lecture.*/community.* 等动态 kind）逐组与后端 json! 字面量一致；前端引用的全部事件 kind（约 110 个）无拼写漂移。
- **capabilities**：六项授权与前端实际插件调用一一对应（listen/unlisten、dialog open/save×9 处、opener open-url[https scope]/reveal-item-in-dir），`onDragDropEvent` 由 core:event:allow-listen 覆盖且 dragDropEnabled: true；`backend/commands.rs:577-612` 有守卫测试锁死。
- **文档量化**：note/14 的 18 预设/八步流水线/四档反馈/8 导出格式、决策的 64MB/1MB/1000 条/压缩比/ZIP 五上限/24h 调度/保留 10 版/20 秒初始等待/SCHEMA_VERSION 2/JWT HS256 七日/PAT SHA-256/256KiB 分块、README 五处版本 1.1.0、195 个测试、CI 与 Makefile 命令逐字一致，全部实测吻合。
- **行为声明**：导出原生保存对话框、全窗口拖放、密钥只进 keyring（前端无 localStorage/sessionStorage）、https 外链走系统浏览器、--verify-native 无界面通道、NSIS 打包与 dist 产物 SHA 校验脚本等抽查全部有实现且 file:line 在案。
- **DESIGN 基线值**：色彩令牌/字体栈/16px 正文/12px 最小字号/行高 1.85/侧栏 248px/顶栏 64px/断点 700-1024-1280/switch 46×26 与 styles.css 逐项一致。
