## P-075 工具参数不是 JSON 对象或不是有效 JSON（以及 call.id 超限）时整轮运行直接失败，而不是作为工具结果回给模型

严重度：低 | 状态：已复核 | 分类：logic | 位置：desktop/src-tauri/src/backend/agent/tools.rs:600-616、545-550；desktop/src-tauri/src/backend/agent/mod.rs:1180、560-571

### 详细说明

触发条件：模型返回的工具调用 arguments 不是 JSON 对象（顶层为数组、字符串或数字）或不是合法 JSON；或 call.id 为空、超过 128 字节，或 arguments 超过 64KB（tools.rs:545-550）。本地小模型流式拼接参数时产出非法 JSON 不罕见。

实际行为：`execute` 先把工具调用登记为 running（tools.rs:552-555），随后解析参数；参数非法时在 `finish_failed_tool_call` 收尾登记行之后直接 `return Err`（tools.rs:600-616），错误从函数逃出。`run_loop` 以 `tools::execute(...)?` 调用（mod.rs:1180），`?` 把错误上抛使 `run_loop` 返回 Err，工作线程据此把运行置为 failed 并附带错误（mod.rs:560-571）。同一函数内其余参数校验错误（缺 key、类型不符等）在闭包内被包装成 `{"status":"failed","error":{...}}` 的正常结果返回（tools.rs:800-805），模型可读到错误并修正参数后重试——两条路径的处理方式不一致。

用户可见后果：Agent 工作台出现错误横幅「invalid_tool_arguments：工具参数必须是 JSON 对象」或「工具参数不是有效 JSON」，运行状态标记为失败（AgentCenter.tsx:138），用户需点「恢复运行」继续。恢复时 23#9 的历史修剪会把无对应回复的 tool_calls 从重放序列裁掉，序列恢复自洽（mod.rs:741-744），但每次坏参数仍造成一次用户可见中断。
