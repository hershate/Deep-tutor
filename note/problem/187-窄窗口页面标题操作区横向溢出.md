# 187：窄窗口页面标题操作区横向溢出

## 证据

- `desktop/src/styles.css:170-174` `.page-heading` 默认横排且没有换行。
- `desktop/src/styles.css:364-370` 小于 640px 时仅改为顶部对齐，同时强制末尾操作区 `flex-shrink: 0`，并将说明文字限为 280px。
- `desktop/src/pages/PlanGenerator.tsx:353` 等 13 个页面在该区域放置历史方案下拉框、多个按钮或分段控件；全局 `select { width: 100% }` 与长方案名进一步增加最小内容宽度。
- 仅 Plan/ProviderHub/Reports/Settings 有各自的纵向覆盖，其他页面没有统一的窄窗出口。

## 完整传递链条

375px 窗口 → 页面内容宽约 343px → 左侧标题和右侧不可收缩操作区仍保持同一 flex 行，另有 20px 间距 → 长方案名、下拉框或多个操作按钮的最小宽度超过可用空间 → 操作区被挤出页面，产生横向溢出、控件移出对应框或不可见。

## 影响范围

- PlanGenerator、Dashboard、Library、KnowledgeMap、Practice、Review、Projects、Community、Integrations 等使用统一 `.page-heading` 的页面。
- 窄窗口、长目标文本、大字模式下的全部标题操作入口。
- 不影响后端数据与命令，仅影响可达性和布局。

## 修复验收

- 小于 640px 时所有页面标题区统一纵向排列，操作区可收缩并占满可用宽度，说明文字不再固定为 280px。
- 保留各页面已有的同类覆盖，行为不互相冲突。
- 增加全局窄窗样式契约检查，前端生产构建通过；真实窗口交互验收仍按项目约束单独记录。
