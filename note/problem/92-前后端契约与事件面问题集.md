## 信息

### 92#1 events_since 注册但前端零调用，构成 IPC 死命令面

- 位置：注册 `desktop/src-tauri/src/main.rs:190`（`commands::events_since,`）；定义 `backend/commands.rs:185-188`；前端 desktop/src 全目录 grep `events_since` 零命中。
- 传递链条：①前端已改为「事件触发即全量快照」策略（useBackendState.ts:56-59 注释明确废弃逐页 eventsSince 拉取） → ②命令仍暴露在 invoke_handler → ③WebView 侧任何脚本可调用该命令逐页读取事件表；与 main.rs 中已主动移除的 fetch_webpage/stream_provider_chat_with_tools/export_usage_csv/export_practice_mistakes（main.rs:255-331 注释留痕）属同类，但此命令仍留在注册表。
- 影响范围：无功能缺陷；增大 IPC 暴露面，且「注册表=实际使用面」的读者预期被打破（维护心智负担）。
- 修复方向：从注册表移除并留注释（同 61 号删 export_usage_csv 的先例）；或若计划恢复增量拉取则在前端补消费方。

### 92#2 六类事件 kind 无任何专项监听，仅靠全局快照兜底

- 位置：后端发出 `application.reset`（store.rs:823-825）、`backup.exported`/`backup.imported`（backup 域）、`content.exported`（export 域）、`draft.saved`/`draft.deleted`（store.rs:758/772-774）；前端 27 处 onBackendEvent 分支（App.tsx:151/177、useAgent.ts:133、SecurityPanel.tsx:59、SyncPanel.tsx:53、MaintenancePanel.tsx:32、SharePlanDialog.tsx:47、ExportCenter.tsx:62、AgentTaskCenter.tsx:59、SubjectivePractice.tsx:79、UsagePanel.tsx:45、WikiPanel.tsx:43、PlanGenerator.tsx:126、Practice.tsx:86、KnowledgeMap.tsx:85、Projects.tsx:80、Community.tsx:63、ExamWorkspace.tsx:102、Integrations.tsx:53、Plan.tsx:86、Reports.tsx:60、Library.tsx:127/152、ProviderHub.tsx:149、StudyRoom.tsx:78/161、Review.tsx:62、Settings.tsx:69）无一覆盖。
- 传递链条：①这六类操作的发起方 UI 直接消费命令返回值 → ②事件到达时无组件响应，仅 useBackendState.ts:192 全局合并快照刷新（requestSyncCoalesced） → ③数据不失步，但多窗口/未来多视图场景下这六类变更无定向通知路径。
- 影响范围：当前单窗口架构下无用户可见缺陷；事件契约的「发出面=消费面」不对称，属可维护性债。
- 修复方向：维持现状可接受；若做事件契约清单（emit 面 ↔ 监听面双向文档化），把这六类标注为「仅全局快照消费」。

### 92#3 AgentArtifact.content 为自由 Value 透传，前端窄化断言无运行时守卫

- 位置：Rust `desktop/src-tauri/src/backend/agent/mod.rs:136`（`pub content: Value`）；TS `desktop/src/backend/client.ts:324`（`content: LectureContent`，无守卫窄化）。
- 传递链条：①后端把讲义产物 JSON 作为自由 Value 存取 → ②前端类型断言为 LectureContent 直接渲染 → ③后端侧键名漂移（Value 无编译期约束）在渲染层以 undefined 形式暴露（讲义字段空白），而非可定位的类型化错误。
- 影响范围：Agent 产物渲染面；对照同边界 `LearningPlan.result.resources` 已有运行时守卫 `guardLearningPlan`（client.ts:355-362，注释明说「后端 Rust 侧为自由 Value，改键名编译期不报错」）——该范式未推广到本处。
- 修复方向：为 artifacts[].content 补 guardArtifactContent 运行时守卫（同 guardLearningPlan 范式），坏形状降级为「产物格式不受支持」提示。

### 92#4 Agent 域 id 的 TS 类型为 number 而 Rust 侧为 String，靠手工 String() 约定维持

- 位置：TS `desktop/src/backend/client.ts:430-437`（getAgentSession 等声明接收 number）；Rust `agent/commands.rs:22-60`（`id: String`）；现存调用方手工转换 useAgent.ts:64/199/208/218/225/234-235、AgentTaskCenter.tsx:44（`String(id)`）。
- 传递链条：①TS 类型系统认为 id 是 number → ②serde 期望 JSON string，直接传 number 会整体反序列化失败（命令报错而非局部字段缺失） → ③当前靠 8 处调用点手工 String() 约定不出错；未来新增调用方漏写只会在运行时暴露为整条命令失败。
- 影响范围：Agent 域 10 个命令的调用约定；现状无 bug。
- 修复方向：client.ts 封装层入参改 string（或封装内统一 `String(id)`），让类型与 serde 期望对齐。
