## P2

### 155#1 focus_sessions.task_id 悬挂——常规操作链（用过专注→删任务→导出）产出的备份在任何目标机整单拒导入

- 位置：`desktop/src-tauri/src/backend/backup/transfer.rs:688`
  （`task_id → kv:tasks` 父表校验）；豁免表 `:1280-1285`
  （`lenient_backup_parent` 仅 provider_requests/provider_route_runs/
  events）；失败面 `:1088-1094` + `:1370-1382`（非豁免码即
  `invalid_backup_reference`「任务与笔记集合 缺少记录 N」整单拒绝）。
- 缺口：任务删除（kv replace）时只 GC 笔记与项目（`store.rs:916-925`
  仅 notes→learning_annotations、projects→project_versions）；
  focus_sessions 建行时校验任务存在（reports/mod.rs:318-324）但删除后
  无 GC（全仓仅 clear_all 一处 DELETE，reports/mod.rs:212）。
- 传递链条：①对任务用过专注 → focus_sessions 行携带 task_id；②在任务
  列表删除该任务（常规操作，无任何阻止或级联）；③导出 .dtbackup——
  备份内 focus_sessions 引用了 kv:tasks 已不存在的 id；④任意目标机
  （含本人换机恢复）导入 → 父表校验失败 → **整份备份不可导入**，恢复
  路径完全阻断。与 99#6（provider_requests 悬挂，已修 lenient）同类
  同危害，但 kv 类父表未纳入豁免/置空口径。
- 影响范围：受影响=所有「用过专注后删除对应任务」的备份导出。损害
  性质=数据保全承诺失效（备份在需要时不可恢复），确定性触发。
- 修复方向：任务删除 GC focus_sessions（store.rs:916-925 补
  `DELETE FROM focus_sessions WHERE task_id NOT IN (…)`），或
  lenient_backup_parent 纳入 focus_sessions（导入侧置空）——建议双侧。

## 待核

### 155#5 OPML 导出未滤 C0 控制字符——可产出非法 XML 1.0

- 位置：`export/formats.rs:198-200`（`xml_attr` 仅 `\n→&#10;`、删
  `\r`）；上游无过滤（笔记/草稿校验只限长度/空白 store.rs:1174-1185，
  material_text 解析亦不滤）。
- 传递链条：①用户粘贴含垂直制表符（\x0B）/换页符（\x0C）/\x00-\x08
  的笔记正文或资料解析文本含此类字符；②以笔记/资料范围导出 OPML；
  ③控制字符原样进入属性与 `<title>` 文本——XML 1.0 规定此类字符非法，
  严格解析器（多数 XML 工具/Anki 导入器）拒收整个文件。对照：PDF/Anki
  路径各自滤了控制符（anki.rs:45-56、pdf.rs:328），OPML/CSV/TXT/MD
  未滤——其中仅 OPML 因控制符整体解析失败。
- 影响范围：受影响=含控制字符内容的 OPML 导出文件可用性；不受影响=
  应用内数据与其余格式。export/tests.rs 无控制符用例。损害性质=导出
  产物不可用（触发依赖内容含罕见控制字符）。
- 修复方向：OPML 序列化统一滤 C0（保留 \t\n）。

### 155#6 原件导入扩展名不校验（加固项）

- 位置：`transfer.rs:1443-1456`（`materials/originals/{name}` 仅强校验
  stem==sha256 即 64hex 小写；扩展名任意、不限长、不限字符集——仅受
  12 组件路径限制）。
- 传递链条：①导入异常/敌意构造的 .dtbackup；②原件落盘为
  `{64hex}.{任意}`——可产生超长扩展名或怪异后缀文件；③后续导出原件
  按行内 kind 补扩展名，磁盘文件名与行 kind 可长期不一致。兜底：DB
  行级 sha 校验（137#1）+ install 包含检查 + 内容哈希一致性，文件不能
  逃出 originals 目录，也不能冒充其他资料的内容。
- 影响范围：受影响=异常备份导入后的文件区卫生；不受影响=正常自产
  备份（导出侧按 kind 命名）与数据完整性。损害性质=加固缺口（低）。
- 修复方向：导入侧扩展名白名单（与 12 媒体格式 + 文档格式对齐）。

- 修复方向：清除凭据时按 kind 双键都清，或保存时清掉非当前 kind 的
