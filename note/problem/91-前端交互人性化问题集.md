### 「点击打开工作区是否弹出任务管理器式选择器」——未发现

- 证据：应用内所有「在资源管理器中显示」入口（DataDirectoryPanel.tsx:93、BackupPanel.tsx:63、
  ExportCenter.tsx:121）统一走后端 `reveal_path`（commands.rs:47-64，白名单校验后经
  tauri-plugin-opener 2.7.2 的 `reveal_item_in_dir`）；该插件 Windows 实现直接调
  `ShellExecuteExW`（reveal_item_in_dir.rs:102-164），定位目录/文件由资源管理器处理，
  不经过「选择打开方式」关联查册。外链入口（UI.tsx:22、ProviderHub.tsx:410）走
  `opener:allow-open-url`（https scope）→ `ShellExecuteW` 默认浏览器，同样无关联选择器。
  目录未就绪时按钮禁用并提示（DataDirectoryPanel.tsx:93，62#8 在位）。

### 「点击按钮是否弹出命令行窗口哪怕一瞬间」——未发现

- 证据：①后端 Rust 全库无 `Command::new`/`process::Command` 子进程调用（`std::process` 7 处
  均为 `process::id()` 取 PID 命名临时文件与 main.rs:171 verify 模式 `exit(2)`）；②窗口子系统
  `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`（main.rs:1）在位，release
  构建不带控制台；③tauri-plugin-opener 用 ShellExecute 系 API 不产生控制台子进程；④文件对话框
  走 tauri-plugin-dialog 原生 API；⑤NSIS 打包无自定义钩子脚本（tauri.conf.json bundle 段核实）。
  唯一外部进程调用是资源管理器（GUI 程序，无控制台）。

## P3

### 91#1 Markdown 中非 https 链接渲染为可点击但点击必然失败，报错为插件原始英文串

- 位置：`desktop/src/components/UI.tsx:15-26`（MarkdownLink：非 `#` 开头 href 一律 `openExternalUrl(href).catch(reportBackendError)`）；`desktop/src-tauri/capabilities/default.json`（opener scope 仅 `https://**`）；错误展示 `client.ts` backendErrorMessage 对非类型化错误直接透传 `error.message`。
- 传递链条：①讲义（模型生成正文）、笔记预览、导入网页文本中出现 `http://`、`mailto:`、`ftp://` 链接 → ②渲染为标准可点击链接样式（无禁用态、无 scheme 标识） → ③点击后 preventDefault 拦截默认导航，`openUrl` 被 capability 拒绝 → ④toast 弹出 opener 插件原始英文错误串（无中文自救指引），链接永远打不开。次要同类：`#` 锚点链接点击后无任何反应（应用内无对应锚点目标）。
- 影响范围：学习讲义、笔记、资料文本全部 Markdown 渲染面（MemoMarkdown/MarkdownLink 消费点 StudyRoom.tsx:20、Library.tsx:371）；72#1 只声明了拦截意图（「非 https 链接在此报类型化错误」），未处理可用性残端。
- 修复方向：渲染层按 scheme 分流——https 正常可点；http:// 转换为提示（「非加密链接，已阻止打开」或经确认后仍走 https 校验）；mailto/ftp/锚点渲染为纯文本或禁用态并说明；openUrl 报错在 shell.ts 统一映射为中文类型化文案。

### 91#2 导师抽屉发送内容拼接固定前缀后越过 32000 字节钳制，报错文案与所见限额矛盾

- 位置：`desktop/src/components/TutorPanel.tsx:55`（输入框 `clampToBytes(event.target.value, 32000)` 只钳用户输入）与 `:34`（发送时拼接约 160-220 字节固定前缀 `【辅导模式：…】…我的输入：`）；后端 `agent/mod.rs:583-586` 对**拼接后整条 content** 校验 `> 32_000` 报「消息不能为空且不能超过 32000 字节」。
- 传递链条：①用户贴入约 31780-32000 字节长问题，输入框钳制通过（所见限额 32000） → ②前端拼上前缀后总长 32001+ 字节 → ③后端拒绝并弹「不能超过 32000 字节」 → ④用户按提示删到自认 ≤32000 仍可能再次失败（前缀不可见），错误信息与界面限额口径不一致。
- 影响范围：导师抽屉长输入场景；其余全量前后端字节口径比对一致（社区帖 200/20000、回复 10000、复习卡 8000/20000/100、档案 80/100/200、批注 100000、纯文本 500000 等），仅此一处失配。
- 修复方向：钳制值改为 `32000 - 前缀长度`（前缀按 mode 动态计算），或后端只校验用户输入部分长度。

### 91#3 练习填空输入完全未钳制，超长粘贴直接吃后端报错

- 位置：`desktop/src/pages/Practice.tsx:252`（`practice-fill-input` 的 onChange 直接 `setTextAnswer(event.target.value)`，无 clamp/maxLength）；后端 `practice/mod.rs:1187` 校验 30000 字节。同类场景对照：ExamWorkspace.tsx:201、SubjectivePractice.tsx:143 均 `clampToBytes(…, 30000)` 对齐后端。
- 传递链条：①用户向填空框粘贴超 30000 字节内容 → ②前端无任何限制照常显示 → ③提交时后端拒绝，弹错误才发现超限。
- 影响范围：练习填空题单一输入框；属全仓输入钳制网中的漏点（其余场景已对齐）。
- 修复方向：补 `clampToBytes(event.target.value, 30000)`，与另两处同口径。

### 91#4 社区预约提醒轮询整段静默吞错

- 位置：`desktop/src/App.tsx:186-195`（`claimDueReminders` 是写路径——后端置 delivered_at 并返回到期提醒；catch 完全静默，无 console、无 toast）。
- 传递链条：①每 60s 轮询领取到期提醒 → ②任何持续失败（库故障、会话失效）静默 → ③用户设置的「开始前 15 分钟提醒」静默失效，仅能盲试下一轮。
- 影响范围：预约提醒功能可信度；有注释声明「尽力而为」取舍，但写路径静默与 B-17 口径（写失败必须可感知）不符。
- 修复方向：连续 N 轮失败时降级提示一次（如通知中心插一条系统消息），避免每分钟打扰。

### 91#5 方案重生成上限读取失败静默回退默认值，按钮配额显示失真

- 位置：`desktop/src/pages/PlanGenerator.tsx:81-82`（usage.overview 失败时 `.catch(() => {})` 按默认上限 2 展示）；按钮文案 `:315`「局部重生成（剩余 N 次）」。
- 传递链条：①用户在用量页把重生成上限配为 1 或 3 → ②本页读取失败静默回退 2 → ③配 3 的用户被提前禁用按钮（误以为无次数），配 1 的用户看到剩余 2、点击被后端拒绝才报错。
- 影响范围：方案生成器局部重生成入口；读取失败无任何提示。
- 修复方向：读取失败时禁用重生成按钮并提示「配额读取失败，点击重试」，而非展示可能错误的默认值。
