## 安全实现

### 1. IPv6 保留段排除条件为死代码，3fff::/20 与 3ffe::/16 类地址未被拦截
- 证据：`providers/openai.rs:139`——`!(segments[0] & 0xfff0 == 0x3fff)`：`x & 0xfff0` 低 4 位恒 0，永不等于 0x3fff（低 4 位为 f），分支永不生效；该函数被 `web/mod.rs:122` 与 providers 端点校验共用。
- 影响：`public_address` 放行新文档段 3fff::/20（RFC 9637）与旧 6bone 段；实际可利用性接近零（段地址不可路由），属防护意图未执行。[原意是 0x3ff0 还是 ==0x3fff 待作者确认]
- 传递链条：供应商 base_url 或 web.fetch 目标解析到 3fff::/20 地址 → 根因（`providers/openai.rs:139` `segments[0] & 0xfff0` 低 4 位恒 0，与 0x3fff 恒不相等，取反恒真，分支永不排除任何地址）→ 传导（该地址经 `web/mod.rs:118-124` 的 public_address 判定放行，SSRF 检查继续通过）→ 症状：本应报 ssrf_blocked 的保留段地址被当作公网目标放行，防护日志无异常。
- 影响范围：功能面：SSRF 防护链（web.fetch 与供应商端点校验共用 public_address）；触发条件：默认配置即存在缺陷，但需目标恰为 3fff::/20 段（实际不可路由，可利用性趋零）；受损面：安全纵深（意图拦截未执行，无数据/费用损失）。

### 2. 全部导出/导入命令接受 WebView 任意路径且静默覆盖既有文件
- 证据：`materials/commands.rs:76-92`（export 目的地任意）、`export/commands.rs:8-26`、`sharing/commands.rs:47-53`、`backup/commands.rs:21-34`、`reports/commands.rs:92-101`；`materials/mod.rs:1191-1213` 对任意 parent create_dir_all、对已存在目标先备份再替换（静默覆盖）；读侧 import 同样任意路径。
- 影响：正常 UI（系统对话框有覆盖确认）无损害；但后端命令层不提供第二道路径遏制——配合 06#4 无 CSP，注入脚本即得"任意内容写任意路径+任意文件读（受扩展名/大小/签名约束）"原语。属单层防御缺口。
- 传递链条：WebView 内脚本携带任意 destination/path 字符串调用 export_*/import_* 命令 → 根因（`materials/commands.rs:76-92` 等命令把字符串直接 `Path::new`，无沙箱根约束）→ 传导（`materials/mod.rs:1191` 对任意 parent create_dir_all，`:1202-1206` 已存在目标先改名再替换）→ 症状：任意内容写任意路径并静默覆盖既有文件；读侧（import、`sharing/commands.rs:56-60`）同样可读任意路径。
- 影响范围：功能面：materials/export/sharing/backup/reports 全部导出导入 IPC 命令；触发条件：正常 UI 走系统对话框不命中，需先有脚本注入（如配合 06#4 无 CSP）才成为攻击原语；受损面：安全（单层防御缺口——命令层无第二道路径遏制）。

### 3. 离线分享包校验仅完整性无真实性：任何人可伪造永不过期的合法 .dtshare
- 证据：`sharing/mod.rs:489-500`——checksum 为普通 SHA-256（无 MAC/签名），伪造者可自算；`:195-209` token 只验格式不查库；`:501-503` 过期校验用包内自声明值；`read_shared_plan_package/file` 在认证白名单内（guard.rs:158-163）。
- 影响：可构造内容任意的"分享方案"诱导用户打开；README"分享可撤销可过期"对离线包不成立（React 转义使内容注入不升级为 XSS，无 dangerouslySetInnerHTML）。
- 传递链条：攻击者自造 .dtshare（自选 plan/expires_at/token）投递并诱导用户在分享页打开 → 根因（`sharing/mod.rs:494` checksum 为普通 SHA-256 无 MAC，伪造者可对自造 payload 重算；`:195-209` token 只验 dt_+43 字符格式不查库；`:501-503` 过期判断取包内自声明值）→ 传导（`guard.rs:158-163` 将 read_shared_plan_package/file 列入免登录白名单直接读包）→ 症状：内容任意且永不过期的"合法"分享方案被渲染展示。
- 影响范围：功能面：离线分享包读取链（read_shared_plan_package/file 命令与分享页渲染）；触发条件：默认配置命中，需攻击者投递文件并诱导打开（社工前提）；受损面：安全（真实性缺失，README"可撤销可过期"承诺对离线包不成立）。

### 4. API Key/同步凭据/PAT 的输入路径未用 Zeroizing，明文驻留堆内存
- 证据：`providers/mod.rs:57/441/501-510`（ProfileInput.api_key 普通 String + clone）、`sync/mod.rs:99-101/359-379`、`security/mod.rs:1131-1140`（PAT 参数）；对比读取侧与 JWT 均正确使用 Zeroizing。
- 影响：密钥在 IPC 反序列化/校验克隆后堆中残留，进程内存转储可提取；可利用前提是本机内存读取权限（已越过全部应用边界），属纵深加固缺口。
- 传递链条：用户在供应商/同步/成员安全页提交 API Key、WebDAV/S3 凭据或 PAT → 根因（`providers/mod.rs:57` api_key 为普通 `Option<String>`，`:441` 校验中 clone；`sync/mod.rs:99-101`、`security/mod.rs:1131` 同为普通 String 入参）→ 传导（IPC JSON 反序列化与函数克隆在堆上留多份明文副本，仅 `sync/mod.rs:357/365` 对原值事后 zeroize）→ 症状：密钥明文长期驻留堆内存，进程/崩溃转储可提取。
- 影响范围：功能面：供应商档案保存、同步配置、PAT 认证命令的入参路径（读取侧与 JWT 不受影响）；触发条件：默认配置命中，提取需本机内存读取权限（已越过全部应用边界）；受损面：安全纵深（密钥泄露面扩大，非直接可利用）。

### 5. 文档宣称 JWT"常量时间比对"，实现为短路逐字节比较
- 证据：`docs/architecture/01-architecture.md:177` vs `security/mod.rs:582-587`——`all(|(l,r)| *l == *r)` 首异即短路，另有长度早退。
- 影响：违反 DEEPTUTOR"不得宣称无强制实现的安全属性"；实际可利用性可忽略（比较对象是 HMAC 结果、经本地 IPC 测时）。
- 传递链条：读者按 `docs/architecture/01-architecture.md:177`"常量时间比对 :569"理解会话安全模型 → 根因（`security/mod.rs:582-587` 实现为长度早退 + `all(|(l,r)| *l==*r)` 首异即短路）→ 传导（每次会话验证按位短路返回；比较对象是 HMAC 输出且经本地 IPC，时序差异不可观测）→ 症状：文档宣称的属性无强制实现，审计/评审按错误前提决策。
- 影响范围：功能面：JWT 会话验证（security::verify）与架构文档一致性；触发条件：默认配置命中，仅规约审计或理论计时攻击（本地 IPC 场景不可行）时显性化；受损面：合规/文档可信（无实际数据风险）。

### 6. agent 免审批工具构成"读取本地数据→公网外发"链路，未在文档/UI 披露
- 证据：审批仅覆盖 memory.save/delete 与 artifact.promote（`agent/tools.rs:554-630`）；`web.search/web.fetch/history.search（跨全部会话）/memory.recall/workspace.read` 免审批；工具结果原文进入模型上下文（`agent/mod.rs:851-873`），web.fetch 抓回内容构成提示注入载体。
- 影响：被污染网页或恶意模型可在无用户确认下读本地学习数据再经 web.fetch 编码进 URL 外发任意公网地址；SSRF 链只拦私网目标不拦数据外发。与 02 文档 §313 记载一致（设计如此），但外发边界未披露。
- 传递链条：用户让 agent 浏览网页（或模型被提示注入）→ 根因（`agent/tools.rs:554-630` 审批仅覆盖 memory.save/delete 与 artifact.promote；web.search/web.fetch（:552）/history.search（:610）/memory.recall/workspace.read（:477）免审批直接执行）→ 传导（工具结果原文 push 进模型上下文 `agent/mod.rs:851-873`，被污染内容可指示模型再读本地数据并经 web.fetch 编码进 URL 外发公网）→ 症状：本地学习数据在无用户确认下外流；SSRF 链（`web/mod.rs:118-124`）只拦私网目标不拦外发。
- 影响范围：功能面：agent 运行循环全部免审批工具与 web.fetch 出口；触发条件：默认配置命中——需用户运行 agent 且模型发起工具调用（被污染网页即够）；受损面：安全（本地数据机密性），兼有费用面（工具步消耗）。

### 7. Agent 双层预算完全依赖供应商上报 usage，缺 usage 时形同虚设
- 证据：token 预算按 `json_extract(usage_json,...)` 求和（`agent/mod.rs:608-615/787-791`，NULL→0）；USD 的 known_spend 要求 input+output 同时存在（`providers/usage.rs:261`）。
- 影响：不上报 usage 的兼容服务下真实计费不被任何预算拦截，仅受 25 步硬顶；与 02#8（直连旁路）不同根因。
- 传递链条：用户为不上报 usage 的兼容服务配 agent 并设置 token/USD 预算后发起 agent 任务 → 根因（`agent/mod.rs:608-615/787-791` 预算按 json_extract(usage_json) 求和，缺失经 COALESCE 记 0；`providers/usage.rs:261` known_spend 要求 input+output 同时存在否则 None）→ 传导（预算检查读到 0/None 判定未超限，运行继续到 25 步硬顶）→ 症状：真实供应商侧计费不被任何预算拦截。
- 影响范围：功能面：agent 双层预算（token/USD）与 run 账单统计；触发条件：非默认——需接入不上报 usage 的兼容服务；受损面：费用（预算失守）。
