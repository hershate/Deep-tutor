### 42#1 保存对话框 defaultPath 未统一清洗——原始资料标题含 Windows 非法字符时保存对话框直接打不开

- 位置：`desktop/src/pages/StudyRoom.tsx:228`、`desktop/src/pages/Library.tsx:168`、`desktop/src/pages/Library.tsx:177`；清洗函数仅存在于 `desktop/src/components/ExportCenter.tsx:25-29`（`fileName()`）；标题入口 `desktop/src/pages/PlanGenerator.tsx:197`（`textTitle` 手输，无字符校验）与后端 `desktop/src-tauri/src/backend/materials/mod.rs`（`import_text` 仅限长度 ≤200 字节，不限字符）。
- 证据：
  ```tsx

  // ExportCenter.tsx:25 —— 唯一有清洗的调用方
  function fileName(title: string, extension: string) {
    const safe = title.replace(/[\\/:*?"<>|]/g, '_').replace(/[.\s]+$/, '')
  ```
  ```ts
  // client.ts:343 —— defaultPath 原样透传
  saveMaterialFile: (title: string, extension: string) => invoke<string | null>('plugin:dialog|save', {
    options: { title: '保存到本地', defaultPath: title, ... } }),
  ```
  插件侧链路（cargo 缓存源码）：tauri-plugin-dialog `src/commands.rs:93-94`
  `default_path.file_name()` → `set_file_name(...)` → rfd `dialog_ffi.rs:255-261`
  `self.0.set_filename(&wide_path)?` —— `IFileDialog::SetFileName` 遇
  `\/:*?"<>|` 返回 E_INVALIDARG，`?` 直接把整个对话框创建置为失败。
- **传递链条**：① 方案生成器「粘贴文本」页输入标题「线代: 第1讲?」（PlanGenerator.tsx:197 `textTitle`，前端无字符校验）→ ② `import_material_text` 落库（后端只校验长度，materials/mod.rs `import_text_with_source`：`title.len() > 200` 之外不限字符）→ ③ 之后在资料库（Library.tsx:168/177）或学习室资料卡（StudyRoom.tsx:228）点「导出原件 / 导出文本」→ ④ `saveMaterialFile(title, …)` 把标题原样作为 `defaultPath`（client.ts:343）→ ⑤ dialog 插件 → rfd `SetFileName` 返回 E_INVALIDARG → ⑥ **保存对话框根本不弹出**，invoke 拒绝 → ⑦ 前端 catch 走 `reportBackendError`，用户看到的是不可读的英文插件错误，而非对话框。
- **影响范围**：所有含 `: ? * " < > | / \` 或尾部空格/点号的资料标题（中文用户手输标题常含半角冒号）；导出原件/导出文本两条路径在 37#5 修复后成为主路径，此缺陷把「导出」变成「报错」。不影响标题合法的文件名导入（文件名本身受文件系统约束）。ExportCenter 的 `fileName()`（含 E-5 码点截断修复注释）证明该清洗是既定约定，本轮属「同一约定修了一处漏了三处」的漏网族。

### 42#2 StudyRoom/Library 导出的 defaultPath 不带扩展名、扩展名大小写口径不一

- 位置：`desktop/src/pages/StudyRoom.tsx:228`（`detail.kind` 大写直传，后端 `materials/mod.rs:380` detail 视图 `kind.to_uppercase()`）；对照 `Library.tsx:168`（`toLowerCase()`）、`ExportCenter.tsx:27-29`（`${clipped}.${extension}` 显式补后缀）。
- **传递链条与影响**：① 学习室资料卡点「导出原件」（StudyRoom.tsx:228 传大写 `detail.kind`）或资料库导出（Library.tsx:168 传小写）→ ② `saveMaterialFile(title, kind)` 的 defaultPath 只有标题不带扩展名（client.ts:343）→ ③ 是否补 `.pdf` 取决于 IFileDialog 按当前过滤器自动补全的行为，三个调用点口径不一；StudyRoom 过滤器扩展名大写（`extensions: ['PDF']`），Windows 匹配大小写不敏感。
- **影响范围**：所有经 StudyRoom/Library 导出资料的用户——默认文件名可能无后缀（依赖对话框自动补全）、扩展名大小写与 ExportCenter 不一致；功能可用、数据无损，纯展示层口径问题。不影响 ExportCenter 导出（显式补后缀）。触发条件=使用这两处导出入口即可见。

### 42#3 拖入文件夹触发逐条 unsupported_format 错误提示——「拖文件夹」常见手势无引导

- 位置：`desktop/src/App.tsx:193-199`（全局 drop 不区分目录/文件）、`desktop/src/backend/materialImport.ts:13-26`、后端 `desktop/src-tauri/src/backend/materials/mod.rs:484-492`（目录无扩展名 → `unsupported_format`）。
- **传递链条**：① 用户把整个文件夹拖入窗口 → ② `onDragDropEvent` paths 含目录路径 → ③ `importMaterialPaths` 当普通文件发给 `import_material_files` → ④ 后端 `validate_source` 对目录报 `unsupported_format`（「当前支持 PDF、DOCX…」）→ ⑤ toast「N 份失败：当前支持 PDF…」。错误有出口、无静默，但对「拖文件夹」这一高频手势没有专门文案（「暂不支持拖入文件夹，请拖入单个文件或 ZIP」），体验粗糙。同批多个 ZIP 时若第 2 个 ZIP 导入抛错，第 3 个及之后不再导入（materialImport.ts:20-24 顺序 await、整体 reject），用户需逐次重试。
- **影响范围**：所有把文件夹（而非散文件/ZIP）拖入窗口的用户——第一次尝试即触发，报错文案答非所问；多 ZIP 批量拖入且中途失败的用户需逐次重试剩余 ZIP。不影响文件选择器路径（对话框天然选不了目录进导入通道）与单个 ZIP 拖入。无数据损害。

### 42#4 DataDirectoryPanel「保存并立即重启」一键即重启应用，无确认层

- 位置：`desktop/src/components/DataDirectoryPanel.tsx:96`（`onClick={() => void restart()}`）→ `storageBackend.restart()`（storage.ts:18）→ `restart_application`（startup.rs:490-493，`app.restart()`）。
- **传递链条**：① 数据目录面板存在 pending 变更时出现「保存并立即重启」按钮 → ② 一次点击直接 `invoke('restart_application')` → ③ `app.restart()` 立即重启进程——无 ConfirmDialog 层、无未保存状态检查（学习数据均落库、草稿有后端暂存，实际不丢数据）→ ④ 用户所有界面状态（滚动位置、打开的弹窗、进行中的浏览上下文）整窗消失。
- **影响范围**：配置过新数据目录待生效的用户；危害仅限上下文丢失（数据无损），但与应用内其余「改变全局状态」操作均有确认层（20#5/37#1/37#2 家族）的交互模型不一致——用户在别处学到「大红按钮才直接执行」，此处静默突破预期。不受影响：数据完整性、其余页面。
