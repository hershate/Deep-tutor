# 24 号 · 前端骨架缺陷（P1 × 1 + P2 × 1 + P3 × 6）

> 第十一轮对全局骨架（useBackendState/useAgent/App/UI/styles）逐行深审。核心机制
> （事件游标单调、工作区串台防护、取消/failover 流式丢弃、浏览器存储零使用）核对成立；
> 主要缺陷集中在错误处理路径过激。

## P1

### 24#1 一次瞬态读失败即把整个应用卸载成错误页（database_busy 豁免只保护了 toast）

- 位置：`desktop/src/backend/useBackendState.ts:75-87`（fail 无错误码豁免）、`:144-150`（事件驱动 requestSync 失败直接 fail）、`desktop/src/App.tsx:285-287`（startupError 非空即整树早退替换）
- 证据：
  ```ts
  // client.ts:447-449 注释承诺：database_busy 是瞬态争用……不打断用户
  // ——但该豁免只作用于 reportBackendError 的 toast 分支；
  // useBackendState.fail 仍然无条件 setStartupError(...) + setReady(false)
  ```
  App.tsx:285 `if (startupError) return <main className="page-loading startup-recovery">…`
  卸载整个 app-shell。备份导入大事务、Agent 写入密集期任何一次 `eventsSince/getAppState`
  读争用失败 → 用户正在使用的页面、弹层、输入内容全部丢失，换成"本地数据或实时连接
  打开失败"，直到下一个事件或窗口 focus 才自愈（又一次整树重建）。
- 修复方向：fail 对 database_busy（及同类瞬态码）降级为保留当前快照 + 延迟重试，
  仅持续失败才进入错误页。

## P2

### 24#2 Escape 无层叠仲裁：一次 Esc 关闭所有叠加弹层，body 滚动锁同时被错误恢复

- 位置：`desktop/src/components/UI.tsx:98-103`
- 证据：每个 open 的 Modal 在 `document` 上注册 keydown，命中 Escape 直接
  `closeRef.current()`——多个监听器都会执行，无 stopPropagation、无"仅最顶层"判断。
  ⌘K 搜索层可叠在页面 Modal 之上（App.tsx:180-182 只查 focusOpen）；App 的全局 keydown
  还会同时收起导师抽屉/专注层/共享页。一次 Esc 全关，焦点恢复链（UI.tsx:80
  `previous?.focus()`）错乱；嵌套关闭时 `document.body.style.overflow` 无计数恢复为
  `''`（UI.tsx:101-102 cleanup），外层 Modal 还开着但背景已可滚动。
- 修复方向：Esc 只关最顶层（如维护打开栈或比较 z-index），overflow 锁加引用计数。

## P3

### 24#3 useAgent 流式预览：getProviderChat 快照覆盖可丢弃已拼接的 delta

- 位置：`desktop/src/backend/useAgent.ts:100-117`
- 证据：effect 先 `setStream(emptyStream)` 再拉 `getProviderChat`，成功回调是
  `setStream({text: request.output})` 全量覆盖；而 `chat_delta` 事件走函数式追加
  （:139-141）。invoke 响应晚于其后产生的 delta 到达时，已拼接增量被不含它的快照覆盖。
  最终内容以 `message_saved` 持久化消息为准（AgentCenter.tsx:102-103），仅 running 期间
  预览短暂缺一段。
- 修复方向：覆盖前比较游标或改为 merge。

### 24#4 前端 localId()（Date.now 基）与后端补学任务 next_free_id（MAX+1）共享 id 空间，同毫秒交错可撞车

- 位置：`desktop/src/ids.ts:6-9`（注释自认"后端集合写入不做 id 去重"）；`desktop/src-tauri/src/backend/store.rs:727-734`（next_free_id），调用点 `learning/knowledge.rs:206-211`
- 证据：前端写入时间戳大 id 后，后端补学任务 `MAX+1` 紧贴时间戳序列；同一毫秒内
  "前端建任务 → 后端建补学任务 → 前端再建任务"时前端下一个 localId 命中后端刚占用的
  id：后端 UNIQUE 失败或前端集合 React key 冲突。低概率、单次可重试。
- 修复方向：后端 next_free_id 基数加偏移（如从 Date.now 起），或后端 INSERT 冲突时重试。

### 24#5 replaceCollection 一帧窗口竞态可静默丢数据（revision 防护被新版本号绕过）

- 位置：`desktop/src/App.tsx:58-60`（setTasks 用渲染闭包集合）+ `desktop/src/backend/useBackendState.ts:182-197`
- 证据：`replaceCollection` 携带 `versions.current[namespace]`（ref，applySnapshot 后立即
  前进），但 `value` 是渲染闭包的旧集合。一帧内连续两次新增：第二次携带"新版本号 +
  不含第一条的旧集合"，后端版本校验通过，**第一条被静默丢弃**——revision_conflict
  防护恰因版本号已更新而被绕过（该防护只拦"旧版本号"提交）。
- 修复方向：提交前从 ref/最新快照取集合，或对同命名空间在途写做本地排队。

### 24#6 StrictMode 双执行下事件监听器泄漏 + 双 bootstrap（mounted 共享 ref 误判）

- 位置：`desktop/src/backend/useBackendState.ts:21,68-69,164-169`
- 证据：`mounted = useRef(true)`；StrictMode mount→cleanup→remount 序列中第二轮 mount
  立刻把 `mounted.current` 置回 true，第一轮 onBackendEvent promise resolve 时误判存活：
  监听器 1 永不移除（被 `unlisten = stop` 二次赋值覆盖）且 start() 双跑。对比同型代码
  App.tsx:120-136 与 useAgent.ts:121 用闭包局部标志无此问题。仅影响开发构建。
- 修复方向：改用闭包局部 active 标志（对齐同型代码）。

### 24#7 手动"减少动态"通道不覆盖 html 自身 smooth scroll；JS 滚动忽略系统偏好

- 位置：`desktop/src/styles.css:69`（html smooth）、`:993`（`.reduce-motion *` 后代选择器不含 html 自身）vs `:995`（媒体查询通道用 `*` 含 html）；`desktop/src/App.tsx:219`
- 证据：OS `prefers-reduced-motion` 通道禁用了 html 的平滑滚动，应用内手动开关的类通道
  没有；`window.scrollTo({behavior: preferences.reducedMotion ? ...})` 只看应用内偏好，
  系统开启而应用未开时仍平滑滚动（显式 behavior 覆盖 CSS）。
- 修复方向：`.reduce-motion` 规则补 `html.reduce-motion` 自身匹配；App.tsx 读取
  matchMedia 并入判定。

### 24#8 20 秒超时计时器覆盖 bootstrap+sync 全程，临界误报即触发 24#1 的整树错误页

- 位置：`desktop/src/backend/useBackendState.ts:88-97`（timer 20s 触发条件 `!settled && starting`）、`:119-125`（settled 要等 sync() 完成才置位）
- 证据：bootstrap 临近 20s 成功而 sync 追平稍慢时，timer 误报"等待本地后端响应已超过
  20 秒"并 setReady(false)——结合 24#1 渲染分支即整树切错误页，随后 promise 链完成又
  自动恢复，造成一次全应用卸载重建。
- 修复方向：bootstrap 完成即视为 settled（超时只管 bootstrap），或误报后立即被
  sync 完成覆盖时不切错误页。

## 传递链条与影响范围（补链）

### 24#1
- 传递链条：触发（备份导入大事务/Agent 流式写入密集期，任一次事件驱动的
  eventsSince/getAppState 读撞 database_busy）→ 根因（useBackendState.ts:75-87
  fail 无错误码豁免；:144-150 事件刷新失败直通 fail；App.tsx:285-287 startupError
  非空即整树卸载换错误页）→ 传导（client.ts:447-449 的 database_busy 豁免只挡
  toast，挡不住 fail → 全部页面/弹层/输入态卸载 → 等待下一个事件或窗口 focus
  （useBackendState.ts:178 visibilitychange）触发 sync 成功后又一次整树重建）→
  症状（正常使用中被弹回"本地数据或实时连接打开失败"错误页数秒至数十秒，
  未保存的弹窗输入全部丢失）。
- 影响范围：功能面为整个应用 shell 的存活逻辑——所有页面、所有进行中弹层；
  触发条件为一次瞬态读争用（备份导入/流式高峰期概率可观）；受损面为用户
  会话连续性（数据不丢——都已在后端，丢的是界面状态与信任感），自愈但以
  整树重建为代价。

### 24#2
- 传递链条：触发（叠加弹层时按 Esc：⌘K 搜索叠在页面 Modal 上、Modal 内 Modal）→
  根因（UI.tsx:98-103 每个 open Modal 各自 document keydown 且都执行 close；
  App.tsx:182 全局 Esc 还同时收起抽屉/专注层/共享页）→ 传导（一层 Esc 三处
  关闭；嵌套关闭时 body overflow 无计数被恢复为 ''（UI.tsx:101-102）→ 外层
  还开着背景已可滚动；previousFocus 恢复链错乱）→ 症状（只想关最外层却全关、
  焦点掉到 body、背景滚动穿透）。
- 影响范围：功能面为所有 Modal（Library 5/Community 12/Review 3 个实例等）与
  全局搜索/抽屉/专注层的任意叠加组合；触发条件为键盘 Esc（一级操作）；受损
  面为弹层交互正确性（不丢数据，丢操作意图与焦点可达性）。

### 24#3
- 传递链条：触发（Agent 运行中切换到该会话）→ 根因（useAgent.ts:100-117 effect
  先拉 getProviderChat 快照、成功回调全量 setStream 覆盖；delta 事件走 :139-141
  函数式追加）→ 传导（invoke 响应晚于其后到达的 delta 事件时，快照（不含这些

- 影响范围：功能面为 Agent/导师流式实时预览；触发条件为进入会话时机与事件

### 24#4
- 传递链条：触发（同一毫秒内：前端建任务 → 后端补学任务生成（knowledge.rs:206-211
  经 store.rs:727-734 next_free_id=MAX+1）→ 前端再建任务）→ 根因（ids.ts:6-9
