# P3 性能放大与配置加固问题（5 项）

性能类问题在同步命令主线程执行的架构背景下会被放大为窗口卡顿；
配置类为加固缺口（文档未做相反声明，不构成声明矛盾）。

## 1. App 全局仪表盘与 Dashboard 页对同一事件集双份重复加载 `get_dashboard`
- 前端：`App.tsx:129-131`（homeSummary 监听 `state.changed/plan./study.checkin/
  security.session_started/focus.`）与 `Dashboard.tsx:26-28`（overview 监听超集）——
  停留"今日"页时 5 个重叠前缀每个事件触发两次相同请求。
- 后端：`engagement/mod.rs` dashboard 为同步聚合命令（主线程执行）。
- 影响：每次任务勾选/专注切换/方案事件在今日页产生双份聚合查询，纯重复开销。
- 传递链条：触发（停留"今日"页时任一 state.changed/plan./study.checkin/security.session_started/focus. 事件）→ 根因（`App.tsx:129-131` homeSummary 与 `Dashboard.tsx:26-28` overview 各自订阅，5 个前缀完全重叠）→ 传导（两处 effect 均调用 `engagementBackend.dashboard()` → `engagement/mod.rs:729` 起的同步聚合（档案+方案列表+逐阶段进度查询+复习统计+日历+4w 报告），主线程执行）→ 症状（每个事件触发两份相同聚合查询，窗口卡顿被放大）。
- 影响范围：今日页与全局侧栏摘要（get_dashboard 命令）；停留今日页且有任务/专注事件流即命中（默认配置）；性能受损，功能正确、无数据风险。

## 2. 全局搜索每次击键（120ms 防抖）触发三段 LIKE + 全量方案反序列化 + 节点 N+1 查询

## 4. 生产与开发环境均未配置任何 CSP，WebView 无内容安全策略兜底
- 配置：`tauri.conf.json:12-27` 无 `security/csp/devCsp` 键；`index.html` 无 CSP meta；
  无任何文档声明配置了 CSP。
- 事实：前端依赖 blob: 媒体 URL（`MediaPlayer.tsx:35`）与 inline 样式——当前无 CSP 可违反，
  功能正常；但应用自有命令不经 ACL 约束（本地内容 + 无插件 manifest，tauri 仅对
  `plugin:*` 或远程来源做 ACL 检查）。
- 影响：属加固缺口——一旦 Markdown/网页抓取渲染链路出现 XSS，注入脚本可直达全部命令
  （导出、备份读取、同步上传）。若未来补 CSP，需放行 `media-src blob:` 与
  `style-src 'unsafe-inline'`，否则媒体预览会被自身策略阻断。
- 传递链条：触发（WebView 渲染任意内容，含 Markdown/网页抓取文本）→ 根因（`tauri.conf.json:12-27` app 段无 `security/csp/devCsp` 键；`index.html` 无 CSP meta）→ 传导（`MediaPlayer.tsx:35` 依赖 `URL.createObjectURL(blob)` 的 blob: 媒体地址与内联样式在无 CSP 下正常；本地内容+无插件 manifest 使应用自有命令不经 tauri ACL 检查）→ 症状（当前功能正常；一旦渲染链路出现 XSS，注入脚本可直达全部命令）。
- 影响范围：整个 WebView 内容加载策略与全部自有命令；默认配置即命中（加固缺口而非缺陷，前置需先存在 XSS）；安全受损面为潜在，无当前功能影响。
