# 23 号 · 后端逻辑缺陷（P2 × 10）

> 第十一轮后端逐文件深审（learning/planning/reports/community/projects/engagement、
> practice/review/knowledge/notes、export/sharing/backup、security/store/providers、
> agent/web/plugins/sync/materials/maintenance 全覆盖）。每条经主审回源码实证。

## 23#1 强度切换用容量不等式重算 `within_deadline`，逾期方案被持久化翻成"在目标日内"

- 位置：`desktop/src-tauri/src/backend/planning/mod.rs:414-417`；生成时定义 `desktop/src-tauri/src/backend/learning/validate.rs:293`；消费 `desktop/src-tauri/src/backend/reports/mod.rs:770-775`
- 证据：生成时 `within_deadline: end_date <= deadline`（纯日期比较）；`apply_intensity` 重算改为
  `total_minutes <= daily_minutes × days`（容量不等式）。强度切换对 minutes 与 daily_minutes
  **同比例**缩放、不动日期，原排式恒满足 → 原本晚于截止日的方案在任意一次强度切换后
  `within_deadline` 翻成 true，随 `result_json` 持久化，首页/报告据此显示"当前计划日期
  在目标日内"，与旧 `warnings` 里"结束日晚于截止日"文案自相矛盾。`within_milestone`
  （:418-424）同病。
- 修复方向：重算时保持 `end_date <= deadline` 语义，或直接不重算该标志。

## 23#2 hints 模式主观题错答仍写入错题本，泄露"只给提示"遮蔽承诺（B-11 漏抄到主观路径）

- 位置：`desktop/src-tauri/src/backend/practice/subjective.rs:468-473`；对照正确实现 `practice/mod.rs:1155-1161`
- 证据：客观题路径带 B-11 注释与守卫 `if !correct && set.feedback_mode != "hints"`；主观题路径
  只有 `if !correct` 即 `INSERT INTO practice_mistakes`，`reason` 是模型总体反馈文本。
  `GradingTask` 已加载 `feedback_mode`（subjective.rs:290,303）但未使用；同事务的
  `mark_mastered`（:511-512）在 hints 模式下同样发出掌握事件，二次泄露。测试仅覆盖
  hints+choice（practice/tests.rs:485-505），主观题无 hints 用例。
- 修复方向：主观题 mistake 写入与掌握事件补同一 `feedback_mode != "hints"` 守卫。

## 23#3 到期考试存在未完成评分时 `get_practice_set` 整体报错，评分失败后形成恢复死锁

- 位置：`desktop/src-tauri/src/backend/practice/exams.rs:112-121`（pending>0 → `grading_in_progress`）；`practice/commands.rs:23-26`（`lazy_finalize_expired_exam(...)?` 直接上抛）
- 证据：惰性收卷在考试到期（`remaining()` 判 expired）后执行；`pending` 统计含
  failed/cancelled/interrupted 等全部非 done 状态。触发链：模拟考含主观题 → 评分失败或
  应用重启（recover 置 interrupted）→ 考试到期 → 此后每次读详情都报 `grading_in_progress`，
  题目与 pending 答案列表完全不可读；而恢复命令 `resume_practice_answer(answer_id)` 所需的
  `answer_id` 只能从该详情枚举——重启后无从恢复。
- 修复方向：pending>0 时跳过惰性收卷仅返回详情，报错留给显式 `submit_exam`。

## 23#4 备份追加导入：「主键=外键」子表被按本表 max+1 重映射，导入失败或错挂

- 位置：`desktop/src-tauri/src/backend/backup/transfer.rs:197-280`（prepare_ids）+ `transfer.rs:453-489`（reference() 无 material_id/group_id/room_id 分支）
- 证据：`material_text`（materials/mod.rs:249-254，`material_id INTEGER PRIMARY KEY REFERENCES
  materials(id)`）、`community_group_members`（community/mod.rs:205-207，PK(group_id)）、
  `community_reservations`（:221-223，PK(room_id)）三表主键即外键。prepare_ids 对冲突主键
  按子表自己的 `MAX+1` 重映射（transfer.rs:255-270），而非父表映射；导入时该行要么违反
  外键（`backup_constraint_failed` 整单回滚），要么静默挂到错误父记录。对照
  `learning_plan_adoptions` 因 reference() 有 `plan_id` 分支而幸免——设计内机制漏了这三张表。
  现有测试夹具 `material_text` 为空（import_text 只 staged 不落 text），未覆盖此路径。
- 修复方向：reference() 补三个主键分支（或按父表映射重写子表主键）+ 补已解析资料重复
  导入测试。

## 23#5 登录用户的备份重复恢复必整体失败（security_quotas 复合主键撞 UNIQUE）

- 位置：`desktop/src-tauri/src/backend/backup/archive.rs:384-408`（导出时把当前用户 local_users + security_quotas 注入快照）+ `transfer.rs:875-885`（global_conflict 白名单无 security_quotas）
- 证据：`INSERT OR REPLACE INTO security_quotas` 入快照（复合主键 user_id+resource）；导入侧
  prepare_ids 跳过复合主键、global_conflict 不含该表 → 同一登录用户第二次导入自己任何一份
  备份（恢复后再恢复）必 `UNIQUE constraint failed` → `backup_constraint_failed` 整单回滚。
  测试环境 `principal_id()` 为 None、快照无配额行，故现有重复导入测试恒过。
- 修复方向：security_quotas 加入 global_conflict 白名单（按原键跳过）。

## 23#6 登出不撤销旧会话：切换用户后登出会静默回退到上一位用户的会话

- 位置：`desktop/src-tauri/src/backend/security/mod.rs:930-953`（logout 仅撤销 `current()` 最新一条）；`:709-727`（initialize 仅在 login_required 分支检查 `logged_out` 标志）；`:558-563`（current 取最新未撤销）
- 证据：`login`/`issue` 只插新会话不撤旧会话。序列：登录用户1（S1）→ 切换用户2（S2）→
  登出（仅撤 S2）→ 下一条受守卫命令 `current()` 命中 S1，`logged_out` 标志被绕过，
  以用户1身份静默续用（本地多用户越权续用）。现有测试（tests.rs:242）只覆盖单会话。
- 修复方向：logout 撤销该用户全部会话，或切换登录时撤销旧会话，或 current() 也检查
  logged_out 标志。

## 23#7 providers 五个异步命令丢失 thread-local principal，非 user1 用户数据写入 user1 工作区

- 位置：`desktop/src-tauri/src/backend/providers/commands.rs:26,73,90,117,194`（`spawn_blocking`）；`security/mod.rs:33-37`（PRINCIPAL thread_local）；`store.rs:70-74`（fail-open 回退 1）
- 证据：`upsert_provider_profile`/`test_provider`/`stream_provider_chat`/
  `stream_provider_chat_with_tools`/`route_provider_chat` 全部 async，实际工作在
  `tauri::async_runtime::spawn_blocking` 线程执行；guard 的 `with_user` 只在 IPC 线程设置
  PRINCIPAL thread-local，不跨线程传播 → `Store::new` 落到 `principal_id().or(Some(1))`，
  `credential_name` 的 `unwrap_or(1)` 把 API key 写入 `provider-u1-*` 槽。用户2 保存的
  档案/密钥/请求记录全部落入用户1 工作区，而同步命令（list 等）仍读用户2——跨用户隔离
  破裂 + 同用户视角数据分裂。**本条推翻 22#1"当前被守卫覆盖未形成暴露路径"的判定，
  22#1 已加注。**
- 修复方向：spawn_blocking 闭包内显式捕获 user_id 并 `with_user` 包裹；或改同步命令；
  或 principal 改为随 BackendState 传递。

## 23#8 web/html.rs 标签扫描遇未闭合引号整体 break，正文静默截断

- 位置：`desktop/src-tauri/src/backend/web/html.rs:233-246`
- 证据：扫描器对每个 `<` 找引号外的 `>`；引号打开后在剩余文档中永不闭合时
  `let Some(end) = end else { break }` 终止整个解析循环。常见触发：`<!-- don't do this -->`
  （注释内撇号开单引号态）且其后文档无第二个 `'`；或畸形属性 `<a title="unclosed>`。
  注释分支（`tag.starts_with("!--")` + find("-->")）在此场景根本执行不到。
  `fetch`/`web.search` 静默返回截断正文或 `web_empty_content`，无错误无 warning。
- 修复方向：未闭合引号时按畸形标签跳过该 `<` 继续扫描（cursor = open+1），或引号扫描
  限定在合理标签长度内。

## 23#9 Agent 悬挂 tool_calls：取消/超限后的 run 永久无法恢复

- 位置：`desktop/src-tauri/src/backend/agent/mod.rs:838-880`
- 证据：assistant 消息（含全部 tool_calls）在 `too_many_tool_calls` 判定（:863-869，检查在
  保存**之后**）与循环内取消检查（:871-879，取消时只落了前 k 条 tool 回复）之前已落库，
  留下"assistant.tool_calls 无完整对应 tool 消息"的历史。`history()` 原样重放，
  OpenAI 系 API 对以悬挂 tool_calls 结尾的请求返回 400，`resume` 每次必败，run 卡死直到
  预算耗尽。同族：100 条历史窗口（:352）截断边界落在 assistant/tool 对中间时，重放历史
  以孤儿 tool 消息开头，同样 400。
- 修复方向：保存 assistant 前完成上限/取消判定；resume 前修剪悬挂 tool_calls 与孤儿
  tool 消息。

## 23#10 sync 下载/恢复的用户自选写盘目的地绕过数据根遏制

- 位置：`desktop/src-tauri/src/backend/sync/commands.rs:19-27,54-67`（destination 直传）+ `sync/mod.rs:560-563`（`atomic_export` 写盘）；对照调用方 `backend/mod.rs:28-58` 的 `reject_data_root_destination`（backup/export/materials/reports/sharing 均调用，唯 sync 缺失）
- 证据：`start_sync_job`(download+destination) 与 `restore_sync_version` 只校验 `.json`
  扩展名即写盘，还会在目的地目录生成 `*.download-N`/`*.previous-N` 临时文件。该函数
  自述为"注入脚本若借导出命令写盘，也不能覆盖工作区数据库、原件或配置（08#2）"的第二道
  遏制，sync 路径未接入，违背自述承诺。
- 修复方向：sync 两条命令补 `reject_data_root_destination`。
