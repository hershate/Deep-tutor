## P3

### 68#1（=P-1）兄弟型双层弹层焦点圈禁互相争抢——Tab 困死在内层首元素，无法到达确认按钮

- 位置：`UI.tsx:70-84`（useFocusContainment 两实例同时激活）。
- 机理：外层 onKey 发现焦点不在自己容器 → preventDefault + 拉回自己首元素；内层 onKey 后执行又拉回内层首元素（关闭 X 钮）——每次 Tab 重复拉锯。
- 真实场景（DOM 兄弟型）：① Review 管理记忆卡 + 删除确认；② Library 编辑笔记 + 删除笔记确认；③ Library KB 文档管理 + 删除资料确认；④ 抽屉/页面 Modal 上叠 ⌘K 搜索（较轻，↑↓↵ 可替代）。DOM 嵌套型（SharePlanDialog 内 ConfirmDialog）不受影响。
- 后果：键盘用户无法 Tab+Enter 触发「确认删除」，只能鼠标或 Esc。修复方向：圈禁协调（Modal 栈只让栈顶实例拦截 Tab）。

### 68#2（=P-2）Review 空格快捷键劫持页面内其他按钮的空格激活

- `Review.tsx:80` 守卫只排除输入类元素不排除 button——Tab 到「创建记忆卡」等按钮按空格 → preventDefault 翻面而非激活按钮；页面空格滚动同被吞（小屏影响）。flashcard 自身 button 的 preventDefault 恰好防双翻（正确部分）。修复方向：`target.closest('button')` 时排除非 flashcard 按钮。

### 68#3（=P-3）全局搜索 ↑↓ 无 isComposing 检查

- `App.tsx:506`——IME 组字时按 ↑↓ 选候选词，结果高亮同步漂移（Enter 有守卫不会误开结果）。轻微。

## 信息性

- 68#4（=P-4）Esc 仲裁顺序与视觉层级不一致。链条：① App 仲裁固定顺序 Modal(.overlay)→focus→tutor，而 z-index 为 focus(z90)>Modal(z70)>tutor(z60) → ② 若未来允许专注层上叠弹窗，Esc 会先关视觉下层。影响：当前 focusOpen 时 ⌘K 被禁且全屏遮罩挡入口，Modal+focus **无法同开**——路径不可达，仅口径记录。
- 68#5（=P-5）移动导航无焦点圈禁。链条：① <1024px 打开 mobileNav 抽层 → ② 无 useFocusContainment 接线 → ③ Tab 从导航逃到遮罩背后的主内容；Esc 可关。影响：窄窗口键盘用户（低频组合）焦点顺序异常；对照 tutor 抽屉与 FocusLayer 均有圈禁。
- 68#6（=P-6）Review 空格长按重复翻面。链条：① keydown 未检查 event.repeat → ② 长按空格每 33ms 重复触发 toggle → ③ 卡片正反面高频抖动。影响：仅视觉噪声，松手即停；数字键评分被 grade 内 busy 守卫挡住无实质风险。

## 正向结论

- **泄漏零**：4 处原生监听全部对称 removeEventListener；MODAL_STACK push/splice 与滚动锁计数对称。
- **Esc 单一消费**：栈外仅 App 全局仲裁且有 .overlay 让位；「确认弹窗套 Modal」逐层退出正确；抽屉/专注层由 App 层统一排序。
- Review 19#1 守卫覆盖完整（3 类 overlay 全含 ConfirmDialog）。
- ⌘K 输入框聚焦时仍可用且幂等；FocusLayer Esc 可完全恢复（后端持续计时）。
- 快速记录/Agent/导师的 Enter 与按钮双路径守卫一致（43#1 验证通过）；4 处 Enter 全有 isComposing。
- 空格与按钮激活无双重触发（flashcard 单次翻面；非 Review 页原生正常）。
