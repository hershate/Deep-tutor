## 用户点名项复验结论（两项均无问题，第四轮复扫继续成立）

- **「打开工作区弹程序选择框」不存在**。全部「在资源管理器中显示」入口（共 7 处：
  DataDirectoryPanel.tsx:89、BackupPanel.tsx:38、ExportCenter.tsx:136、UI.tsx:215
  RevealExport 被 UsagePanel/Integrations/Practice/ProviderHub/Reports/SyncPanel 六处
  复用）走 `invoke('reveal_path')` → 后端白名单校验（数据根或 24h 导出回执）→
  `tauri-plugin-opener 2.7.2` 的 `reveal_item_in_dir` → Windows 分支
  `SHOpenFolderAndSelectItems`（reveal_item_in_dir.rs:110-170，打开父目录并选中
  目标；仅 ERROR_FILE_NOT_FOUND 时 fallback `ShellExecuteExW` 且对目录显式
  lpClass="folder" + lpVerb="explore"）。「你要如何打开此文件」只在 ShellExecute
  打开无关联**文件**时触发；仓库内 `open_path` 前端零调用，open_url 被 capabilities
  限定 https://**，不存在把文件夹/无关联文件交给 shell 默认动词打开的调用。按钮
  文案「在资源管理器中显示」（DataDirectoryPanel.tsx:101）与 reveal 选中语义一致。
- **「按钮闪命令行黑窗」不存在**。全链四类路径逐一核实：①应用自有 Rust 代码零
  `std::process::Command`（`std::process` 全部出现为 `process::id()` 临时名 6 处与
  `process::exit` 退出码 3 处，均非子进程）；②opener 插件启用 open crate 的
  `shellexecute-on-windows` feature，open_url/open_path Windows 直接
  `ShellExecuteExW`（open-5.4.5 src/windows.rs:293-319）零子进程；即便走该 crate
  的兜底 spawn 路径，每条命令显式 `creation_flags(CREATE_NO_WINDOW)`
  （windows.rs:8,81,86,102,192）；③restart_application 的子进程为
  windows_subsystem="windows" 的 GUI exe（GUI 进程不分配控制台，不闪窗）；
  ④文件/保存对话框走 rfd 0.17.2 的 IFileDialog COM（无子进程）。npm scripts 与
  Makefile 全部为构建期目标，前端按钮只经 IPC，运行时无触发链路。
- **外部动作面闭合**：运行时可触达 OS 的动作仅三类（资源管理器定位、系统浏览器
  https 外链、原生打开/保存对话框），capabilities/default.json 5 项权限最小充分，
  无 window.open / target=_blank 残留，reveal 权限已收回后端并有测试断言
  （commands.rs:1056-1072）。

## 待核

### 140#1 MarkdownLink 对协议相对链接 `//host/path` 强制升 https

- 位置：`desktop/src/components/UI.tsx:23`（`//` 前缀链接改写为 `https://...`）。
- 传递链条：①讲义/笔记含协议相对链接 `//example.com/x`（作者按源站 http 写入）；
  ②前端统一改写为 `https://example.com/x` 后交系统浏览器；③若源站不支持 https，
  浏览器报连接错误，用户误以为应用故障。
- 影响范围：受影响=资料作者使用协议相对链接且目标站不支持 https 的极窄场景；
  该行为同时是安全收紧（防止降级到 http）的有意设计。损害性质=链接不可达的
  归因误导。
- 修复方向：维持现状可接受；可选在改写处注明「已按 https 打开」。需真实资料
  样本确认实际出现频率后定级。

### 140#2 App 级弹层顶栏/侧栏按钮互相顶替无守卫，与 133#6 修复口径不一致

- 位置：`desktop/src/App.tsx:479`（顶栏 `global-search`/`quick-add`/通知铃铛三个
  按钮的 `onClick={() => setModal(...)}` 均无守卫）、`App.tsx:475`（侧栏「Agent
  任务中心」`setModal('tasks')` 同）；对照 `App.tsx:305` 的 Ctrl+K 路径已带
  `!modal && !hasOpenModal()` 守卫（133#6 修复）。
- 传递链条：①快速记录弹层半填中；②点击顶栏铃铛或搜索框；③`modal` 单值状态从
  `'quick'` 直翻 `'notifications'`/`'search'`，原弹层无确认直接卸载。损失有限：
  `quickTitle/quickType` 是 App 级 state 不丢失，SearchLayer 常驻不卸载——实际丢失
  的是弹层上下文（列表滚动位、半填的即时视觉）。但 133#6 注释宣称「任一 App 级
  弹层打开时再开搜索会直接顶替……补 !modal 守卫」，守卫只覆盖键盘路径，按钮
  路径未覆盖，注释口径与实际覆盖面不符。
- 影响范围：受影响=弹层间切换的上下文丢失；不受影响=数据本身。损害性质=交互
  细节 + 修复口径不一致。
- 修复方向：四个顶栏/侧栏入口复用 Ctrl+K 同款 `!modal && !hasOpenModal()` 守卫
  （或同步修正 133#6 注释声明只保键盘路径）。

### 140#3 后端错误英文 code 前缀直接拼接展示给用户

- 位置：`desktop/src/backend/client.ts:504-510`（`backendErrorMessage` 输出
  `code：message`）；展示点如 `DataDirectoryPanel.tsx:103`、`Library.tsx:428`、
  `TutorPanel.tsx:57`。
- 传递链条：①操作失败；②`BackendError{code,message}` IPC 透传；③用户看到如
  `reveal_not_allowed：只能定位数据目录或本应用刚导出的文件`——message 为可行动
  中文（error.rs 全部构造点核实为中文自释文案），英文 snake_case code 对普通
  用户是噪声前缀。
- 影响范围：受影响=全部错误提示的可读性；code 便于反馈定位与日志对账，属设计
  取舍。损害性质=提示文案观感。
- 修复方向：如需收敛，仅开发模式拼 code，或错误提示附「复制详情」入口。

### 140#4 数据目录位于盘根时 reveal 失败的边界

- 位置：`tauri-plugin-opener 2.7.2 src/reveal_item_in_dir.rs:115-125` +
  `windows_shell_path.rs:89-118`（盘根无父路径，`ILCreateFromPathW(空串)` 失败）。
- 传递链条：①用户把数据目录配置为 `F:\`（盘根）；②点击「在资源管理器中显示」；
  ③`shell_parent_path` 返回空、ITEMIDLIST 构造失败 → 后端报
  `reveal_failed：资源管理器定位失败`（commands.rs:63）——弹中文错误横幅而非
  资源管理器。
- 影响范围：受影响=数据根为盘根的极端配置；有明确中文错误提示，无弹框无黑窗。
  损害性质=边缘配置下按钮不可用。
- 修复方向：可忽略；若兜底，后端对数据根==盘根时直接 explorer 打开该卷根目录。
