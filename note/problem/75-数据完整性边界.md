## P3

### 75#1（=F-1）唯一非幂等迁移：routing legacy 表重建在崩溃窗口内滞留数据且永不重试

- 位置：`providers/routing.rs:155-182`。
- 传递链条：① 旧表检测 → `execute_batch("RENAME…; CREATE…; INSERT…SELECT; DROP…")` 四条各自 autocommit（无事务）② 进程在 RENAME 后、DROP 前崩溃 → 新表已建，下次启动谓词读新表为 false → 重建永不重跑 ③ `provider_route_attempts_legacy` 永久滞留；备份 TABLES 67 张白名单不含 `_legacy` → 该部分历史从备份面消失；CASCADE 删除不再触及。
- 影响范围：路由尝试审计历史（计费重试）滞留不可达表。全仓唯一破坏「崩溃后重跑可自愈」的迁移（其余全为 IF NOT EXISTS/PRAGMA 守卫幂等）。
- 修复方向：批处理包事务；或残留检测（`_legacy` 表存在即 DROP/重吸收）。

### 75#2（=F-2）备份快照与文件收集时序窗：恢复库可含无文件、无披露的 agent_artifacts 行

- 位置：`backup/archive.rs:403`（VACUUM INTO 快照）→ `:449`（collect_files 时在活连接重查 artifact 行）。
- 传递链条：① 快照 T1 后、行查询 T2 前，purge_expired_artifacts 或 delete_session 提交删行删文件 ② 快照库仍含行、T2 查不到 → 文件既不在 files 也不在 missing_files ③ 导入后目标库有行无文件无披露——read_artifact 直接 io 错误（content_json 仍在库内可手工救回）。秒级窗口、需与清理并发。
- 修复方向：行清单也从快照连接读取（T1 一致性），或 manifest 补「快照内行数 vs 收集差集」披露。

### 75#3（=F-3）单行损坏 JSON 直穿 `?` 使整页/整域失败（7 处，与既有容错口径不一致）

- 位置与链条：`store.rs:516`（collection_value——一条坏 kv 行使 app_state/bootstrap 整体失败）、`store.rs:868`（events_since——坏 payload 使事件轮询分页全失败）、`knowledge/mod.rs:284/:303-316`（坏 citations_json 使 Wiki 列表全空）、`learning/mod.rs:525-527/:581-587/:613`（任一方案任一 JSON 列坏使方案列表整页失败）、`agent/mod.rs:404-426`（坏 content_json 使整个会话视图失败）、`providers/usage.rs:269/:521`（坏 usage_json 使总览+CSV 全失败）、`engagement/mod.rs:389`（搜索）。对照已容错点：agent tool_calls `unwrap_or_default()`、providers usage `unwrap_or(None)`。
- 影响范围：外部篡改/文件层 bitrot 下 1 行损坏放大为整域不可用，且错误不含行 id 无法定位。
- 修复方向：读路径统一降级（跳过坏行+计数披露），与既有容错口径对齐。

### 75#4（=F-4）put_draft/delete_draft 无 revision 守卫——双编辑面 last-writer-wins 可丢草稿

- 位置：`store.rs:716-747`。replace_collection 在 IMMEDIATE 内比较 revision 拒冲突；草稿路径只递增从不比较——两个窗口（或自动保存与关闭清理）并发时后提交者胜，刚保存内容可被静默删除且无 revision_conflict 提示。草稿按设计为易失内容（≤1MB）定 P3；与集合路径防线不对称。

### 75#7（=F-7）读路径 `i64 as u8/u32/u64` 依赖「库内恒非负」不变量，备份导入是唯一旁路

- 导入校验不查每列符号域——含负 attempts 档案导入后读取 `-1 as u8 → 255`（展示层噪声）。对照 materials `max(0) as u64` 显式防负。

### 75#8（=F-8）成本/评分 f64 入口验证齐备，无 NaN/Inf 入库路径

- 预算/费率 is_finite 非负、主观分 clamp(0,1)、SQL AVG 的 max_score=0 行自动排除。
