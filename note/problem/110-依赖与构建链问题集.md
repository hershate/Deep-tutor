### 110#1 vite 5.4.21 / esbuild 0.21.5（devDependencies）带 2 条未修复安全通告——含 Windows 专属命令执行族，门禁无审计步骤漏网

- 位置：`desktop/package.json:31`（vite ^5.4.14，lock 钉 5.4.21；esbuild 随 vite 锁 0.21.5）；`desktop/vite.config.ts:6-9`（dev server 仅 host 127.0.0.1，缓解但不消除）。
- 实跑证据（本轮 `npm audit`）：**runtime 侧 0 漏洞**；含 dev 侧 2 漏洞——esbuild ≤0.24.2 moderate（任意网站可向 dev server 发请求并读响应，localhost 绑定不能防）+ vite ≤6.4.3 **high**：8 条 via，含 launch-editor 任意命令执行、escapeCmdArgs % 转义遗漏、fs.existsSync 绕过（三条 Windows 专属）、server.fs.deny Windows 备用路径绕过、path traversal .map、跨源中间件。
- 传递链条：①开发者 npm run dev（:1420）→ ②访问含恶意脚本的网页，或点击被污染的错误叠加层「跳转编辑器」→ ③esbuild dev server 无防护响应 / launch-editor 在 Windows 上被构造参数执行命令 → ④本机源码泄露或开发机命令执行。CI 与本地门禁均无 npm audit/cargo audit 步骤，该漏洞面长期无检出通道。
- 影响范围：仅开发期（vite 不进安装包，发布产物不受影响）；影响所有本机跑 dev server 的开发者，Windows 全命中。
- 修复方向：vite 升至修复版（audit 建议 8.x breaking；保守可评估 6.4.4+ 回移）；门禁加 `npm audit --omit=dev` 或全量白名单基线；server.fs.allow 显式收窄为 src。

### 110#2 双 reqwest 并存：应用钉 0.12.28、tauri 2.12.5 传递引入 0.13.5——两套 HTTP 栈同链编译

- 位置：`Cargo.toml:24`（reqwest 0.12.12 约定，lock 0.12.28 native-tls）；`Cargo.lock:3151`（0.13.5 无 TLS 后端，来自 tauri 2.12.5）。
- 传递链条：①tauri 上游迁 0.13，应用仍钉 0.12 → ②同二进制链接两份 reqwest+hyper → ③体积/编译时长上浮；tauri 内部 fetch 当前被 CSP connect-src ipc: 封死 → ④无运行时风险，纯维护面。
- 影响范围：二进制体积与编译时长上浮（两份 HTTP 栈）；依赖审计面名义条目翻倍；无运行时风险（tauri 内部 fetch 被 CSP 关闭）。
- 修复方向：跟踪上游，条件成熟时归一（需同步 native-tls feature 决策）；记录现状。

### 110#3 Cargo.toml 版本约定「半钉半漂」——patch 号写出但 ^ 语义下已漂移，宽 major 约定构成漂移面

- 位置：`Cargo.toml:11-31`。事实：zeroize 写 1.8.1 实锁 1.9.1；reqwest 写 0.12.12 实锁 0.12.28（证明 ^ 语义、数字非钉住）；tauri/serde/serde_json/encoding_rs/tempfile 为 major-only 宽约定，rusqlite/time/quick-xml/lopdf 为 minor 级。
- 传递链条：①主动 cargo update 可在约定内跳跃 → ②--locked 只保证「不更新 lock」不阻止主动 update → ③构建可复现性依赖「不去动 lock」的纪律而非声明本身。lock 入库 + --locked 门禁（Makefile/ci.yml）使当前实际可控。
- 影响范围：构建可复现性与变更审查面；tauri/serde 类核心的小版本升级行为变化只能靠测试拦截；当前 lock+门禁纪律下无实际漂移。
- 修复方向：统一为 major-only（承认 lock 是唯一钉住层）或对行为敏感项（tauri/rusqlite/reqwest）加 =x.y.z 精确钉；在 AGENTS.md 记录「patch 号写出≠钉住」。

### 110#4 依赖滞后事实清单（只记录，不升级）——解析用户输入的两个 crate 滞后最多

- 位置与对照（crates.io 实查 2026-11-10）：rusqlite 0.38.0 vs 0.41.1（落后 3 minor）；zip 2.6.1 vs 9.5.0；**lopdf 0.35.0 vs 0.47.0（落后 12 minor；lopdf 直接解析用户提供的 PDF，该 crate 历史多次修复解析 panic/内存安全）**；keyring 3.6.3 vs 4.2.0；tauri/quick-xml 持平；npm 侧 vite 5/react 18/ts 5.6 均在支持带内。
- 传递链条（lopdf 为例）：①用户导入构造的 PDF → ②lopdf 0.35 解析 → ③上游后续修复的解析缺陷在本版本存在（是否可触达需逐 CVE 比对，未逐条核实）→ ④潜在 panic 到后端命令错误路径。
- 影响范围：面向用户输入的两个解析 crate（lopdf PDF / rusqlite 捆绑 SQLite）滞后最多；无已证实的用户可感缺陷，属攻击面维护性前瞻。
- 修复方向：排期小步跟进（rusqlite/lopdf 优先——面向用户输入）；每次升级走完整 make check。

### 110#5 CI（MSVC host）与本地（GNU host）工具链口径分叉由 rustup 默认 host 决定，仓库侧未钉 host triple

- 位置：`rust-toolchain.toml:3`（channel 1.99.1 无 host 说明）；CI windows-latest 默认解析 msvc；本机实跑 rustup show 解析 1.99.1-x86_64-pc-windows-gnu（与 AGENTS.md 一致）。
- 传递链条：①同一 toolchain 文件两环境解析不同 host ABI → ②本地 dist/ 安装包为 GNU 构建、CI 为 MSVC → ③GNU 特有问题（100#2 manifest 遮蔽、dlltool）CI 永远测不到，反之亦然 → ④「CI 绿」与「本地可发布」互不充分保证；存在两个来源的 NSIS 安装包。
- 影响范围：构建链口径与发布物溯源（本地 dist/ 与 CI artifact 是不同 ABI 的安装包）；当前双端均绿无功能影响，纯口径风险。
- 修复方向：rust-toolchain.toml 显式 targets 或 CI 加 --target gnu 统一口径；或文档化双轨现状；make check 可选补 --verify-native（当前仅 CI 有，79#5）。

### 110#6 collect-licenses.mjs 的 licensePattern 不匹配 COPYING——licenseScore 的 COPYING 分支是死代码，未来 COPYING-only 包将落入缺失通道

- 位置：`scripts/collect-licenses.mjs:28`（`/^licen[cs]e|notice/i` 不匹配 COPYING）、`:36`（score 专门写了 COPYING 分支但 pickFromNames:44 先按 pattern 过滤，永远进不了候选）；归档直抽路径 :218 同样遗漏。
- 传递链条：①未来依赖树引入 COPYING-only 包（GNU 风格惯例）→ ②两道均不命中 → ③落入 missingCrates 靠兜底声明而非全文。当前 527 crate 对账 0 个 COPYING-only 包，无实际缺失。
- 影响范围：仅未来引入 COPYING-only 包时的许可全文分发缺口（当前依赖无此形态，COLLECTED.md 兜底声明在位）；脚本自身的死代码。
- 修复方向：licensePattern 加 `|^copying` 一行即闭合。

### 110#7 npm overrides 强制 katex 0.19.1 越过 rehype-katex 的 ^0.16.0 语义边界——@types/katex 类型版本错位

- 位置：`package.json:33-35`（overrides katex ^0.19.1，59#8 有意决策）；lock：rehype-katex@7.0.1 声明 ^0.16.0 实际解析 0.19.1，@types/katex 停在 0.16.8。
- 传递链条：①overrides 覆盖 semver 声明 → ②类型面与运行时错位（新 API 无类型提示、行为差异无编译期信号）→ ③未来任一侧升级时冲突被 override 掩盖。当前渲染功能正常（104/105 号门禁留证）。
- 影响范围：公式渲染链的维护性（rehype-katex 运行在其声明版本之外的 katex 上）；当前用户可见渲染正常，纯前瞻排障成本。
- 修复方向：跟踪 rehype-katex 支持 katex 0.19 的版本，就绪后移除 override；或注释补退出条件。

### 110#8 icon.ico 仅含单一 256×256 图层——小尺寸场景依赖系统运行时缩放

- 修复方向：用 tauri 官方 `tauri icon` 重生成多尺寸 ico（16/24/32/48/64/128/256）。

### 110#9 tauri-plugin-fs 2.7.1 随 dialog 插件入树编译但未注册——零权限授予，仅记录事实
