# 待确认问题（5 项）

以下问题涉及竞态窗口、产品意图或依赖模型行为的约束，无法仅凭静态核对定论，
修复前需人工判定设计意图。

## 1. [待确认] `agent.step_started` 后立即 `getProviderChat` 存在 not_found 竞态
- 前端：`desktop/src/backend/useAgent.ts:83-88`——liveRequestId 一更新即调用
  `getProviderChat`，失败即 `setError`，`AgentCenter.tsx:99-100` 显示“后端连接异常”横幅。
- 后端：`agent/mod.rs:711-718` step_started 事件在路由登记前提交；`providers/routing.rs:887-932`
  route run 行之后才落库；`providers/mod.rs:915-921` 两级查找均缺失时报 `not_found：模型请求不存在`。
- 判定点：若 invoke 先于工作线程落库执行，界面短暂闪现 not_found 错误（随下一个
  agent 事件清除）。触发概率低；是否需要在前端忽略该竞态错误或后端保证先后顺序，需设计判断。

## 2. [待确认] hints 反馈模式完成后仍显示总分与正确率
- 前端：`desktop/src/pages/Practice.tsx:210` 选项文案“只给提示，不显示答案”；
  `:187` completed 分支无条件展示 `set.score / maxScore` 与正确率。
- 后端：`practice/mod.rs:1119-1147` hints 模式分数照常落库与汇总；`:993-1025`
  仅对逐题 score/correct/feedback 做遮蔽，set 级分数不遮蔽。
- 判定点：若产品有意在完成后公布总分则非缺陷；否则 set 级遮蔽需补。

## 3. [待确认] 主观题“固定生成 1 道简答题与 1 道论述题”文案，后端不保证题型各一
- 前端：`desktop/src/components/SubjectivePractice.tsx:25` 请求 `{count: 2, kinds: ['short','essay']}`；
  `:133/141` 文案“固定生成 1 道简答题与 1 道论述题”。
- 后端：`practice/mod.rs:484-499` 仅校验 kinds 合法非空；`:788-877` 逐题仅校验题型属于请求集合，
  无各题型数量约束；`:414-422` 提示词也未强制各 1 道。
- 判定点：模型返回两道同题型时不被判无效。是否把提示词约束视为足够，或需后端强校验，需产品判断。

## 4. [待确认] 每条流式 delta 触发一次 `getProviderChat` 全量重放（O(n²)）
- 前端：`desktop/src/pages/ProviderHub.tsx:153-157` 每个 `provider.chat_*` 事件（含每条 delta）
  都 invoke 一次 `getProviderChat`。
- 后端：`providers/mod.rs:890-911` 对未完成请求每次全量回放 events 表该 requestId 的全部 delta
  拼接输出。
- 判定点：长回答（数百 delta）时每增量一次全表扫描+拼接+IPC，叠加同步命令跑在主线程的架构特性，
  流式面板可能可感知卡顿。功能正确，属性能风险；是否优化取决于实测体感。

## 5. [待确认] 取消请求在“后端已终态、invoke 未返回”窗口报 `no_active_request`
- 前端：`desktop/src/pages/ProviderHub.tsx:347-350` 取消失败写入 `streamError`；
  取消按钮在 `streamBusy` 期间可用。
- 后端：`providers/routing.rs:1133-1137`、`providers/mod.rs:1193-1203`——取消注册表已摘除时
  返回 `no_active_request：该请求没有正在执行的任务`。
- 判定点：竞态窗口极小（流已结束但 invoke 未 resolve 时点取消），用户看到误导性错误，
  实际请求已正常完成。是否把该错误码在前端静默处理，需判断。
