# 58 · 窗口弹出与子进程专项（第二十四轮·用户点名场景核查）

> 审计范围：用户点名两个场景（① 点击「打开工作区」是否弹出系统选择器；
> ② 点击任意按钮是否闪现命令行窗口）+ 全链路子进程/控制台 spawn 排查。
> 方法：应用源码 grep + 依赖 crate 源码级核验（tauri-plugin-opener 2.7.2、
> open 5.4.5，取自本机 cargo registry 与 Cargo.lock 锁定版本）。

## 结论（正向）

### 58#P1 应用自身零子进程 spawn——按钮点击不存在命令行窗口路径

- 证据：`grep -rn "process::Command|Command::new" desktop/src-tauri/src` 仅命中
  `std::process::id()`（取 PID 命名临时文件，7 处）与 `--verify-native` 的
  `std::process::exit(2)`（1 处）。无任何子进程启动。
- 主二进制 `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`
  （main.rs:1）——release 构建自身无控制台。

### 58#P2 外链与「在资源管理器中显示」全走 Shell API，零子进程零控制台

- tauri-plugin-opener 2.7.2 对 open crate 启用 `shellexecute-on-windows`
  feature（插件 Cargo.toml:66-68）：
  - `openUrl`（ProviderHub 16 条 https 文档链接）→ `ShellExecuteExW` 纯 API
    （open-5.4.5/src/windows.rs `that_detached`）。
  - `revealItemInDir`（DataDirectoryPanel dataRoot / BackupPanel 刚导出文件 /
    ExportCenter 刚导出文件，共 3 调用点）→ `SHOpenFolderAndSelectItems` COM
    API + `ERROR_FILE_NOT_FOUND` 时 `ShellExecuteExW(explore)` 兜底
    （reveal_item_in_dir.rs:107-170）。不弹「打开方式」选择器。
- 附注：open crate **默认 feature**（若未启用 shellexecute）会 spawn
  `powershell.exe`/`explorer.exe` 子进程——虽有 `CREATE_NO_WINDOW` 不闪窗，
  但存在启动开销与 EDR 关注面；当前锁定配置已绕开该路径。升级插件/open
  版本时需复核该 feature 仍在（升级清单项）。
- reveal 三处调用点的路径在调用时必然已存在（dataRoot 由初始化创建、导出
  文件刚写入）；不存在路径走 ILCreateFromPathW→SHOpenFolderAndSelectItems
  失败→错误返回前端 notify，不弹系统对话框。

## 问题

### 58#1 `--verify-native` 失败路径在无 stderr 句柄环境 panic——退出码 101 取代设计的 2

- 位置：`desktop/src-tauri/src/main.rs:162`（`eprintln!` + `exit(2)`，50#1 引入）。
- 传递链条：① 从资源管理器双击 / 无控制台服务上下文运行 verify 通道 →
  ② GUI 子系统进程 `GetStdHandle(STD_ERROR_HANDLE)` 为 NULL → ③ `eprintln!`
  写入失败触发 std panic（`failed printing to stderr`）→ ④ 进程以 **101**
  退出而非设计的 2；50#1 注释宣称「stderr 不可见时也无栈噪声」不成立——
  不是静默而是 panic。
- 影响范围：仅无句柄环境跑 verify 的调用方（正常终端/CI 重定向均有句柄，
  退出码语义正确）。脚本若严格判 `exit==2` 会把 101 当「未知崩溃」。
- 修复方向：`let _ = writeln!(io::stderr(), ...)` 忽略写失败，或先探测句柄
  存在再打印。

### 58#2 debug 构建保留控制台窗口（dev 预期，记录口径）

- `windows_subsystem = "windows"` 仅 `not(debug_assertions)`——`npm run tauri dev`
  / `cargo run` 启动时伴随一个控制台窗口。属开发调试预期（可看日志）；
  打正式安装包走 release 不受影响。信息级，无需处理；若要 dev 也无控制台，
  需另配 `#![windows_subsystem]` 与日志重定向，不建议。
