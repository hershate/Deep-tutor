# 159 · 设置与模型路由

## 159#1 设置页读取成功后仍永久显示加载中

- 严重度：P1。
- 传递链：`Settings` 的 `load()` 调用 `engagementBackend.profile()` 成功后只执行 `setDraft(next)`，没有执行 `setProfile(next)`；主区域所有正常内容都以 `profile` 非空为条件，因此成功读取后仍显示“正在读取学习档案”。编辑弹窗又只能通过“重新学习诊断”间接触发。
- 影响范围：个人档案、语言、每周投入、学习方式、讲解方式、免打扰设置及首次使用引导；直接保存和事件刷新不能修复主状态。

## 159#2 模型中心在仅配置任务路由时禁止发送

- 严重度：P2。
- 传递链：`ProviderHub.startChat` 与发送按钮以 `!activeId && routing.mode !== 'aggregate'` 为禁用条件；后端 `routing::select` 在 routing 模式可完全依据 `routes.agent` 选择供应商，不需要 active 默认值。前端因此拒绝了后端支持的合法配置。
- 影响范围：只设置任务路由、未设置当前供应商的模型检测与首次接入流程。

## 159#3 脱敏配置预览漏监听实际导出字段

- 严重度：P2。
- 传递链：配置预览 effect 的 `configKey` 只包含 active、路由模式、档案 id/enabled/hasKey/模型数量/默认模型；名称、Base URL、协议、备注、模型名称及路由分配变化不会改变 key；effect 不重新调用 `export_provider_config`。
- 影响范围：模型中心“配置与同步”页展示的 JSON；用户复制或核对的配置可能不是刚保存的配置。

## 159#4 路由面板展示没有执行链的任务类型

- 严重度：P2。
- 传递链：`taskRoutes` 展示 `resources`“检索与筛选学习资源”和 `embedding`“向量嵌入”；实际资源步骤直接调用 `web::search`，全仓没有嵌入请求或向量索引实现；后端 `TASKS` 仍允许保存这两个路由键。
- 影响范围：任务路由、快速策略、脱敏配置与同步；用户会以为资源配置影响网页检索、嵌入配置会启用不存在的功能。
