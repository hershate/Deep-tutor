## P3

### 22#1 Store::new 无 principal 线程 fail-open 回退 user 1 工作区

> **第十一轮修订（2026-11-07）**：原文判定"当前被守卫覆盖，实际无暴露路径"已被
> 23#7 推翻——providers 域 5 个 `spawn_blocking` 异步命令不继承 thread-local
> principal，正是踩中本条 fail-open，形成 user2 数据写入 user1 工作区的实际暴露。
> 本条维持 P3（机制弱点），实际暴露路径见 23#7（P2）。

- 位置：`desktop/src-tauri/src/backend/store.rs:70-74`
- 证据：
  ```rust
  #[cfg(not(test))]
  let owner = super::security::principal_id().or(Some(1));
  ```
  当前全部 188 个命令经 `security::guard_handler`（main.rs:79）包裹，后台线程经
  `security::thread_builder()` 传播 principal，实际无暴露路径；但若未来任何代码在
  无 principal 的裸线程打开 Store，将静默落到 user 1 工作区而非报错。
- 影响：纵深防御弱点（fail-open 默认），非当前漏洞。
- 修复方向：改为无 principal 时返回类型化错误（`store_unavailable`），测试环境
  维持显式注入。

### 22#2 Python 时代运行时数据滞留磁盘，含旧密钥文件

- 位置：`data/`（含 `.jwt_secret`、`deep-tutor.db`、sessions、workspaces、kb、logs、plugins、runs）、`backend/data/`（旧库+会话）、`.pytest_cache/`
- 证据：`ls -a data/` 确认 `.jwt_secret` 存在；`backend/` 目录内仅 `data/` 子目录，
  当前代码零引用（Python 后端已删除）。三者均被 .gitignore 覆盖（`/data/`、
  `/backend/data/`、`.pytest_cache/`），不在 git 内；.pytest_cache 的 ACL 损坏问题
  已在 .gitignore 注释中说明（需提权手动删除）。
- 影响：按仓库自身清理规约（AGENTS"非后期复用缓存必须清理"），旧运行时数据与
  旧密钥文件属待清理项；`data/.jwt_secret` 若曾被真实使用，属应销毁的敏感残留。
- 修复方向：确认无复用价值后分批清理（.pytest_cache 需提权）；`backend/` 空壳
  目录一并移除。

### 22#3 `TEMP/` 无 .gitignore 规则

- 位置：仓库根 `TEMP/`（当前为空目录）
- 证据：.gitignore 全文无 TEMP 条目；空目录不被 git 跟踪故 status 干净，但一旦
  作为临时测试环境放入文件即以 `??` 出现在 git status。
- 影响：与"临时文件使用项目 TEMP 子文件夹"的全局规约配套的忽略规则缺失。
- 修复方向：.gitignore 增加 `/TEMP/`。

### 22#4 docs/architecture/index.md 的 CI 步骤描述与 ci.yml 实际不符

- 位置：`docs/architecture/index.md:13` vs `.github/workflows/ci.yml:36-51`
- 证据：文档称 CI 为"fmt + 前端构建 + 原生测试串行 + NSIS 安装包"；实际步骤为
  Install deps → Rust format → Native tests → Check versions → Collect licenses →
  Build NSIS，**无独立前端构建步骤**——`npm run build` 由 tauri.conf.json 的
  beforeBuildCommand 在最后的 NSIS 步骤内执行。前端类型错误要等 Rust 测试全跑完
  才暴露（CI 耗时损失，非正确性问题）。
- 修复方向：文档改述为"fmt + 原生测试串行 + 版本/许可证 + NSIS（内含前端构建）"；
  或 CI 在 fmt 后加独立前端构建步骤（提前暴露前端错误）。
