# 51 · 前端数据流竞态（第二十二轮）

> 审计范围：25 个 backend/*.ts + 全部页面/组件（约 7,250 行）穷尽通读，
> 六类竞态模式（依赖闭包/事件刷新覆盖/响应乱序/乐观回滚/派生同步/key）。
> 主审对 P2 与 P3-4/P3-3 逐条亲验。Community reserve 无 busy（=43#17）与
> notify 不稳定（=43#11，现状确认未变）不重复计数。

## P2

### 51#1 Practice 页事件刷新与用户切换互相覆盖——选中集被静默回退、直播流串台

- 位置：`desktop/src/pages/Practice.tsx:41-46`（refresh 无序号守卫，主审亲验）、`:94-102`（chooseSet）、`:130-141`（submit 后 setDetail）、`:193-195`（selectHistory 无 busy 守卫）
- **传递链条**：① 主观题评分期间 `practice.answer_*` 事件持续触发 throttledRefresh（:71）→ ② refresh 在 t0 读 `currentId=A` 并发起 IPC → ③ await 窗口内用户点历史项 B（selectHistory→chooseSet 置 `currentId=B`、渲染 B）→ ④ refresh 的 A 响应后到，无条件 `setDetail(A)` 且 `requestId.current=A` → ⑤ 界面从 B 静默跳回 A，后续事件刷新继续拉 A、直播输出也切到 A。对照 Reports（28#4）/Community（32#11）已有 `refreshSequence` ticket 守卫，Practice/Plan/Review 三个同构页没有。
- **影响范围**：评分活跃期间切换练习集必现（事件频率高、窗口宽）；用户再点一次才能恢复。修法：照抄 28#4 的 ticket 守卫 + selectHistory 加 busy。

## P3

### 51#2 Plan 周历快速翻页 + 事件刷新无序号守卫——表头与内容短暂错周

- 位置：`desktop/src/pages/Plan.tsx:59-73`（refresh 无 ticket）、`:75-82`。
- **传递链条**：① 连点「下一周」两次（week1→week2→week3）→ ② 每次 weekStart 变化产生新 refresh（各自闭包捕获各自 weekStart）→ ③ week3 响应先回、week2 后到 → ④ `setOverview(week2 数据)` 无条件写入——表头显示 week2 而按钮态在 week3；`saveTaskDate`（:128）还会 `setWeekStart(next.weekStart)` 把周起点一并拉回。
- **影响范围**：快速翻页用户（双击/连点即触发）；错误状态短暂（下一次点击或下一个 plan./state.changed 事件自愈），无数据写错（仅显示层）。期间若在错周视图上做拖拽排期，`saveTaskDate` 的周起点回拉会叠加。对照 Reports（28#4）/Community（32#11）已有 ticket 守卫。

### 51#3 Review 刷新无守卫——刚评过的卡可能回队被二次评分；历史卡 A/B 展开交错

- 位置：`desktop/src/pages/Review.tsx:30-39`、`:120-126`。
- **传递链条**：① 事件 X 触发 refresh（Promise.all 拉卡 C）→ ② 用户此刻已翻面并评分（grade 落库、refresh(B) 返回 D、setCard(D)）→ ③ refresh(A) 的 C 后到无条件 `setCard(C)`——刚评过的卡回到作答位且 flipped 已置 false → ④ 用户按 1-4 对 C 二次评分（间隔被重算、reviewed 计数虚增、review_history 落两条）。showHistory 同型：点 A→点 B，A 后到覆盖 B 的展开区。
- **影响范围**：需要事件恰落在评分 await 窗口（窄），但复习页键盘操作快、事件源（别的页面产生 review.*/state.changed 事件）不可见——用户无感知地污染了间隔重复数据（SM-2 参数被二次评分扭曲）。受影响=开着复习页且有并发事件流的用户。不受影响=单独安静复习场景。

### 51#4 Library openNote 连续点击草稿互串——在「以为是 B」的编辑器里写 A

- 位置：`desktop/src/pages/Library.tsx:196-207`（主审亲验）。
- **传递链条**：① 快速点笔记 A 再点 B → ② 两次 `getDraft` 并发（A 的 key=draft-A，B 的=draft-B）→ ③ B 先回打开 B 编辑器 → ④ A 后到，`.then` 无条件 setActiveNote(A)+覆盖标题/正文/标签（整编辑器一致地变成 A）→ ⑤ 用户在「以为是 B」的界面继续打字并保存——内容写入 A（含 B 标题下显示 A 内容的一瞬间错乱）。
- **影响范围**：快速连续打开不同笔记的用户；后果是被写笔记对象错位（数据写进另一条笔记，事后难察觉）。对照 openMaterial 的 openingMaterial 串行守卫（:137）。修复：同款守卫或打开序号。

### 51#5 StudyRoom route_attempt 分支用陈旧 lecture 闭包——failover 后直播预览冻结（15#6 只修了一半）

- 位置：`desktop/src/pages/StudyRoom.tsx:134`（主审亲验）vs `:142`（已用 ref）。
- **传递链条**：① 用户切到某阶段（监听器此时挂载，闭包捕获 lecture=旧快照/ null）→ ② 点「开始生成」，lecture 状态更新但监听器不重挂（deps 为 refreshLecture/refreshProgress）→ ③ 生成中发生 failover：`provider.route_attempt` 携带新逻辑 requestId → ④ :134 `lecture?.units.some(...)` 用陈旧闭包匹配失败 → ⑤ upstream→logical 映射未登记进 routeUpstreams → ⑥ 后续 `chat_delta`（携带 -fN 上游 id）在 :142 的 ref 查表 miss → ⑦ throttledFetch 不触发，直播文本停在 failover 前最后一帧。
- **影响范围**：讲义生成中遇 failover 的用户——弹窗直播预览冻结（生成本身、落库、完成刷新均正常，lecture.* 事件照常收尾）。纯显示层缺陷。修复：:134 改 `lectureUnitsRef.current`（与 :142 对齐，一行）。

### 51#6 App 双通道轮询+事件并发无序号守卫——侧栏角标与今日摘要短暂回跳

- 位置：`desktop/src/App.tsx:129-148`、`:151-165`、`:232-234`（同型 openFocus）。
- **传递链条**：① 事件密集期（lecture 逐单元/practice 逐题）多个 `notifications()`/`dashboard()` 并发在途 → ② 仅 `active` 挂载守卫、无顺序守卫 → ③ 后到的旧响应覆盖新响应 → ④ 侧栏未读角标/今日摘要短暂显示旧值（如未读数回跳），最长 30s 由定时器或下一事件自愈。
- **影响范围**：全局所有页面的侧栏与今日摘要的瞬时显示精度；无数据写错、无累积错误。openFocus 同型窗口仅毫秒级。属低危一致性抖动。

### 51#7 Plan addTask 半失败重试产生重复任务——UI 未区分「任务已保存/仅排期失败」

- 位置：`desktop/src/pages/Plan.tsx:105-122`。
- **传递链条**：① 弹窗提交「保存任务并排期」→ ② `setTasks(updater)` 成功落库任务 T → ③ `assignTaskDate(T, date)` 失败（如日期越界/database_busy）→ ④ catch 只弹错误、弹窗保留、标题未清空 → ⑤ 用户再点保存 → ⑥ 创建第二个同标题任务 T2（T 已在待排期列表）——两段写无回滚也无「任务已保存，仅日期失败」的分段提示。
- **影响范围**：排期步骤失败（网络抖动/瞬时 busy）后重试的用户——产生重复任务需手动清理；无数据损坏（两个任务各自合法）。修复：失败提示区分两段结果，或失败时回滚已建任务。

### 51#8 PlanGenerator selectPlan A/B 竞态 + 导入循环与勾选交错

- 位置：`desktop/src/pages/PlanGenerator.tsx:103-111`、`:166-176`。
- **传递链条**：（a）① 历史方案下拉快速选 A 再选 B → ② 两次 `getLearningPlan` 并发 → ③ A 后到覆盖 `setPlan(A)+setStep`——界面显示 A 而下拉停在 B（事件路径已有 32#3 planRef 守卫，用户自发路径没有）；（b）① 导入多文件循环以 updater 逐个追加 selectedIds → ② busy='files' 期间暂存列表 checkbox 未禁用 → ③ 用户此刻勾选触发 `setSelectedIds([...selectedIds, id])`（渲染闭包旧快照展开）→ ④ 刚导入追加的 id 被抹掉、8 份额度被重置。
- **影响范围**：（a）快速切换历史方案的用户——进入错误方案的步骤视图；（b）导入期间顺手勾选的用户——选择集静默丢失需重勾。两者均为窄窗口、无数据损坏（选择集是会话态）。

### 51#9 七处监听器随回调 identity 变化反复卸载重挂——unlisten 与 re-listen 之间丢事件

- 位置：`pages/Plan.tsx:65-73`、`Community.tsx:54-63`、`KnowledgeMap.tsx:73-84`、`StudyRoom.tsx:125-149`、`Projects.tsx:55-79`、`Settings.tsx:41-57`、`backend/useAgent.ts:123-166`。
- **传递链条**：① 组件状态变化 → ② 依赖数组中的 useCallback 回调 identity 变化（deps 含 weekStart/tab/plan 等）→ ③ effect cleanup 先 `unlisten()`（同步）→ ④ 新注册经 promise 异步完成 → ⑤ 两次之间的 `backend://event` 到达时无监听者——事件被丢弃（不堆积重放）→ ⑥ 依赖「下一个事件再触发刷新」自愈，静默期 UI 停在旧值。
- **影响范围**：七个页面的刷新实时性——恰好在重挂窗口到达的事件（如解析完成、生成进度）丢失一次更新，用户需手动刷新或等下一事件。无内存泄漏（cleanup 正确）、无错误状态。与 35#8（StudyRoom 已修的同型）对照，属系统性 ref 化未推广——回调 ref 化可整体消除。

## 信息性

- **51#10** notify 不稳定依赖族（=43#11 现状确认）。链条：App 每次渲染新建 notify（App.tsx:89）→ 拖放 effect 依赖含 notify（:203）→ 每渲染注销/重挂 onDragDropEvent，重挂窗口拖入被吞。同族新例：App.tsx:454 FocusLayer 计时 effect 依赖每次渲染新建的 onFinish → interval 反复重建（tick 以 startedAt 绝对时间计算，功能无损）；Practice.tsx:92 onTargetConsumed 同型（首跑即消费置空，无实际影响）。影响：拖放丢事件窗口极窄 + 无谓 IPC；其余两处纯噪音。
- **51#11** StrictMode 双执行的写命令。链条：dev 双挂载 → App.tsx:171-183 claimDueReminders 双发领取 → 后端 delivered_at 幂等（第二轮无可领）。影响：仅开发模式、无实害；全仓唯一 effect 内写语义 invoke，其余均为读。
- **51#12** Practice 选项 key 重复。链条：模型生成两个相同文本的选项 → Practice.tsx:223 `key={option}` 重复 → React 重排/高亮可能错位。影响：仅畸形生成结果触发；ExamWorkspace 同处已用 option-index 组合，对齐即可。
- **51#13** deltaThrottle 无尾沿冲刷。链条：最后一批 delta 进入 150ms 窗口 → 此后无新事件 → 定时拉取永不触发（client.ts:403-409 无 trailing 调用）→ 直播预览缺最后 150ms 文本。影响：各直播弹窗的瞬时完整度；终态由 lecture.*/answer.status/终值 invoke 落定，不会停留在旧文本。
- **51#14** 编辑弹窗保存期间的输入丢弃。链条：点保存 → await 期间继续打字（输入框未禁用）→ 成功后 modal 关闭 → 窗口内输入未入保存值即丢弃。影响：Library/Review 编辑弹窗，丢字量≤窗口时长×打字速度（通常几个字）。
- **51#15** profile 弹窗草稿覆盖。链条：弹窗打开（跳过 preferences 刷新但 Settings.tsx:53-54 未跳过 security.session_started）→ 恰在他处切换会话 → load() 的 setDraft 覆盖编辑中草稿。影响：需两窗口/双实例并发操作，窗口极窄；修复同 28#10 的 configOpenRef 模式。

## 正向结论（六类核对过、无问题）

- **草稿保护覆盖完整**：Library 笔记编辑器（事件只刷 overview/详情）、Settings/SyncPanel/SecurityPanel/UsagePanel 草稿（28#10/32#1）、Community 回复分桶（09#3）、Subjective/Exam 按题 ref（28#2）、ProviderHub 表单字段不在 refresh 写入集——除 51#4（用户自发 openNote）与 51#15 外无「事件冲掉编辑中内容」路径。
- **既有守卫全部有效**：StudyRoom stageRef（32#4/35#4/35#9）、KnowledgeMap/PlanGenerator planRef（32#7/32#3）、WikiPanel currentId（32#23）、Reports/Community refreshSequence（28#4/32#11）、useAgent deltaEpoch+activeIdRef（24#3）、Library openMaterial 串行守卫、24#5 updater/inflight/revision_conflict 三件套。
- **乐观回滚**：全仓集合写入走 replaceCollection（成功后快照回填），无「先改本地再 invoke 失败不回滚」模式；遗留仅 43#3（无 pending 指示）与 51#7（两段写半失败）。
- **派生同步/key/hook 规则**：删除后过滤同步齐备（PlanGenerator/WikiPanel/Reports/Integrations/Projects）；列表 key 均稳定 id（唯一例外 51#12）；无条件 hook、early-return 均在 hook 后。
- **内存泄漏**：全部 26 处 `onBackendEvent(...).then(stop => { if (disposed) stop() ... })` 模式核对一致，无 promise 晚于卸载泄漏；定时器 cleanup 齐备。
