## P2

### 51#1 Practice 页事件刷新与用户切换互相覆盖——选中集被静默回退、直播流串台

- 位置：`desktop/src/pages/Practice.tsx:41-46`（refresh 无序号守卫，主审亲验）、`:94-102`（chooseSet）、`:130-141`（submit 后 setDetail）、`:193-195`（selectHistory 无 busy 守卫）
- **传递链条**：① 主观题评分期间 `practice.answer_*` 事件持续触发 throttledRefresh（:71）→ ② refresh 在 t0 读 `currentId=A` 并发起 IPC → ③ await 窗口内用户点历史项 B（selectHistory→chooseSet 置 `currentId=B`、渲染 B）→ ④ refresh 的 A 响应后到，无条件 `setDetail(A)` 且 `requestId.current=A` → ⑤ 界面从 B 静默跳回 A，后续事件刷新继续拉 A、直播输出也切到 A。对照 Reports（28#4）/Community（32#11）已有 `refreshSequence` ticket 守卫，Practice/Plan/Review 三个同构页没有。
- **影响范围**：评分活跃期间切换练习集必现（事件频率高、窗口宽）；用户再点一次才能恢复。修法：照抄 28#4 的 ticket 守卫 + selectHistory 加 busy。

## 正向结论（六类核对过、无问题）

- **草稿保护覆盖完整**：Library 笔记编辑器（事件只刷 overview/详情）、Settings/SyncPanel/SecurityPanel/UsagePanel 草稿（28#10/32#1）、Community 回复分桶（09#3）、Subjective/Exam 按题 ref（28#2）、ProviderHub 表单字段不在 refresh 写入集——除 51#4（用户自发 openNote）与 51#15 外无「事件冲掉编辑中内容」路径。
- **既有守卫全部有效**：StudyRoom stageRef（32#4/35#4/35#9）、KnowledgeMap/PlanGenerator planRef（32#7/32#3）、WikiPanel currentId（32#23）、Reports/Community refreshSequence（28#4/32#11）、useAgent deltaEpoch+activeIdRef（24#3）、Library openMaterial 串行守卫、24#5 updater/inflight/revision_conflict 三件套。
- **乐观回滚**：全仓集合写入走 replaceCollection（成功后快照回填），无「先改本地再 invoke 失败不回滚」模式；遗留仅 43#3（无 pending 指示）与 51#7（两段写半失败）。
- **派生同步/key/hook 规则**：删除后过滤同步齐备（PlanGenerator/WikiPanel/Reports/Integrations/Projects）；列表 key 均稳定 id（唯一例外 51#12）；无条件 hook、early-return 均在 hook 后。
- **内存泄漏**：全部 26 处 `onBackendEvent(...).then(stop => { if (disposed) stop() ... })` 模式核对一致，无 promise 晚于卸载泄漏；定时器 cleanup 齐备。
