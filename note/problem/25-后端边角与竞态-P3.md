# 25 号 · 后端边角与竞态（P3 × 18 + 信息性 × 3）

> 第十一轮逐文件深审的 P3 级发现，均经主审回源码实证。

## P3

### 25#1 `start_focus` 活跃检查在事务外，并发双开专注会话

- 位置：`desktop/src-tauri/src/backend/reports/mod.rs:318-331`
- 证据：EXISTS 检查在 autocommit 态，INSERT 在其后 DEFERRED 事务内；并发两次 IPC 同时
  通过各插一条 running。`finish_focus` 只收尾 `ORDER BY id DESC LIMIT 1`，另一条残留为
  running 直到重启 recover。对照 projects::submit（projects/mod.rs:310-313）已在 IMMEDIATE
  事务内二次检查。

### 25#2 知识检索大小写不敏感命中、大小写敏感定位，citation 系统性缺失

- 位置：`desktop/src-tauri/src/backend/knowledge/mod.rs:354-357`（terms 全部 to_lowercase）、`:342`（`locate(source, &terms[0]).ok()` 吞错）、`:176-185`（locate 用大小写敏感 `text.find(quote)` 且要求 2..=1000 字符）
- 证据：查 "bayes" 命中含 "Bayes" 的资料时 citation 静默降级 None；中文单字检索词（常见）
  因长度门槛永远无 citation。excerpt 同样用 lowercased 词 find 失败后回退"前 180 字符"。

### 25#3 对暂停卡评分返回误导性错误文案

- 位置：`desktop/src-tauri/src/backend/review/mod.rs:443-452`
- 证据：UPDATE 带 `AND suspended = 0`，changed==0 统一报"这张卡片已被其他操作复习"；
  实际原因是卡片已暂停（get_card :252-260 不过滤 suspended，队列刷新前的窗口内可触发）。

### 25#4 `update_goal` 先提交目标/偏好，再由 regenerate 校验方案状态，失败时改动已落库

- 位置：`desktop/src-tauri/src/backend/planning/mod.rs:521-528`
- 证据：`tx.commit()` 后才调 `regenerate`；对 running/failed/超限重生成次数的方案，
  用户收到错误但 goal/deadline/daily_minutes 已被改写且未触发重生成（部分提交）。

### 25#5 强度切换作用于"最新方案"，首页/报告/学习空间口径是"最近采用方案"

- 位置：`desktop/src-tauri/src/backend/planning/mod.rs:270-272`（`latest_plan(state, None)`）vs `engagement/mod.rs:753,772`（`adopted_plan_id` 优先）
- 证据：先采用 A、再生成未采用的 B 后切换强度，改写的是 B 的排期与 tasks，而首页仍
  展示 A——操作对象与用户所见方案错位。

### 25#6 讲义单元 attempt 裸 `+1` 无上限（对照流水线 checked_add + too_many_attempts）

### 25#7 一条脏掌握证据即令学习报告（含首页）硬失败；两路径口径不一致

### 25#8 局部重生成后 `completed_stages` 可大于 `total_stages`

### 25#9 填空题作答无长度上限，超大载荷直写数据库

- 位置：`desktop/src-tauri/src/backend/practice/mod.rs:1135-1141,1150-1153`

  填空作答不限长；几十 MB 字符串经 normalize 全量入库 response_json（自伤型 DoS 面）。

### 25#10 知识库总览对"方案行损坏/缺失"无降级，单条坏数据放大为整页失败

  `learning::get(&format!("plan-{plan_id}"))?` 直接传播（plan 行缺失或 input_json 损坏
  均触发 not_found/存储错误）。

### 25#11 同哈希资料并发导入竞态可删除已入库原件

- 位置：`desktop/src-tauri/src/backend/materials/mod.rs:526-555`（查重）+ `:596-610`（错误清理 `if !reused { fs::remove_file(&destination) }`）
- 证据：两并发命令同时通过 sha256 查重（reused 均 false）后，B 的 INSERT 撞 UNIQUE
  走清理分支，删掉 A 已提交记录指向的同路径原件，留下永久 missing_original。

### 25#12 分享创建失败路径遗留 share_index 孤儿行

- 位置：`desktop/src-tauri/src/backend/sharing/mod.rs:300-317`
- 证据：`register_index` 在事务前执行；回滚清理只包住 `tx.commit()` 失败，INSERT/event
  失败提前返回时根库留下指向不存在分享的哈希行（后续命中报 share_not_found，无安全后果）。
  另 `:301` `principal_id().unwrap_or(1)` 是又一处 fail-open 回退。

### 25#13 study_checkins 冲突行被改写成 `imported-N` 假日期脏行

- 位置：`desktop/src-tauri/src/backend/backup/transfer.rs:249`（prepare_ids 排除清单不含 study_checkins）+ `:875-885`（global_conflict 想按 date 跳过但键已被改写）
- 证据：重复导入时日期冲突的打卡行主键被 free_text_id 改成 "imported-1"，冲突消失，
  插入一条日期不可解析的签到（按日期聚合的报表漏算或报错），而非设计的"保留目标侧"。

### 25#14 prepare_ids 的 max+1/TEXT id 在事务外一次性计算，并发写可致导入整单失败

- 位置：`desktop/src-tauri/src/backend/backup/transfer.rs:254-270,1122-1153`
- 证据：分配在 autocommit 态读取，之后才开事务插入；窗口内其他连接写入同号 id 时以
  `backup_constraint_failed` 整单回滚（fail-safe，无半成品），需重试。

### 25#15 房间/提醒时间戳未归一化为 UTC 即做字典序比较（潜伏契约弱点）

- 位置：`desktop/src-tauri/src/backend/community/mod.rs:823-829`（remind_at 保留输入偏移格式化）+ `:912`（claim 用字符串 `<=` 比较 now() 的 Z 串）；`engagement/mod.rs:608-611` 同类
- 证据：parse_time 接受任意 RFC3339 偏移；"+08:00" 串与 "Z" 串按字节比较会错时触发提醒。
  当前前端 Community.tsx:105 用 toISOString()（恒 Z）未显性触发；对照 review/mod.rs:125
  明确统一转 UTC。Rust 侧契约未强制，属脆弱镜像。

### 25#16 打卡日期无下界，84 天窗口外的打卡"存而不显"

- 位置：`desktop/src-tauri/src/backend/reports/mod.rs:1034-1045`（只挡 future_checkin）

  后端未封）。

### 25#17 anthropic/responses 流式工具参数累积无上限、流无总时长上限；CJK 预算低估 + 无费率绕过

- 位置：`desktop/src-tauri/src/backend/providers/anthropic.rs:243-245`（push_str 无界，对照 openai.rs:947 有 256KiB 检查）；`responses.rs:191` 同；`agent/mod.rs:634`（`(LENGTH+1)/2` 按字符计，中文低估 2-4 倍，与"宁可高估"注释相反）；`usage.rs:422-424`（`filter_map(cost).sum()`，未配费率模型对金额预算贡献恒 0）
- 证据：恶意/故障的自配供应商可借 endless delta 使内存无界增长（chunk 间超时存在、
  总时长无上限）；预算护栏在中文长输出或未配费率时可被穿透。

### 25#18 配额 check-then-insert 窗口与熔断计数丢更新；startup 目录黑名单 Verbatim 绕过；免会话分享扫描

- 位置：`store.rs:337-390`（配额 COUNT 在只读连接、插入在后，threads=帖+回 跨命名空间配额可超在途并发数）；`routing.rs:670-713`（circuit_row 读改写竞态，并发失败计数互相覆盖，熔断晚开；open→half_open 已是原子条件 UPDATE 无此问题）；`startup.rs:100-133`（UNC/VerbatimUNC 被拒，但 `\\?\C:\Windows` 的 VerbatimDisk 前缀与 `C:\Windows` 的 Path::starts_with 组件比较恒 false，SystemRoot/ProgramFiles 黑名单被绕过）；`sharing/mod.rs:396-427`（索引 miss 后遍历 users/ 最多 10,000 个目录、每个 `Store::at_user` 触发全套指纹比对与迁移——未认证 IPC 的 IO/写放大面；token 本身为哈希查询不可枚举）
- 证据：本地桌面并发低/需本地访问，均为纵深弱点而非直接漏洞。

## 信息性

1. **通知按日幂等**：`engagement/mod.rs:537` `INSERT OR IGNORE`，id 如
   `review-due-{today}`——同日到期数增长时通知正文数字冻结在首次生成（次日才刷新）。
2. **搜索大小写折叠口径不一**：全局搜索 `COLLATE NOCASE`（engagement/mod.rs:364,408，
   仅 ASCII 折叠）vs 社区搜索 `uni_lower`（community/mod.rs:349，Unicode 折叠）；非 ASCII
   字母在全局搜索中大小写不敏感失效。两处 LIKE 转义（`\` 与 `~`）各自正确无注入。
3. **上游错误文本进入 BackendError.message 并持久化**（anthropic.rs:262-275、gemini.rs、
   responses.rs）：内容注入面（进入 provider_requests.error_message、事件载荷与 UI）；
   API key 本身全路径 grep 证实不出现在错误/日志/事件中。
