## P3

### 25#1 `start_focus` 活跃检查在事务外，并发双开专注会话

- 位置：`desktop/src-tauri/src/backend/reports/mod.rs:318-331`
- 证据：EXISTS 检查在 autocommit 态，INSERT 在其后 DEFERRED 事务内；并发两次 IPC 同时
  通过各插一条 running。`finish_focus` 只收尾 `ORDER BY id DESC LIMIT 1`，另一条残留为
  running 直到重启 recover。对照 projects::submit（projects/mod.rs:310-313）已在 IMMEDIATE
  事务内二次检查。

### 25#2 知识检索大小写不敏感命中、大小写敏感定位，citation 系统性缺失

- 位置：`desktop/src-tauri/src/backend/knowledge/mod.rs:354-357`（terms 全部 to_lowercase）、`:342`（`locate(source, &terms[0]).ok()` 吞错）、`:176-185`（locate 用大小写敏感 `text.find(quote)` 且要求 2..=1000 字符）

  因长度门槛永远无 citation。excerpt 同样用 lowercased 词 find 失败后回退"前 180 字符"。

### 25#15 房间/提醒时间戳未归一化为 UTC 即做字典序比较（潜伏契约弱点）

### 25#17 anthropic/responses 流式工具参数累积无上限、流无总时长上限；CJK 预算低估 + 无费率绕过

## 信息性

1. **通知按日幂等**：`engagement/mod.rs:537` `INSERT OR IGNORE`，id 如
   `review-due-{today}`——同日到期数增长时通知正文数字冻结在首次生成（次日才刷新）。
2. **搜索大小写折叠口径不一**：全局搜索 `COLLATE NOCASE`（engagement/mod.rs:364,408，
   仅 ASCII 折叠）vs 社区搜索 `uni_lower`（community/mod.rs:349，Unicode 折叠）；非 ASCII
   字母在全局搜索中大小写不敏感失效。两处 LIKE 转义（`\` 与 `~`）各自正确无注入。
3. **上游错误文本进入 BackendError.message 并持久化**（anthropic.rs:262-275、gemini.rs、
   responses.rs）：内容注入面（进入 provider_requests.error_message、事件载荷与 UI）；
   API key 本身全路径 grep 证实不出现在错误/日志/事件中。
