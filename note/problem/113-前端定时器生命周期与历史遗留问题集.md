## P3

### 113#1 Projects.tsx 的 throttledFetch.cancel() 排在 return 之后——不可达死代码，76#7 注释声称的「卸载取消」自引入起从未生效（a4cda0c4，非 1.1.6）

- 位置：`desktop/src/pages/Projects.tsx:97-100`（`return () => { active = false; stop?.() }` 之后才是 `// 76#7：卸载取消武装中的定时器` 与 `throttledFetch.cancel()`——return 之后的语句永不出执行）；throttledFetch 为 deltaThrottle（client.ts:484-496 自带 cancel）。
- 传递链条：①项目反馈运行中每条 delta 武装 150ms 定时器 → ②用户离开 Projects 页（lazy 路由卸载）→ ③cleanup 只移除监听，cancel 调用不可达 → ④卸载后 150ms 内武装的定时器照常触发 getProviderChat + setLiveOutput（React 18 no-op）——注释宣称的防线不存在，多余 IPC + 与 111#3 同型的口径失守；git blame 实证 a4cda0c4（76 号问题集）引入，80/104/108 各轮均未发现。
- 影响范围：Projects 页卸载瞬间的迟到请求；无功能损坏。
- 修复方向：cancel 移入 return 的 cleanup 函数体内（与 111#3 一并收口）。

### 113#2 Projects 页 skippedVersions 提示的归属与可见性——全局计数挂在单项目区块、无项目时不显示

- 位置：`desktop/src/pages/Projects.tsx:193`（`{skippedVersions > 0 && …}` 位于当前选中项目的 project-feedback section 内）；`Apps.tsx` 渲染层（无项目时走 EmptyState 分支，全局跳过数不渲染）。
- 传递链条：①workspace 含跨项目的损坏版本行 → ②提示挂在当前项目的反馈区、文案「未计入上方列表」指向当前项目历史列表 → ③若损坏行属其他项目（或尚无选中项目），归属误导/不可见 → ④101#8 的「坏行可见性」目标打折（无数据丢失，仅提示精度）。

- 修复方向：提示挪到工作区级（列表头部）或按 project_id 分桶计数。

- 位置：`desktop/src/pages/Library.tsx:114`（VISIBLE_NOTES_LIMIT=200）、`:390`（slice 渲染 + 「已显示前 200 条（共 N 条匹配）」提示）；全前端无分页交互（仅 Integrations 有事件游标分页）。
