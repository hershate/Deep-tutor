# 183：架构文档错误描述通用导师调用链

## 证据

- `docs/architecture/03-workflow.md:204` 写明“全局导师使用 `route_provider_chat` 直接发送消息”。
- `desktop/src/components/TutorPanel.tsx:14` 实际调用 `useAgent({ planId, sessionTitle: '知舟导师' })`。
- `desktop/src/backend/useAgent.ts:197-231` 无会话时先创建 Agent 会话，再调用 `send_agent_message`；模型路由由 Agent 后端执行，并非前端直接调用 `route_provider_chat`。

## 完整传递链条

维护者依据架构文档追踪全局导师 → 文档把调用链指向 `route_provider_chat` → 实际链路却是 TutorPanel → useAgent → create/send Agent IPC → Agent run 与工具循环 → Rust routing → 排查会话、持久化、取消、工具权限或预算问题时定位到错误层级，可能遗漏 Agent 会话状态与事件。

## 影响范围

- 架构维护、通用问答故障定位、工具权限审查和后续测试设计。
- 不改变当前运行时行为；全局导师仍可不绑定方案使用。

## 修复验收

- 文档分别说明全局导师与模型接入中心手动请求的调用链，不再混用二者。
- 明确通用会话 `planId=null`、会话与 run 持久化及事件续接路径。
