## P1

### 31#1 会话预算护栏失效：budget_spend 的 Session GLOB 用 session_id 匹配按 run_id 命名的请求

- 位置：`providers/usage.rs:437`（`BudgetScope::Session { prefix } => (" AND r.request_id GLOB ?1", ...)`）、
  `usage.rs:479-484`（`prefix: format!("agent-{session_id}-*")`）；对照
  `agent/mod.rs:772`（`format!("agent-{}-{attempt}-{step}", run.id)`）与 `:837`
  （`ensure_budget(.., Some(session_id))` 唯一调用方）
- 证据：请求 id 按 **run.id** 命名；`agent_sessions` 与 `agent_runs` 是两张独立
  AUTOINCREMENT 表（agent/mod.rs:189/201），session_id 几乎不等于 run_id。
- 触发与影响：GLOB `agent-{session}-*` 通常匹配 0 行 → session_usd 预算永远读到 0
  花费、**从不拦截**；数值撞号时把另一会话的 run 花费计入本会话（误拦/漏计）。
  同文件 agent 自身的 `session_output_tokens`（agent/mod.rs:643）用
  `JOIN agent_runs ... GLOB 'agent-' || agent_runs.id || '-*'` 的正确写法。
  `usage/tests.rs:284` 用例因 `session_usd=0.0` 平凡通过，未覆盖该语义。
- 修复方向：budget_spend 的 Session 分支改为 JOIN agent_runs 的正确口径；补
  「session_usd 有限 + 会话内多次请求到额即拒」的测试。

### 31#2 备份 events 的 sessionId 通用重映射误伤专注会话事件：用过专注但没用过 Wiki 的备份整单不可导入

- 位置：`backup/transfer.rs:604-610`（sessionId → agent_sessions/knowledge_sessions 二分）；
  `reports/mod.rs:344-469`（`focus.*` 事件 payload 的 `sessionId` = focus_sessions.id）
- 证据：
  ```rust
  "sessionId" if !table.starts_with("event:security.") => Some(
      if table.starts_with("agent_") || table.starts_with("event:agent.") {
          "agent_sessions"
      } else {
          "knowledge_sessions"     // focus.* 事件落入此支
      },
  ),
  ```
- 触发与影响：**已实证**——源库仅一条 focus 事件且无 knowledge_sessions 行时，导入报
  `备份关联目标 knowledge_sessions 缺少记录 "1"`，整单失败；备份恰有同号知识会话行时
  事件 sessionId 被静默改写为错误引用。同类变体：历史事件的 taskId/noteId/projectId
  指向已删除行时，`map_plain` 同样报 invalid_backup_reference 使整单失败。
- 修复方向：focus.* 事件按事件前缀豁免；历史事件中对已消亡引用的映射失败降级为跳过
  该键而非整单失败。

### 31#5 learning step7 已落盘但 result_json 未写的断点窗口：resume 永久死循环

### 31#6 projects::recover 在重放评价失败时中止全部恢复并上抛，可致后端每次启动都失败

### 31#7 登出与 PAT 登录不停止旧用户的后台任务与同步调度器——单活动会话模型的后台穿透

- 位置：`security/mod.rs:969-1005`（logout 只撤会话与凭据，无 stop_all/停调度器）、
  `:1259-1261`（authenticate_token 直接 issue 返回）；对照 `guard.rs:49-130`（login 走
  switch：stop_all → 换库 → 重启调度器）；`sync/scheduler.rs:53-67`（调度线程持签发时
  principal 快照每 60s run_due）
- 触发与影响：A 登出或 PAT 切到 B 后，A 的调度线程仍每 60 秒以 A 身份打开 A 的工作区
  执行 run_due——A 开启 auto_sync 且到期时在 B 使用期间自动上传 A 的数据，持续到下一
  次 login 或退出。会话已撤销但派生后台活动无限存续，确定性行为。
- 修复方向：logout 与 authenticate_token 成功路径复用 switch 的 stop_all（或调度 tick
  内校验会话归属）。
