# 176：会话切换事件在去抖阶段丢失

## 证据

- `desktop/src/backend/useBackendState.ts:247-256` 仅在 `requestSync` 收到 `security.session_started` 时递增 `generation`、清空旧快照并重新 bootstrap。
- `desktop/src/backend/useBackendState.ts:276-285` 的 `requestSyncCoalesced(event)` 在定时器中调用 `requestSync()`，没有传递 `event`。
- `desktop/src-tauri/src/backend/security/mod.rs:742-749` 登录签发会话后实际发送 `security.session_started`。

## 完整传递链条

本地用户切换或 PAT 登录 → 后端提交新会话并发送 `security.session_started` → 前端事件监听调用 `requestSyncCoalesced(event)` → 120ms 去抖回调丢弃事件参数 → `requestSync()` 走普通快照同步分支 → 会话代际不递增、旧快照不清空、旧启动流程不作废 → 切换前已在途的旧工作区 IPC 响应可在切换后通过 `applySnapshot` → 旧用户集合可覆盖新用户集合。

## 影响范围

- 本地用户切换、登录门内重新选择用户、PAT 登录。
- 全局任务、笔记、资料、项目和偏好快照；依赖 `generation` 作废的旧请求与旧启动流程。
- 慢磁盘或事件密集时存在跨工作区旧数据回显风险，既是正确性问题，也是工作区隔离的前端呈现边界问题。

## 修复验收

- 去抖后的回调必须把原事件传给 `requestSync`，会话切换走代际递增与 bootstrap 分支。
- 旧代际响应不得覆盖新工作区；普通事件仍保持 120ms 合并。
- 前端构建和会话隔离相关 Rust 测试通过；增加静态契约检查防止该调用再次退化为无参调用。
