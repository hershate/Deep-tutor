# 47 · 时间时区与数值边界（第二十一轮）

> 审计范围：backend 全部 109 个 .rs 文件的时间获取/比较/运算、周界与日界、
> 除零与浮点、整数收窄、超时与调度。子审计全量核对 + 主审对 P2 与主要 P3
> 逐条源码复核（F-3/F-2/F-5/F-7 与 F-1 条件性均亲验）。严重度按本仓口径
> 校准：仅防御缺失/平台条件性/脏数据才可达的降为 P3。

## P2

### 47#1 模拟考试计时从「生成完成」起算——生成耗时与学生等待都吃掉考试时长

- 位置：`desktop/src-tauri/src/backend/practice/mod.rs:888-898`（`finish` 路径，与 `status: 'generating' → 'ready'` 同一条 UPDATE）；全后端 `exam_started_at/exam_deadline` 仅此一处写入；消费方 `src-tauri/src/backend/practice/exams.rs:64-71`（`ensure_accepting` 按 `exam_deadline` 拒答）。
- 证据（主审亲验）：
  ```rust
  let started_at = now()?;
  let deadline = (OffsetDateTime::now_utc() + Duration::from_secs(minutes as u64 * 60)).format(&Rfc3339)?;
  ```
- **传递链条**：① 用户创建 45 分钟模拟考 → ② 后台异步生成（真实模型调用，数十秒到数分钟）→ ③ 生成完成瞬间写入 `exam_started_at=now、deadline=now+45min`（与状态转 ready 同一事务）→ ④ 学生此刻往往还在等结果页、尚未打开试卷 → ⑤ 打开作答时剩余时长已被生成+等待吃掉 N 分钟；生成失败重试一次则吃掉双倍 → ⑥ 超时后 `ensure_accepting` 以 `exam_deadline_exceeded` 拒答。另：从未开考的过期试卷永久停留 ready（首页 `exam_deadline > now` 过滤后消失，但库内无终态标记，`ExamWorkspace` 直接进入仍会撞拒答）。
- **影响范围**：所有模拟考用户；考试时长越紧失真越明显。修复方向：deadline 改为「学生首次拉题/显式开考动作」时起算，或至少在试卷页展示「剩余时长已从生成完成起计」。

## P3

### 47#2（平台条件性）`now_local()` 的 UTC 静默回退——非 Windows 构建下全部「本地日界」错位

- 位置：`Cargo.toml:15`（`local-offset` feature）；12 处调用点统一 `now_local().unwrap_or_else(|_| now_utc())`：`learning/validate.rs:8-10`（排期起始日）、`planning/mod.rs:282/359`（周视图）、`engagement/mod.rs:552/713`（通知今天/明天与免打扰）、`reports/mod.rs:477/812/874/956/1057`（报告窗口/84 天日历/打卡校验）、`review/mod.rs:494`（到期日）、`providers/usage.rs:327/483`（按日聚合与每日预算重置点）。
- **机理**：`time` crate 在 Unix 上因健全性限制，多线程进程中 `now_local()` 恒 Err → 回退 UTC → 东八区本地 00:00–08:00 之间「今天」差一天（排期首日/复习到期/每日预算重置/免打扰时段全部平移）。
- **影响范围**：**当前发布物不触发**（CI 仅 windows-latest、bundle 仅 nsis，Windows 上 now_local 可用——主审已核 local-offset feature 在列）；一旦增加 macOS/Linux 目标即升级为 P1 级错位。按本仓「唯一交付物为 Windows 安装包」口径记 P3（跨平台前置条件）。修复方向：启动时探测一次本地偏移并缓存，或由前端传偏移。

### 47#3 复习间隔无上限——极端路径 `Duration::seconds_f64`/日期加法 panic

- 位置：`desktop/src-tauri/src/backend/review/mod.rs:424-442`（主审亲验：`next_interval` 按 `prev × ease(≤3.0)[×1.3]` 复利、无 36500 天封顶；`Duration::seconds_f64(next_interval * 86_400.0)` 与 `now + Duration` 越过 9999 年均 panic）；同族 `review/mod.rs:506` `tomorrow.next_day().unwrap()`。
- **可达性**：正常流每次评分需等上一次间隔到期，累计等待达数百万天——人手不可达；触发需「系统时钟调到 9999 年末再评一次卡」或库内 ease 被外部改成 NaN/巨值。panic 发生在同步命令体内（主线程），表现大概率为应用崩溃。
- **影响范围**：防御缺失 + panic 面，现实概率极低（子审计评 P2，主审按可达性校准为 P3）。修复：`next_interval.min(36500.0)` + ease `is_finite` 校验，一行级。

### 47#4 免打扰起止相等被解释为「全天免打扰」——界面允许输入且无提示

- 位置：`desktop/src-tauri/src/backend/engagement/mod.rs:522-529`（`start == end → 恒 true`，主审亲验）；`:206-229` `validate_profile` 只校验时间格式不禁止相等（主审亲验）。
- **传递链条**：① 用户把免打扰起止都填「08:00」→ ② 保存通过 → ③ `quiet()` 恒真 → `NotificationOverview.suppressed` 恒真 → ④ 通知中心被整体压制且无任何文案解释。若产品意图是「相等=全天安静」需写入界面文案；业界更常见语义是「相等=不静音」。
- **影响范围**：所有误填相等的用户，通知静默丢失属可用性损害。修复：校验拒绝相等或文案明示语义，一行级。

### 47#5 自动同步为「上次完成 + 24h」相对周期，失败同样等满 24h

- 位置：`desktop/src-tauri/src/backend/sync/scheduler.rs:27-43`（锚点 `MAX(finished_at)`，失败/取消也写 finished_at——sync/mod.rs:650/888）；调度线程每 60s 轮询。
- **机理**：每周期净漂移 = 检测粒度(≤60s)+任务时长，同步时刻单调后移（非固定时刻）；断网导致失败后不重试，一天最多尝试一次。46 号已录「滚动 24h 与决策文档一致」为正向；本条补充其失败重试缺失与漂移面向，属设计取舍记录。修复方向（可选）：失败后短退避重试或提供「固定时刻+补跑」选项。

### 47#6 通知按 `created_at` 字符串排序的秒级并列不稳定

- 位置：`desktop/src-tauri/src/backend/engagement/mod.rs:694`（`ORDER BY created_at DESC LIMIT 50`，无 id 兜底；同事务多条同秒时间戳）。
- **影响范围**：并列时 SQLite 顺序未定义，50 条截断边界在同秒批内可能闪烁跳变；仅展示顺序，无数据损害。加 `, id DESC` 兜底即可（对照 review `ORDER BY due_at, id` 的既有做法）。

### 47#7 报表正确率无界输入靠 `as u8` 饱和——脏数据被静默钳到 100

- 位置：`desktop/src-tauri/src/backend/reports/mod.rs:759`（`AVG(a.score / a.max_score)` 无 evidence 路径的 finite/界内过滤——对照 `:639-644` 有防护）、`:1203/1211`（`(value * 100.0).round() as u8` 饱和转换）。
- **影响范围**：仅库内存量脏行（score>max_score）触发，CSV 报表把超界百分比静默输出为 100。与 evidence 路径口径不一致，属防御统一项。

### 47#8 项目 `due` 为自由文本，首页待办按字符串排序

- 位置：`desktop/src-tauri/src/backend/store.rs:995`（仅长度校验）、`engagement/mod.rs:891`（`sort_by_key(item.date)`）。
- **影响范围**：混合格式（"2026-1-5"/"2026-01-05"/"明天"）时「按截止日升序」失真；中文兜底串排 ASCII 后尚算良性。可校验 ISO 日期格式或排序时解析失败置后。

## 信息性

### 47#9 serde 数值收窄的报错形态为英文原始消息

- `regeneration_limit: u8`（usage.rs:20）、`count/time_limit_minutes: u32`、`CheckinInput.minutes: u64` 等：超界输入在 serde 反序列化层被拦，用户看到 `invalid type: integer 300, expected u8` 类英文而非业务文案；业务校验（1..=3 等）在反序列化成功后才生效且完备。前端 select 限定了取值，正常 UI 不可达，仅手改状态或异常路径可见。

### 47#10 仅极端时钟/毒数据才触发的边界（同 47#3 族）

- `community/mod.rs:765` `Duration::minutes(duration.max(0))`：库内 i64 巨值时 panic（写入路径已校验 10..=240）；31#33 迁移回填后仍解析失败的 `start_at/remind_at` 毒行保留，claim 的字典序比较行为未定义但不崩溃。

## 正向结论（本轴核对过、无问题）

- **UTC 存储一致性（核心担忧排除）**：18 个域落库时间戳全部为 `now_utc().format(Rfc3339)` 的 Z 形态，无「无时区标记本地串」；字符串比较前均统一 Z 形态（community normalize_time+31#33 回填、engagement 明日边界、review day_start、reports 窗口）；前端 `new Date().toLocaleString()` 渲染不会错小时。remind_at 的 `max(start-15min, now)` 语义正确。
- **打卡日历 84 天**：`[本地午夜, 次日本地午夜)` 窗口（DST 日因日历感知加法得 23/25 小时）、未来日期拒绝、84 天下界拒绝、分钟 1..=1440 校验、checkin_rate 分母 max(1)。
- **周界**：周一为始（number_from_monday）、`[week_start, +7)` 零填充比较成立、学期跨年归年正确、`next_day()` 越界转业务错误。
- **数值**：除零防护齐备（share/load_percent/checkin_rate/AVG→Option）；无浮点等值判定；progress 全整数路径 ≤100 且校验 0..=100 finite；60 余处收窄 cast 均有更严业务校验在前；next_free_id 基数毫秒时间戳远离 2^53。
- **超时**：busy_timeout 10s、供应商流式 request/chunk 双超时、非流式 5s/45s、web 抓取 5s/12s、重试退避封顶且仅对无部分输出错误、熔断 cooldown 绝对时间比较；ICS/S3 签名/版本文件名/90 天裁剪/分享过期/Anki checked_mul 逐一正确。
