# 169：路由变化后模型请求保留失效值

## 现象与触发条件

在模型中心先选择请求模型，再修改 Agent 任务路由的供应商或模型列表，回到真实模型请求面板。旧 `requestModel` 可能已不属于新路由。

## 传递链条

1. `desktop/src/pages/ProviderHub.tsx:69` 保存用户选择的 `requestModel`。
2. `:187` 只在 `activeId` 或 `routing.mode` 改变时清空选择。
3. `:191-195` 的可选模型集合同时依赖 `routing.routes.agent`、启用档案与聚合成员；仅修改这些配置不会触发上述清空。
4. `:426-427` 的受控 select 保留不在选项中的值，提交时仍以 `requestModel || null` 传给 `routeProviderChat`。
5. `desktop/src-tauri/src/backend/providers/routing.rs:555-559` 发现该模型不在新上游列表时返回 `route_model_unavailable`。

## 影响范围

影响模型中心的真实请求面板及路由切换后的验证。用户看到的选择框与即将发送的模型值可能不同；影响请求验证，不改变已保存路由，也不会自动调用错误的上游。

## 修复验收

可选模型集合变化时检查当前值；值不再有效则回到“使用路由与默认模型”，有效选择保留。请求载荷与界面选项一致。
