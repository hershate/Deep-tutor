## P2

### 32#1 UsagePanel 预算输入被后台事件刷新无差别覆盖（编辑期丢输入）

- 位置：`desktop/src/components/UsagePanel.tsx:25-27`（无条件回写）、`:36`（极宽事件过滤）
- 证据：
  ```ts
  setSessionUsd(usage.settings.sessionUsd)
  setDailyUsd(usage.settings.dailyUsd)
  setRegenerationLimit(usage.settings.regenerationLimit)
  // ...
  if (event.kind.startsWith('usage.') || ['completed', 'cancelled', 'failed'].some(suffix => event.kind.endsWith(`.${suffix}`))) void refresh()
  ```
- 触发与影响：过滤命中 `provider.chat_completed`——应用内**任何**模型请求完成（导师面板、
  方案生成每步、Wiki 问答）都触发 refresh，而 refresh 无条件把三个预算输入回写为已保存值。
  用户正在「每日预算/会话预算/重生成上限」输入框打字时，任一后台请求完成 → 输入瞬间被弹回
  旧值。仓库已有两处同型修复未推广：`SyncPanel.tsx`（configOpenRef 守卫，28#10）与
  `SecurityPanel.tsx`（配额草稿仅在实际值变化时覆盖）。
- 修复方向：对齐 SecurityPanel 的草稿守卫或 `document.activeElement` 判断。

### 32#2 Practice/Review 事件监听器晚解析泄漏：StrictMode 下每次进入必泄漏一份

- 位置：`desktop/src/pages/Practice.tsx:73-75`、`desktop/src/pages/Review.tsx:44-48`
- 证据（同型）：
  ```ts
  }).then(stop => { unlisten = stop }).catch(reportBackendError)
  return () => { unlisten?.(); void listening }   // void 丢弃 promise，不注销
  ```
- 触发与影响：卸载/依赖变化发生在 `listen()` promise 解析前时 `unlisten` 为 undefined，
  解析出的 stop 赋给已死闭包永不调用。`main.tsx:34` 启用 `React.StrictMode`——开发模式
  下每次进入练习/复习页双挂载必泄漏 1 份；泄漏回调在每个 `practice.*`（练习页 4 个 IPC）
  /`review.*`+`plan.*`（复习页 4 个 IPC）事件上继续刷新已卸载组件，随页面进出累积。
  仓库其余 14 处监听均采用 `if (disposed) remove()` 正确模式，仅此两处遗漏。
- 修复方向：套用同仓库 `if (mounted) unlisten = stop; else stop()` 模式。

### 32#3 PlanGenerator 事件轮询响应覆盖用户手动切换的历史方案

- 位置：`desktop/src/pages/PlanGenerator.tsx:109-116`
- 证据：
  ```ts
  if (planRef.current?.id === id) {
    setLastEventId(event.id)
    void backend.getLearningPlan(id).then(next => {
      if (disposed) return
      setPlan(next)
      if (next.result) setStep(3)
    })
  ```
- 触发与影响：事件到达时 id 匹配后发起异步拉取，`.then` 内未复查 `planRef.current?.id ===
  next.id`。方案 A 生成中（事件流持续）→ 用户在历史下拉选择方案 B → A 的轮询响应后到 →
  `setPlan(A)` 无声覆盖 B，且 `setStep(3)` 可能把用户强拉回第 3 步。
- 修复方向：then 内补 `if (planRef.current?.id !== next.id) return`。

### 32#4 StudyRoom 切换阶段/课程时旧讲义响应覆盖新阶段讲义

- 位置：`desktop/src/pages/StudyRoom.tsx:68-76`（refreshLecture）；`:118` 事件密集触发
- 证据：
  ```ts
  const next = await backend.getLecture(plan.id, stageId, version)
  readingVersionRef.current = version ?? next.version
  setLecture(next)
  ```
- 触发与影响：无请求序号或「当前 stage 是否仍匹配」检查。讲义生成期间每条 `lecture.*`
  事件都调用 refreshLecture；用户恰在事件密集期点击目录切到阶段 B：阶段 A 的在途响应后到
  → `setLecture(A 的讲义)` 而此时 stageId 已是 B——正文渲染 A 的单元内容与版本号，
  后续 A 的事件不再触发刷新，**无自愈**。
- 修复方向：响应返回后比对 `stageRef.current` 再 set，或递增序号丢弃过期响应。

## 传递链条与影响范围（补链）

### 32#1
- 传递链条：触发（用户正在「每日预算/会话预算/重生成上限」输入框打字 + 任意后台模型请求
