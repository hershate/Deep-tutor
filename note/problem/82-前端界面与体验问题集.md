# 82 号：前端界面与体验问题集（第三十轮审计）

审计基线：`021f2929`（1.1.3）。范围：`desktop/src` 全部 64 个 ts/tsx（App.tsx、backend/ 26、pages/ 14、components/ 15），P2 条目经 react 18.3.1 运行时实证。既往批次（72/74/76/80 号等）已修复项未重复报告。共 12 条：P2×1、P3×7、信息×4。

## P2

### 82#1 FocusLayer 计时 effect 内调用 useRef——启动专注即整树崩溃

- 位置：`desktop/src/App.tsx:470`（76#4 于 commit `a4cda0c4` 引入）。
- 传递链条：①`useEffect(() => { if (session?.status !== 'running') return; const finishRef = useRef(onFinish); ... }, [session, busy])`——`useRef` 位于 effect 回调内部，属渲染上下文之外的条件 Hook 调用；②「今日」页点「进入专注」→ 专注层点「开始专注」（或后端已有 running 会话时打开专注层）→ effect 以 running 状态执行 → react-dom 的 ContextOnlyDispatcher（passive effect 执行期 dispatcher）对 `useRef` 直接抛 `throwInvalidHookError`（本机 react-dom 18.3.1 development.js:16776 实证，生产版同抛）；③异常冒泡至 main.tsx 顶层 ErrorBoundary → 整个界面替换为「界面遇到问题」，专注功能完全不可用。
- 影响范围：专注模式全部入口（Dashboard 行内计时按钮、今日页、学习空间「专注模式」）。tsc/build 检不出（运行时 Hook 违规非类型错误），CI 与 216 项测试均未覆盖该路径。
- 修复方向：`const finishRef = useRef(onFinish)` 提升到 `FocusLayer` 组件顶层，effect 内只做 `finishRef.current = onFinish` 赋值；deps 维持 `[session, busy]`。修复时建议在 CI 或本地补 `eslint-plugin-react-hooks` 的 `rules-of-hooks` 检查以防同类回归。

## P3

### 82#2 资料详情弹窗读取期间无法关闭，且迟到内容强制回显

- 位置：`desktop/src/pages/Library.tsx:162-170`（`openMaterial`）与 `:357`（Modal open 条件 `Boolean(activeMaterial) || openingMaterial !== null`，onClose 仅 `setActiveMaterial(null)`）。
- 传递链条：①资料库点任意资料行 → `openingMaterial = id`，弹窗以「正在读取原生资料记录…」打开；②读取在途时点 X / Esc / 点遮罩 → onClose 只清本就为 null 的 `activeMaterial`，`openingMaterial` 未清 → 弹窗保持打开且关闭动作完全无效；③读取完成后 `setActiveMaterial(detail)` 把用户已明确关闭的内容再次展示。
- 影响范围：慢盘/大记录时用户被锁在关不掉的弹窗里，关闭意图被静默忽略。
- 修复方向：onClose 同时清 `openingMaterial`；为 `openMaterial` 加序号守卫（同页 `openNote` 的 51#4 模式），用户已关闭后丢弃在途响应。

### 82#3 学习空间「批注」弹窗无未保存守卫，静默丢稿

- 位置：`desktop/src/pages/StudyRoom.tsx:297`（`<Modal open={noteOpen} onClose={() => setNoteOpen(false)}>`）。
- 传递链条：①阅读页点「记录学习笔记」或点原文引用 → 批注弹窗打开；②输入长批注后点 X / Esc / 点遮罩 → 弹窗直接关闭，无草稿、无确认，正文全丢；③重新打开是空的（除非再点一次引用重新注入）。
- 影响范围：与 Library 笔记编辑器的「草稿自动暂存 + 离开确认」双保护不一致，一次误点即丢长批注——正是 28#2 在练习侧修过的同型问题。
- 修复方向：dirty 检测 + 关闭确认（复用 ConfirmDialog），或复用 `backend.saveDraft` 通道按 plan-stage 键暂存。

### 82#4 草稿版本冲突后，笔记编辑器关闭按钮变成无声死键

- 位置：`desktop/src/pages/Library.tsx:245`（`const closeNote = () => { if (draftBlocked.current) return; ... }`，75#4 引入）。
- 传递链条：①双窗口并发编辑同一笔记 → 一方保存收到 `revision_conflict` → `draftBlocked = true` 且自动保存停摆；②点 X / Esc / 遮罩 → `closeNote` 开头即 `return`，关闭动作被吞且无任何提示；③用户只能去点「保存笔记/删除」——而保存仍会基于冲突态提交。
- 影响范围：冲突后编辑器处于「关不掉、无反馈」状态，用户不知道为什么点不动。
- 修复方向：draftBlocked 时给出明确文案（如「检测到并发修改，自动保存已冻结」）并提供「丢弃本地修改并关闭」出口。

### 82#5 笔记标签只能从既有标签中选择，标签词表实际被冻结

- 位置：`desktop/src/pages/Library.tsx:81`（`noteTags = 库内已有标签 ∪ 当前 noteTag`）与 `:352`（标签为 `<select>`，无自由输入）。
- 传递链条：①新建/编辑笔记 → 「标签」下拉只含库内已存在标签 + 默认「概率论」；②用户无法输入「线性代数」等新标签——UI 内能引入的新标签只有快速记录固定的「复盘」；③标签体系无法经界面自然生长，与「可按标签筛选」的产品语义不符。
- 影响范围：标签功能名存实亡，长期只能使用初始标签。
- 修复方向：改为可输入的 combobox（`<input list>` + datalist 或输入+下拉），新标签入库后自然进入筛选行。

### 82#6 数字输入的 NaN 绕过禁用校验直提后端（两处漏配）

- 位置：`desktop/src/pages/Plan.tsx:214`（每周可投入 `Math.round(Number(e.target.value))`，禁用条件 `weeklyHours < 1 || weeklyHours > 80` 对 NaN 恒 false）与 `desktop/src/components/ReportViews.tsx:37`（打卡分钟同型）。
- 传递链条：①`input type=number` 输入「-」或「e」→ `Number('')` 类路径产生 NaN 入 state；②所有比较（`< 1`、`> 80`）对 NaN 均 false → 按钮可点；③`JSON.stringify(NaN)` 序列化为 null 发往后端 → 后端拒绝 → 用户看到「按钮放行却保存失败」。
- 影响范围：低频，但与既有口径不一致——Community 房间时长、考试时长/通过线等处均已 `|| 0` / `|| 1` 钳制，仅这两处漏配。
- 修复方向：onChange 改 `Math.round(Number(x) || 默认值)`，禁用条件追加 `!Number.isFinite(...)`。

### 82#7 Agent 流式输出每 150ms 强制滚到底，上翻阅读被打断

- 位置：`desktop/src/pages/AgentCenter.tsx:78` 与 `desktop/src/components/TutorPanel.tsx:20`（`useEffect(..., [messages.length, stream.text])` → `endRef.scrollIntoView`）。
- 传递链条：①Agent 回答生成期间 delta 节流约每 150ms 更新 `stream.text`；②每次更新触发 `scrollIntoView`；③用户向上滚动回看历史 → 视口被强制拉回底部，生成期间无法边看边等。
- 影响范围：长回答期间的阅读体验——「长任务劫持滚动」类问题。
- 修复方向：滚动前检测是否已贴底（`scrollTop + clientHeight >= scrollHeight - 40`），仅贴底时跟随。

### 82#8 两个关键 segmented 控件缺 aria-pressed（74 批次漏网）

- 位置：`desktop/src/pages/ProviderHub.tsx:374`（「接入模式」直连/本地路由/聚合）与 `desktop/src/pages/Plan.tsx:192`（「学习强度」稳妥/标准/冲刺）——仅 `active` class；同文件其他 segmented（视图 tab、筛选行）均已带。
- 传递链条：读屏用户聚焦档位按钮 → 只播报文本，无选中状态语义。
- 影响范围：可访问性状态不同步，两处核心选择控件。
- 修复方向：补 `aria-pressed={routing.mode === mode}` / `aria-pressed={overview?.intensity === item}`。

### 82#9 知识地图图例三档与节点着色语义不齐

- 位置：`desktop/src/pages/KnowledgeMap.tsx:137`（图例：已有测评/阅读完成/待评估）与 `:143`（有测评证据但掌握度 <80% 的节点用 `node-learning` 色）。
- 传递链条：①某节点做过测评但掌握度 <80% → ②`:143` 判定走 `node-learning` 类——与图例「阅读完成」档同色 → ③用户对照 `:137` 的三档图例无法归类该节点状态，只能依赖节点下方的百分比小字自行推断。
- 影响范围：知识地图页所有「已测评未达标」节点可能被误读为「只是读过」——恰恰是最需要复习提示的一类节点。

### 82#10 供应商「全部检测」串行且不可取消

- 位置：`desktop/src/pages/ProviderHub.tsx:266-270`（`for...await testProfile`）。
- 传递链条：①用户点「全部检测」→ ②对 profiles 数组串行逐个真实请求 /models（每个一次完整网络往返）→ ③期间 `testingId` 全局非空使**所有**卡片的单个检测按钮同时禁用，且无中止按钮——档案多+网络慢时用户既不能中断也不能改测单个，只能等全部完成。
- 影响范围：供应商档案较多的用户在检测期间操作被整体锁定；有逐卡片「检测中」反馈故仅信息级；无数据风险。
- 修复方向：提供中断标志位，或改并行 + 可取消。

### 82#11 Agent 任务中心每次刷新按「方案 × 阶段」全量扇出 IPC

- 位置：`desktop/src/components/AgentTaskCenter.tsx:29`（对每个已采用方案的每个 stage 各调一次 `backend.getLecture`）。
- 传递链条：①plan/agent/lecture 任一终态事件到达 → ②`useBackendState` 全局快照刷新（120ms 去抖）触发本组件 effect → ③对 N 个已采用方案 × M 个 stage 逐个 `getLecture`（N×M 次串行 IPC）——弹窗打开期间每次相关事件都重复全量扇出。
- 影响范围：多方案多阶段时的 IPC 开销与后端重复查询随规模放大；无正确性影响（结果幂等）。
- 修复方向：后端提供聚合的运行中任务列表，或前端仅拉 `status === 'running'` 的讲义。

### 82#12 练习「资料依据」引用列表 key 可能碰撞

- 位置：`desktop/src/pages/Practice.tsx:256`（`key={`${citation.materialId}-${citation.quote}`}`）。
- 传递链条：①AI 生成练习题的资料依据时，同一资料的同一句原文被引用两次 → ②两条列表项的 key（materialId+quote）完全相同 → ③React 同 key 告警进控制台，列表更新时元素可能复用错位（内容相同故视觉通常无感）。
- 影响范围：练习页引用列表；同页 :244 详情与 ExamWorkspace:212、SubjectivePractice:154 均已带 index 消歧，仅此一处漏。
- 修复方向：key 追加 index。
