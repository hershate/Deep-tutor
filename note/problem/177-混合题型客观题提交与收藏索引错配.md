# 177：混合题型客观题提交与收藏索引错配

## 证据

- `desktop/src/pages/Practice.tsx:236-239` 渲染时将 `detail.questions` 过滤为 `objectiveQuestions`，再用该数组的 `index` 显示当前题。
- `desktop/src/pages/Practice.tsx:161-169` 提交时却读取未过滤的 `detail.questions[index]`。
- `desktop/src/pages/Practice.tsx:174-185` 收藏时同样读取未过滤数组。
- `desktop/src-tauri/src/backend/practice/mod.rs:1216-1245` 后端题目按 `position` 返回，未按客观题重排；`submit` 以 `questionId` 判定实际题型和答案。

## 完整传递链条

用户在一次生成中同时选择主观题和客观题 → 后端按模型输出顺序保存混合题目 → 前端过滤出选择/填空题并显示第 N 道客观题 → 提交或收藏函数用同一个 N 索引原始混合数组 → 当原始第 N 项是简答/论述或另一道客观题时，前端把显示题的答案提交给另一题，或收藏另一题 → 后端按实际 `questionId` 拒绝答案类型、提交到错误题目或改变错误书签。

## 影响范围

- 同时包含 `choice/fill` 与 `short/essay` 的针对练习。
- 客观题答案、判分、错题记录、掌握证据与收藏。
- 纯客观题集合不受影响；模拟考试使用独立组件，不走这两个函数。

## 修复验收

- 提交和收藏必须与渲染共用同一份 `objectiveQuestions[index]`。
- 构造“主观题位于客观题之前”的混合顺序契约检查，确保界面索引不会回到原始数组。
- 后端真实 `submit_practice_answer` 测试与前端构建通过。
