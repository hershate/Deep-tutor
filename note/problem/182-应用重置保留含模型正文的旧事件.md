# 182：应用重置保留含模型正文的旧事件

## 证据

- `desktop/src-tauri/src/backend/providers/mod.rs:1340-1354` 将增量文本与推理内容作为 `provider.chat_delta` 的 `payload.text` 写入 `events`。
- `desktop/src-tauri/src/backend/store.rs:1045-1097` `Store::reset` 清除业务表和 kv，但未删除 `events`。
- `docs/architecture/02-operation-principles.md:558` 称重置保留事件且“载荷不含正文”，与实际事件结构不符。
- 设置页操作为“清除本地学习数据”，用户没有额外入口清除这些旧事件。

## 完整传递链条

用户使用方案、导师、Agent 或其他模型能力 → 增量正文与推理写入事件 outbox → 用户确认清除本地学习数据 → 业务记录和凭据被清除，旧 `events` 却完整保留 → 直接读取工作区 SQLite 或后续事件回放仍可取得旧模型正文 → 清除操作的隐私边界失效。

## 影响范围

- 当前用户工作区内所有含模型文本、推理及其他学习审计信息的历史事件。
- 应用重置、数据隐私、备份前状态与文档可信度。
- 其他本地用户工作区不受影响；事件 id 单调性必须继续满足前端续接。

## 修复验收

- 重置事务删除既有事件后再写入新的 `application.reset`；插件投递先清理，外键保持一致。
- `sqlite_sequence` 不重置，新事件 id 继续大于重置前最大 id，快照 `lastEventId` 不回退。
- 真实 SQLite 回归同时断言旧正文为零、仅保留重置事件、事件 id 单调；既有重置与恢复测试通过。
- 架构文档改为实际清理语义。
