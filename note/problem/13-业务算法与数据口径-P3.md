## engagement / reports / community

### 1. 免打扰"全天不通知"选项语义反转：实际发送的是"关闭免打扰"，且免打扰无任何实际拦截作用
- 前端：`Settings.tsx:92`——"全天不通知"提交 `{quietEnabled:false, 00:00, 00:00}`；后端 `engagement/mod.rs:483-489` quietEnabled=false 直接 return false；专门实现的 start==end 全天静默分支（:504-505）UI 从不发送。suppressed 唯一消费是通知弹层一行提示（App.tsx:294），全应用无主动弹出的提醒可拦截。

### 2. 通知"今日有 N 项计划任务"把全部历史逾期任务计入"今日"
- `engagement/mod.rs:560-574`——`WHERE date <= today` 含所有过去日期，标题固定"今日有 {N} 项"；上周遗留 10 项+今日 2 项显示"今日有 12 项"。

### 3. 全局搜索排序按 kind 英文字母序而非相关性，导航项被系统性压制
- `engagement/mod.rs:471-479`——(非前缀匹配, kind 字符串, 标题) 排序后 truncate(40)；material<node<note<page<plan<project<task——"资料"恒最前、"功能页面"第 4 类，命中 ≥40 时导航入口可被整体挤出。

### 4. 搜索知识节点用 title+summary 无分隔符拼接匹配，跨字段边界误命中
- `engagement/mod.rs:444-448`——`format!("{}{}", title, summary)`（对比 community 用空格拼接）；标题尾字+摘要首字恰拼出查询词即误命中。

### 5. 仪表盘"接下来"把已无待办里程碑的完成项目仍列为"0 个里程碑待完成"
- `engagement/mod.rs:803-828`——remaining==0 不过滤、不排序不截断（考试 LIMIT 3、项目无限制）。

### 6. [待确认] 首页聚合与报告 goal 状态恒取最新方案（list().next()），无视"采用"状态
- `engagement/mod.rs:735`、`reports/mod.rs:648`——生成新方案（未采用）后首页"当前目标/下一站/方案进度"全部切换，而"继续学习"落到旧方案；与 StudyRoom 只显示已采用方案口径分裂。

### 7. 学习日历同日"自报打卡"整日覆盖"专注计时"：当日计时分钟在日历/总计/连续记录中消失
- `reports/mod.rs:839-843`——`Some((minutes,note)) => (minutes,note,"self_report")` 分支直接丢弃 focus 秒数；与决策"日历保留计时与自报来源"（note/产品与技术决策.md:63）及页面文案"两种来源均保留"不符。[口径需判定]

### 8. "打卡率"分子混入计时日且固定除以 84：从未打卡也可显示高打卡率，新工作区恒被稀释
- `reports/mod.rs:844-847/872`——recorded 计所有 minutes>0 日子（含 timer），`recorded*100/84` 恒以 84 为分母——只专注不打卡的用户显示"打卡率 36%"名实不符；建区 3 天时上限 3%。

### 9. [待确认] "有效学习"对同一学习活动可双计：关联任务的专注秒与任务勾选的计划分钟叠加
- `reports/mod.rs:507-508`——`current + tasks*60` 两来源不互斥；专注 25 分钟后勾选 60 分钟计划任务记 85 分钟，周报通知同口径放大。

### 10. [待确认] "本学期"窗口固定 1/1 与 9/1 切换：寒暑假月计入学期，两段 8 个月 vs 4 个月
- `reports/mod.rs:440-449`——7 月查看"本学期"从 1 月 1 日起算约 190 天，含整个寒假与半个暑假；对比基线随之处漂移。

### 11. CSV 正确率/保持率输出原始浮点（76.92307692307692），与页面整数百分比不一致
- `reports/mod.rs:1013/1021`——`(value*100.0).to_string()` vs 页面 `Math.round`。

### 12. [待确认] 房间预约无任何时段冲突/重叠检测
- `community/mod.rs:672-776`——create/reserve 均不检查重叠（无 end_at 列）；可同时段多房全约，"真实学习安排"自相冲突。决策文档未声明冲突检测，属产品意图待判定。

### 13. 社区帖子搜索先 LIMIT 200 再内存过滤：第 201 条以后的旧帖永远搜不到
- `community/mod.rs:330-347`——`ORDER BY id DESC LIMIT 200` 无关键词条件；threads 配额 500 > 200，更早匹配帖静默缺失。

### 14. 房间/预约取消后，通知中心的"即将开始"通知永久残留
- `engagement/mod.rs:597-609` 插入后无任何删除/失效路径；`community/mod.rs:785-825` 级联清预约提醒但不删 notifications——与前端"相关预约与提醒已同步取消"（Community.tsx:108）矛盾。

### 15. Dashboard 纯日期字符串按 UTC 解析再本地显示，西半球时区目标日显示提前一天
- `Dashboard.tsx:42-44`——`Date.parse("YYYY-MM-DD")` 按 UTC，`toLocaleDateString` 转本地；UTC-5 时区显示前一天。UTC+8 无可见影响。

## review / sharing / backup

### 16. 复习保持率文案漏列"再来一次=0%"，且任何非四档 grade 也按 0 计入均值；无时间窗
- `review/mod.rs:499-503`——`ELSE 0.0` 覆盖 again 与异常档位；`Review.tsx:128` 只写三档权重；全表无时间窗，长期使用者数值趋稳失去参考意义。

### 17. "今日待复习"（含逾期）与日历"今天"桶（排除逾期）同屏两套口径
- `review/mod.rs:487-491` vs `:505-512`——存在逾期卡时同页两数字恒不相等（与 01#17 时区错位不同，本条是语义桶差异）。

### 18. 分享记录列表 LIMIT 100 无分页：第 101 条起最旧有效分享从 UI 永久不可撤销
- `sharing/mod.rs:433-434`——撤销入口仅渲染 list 返回行；只能等 365 天自然过期。

### 19. "预演"与实际导入不是同一套解析：预演只做 open+计数，ID 冲突映射与引用重写仅导入执行
- `backup/mod.rs:26-28` vs `:36-37`；`transfer.rs:1104-1106` 仅导入路径——预演通过后导入仍可失败（如 provider_id 逻辑引用断链，测试 tests.rs:508-535 实证），错误出现在最后一步。

### 20. 导入事务提交后的 reindex/9 个 recover/app_state 任一失败把整条 import 报为失败，数据已提交、重试全量重复追加
- `transfer.rs:1114-1119` commit 后返回；`backup/mod.rs:38-68` 全部 `?` 传播——追加语义无去重（仅 materials 按哈希合并），用户按提示重试即双份。

### 21. [待确认] 决策声明"快照携带工作区 ID 与事件代次"后半句无实现
- Manifest（archive.rs:105-114）无任何事件代次字段；全后端无事件 epoch/generation 概念（仅 plugins.generation 与方案 regeneration，均与事件无关）。

### 22. [待确认] 决策声明"过期后可重新选择本地用户"无与"过期"绑定的实现
- share_index 无过期字段；最接近机制（会话过期重选用户、索引丢失目录扫描重建）均不匹配——需人工确认声明本意。

## practice / projects / sync

### 23. 填空判分等价性缺失：大小写/空白已归一，全半角与标点变体未归一
- `practice/mod.rs:1045-1051`——normalize 仅 split_whitespace+lowercase；中文 IME 全角形态（ＡＢＣ/１２３）语义等价判错。

### 24. 考试到期不自动收卷：过期试卷永久停留 ready，未答题永不按 0 分落定
- `practice/exams.rs:48-72`——remaining/ensure_accepting 仅被动检查；唯一 finalize 入口是手动按钮（ExamWorkspace.tsx:106-113），无后端定时器——"未作答按 0 分"只覆盖主动交卷路径。

### 25. [待确认] 错题变式链深度无限，mastered 只向直接上一级传播不达原题
- `practice/variants.rs:65-78/106-133`——可对变式的错题再生成变式；Q1 错→V1 错→V2 对只标 V1 掌握，原错题 Q1 永远待巩固；UI 文案"自动更新原错题"仅对一级成立。

### 26. 书签写入无题目存在性校验（FK 失败折叠为 storage_failed），且集合滑出 50 条历史窗口后已收藏题目无任何查看途径
- `practice/mod.rs:1239-1254/1201-1210`——无 list 命令，书签状态只随集合 detail 暴露。

### 27. [待确认] 交卷后未作答题目与真实错题同等写入错题本（wrong_count 计 1 次错误）
- `practice/exams.rs:153-156`——未答≠做错但同样占错题本、参与变式流程；大量空题时错题本被未学内容灌满。

### 28. 项目迭代笔记与版本无持久关联：versionId 仅存在于一次性事件载荷与标题文本
- `projects/mod.rs:633-651`——笔记 JSON 无法持久化 projectVersionId（store.rs:833-842 白名单）；事后无法按版本检索迭代笔记。

### 29. sync import/restore 的本地回写文件无限累积：无清理路径、UI 不展示 localPath
- `sync/mod.rs:530-544`——固定写 `users/<id>/sync/{jobid}.json`；运维清理不覆盖 sync 目录；sync.ts:24 定义 localPath 但 SyncPanel 无使用。

### 30. "测试连接"把"对象尚未创建（新配置正常态）"判为失败：首次配置必然报 HTTP 404
- `sync/mod.rs:508-523`——check 对远端对象 HEAD/PROPFIND，404 与 401/403 同样折叠为 sync_http_error——新配置在首次上传前检测必败且误导。

### 31. versions 目录混入任一不合规文件名即令版本列举整体失败，阻断后续上传与恢复
- `sync/versions.rs:60-72/137-145`——任一不合规对象名使 parse_versions 整体 Err；此后每次上传在清理阶段失败（数据已 PUT 但任务判 failed）、版本恢复 UI 同时瘫痪，错误文案不指向真实原因。
