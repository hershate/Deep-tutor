## 证伪记录（代理候选项，经复核不成立）

### 33#3 「useAgent failover 后快照请求持续 not_found」——证伪

- 候选来源：前端批次一审计代理（信息性）。
- 证伪依据：`providers/mod.rs:962-967` 的 `get_chat` 先查 `routing::latest_chat`（按
  逻辑 request_id 查 provider_route_runs），not_found 则回退 `chat()`（按**精确 id** 查
  provider_requests）；failover 的直连层以**上游 id**（`{request_id}-f{index}`，
  routing.rs:999-1016 传入 `stream_chat_with_policy`）落 provider_requests。因此
  route_attempt 后前端用上游 id 调 `getProviderChat` 恰好命中 provider_requests 行，
  查询**成功**——候选所断言的「持续 not_found」不成立。真实行为：首次尝试（index=0，
  上游 id == 逻辑 id）经 latest_chat 合并视图，failover 后经 provider_requests 上游行，
  两条路径均可用。
