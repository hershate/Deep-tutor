## P3

### 85#1 备份导入的 schema 列名未转义直接拼入 SQL，可单语句注入改写活库

- 位置：`desktop/src-tauri/src/backend/backup/transfer.rs:121-134`（`schema()` 从备份库 `PRAGMA table_info` 读列名）、`:1021-1032`（`format!("\"{}\"", column.name)` 拼 `INSERT INTO "{table}" ({names})`）、`:224`（`exists()` 的 `WHERE "{column}" = ?1` 同源）。
- 传递链条：①攻击者构造自洽 .dtbackup——zip 内恶意 state.db 的 CREATE TABLE 使用含双引号的列名（SQLite 标识符合法，如 `"a"", notes) VALUES(...); --"`），manifest 的 sha256 由攻击者自行计算即可通过完整性校验（manifest.tables 只记行数不记列名）；②用户经 import_full_backup 导入；③`schema()` 读出恶意列名，`format!("\"{}\"", ...)` 不转义内嵌 `"`；④拼入对**活库**执行的 INSERT/EXISTS，闭合引号后注入任意单条 SQL（改写 `provider_profiles.base_url` 指向攻击者域、向 kv 插入伪造集合等）；⑤后续对话的 Authorization 头发往被篡改端点 → API Key 外泄；或学习数据被静默破坏。
- 影响范围：导入恶意备份 = 对当前数据库的受限任意写（单语句）。表名来自硬编码 TABLES 常量不受控，风险仅在列名。需社工分发恶意备份，但「导入他人分享的备份」是产品支持场景。
- 修复方向：`schema()` 读出的列名做 `^[A-Za-z0-9_]+$` 白名单校验（不合法报 `invalid_backup_schema` 拒绝整单导入），或将 `"` 转义为 `""`——白名单更彻底，因自有 schema 列名全符合该模式。

### 85#2 deep link 的 name/model 不过滤控制字符与 bidi 字符，可注入伪装文案建钓鱼档案

- 位置：`desktop/src-tauri/src/backend/providers/mod.rs:726-756`（`query_pairs` 值直接进 ProfileInput）；校验仅 `:428-486`（长度/枚举，无字符类过滤）。
- 传递链条：①恶意网页放置 `deeptutor://provider?name=官方 OpenAI %E2%80%AE...&baseUrl=https://attacker.com/v1&model=x`；②用户点击（浏览器仅一次确认弹窗）；③deep_link 静默 upsert 建立立即可用的供应商档案，name 含 U+202E（RTL 覆盖）、\r\n 等在设置页列表中伪装为官方条目；④诱导用户向攻击者 baseUrl 的档案录入 API Key。React 文本节点自动转义无脚本执行；baseUrl 经 endpoint() 的 scheme/SSRF 校验（https 侧漏洞已报 81#2）。
- 影响范围：UI 文案伪装/钓鱼，非 XSS；纵深防御缺层。
- 修复方向：`validate_input` 对 name/default_model 增加 `is_control()` 与 bidi 字符（U+202A-202E、U+2066-2069）拒绝；deep link 建档在 UI 弹一次确认对话框。

- 位置：`desktop/src/backend/client.ts:9-16`（`sanitizeFileBaseName` 只做控制符剥离、非法字符替换、尾部点/空格剥离、80 码点截断）；调用点 `components/ExportCenter.tsx:102`。
- 传递链条：①模型生成的讲义标题恰为 CON/NUL/COM1 等（供应商输出不可信）→ ②`saveMaterialFile(title, ext)` 把 `CON.md` 作为保存对话框 defaultPath → ③旧版 Windows 保存失败或解析为设备。仅影响建议名，用户可手改；后端笔记 zip 条目名有 `{id:03}-` 前缀天然免疫（export/notes.rs:20-50 已核实无穿越）。
- 修复方向：清洗时检测保留名基名（CON/PRN/AUX/NUL/COM1-9/LPT1-9）并追加 `_`。
