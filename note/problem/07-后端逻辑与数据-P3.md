# P3 后端内部逻辑与数据问题（11 项）

第三轮后端内部审计发现。事务"同事务+emit 后置"主模式、SM-2/贪心排期/BFS 算法、
FK 删除顺序、LIMIT/OFFSET、锁序（无死锁组合）均验证通过，未列入。

## 1. agent/方案/讲义的 cancel UPDATE 无状态守卫，终态竞态窗口把 done/failed 行改回 'cancelling' 且无人翻转
- 证据：`agent/mod.rs:899-903`、`learning/mod.rs:820-831`、`learning/lecture.rs:737-744`——无条件 UPDATE 置 cancelling；对比有守卫的 `practice/mod.rs:1310-1315`、`knowledge/mod.rs:684-693`（WHERE status='running' + changed==0 报错）。
- 影响：worker 完成 commit 与摘除 active 标志之间的毫秒级窗口内点取消，终态被覆盖，此后该会话 send 永远报 `run_active`、plan resume 报 `plan_active`，直到重启 recover 才解锁。[是否接受该竞态待确认]

## 2. `agent_tool_calls` 注册行可永久停留 'running'
- 证据：`agent/tools.rs:415-418`（INSERT 'running'）→ `:461-467`（参数校验失败直接 return，未走结果回写）→ 行停留 running；`agent/mod.rs:1011-1052` recover 不覆盖该表。
- 影响：同 id 重放命中 `tool_active` 拒绝执行；数据库累积僵尸 running 行（恢复路径因换新请求 id 通常可绕过）。

## 3. share_index（根库）与 shared_plans（工作库）写入不在同一事务，reset 失败路径无补偿
- 证据：`sharing/mod.rs:299-317`（create 有补偿删除）；`store.rs:602-606`（reset 在主事务 commit 前清根库索引，事务失败则索引已清而 shared_plans 仍在，无补偿；reindex 仅由备份导入触发）。
- 影响：reset 失败后跨用户分享令牌查找失效，直到下次备份导入。

## 4. `adopt_recommendations` 先提交任务再启动专注，start_focus 失败时任务已写入
- 证据：`reports/mod.rs:967-978`——replace_collection 提交任务后 start_focus 失败即整体报错不回滚；预检查（:961-966）与 start_focus 间也有竞态。
- 影响：采纳"记录一次专注"类建议失败时任务已加入清单但用户收到报错。

## 5. 文档 §12 自相矛盾且实现分裂：cancelling 重启翻转目标不一致
- 证据：`docs/architecture/02-operation-principles.md` §12 mermaid（cancelling→interrupted）与文字（cancelling→cancelled）矛盾；实现中 7 个域 cancelling→cancelled，而 `sync/mod.rs:799-816` 与 `providers/routing.rs:1265-1310` 落 interrupted。
- 影响：重启后已取消的同步/路由任务显示"已中断"，与多数域语义不符；验收对照状态机产生歧义。

## 6. materials 是唯一自动重跑的域，与"重启=永不自动重跑"总则相反
- 证据：`materials/mod.rs:1073-1102`——recover 把 queued/parsing 重置 queued 后直接重新解析。
- 影响：本地解析幂等、风险低；属未声明的行为差异。

## 7. 强度缩放基数可被 update_goal 破坏
- 证据：`planning/mod.rs:271-274`（scaled 按"当前强度→目标强度"比例，隐含排期已按当前强度缩放）vs `:461`（update_goal 直接覆写 daily_minutes 不乘强度因子），此后 regenerate 按未缩放基数重建。
- 影响：goal 更新+重生成后再切强度，排期按错误基数缩放（防累积缩放本身验证成立）。

## 8. notes 'updated' 字段混用本地偏移与 UTC 两种格式
- 证据：`notes/mod.rs:214-216`（导入用 now_local 带 +08:00）vs `learning/knowledge.rs:321`（批注用 UTC）。
- 影响：同一字段两种偏移表示；当前无 SQL 排序依赖，属格式统一性隐患。

## 9. 报告趋势图日标签用 UTC 日期，窗口边界却是本地午夜
- 证据：`reports/mod.rs:642-643`（本地午夜转 UTC）vs `:679-681`（按 UTC 日期字符串分组标签）。
- 影响：本地 0–8 点产生的证据记入前一天曲线点，横轴与窗口边界口径不一致。

## 10. practice detail 逐题 N+1 查询
- 证据：`practice/mod.rs:972-976`（每题一次 bookmark EXISTS）、`:1005-1011`（hints 模式每答案一次 hint 查询）；detail 在每次提交返回与每次 practice.* 事件刷新时执行。
- 影响：20 题集合每次刷新 20–40 次额外查询，主线程模型下放大为可感卡顿。

## 11. [待确认] 约 40 处 BEGIN DEFERRED 事务先读后写，与流式 delta 自动提交并发可触发 BUSY_SNAPSHOT——03#6 database_busy 的后端根因
- 证据：`store.rs:498-505`（replace_collection 事务内先 SELECT 后 INSERT）等约 40 处 `unchecked_transaction`；并发写源 `providers/mod.rs:1107-1115` 每条 chat_delta 自动提交写 events；WAL 下 DEFERRED 升级写锁遇 BUSY_SNAPSHOT 不经 busy_timeout 重试。
- 影响：流式任务进行中用户并发保存偶发 database_busy 直接失败；发生率需压测确认。
