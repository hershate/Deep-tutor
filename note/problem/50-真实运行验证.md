### 50#1 verify 通道的 setup 错误以 panic + exit 101 交付——错误消息本身类型化但包装层是 panic

- 位置：`desktop/src-tauri/src/main.rs:22-26`（env 校验 `?` 进 setup 闭包）、`:61-63`（ensure_ready `?`）、`:284`（`.run(context).expect(...)`）。
- **传递链条**：① CI/脚本以非法参数跑 `--verify-native`（如相对路径 DEEPTUTOR_VERIFY_DATA_DIR 或损坏库）→ ② setup 闭包内 `?` 把 BackendError 装箱上抛 → ③ `Builder::run` 的 `expect`（tauri app.rs:1444）收到 Err → ④ **panic**：stderr 打印 `thread 'main' panicked … Failed to setup app: <类型化中文错误>` + `note: run with RUST_BACKTRACE…` → ⑤ exit 101。windows_subsystem 下 stderr 实际不可见——脚本只能靠退出码，无法程序化获取错误码（0/2/101 无区分语义）。
- **影响范围**：仅测试/CI 脚本对该通道的错误处理体验（应判码而非解析输出）；错误消息内容本身正确（storage_failed 等类型化中文）。**正常模式不受影响**——GUI 启动失败走 initialize_background 的 failure 状态与恢复 UI（startup.rs:294-343 及测试在案）。修复方向：verify 分支错误改 `eprintln + std::process::exit(2)`。
