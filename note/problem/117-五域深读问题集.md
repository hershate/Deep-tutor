### 117#1 notes ZIP 导入的 64MB 解压总量与压缩比检查都信任清单声明值——恶意归档可绕至 ~1GB 内存峰值，诚实高压缩比笔记反被整批误拒

- 位置：`desktop/src-tauri/src/backend/notes/mod.rs:183-199`（`entry.size() > MAX_NOTE_BYTES || entry.size() > entry.compressed_size().max(1).saturating_mul(200)` 与 `total += entry.size()` 均用 ZIP 中央目录声明值；zip 2.6.1 读取链只在 compressed_size 上 take，解压输出不受声明值约束）；实读钳制仅 `:205-221` 的 `take(MAX_NOTE_BYTES + 1)`。
- 传递链条：①恶意归档把每条 md 条目声明为 `size=1`（实际解压 1MB）：两项声明检查全过、total 按 1 累加永不触 64MB；②每条实读被 take 钳到 ≤1MB 合法通过，全量驻留 `notes: Vec<NoteSource>`（:228）直到事务写入；③上限 1000 条 × 1MB ≈ 1GB 内存峰值，是宣称 64MB 上限的 16 倍——低端机器导入即 OOM 崩溃。反向：诚实归档中 deflate 压缩比 >200:1 的正常笔记（重复行多的 markdown 表格/日志型 txt）在 :184 被整条拒绝，且报错文案与「超过 1MB」混为一谈。测试（notes/tests.rs:132-163）只用诚实归档，两个方向均未覆盖。
- 影响范围：`import_notes` 命令的任意用户选择 .zip；资源面（OOM 峰值）与误拒面；无代码执行（enclosed_name 防穿越、条目数 ≤1000、整档 ≤64MB 均在位），命令有 principal 门。
- 修复方向：total 改按 `bytes.len() as u64`（实读值）累加并保留 64MB 熔断；删除或放宽声明压缩比检查（实读 take 已封顶放大率，该检查只剩误伤价值），保留则报错区分两种原因；补「声明 size=1 实体 1MB」与「高压缩比诚实归档」两个方向的测试。

### 117#2 plugins×maintenance 并发清理防护落在错误的目录层级（死代码）——并发「安装+清理」可把安装成功的插件变成 reload 永久失败的僵尸行

- 位置：`desktop/src-tauri/src/backend/maintenance/mod.rs:356-361`（根层扫描 `plugins/.manifest-*.tmp` 并按 `modified_recently` 宽限）vs `plugins/mod.rs:363-372` 的 `write_manifest` 把临时件写在插件目录内部（`plugins/{id}/.manifest-{N}.tmp`）——层级永不匹配，防护自引入即死代码；未安装清单孤儿判定（maintenance/mod.rs:388-398）无 mtime 宽限，cleanup 的 plugins 循环（:770-799）也无 31#32 式删除前复查。测试 maintenance/tests.rs:182 把夹具写在根层，与真实布局不符故全绿。
- 传递链条：①`plugins::install` 顺序为 INSERT 行 → write_manifest（rename 出 `plugins/{id}/manifest.json`）→ tx.commit()（plugins/mod.rs:475-482）；②并发 cleanup 在 rename 与 commit 之间的毫秒窗扫描：install 事务未提交，另一连接 SELECT EXISTS 见 installed=false、清单校验通过 → 按「未安装插件的合法清单」推入孤儿 → remove_tree 删掉整个 `plugins/{id}`；③install 随后 commit 成功 → 插件入库但磁盘清单永久缺失：reload 恒报 `plugin_manifest_missing`，重装被 `plugin_already_installed` 挡死，须手动卸载重装；B-13 暴露检查要求目录存在才报告——目录已删，运维面板零可见。maintenance 的 try_lock 拦不住 install（plugins 域自开连接不持共享 store 锁）。
- 影响范围：并发「安装插件 + 运行维理清理」的窄窗口；命中即僵尸行（UI 可见、功能不可用）。
- 修复方向：write_manifest 临时件改写到 `plugins/` 根层（与扫描层级一致），或扫描对 `plugins/{id}` 内 `.manifest-*.tmp` 与未安装清单加宽限；cleanup plugins 循环补 31#32 同款删除前 mtime 复查；B-13 检查改「已安装但 manifest.json 不存在」；夹具与测试同步改到真实层级。

### 117#3 插件事件订阅白名单遗漏 7 个真实 emit 的命名空间——focus/study/lecture/report/security/notifications/usage 不可订阅，与「只含真实 emit」的自定准则矛盾

- 位置：`desktop/src-tauri/src/backend/plugins/mod.rs:296-312`（白名单 14 项，61#1 注释自称「只含真实 emit 的命名空间」）；全库实发还包括 focus（reports/mod.rs:348,383,421 等）、study（note_saved/checkin_saved/progress_changed）、lecture（6 种）、report.exported、security.*（9 种）、notifications.*、usage.*。dispatch（:740-754）对这些事件本会真实投递，唯一障碍是安装/重载白名单校验（:316-321 invalid_plugin_subscriptions）；前端 Integrations.tsx:9 的「只允许下列真实命名空间」列表与后端同源。
- 传递链条：①用户按 UI 指引写 `focus.*` 订阅（确凿存在 focus.started/paused/resumed/interrupted）→ ②validate 拒绝 → ③专注/打卡/讲义/报表/安全/通知/用量七类真实事件对声明式插件不可达——「白名单只含真实 emit」准则被遗漏项反向违反（过度限制方向，无安全收益）。
- 影响范围：声明式事件插件的功能面；无错误数据、无安全问题。

### 117#4 cleanup 的 plugins 循环把「同批连带删除项」计入 deleted_files——与同函数 70#6 既定语义相反，freed_bytes 记账失真

- 位置：`desktop/src-tauri/src/backend/maintenance/mod.rs:785-798`（`!exists → Ok(0)` 走与真删除相同的 `Ok(bytes)` 臂，`deleted_files += 1` 照加；对照同函数 sync 循环 :753-760 的 70#6 语义「非本轮删除不计 deleted_files」）。remove_tree 成功时只记 item.bytes（清单字节或 0），整目录实际释放量未计入。
- 传递链条：①一次 cleanup 中「无清单空目录占位项」与「同目录清单项」都进 orphans.plugins → ②前者删掉整个目录后，后者命中 `!exists → Ok(0)` → ③返回值 deletedFiles 虚高（每多一个占位项 +1）、freed_bytes 少记——运维面板「已删除 N 个文件 / 释放 X 字节」与磁盘事实不符。
- 影响范围：仅 cleanup 结果展示口径；remaining 不受影响（batch 同步 +1）、无数据风险。
- 修复方向：plugins 循环 Ok(0) 分支单独入账（batch += 1 后 continue，对齐 :753-760）；remove_tree 以删前目录遍历字节数计入（tempdirs 循环 :815 已是该做法）。

### 117#5 CI 不跑 dev server 冒烟——116#3 新门禁仅本地生效，dev 工作流回归在 CI 侧无检出通道

- 位置：`.github/workflows/ci.yml`（步骤为 npm ci → tsc → fmt → 测试 → check-versions → collect-licenses → NSIS，无 dev-smoke）；`Makefile` check 含 `scripts/dev-smoke.sh`（本地）。
- 传递链条：①贡献者只跑 CI 不跑本地 make check → ②vite 配置类回归（111#2 型：build 成功但 dev server 403）在 CI 全绿 → ③合并后本地开发者首跑 `npm run dev` 才发现。
- 影响范围：CI-only 流程的 dev 回归发现时机；发布产物不受影响。
- 修复方向：ci.yml 增加一步 `bash scripts/dev-smoke.sh`（windows-lateral 兼容：脚本用 bash + netstat + taskkill，GitHub windows runner 的 Git Bash 可用）；或文档化「CI 不含 dev 冒烟，合并前本地跑 make check」。
