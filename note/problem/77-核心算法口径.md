## P3

### 77#1（=H-1）掌握度三处聚合口径不一致——脏数据下三页三种表现

- 位置：`learning/knowledge.rs:43-106`（pooled SUM/SUM，脏行整组失效该节点消失）、`reports/mod.rs:859-916`（行级过滤 finite/界内后 mean-of-ratios）、`engagement/mod.rs:473`（搜索结果 AVG 无任何过滤）。
- 传递链条：当前 max_score 恒 1 时三者数值等价；外部改库产生 score>max 行时——engagement 可显示「掌握度 130%」、knowledge 页整节点消失、报告页仅丢单行。
- 影响范围：正常使用无差异；脏数据下跨页数字互相矛盾。
- 修复方向：统一行级过滤口径（报告页的 evidence() 过滤推广）。

### 77#2（=H-2）用量页「模型明细/份额」聚合全部历史而非所选窗口——与趋势图并排易误读

- 位置：`providers/usage.rs:390-407`（models HashMap 聚合遍历全部 entries，无 days 过滤；entries 全表载入后逐日 O(N×days) 过滤）。
- 传递链条：① 用户选「近 7 日」② 趋势图 7 日、模型明细/份额为全历史 ③ UsagePanel 两块并排（「近 N 日已计价成本」vs「按真实模型明细」）→ 账单核对偏大。反例：4 月 $50、近 7 日 $1，仍显示 $50/share 100%。
- 影响范围：所有用量页用户；核对成本的直接误读源。
- 修复方向：models 聚合同窗口过滤；UI 补窗口说明。

### 77#3（=H-3）adopt_recommendations 事务外分配 next_free_id——并发采纳同 id 静默互相覆盖

- 位置：`reports/mod.rs:1179-1200`（autocommit 连接取 id → 多个建议循环各取 → 最后才 replace_collection）。
- 传递链条：两次并发 adopt 各取同一 MAX+1 → 两条建议任务同 id → kv upsert 互相覆盖，返回 added=2 实落 1 条。对照 knowledge.rs:221/save_note:325 均在事务内分配（冲突表现为可重试错误而非静默丢失）。窗口毫秒级。
- 影响范围：报告页快速连点采纳（UI busy 守卫未完全挡住时）。
- 修复方向：分配移入 replace_collection 同事务。

## 信息性

### 77#4（=H-4）保持率 CASE 语义不一致

- 位置：复习统计 `review/mod.rs`（CASE … ELSE NULL）vs 报告页保持率 `reports/mod.rs`（CASE … ELSE 0.0）。
- 传递链条：① 复习页遇到未知档位行输出 NULL → SQL AVG 自动排除该行（13#16 修复口径）② 报告页同型聚合遇到未知档位输出 0.0 → 计入分子分母、拉低均值 ③ 同批数据两页两个数；另有复习页全历史均值 vs 报告页窗口均值的天然差异，UI 未说明。
- 影响范围：出现未知档位行时两页数字矛盾；正常数据无差异。

### 77#5（=H-5）复习耗时估算双口径

- 位置：复习统计 stats（40 秒/卡）vs 到期提醒通知文案（2 分钟/卡）。
- 传递链条：① 用户在复习页看到「预计 X 分钟」按 40 秒/卡 ② 同日收到到期通知按 2 分钟/卡估算 ③ 30 张卡一处 20 分钟、另一处 60 分钟（封顶）——两入口对同一数字给出不同预期。
- 影响范围：复习时长预期的认知不一致；无功能影响。

### 77#6（=H-6）Wiki 检索无数量上限无分页

- 位置：`knowledge/mod.rs:392-456`（Wiki 提问的知识检索路径）。
- 传递链条：① Wiki 面板提问触发资料检索 ② 每个关键词对全部资料全文 matches 计数 + O(n·m) 逐段扫描 ③ 全量返回无 LIMIT 无分页——对照 engagement 搜索固定 40 条的有界口径 ④ 大资料库下检索耗时与返回载荷均无上界。
- 影响范围：大库 Wiki 提问延迟；与全仓有界查询口径不一致。

### 77#7（=H-7）掌握度全历史等权语义说明

- 位置：`learning/knowledge.rs` 掌握度聚合（全历史均值）；报告页推荐排序复用同一均值。
- 传递链条：① 掌握度 = 全部历史 evidence 等权平均（无时间衰减、无最新优先）② 半年前的 0 分永远拉低当前估计 ③ 报告「薄弱点推荐」用同一均值排序——语义自洽，但用户直觉是「当前水平」。
- 影响范围：长期学习用户掌握度展示偏低；属设计语义，宜在文档/界面声明。

### 77#8（=H-8）review 到期日 9999 边界 unwrap

- 位置：`review/mod.rs:546-547` `checked_add(...).unwrap()`。
- 传递链条：① SM-2 间隔上限 36500 天 + 前置 clamp → 正常路径日期相加不溢出 ② 该行仍用 unwrap——同函数 next_day() 已按 47#3 转类型化错误，此处同类遗漏 ③ 一旦毒数据（超大间隔）进库，panic 使命令层返回通用错误而非类型化错误。
- 影响范围：实际不可达（防御深度不一致）；修复对齐 47#3 即可。

### 77#9（=H-9）share 为 token 份额非成本份额

- 位置：`usage.rs:408-416`（模型份额计算）。
- 传递链条：① 用量页「份额」按 tokens 占比计算 ② 高输入价模型（input 单价远高于 output）的 token 占比与真实成本占比显著背离 ③ 用户把份额当成本占比读——核对账单时误判哪个模型更贵；UI 无「按 token 计」标注。
- 影响范围：用量页份额的误读面。

### 77#10（=H-10）排期首日不按生成时刻折算

- 位置：`learning/validate.rs:227-228`（首日装填按完整 daily_minutes）。
- 传递链条：① 23:50 生成方案 ② 首日任务按完整 daily_minutes 装填 ③ 落地任务当天仅剩 10 分钟却排了 60 分钟——生成即「逾期」，首日体验从起点就是红色。
- 影响范围：深夜生成方案的用户首日观感；任务量本身不受影响。

### 77#11（=H-11）主观题两处硬编码

- 位置：`practice/subjective.rs`（rubric 总和校验与 correct 判定）。
- 传递链条：① rubric 总和 ±1e-4 容差校验存在，但后续得分再 clamp 到 [0,1]——容差校验实际被 clamp 掩盖（越界 rubric 仍产出合法分数）② `correct = score >= 0.8` 阈值硬编码，与考试 set 的 pass_score_percent 无联动 ③ 仅影响错题本归集口径。
- 影响范围：主观题错题判定阈值不可配置；评分本身正确。

### 77#12（=H-12）强度缩放 0.8/1.2 往返舍入漂移

- 位置：`planning/mod.rs:312-315`（强度缩放取整）。
- 传递链条：① 7 分钟任务 → 切冲刺 ×1.2=8.4 → 取整 8 ② 切回稳妥 ×0.8=6.4 → 取整 6 ③ 一来一回每条目 -1 分钟；52#1 修了 clamp 卡死（0.4×1.2=0.48 取整卡 0）未处理往返不闭合。
- 影响范围：反复切换强度的方案总时长缓慢缩水；无功能错误。
