# 185：社区概览异步命令丢失会话身份

## 证据

- `desktop/src-tauri/src/backend/community/commands.rs:15-26` `get_community_overview` 是 `#[tauri::command(async)]`，在 `spawn_blocking` 内直接执行 `overview`，未调用 `session_principal_existing` 或 `with_principal`。
- `desktop/src-tauri/src/backend/community/mod.rs:47-49` 社区数据层通过 `Store::new` 打开数据库，依赖当前 principal 决定工作区。
- `desktop/src-tauri/src/backend/security/mod.rs:75-100` 明确规定 async 命令无法继承 IPC 线程的 thread-local principal，必须从会话重新派生并传播。
- `desktop/src-tauri/src/backend/security/guard_tests.rs` 现有异步隔离测试只覆盖供应商档案，未覆盖社区概览。

## 完整传递链条

前端进入学习社区或刷新讨论 → `get_community_overview` 经 Tauri `respond_async` 调度到 Tokio worker → IPC 线程中的 principal 不可见 → `spawn_blocking` 内 `CommunityState::store()` 打开数据层时缺少当前用户 → 生产构建返回 `store_unavailable`，测试构建则可能回退根库并读出其他工作区内容 → 社区首页不可用或工作区呈现隔离失效。

## 影响范围

- 学习社区首次读取、讨论/小组/预约页全部概览数据和后续刷新。
- 生产环境所有本地用户；多用户场景还涉及跨工作区旧数据回显。
- 社区同步写命令不经过此 async 入口，不受同一缺陷影响。

## 修复验收

- 命令从现有会话派生 principal，并在阻塞闭包中用 `with_principal` 包裹真实读取。
- 在带 `SecurityState` 的 MockRuntime IPC 测试中：user1 创建讨论，切换 user2 后概览不得返回 user1 帖子。
- 既有社区测试、异步身份测试和全量后端测试通过。
