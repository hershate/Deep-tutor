## P3

### 64#1（=I-1）`cancel_material_parse` 零测试触达

- 位置：`materials/commands.rs:68`（定义）、`main.rs:240`（注册）——此外全库零命中。
- 传递链条（防线如何漏过）：① 未来改动取消逻辑（如排队/运行中分支、cancel_requested 置位、status→cancelling 转移）→ ② `cargo test` 全绿（无任何测试执行该命令或其内部函数）→ ③ 回归直达用户——UI「请求取消」按钮即走此命令。
- 影响范围：解析取消路径的全部行为回归（取消排队任务、取消运行中任务、取消后的 recover 语义）无自动化护栏；用户可见后果是取消失灵或状态卡死才被发现。补测成本低（域内已有 TestServer/夹具模式）。

### 64#2（=I-2）`export_material_original` 注册未调用

- 位置：`materials/commands.rs`；测试 app 已注册（commands.rs:158）但零调用。
- 传递链条：① 未来改动原件导出链（`reject_data_root_destination` 遏制 + 原件 SHA-256 复核 + atomic_export 组合）→ ② 该组合无任何直接断言（写盘回执模式仅由 `export_usage_csv_file` 代理覆盖）→ ③ 遏制或哈希复核被误删时测试不报警。
- 影响范围：KB 文档「下载原件」功能的三个安全属性（目的地遏制、原件篡改检测、原子写）依赖代理测试间接保护；代理与真链的差异（原件走 fs::read+比对 vs CSV 直写）正是未测面。

### 64#3（=I-3）`get_learning_profile` 零断言

- 位置：`engagement/commands.rs:39`。
- 传递链条：① save 有测（含无效输入拒绝）但读取命令零断言 → ② 未来改动 profile 读取（如字段增删、序列化默认值）→ ③ 保存-读取往返的破坏不被发现——设置页档案面板读到 undefined 字段。
- 影响范围：设置页「个人学习档案」展示与导师行为档案读取路径无回归护栏；风险低（简单 SELECT），但属 save/read 只有半边的覆盖。

### 64#4（=K-1）`replace_collection` 无并发写测试

- 位置：`store.rs:593`；顺序 revision_conflict 有测（store.rs:1249 + 根 IPC 测试），全文件无 thread::spawn。
- 传递链条：① 前端多命名空间/同命名空间并发提交（inflight 串行化在**前端**，后端无防线测试）→ ② IMMEDIATE 事务 + busy_timeout(10s) 的实际并发行为（谁拿锁、谁 busy、revision 复查是否在锁内）只有实现没有验证 → ③ 未来重构事务范围/锁顺序引入双写或死锁时测试全绿。
- 影响范围：kv 六命名空间（任务/笔记/资料/项目/偏好/草稿）的并发写正确性——这是全站数据写入的底座；对照 review 已有并发 grade 测试（mod.rs:817）证明此模式可测，唯独 store 缺。

### 64#5（=K-2）用户切换「命令在途」窗口无测试

- 位置：`security/guard_tests.rs`（3 个测试全部顺序：先 login 完成再发新命令）；security 域无 thread::spawn。
- 传递链条：① 用户 A 会话命令在途（如长导出）→ ② 同窗口另一处 login_local_user 切到用户 B（写锁替换 store）→ ③ 在途命令恢复执行时读到的 store/principal 归属——该竞态窗口的归属正确性无验证（stop_all 停机路径在并发下同样未验）。
- 影响范围：多用户本机场景的数据隔离底线（A 的写入落进 B 的工作区或反之）。23#7 修过一次同类 fail-open，但当时的回归测试是顺序模拟；真正的并发窗口仍无直接覆盖。风险窄（需同窗口并发操作）但后果是跨用户数据串写。

### 64#6（=K-3）备份导入后 events id 续接语义无断言

- 位置：`backup/transfer.rs:706`（payload 内 eventId remap）；存在性断言在 backup/tests.rs:274。
- 传递链条：① 备份导入对 events 表做 id 重分配（prepare_ids）→ ② 导入后新事件的 AUTOINCREMENT 接续、前端 lastEventId 游标续接（不重不漏不重复消费）与 payload 内嵌 eventId 引用改写**均无断言** → ③ 未来改 id 分配策略（如不再 MAX+1）时，可能出现前端游标回退丢弃事件或插件去重键错位——测试不报警。
- 影响范围：导入备份后的所有实时事件消费者（页面刷新、插件投递去重、outbox 续接承诺）。outbox 常规顺序性有独立测试（store.rs:1302），盲区仅在导入路径与其衔接。

### 64#7（=K-5）`verify_material_media` 拒绝路径零断言

- 位置：`materials/media.rs:161`（verify）与 :128（info 传输前流式校验）；通过路径有测（commands.rs:461）。
- 传递链条：① 媒体原件在盘上被外部工具篡改（同长度字节替换，绕过文件名）→ ② 前端预览流程调用 verify/info 应返回 `media_integrity_failed` 拒绝渲染 → ③ 该错误码全库测试零断言、info 流式校验同样只测通过 → ④ 拒绝逻辑被误改（如比较被跳过）时测试全绿，篡改内容照常进 WebView 渲染。
- 影响范围：媒体预览完整性承诺（46#2 二进制通道的核心安全语义）——防「原件被替换后仍以旧哈希身份播放」。属安全语义盲区而非功能盲区。

## 正向结论

- export 8 格式全部有断言（PDF 解析性/apkg 真实 zip+due 语义/scope 组合）。
- notes/engagement/sharing/maintenance/community 提醒/backup 拒绝路径/review 并发/store outbox 顺序/guard async principal 回归/security 全域——均有 IPC 级或并发级覆盖。
- 测试基建健康：全部回环 TestServer（零真实网络）、sleep 均为轮询+deadline（除 64#12 三处故意延迟）、全局状态 SEARCH_ENDPOINT/TEST_LOCK/DEFER 隔离完备。
- 总评：192 命令中仅 6 个完全无行为级断言（64#1-3 + 三个写盘/重启壳）；缺口集中在并发直接测试（64#4/5）与两个安全拒绝路径（64#6/7）。
