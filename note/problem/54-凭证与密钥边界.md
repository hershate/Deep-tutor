## P3

### 54#1 API Key 校验上限 4096 字节，而 Windows 凭据库上限 2560 字节——1281~4096 字节的 Key 保存必败且报错无指向性

- 位置：后端校验 `desktop/src-tauri/src/backend/providers/mod.rs:458`（`key.len() > 4096` 才拒）；前端同口径 `src/pages/ProviderHub.tsx:390`（`clampToBytes(..., 4096)`）；keyring 实际限制 `keyring-3.6.3/src/windows.rs:223-229`（`password.encode_utf16().count() * 2 > CRED_MAX_CREDENTIAL_BLOB_SIZE` 即 2560 字节 = **1280 个 UTF-16 码元**时返回 `TooLong`）；错误出口 `providers/mod.rs:127-128`（一切 set 失败统一映射「credential_error: 无法写入系统密钥库」）。
- **传递链条**：① 用户粘贴 1300~4096 字节的长令牌（网关 JWT / 超长连接串场景存在）→ ② 前端 clamp 放行、后端 4096 校验放行 → ③ `Entry::set_password` 在 WinCredential::validate_attributes 处返回 `TooLong` → ④ 应用把一切错误折叠成「无法写入系统密钥库」→ ⑤ 用户不知道是长度问题（校验层声称合法、存储层拒绝、文案零指向）。
- **影响范围**：仅超长 Key（>1280 字符）用户；无数据损害、无安全问题。修复：校验上限降到 1200 字符（或捕获 keyring TooLong 单独映射为「密钥过长，系统密钥库上限约 1280 字符」）。另注：keyring 对非 BMP 字符按 UTF-16 代理对计 4 字节，App 的 4096 是 UTF-8 字节口径，两口径本身也不同。

## 正向结论（核对过、无问题）

- **令牌熵与校验**：PAT（dtp_）与分享令牌（dt_）均为 32 字节 CSPRNG（Windows `BCryptGenRandom` 系统首选 RNG，flags=2；random.rs）→ base64url 43 字符 = **256 位熵**；存 SHA-256 哈希、校验为哈希查表——256 位随机令牌无需尝试限速（与密码场景不同），无限速锁定是可接受口径。
- **JWT**（security/mod.rs:590-620）：alg 钉 HS256 + typ 校验；签名常量时间比对（08#5）；exp>now 且 **exp ≤ iat+7 天+60s**（寿命上限绑定，无法自签超长会话）；**iat ≤ now+30s**（时钟偏移容忍合理）；token 长度 ≤4096 防滥用。
- **草稿限额**（store.rs:1132-1146）：对象形态 + 字段白名单（id/title/content/tag/savedAt）+ 整体 ≤1MB + 分字段限额 + IMMEDIATE 事务——完备。
- **keyring 错误面**：读/写/删全部类型化中文错误；删除对 NoEntry 幂等；user1 有旧命名（provider-{id}）回退兼容；12#15 有故障注入测试。
- **PAT 展示边界**：明文仅创建时返回一次，库存 hash+尾 4 字符前缀——符合「明文只显示一次」文案。
