# 21 号 · 接线与类型漂移（P3 × 5）

> 总量结论先行：前端 186 个 invoke 命令（另 9 处 dialog 插件调用）全部在
> `main.rs` generate_handler 注册，缺 0；事件为单通道 `backend://event`
> （backend/commands.rs:22-26），前后端 kind 与载荷字段全对齐，无不一致。
> 以下为仅存的边角项。

## 21#1 `authenticate_access_token` 已注册但前端从未调用

- 位置：注册 `desktop/src-tauri/src/main.rs:139`；定义 `desktop/src-tauri/src/backend/security/commands.rs:78`；全前端 0 引用
- 证据：`security/guard.rs:159` 将其列入免登录白名单，说明设计上是外部/未来
  流程（如外部令牌登录入口）预留；当前 UI 无任何接入，`desktop/src/backend/security.ts`
  也无封装。
- 影响：死暴露命令。IPC 面积大于实际功能面；白名单入口无对应 UI。
- 修复方向：接入 PAT 登录入口，或暂从注册表移除（保留函数）。

## 21#2 `stream_provider_chat_with_tools` 已注册但前端从未调用

- 位置：注册 `desktop/src-tauri/src/main.rs:166`；定义 `desktop/src-tauri/src/backend/providers/commands.rs:107`
- 证据：前端唯一流式封装是无 tools 版 `streamProviderChat`（client.ts:365）；
  Agent 的工具调用流量实际经 `route_provider_chat` 在 Rust 内部直调函数完成。
- 影响：IPC 层死代码；与 21#1 同属注册表瘦身项。
- 修复方向：确认无外部脚本消费后从注册表移除。

## 21#3 `webBackend.fetch` 封装（fetch_webpage）无任何 UI 调用方

- 位置：封装 `desktop/src/backend/web.ts:7`；唯一同域消费方 `PlanGenerator.tsx:193` 只用 `webBackend.import`
- 证据：全前端 grep `webBackend.fetch` 无结果；命令本身已注册且后端实现完整
  （web/mod.rs:21-28）。
- 影响：封装层死代码；若未来接入需同步修 21#5 的类型缺口。
- 修复方向：保留待用或删除封装（命令保留给后端内部 import_webpage 复用通道）。

## 21#4 TS `KnowledgeCitation` 类型声明了后端不存在的 `kind` 字段

- 位置：`desktop/src/backend/knowledge.ts:4-10` vs `desktop/src-tauri/src/backend/knowledge/mod.rs:87-97`
- 证据：TS 为 `KnowledgeCitation = KnowledgeSource & {...}`，继承
  `kind: string`；Rust 结构体字段为 `material_id/title/sha256/quote/char_start/char_end/line`
  （camelCase 序列化），无 kind。
- 影响：无运行时影响（WikiPanel/Library 只读 materialId/quote/line/charStart/charEnd），
  但类型误导后续开发者按 kind 分支。
- 修复方向：KnowledgeCitation 不再继承 KnowledgeSource，显式声明真实字段。

## 21#5 TS `WebPage` 类型缺少 Rust 侧可选字段 `warning`

- 位置：`desktop/src/backend/web.ts:4` vs `desktop/src-tauri/src/backend/web/mod.rs:21-28`
- 证据：Rust `pub warning: Option<String>`（`skip_serializing_if = "Option::is_none"`）；
  TS `{ url; title; text; sha256 }` 无 warning。
- 影响：当前无运行时影响（该命令未被 UI 调用，见 21#3）；未来接入时抓取降级
  警告会丢失展示。
- 修复方向：补 `warning?: string`。

## 附：命令/事件对照方法与正面对照点

- 命令名逐字 diff（前端 186 字面量 vs 注册表 188 项）通过；无动态命令名拼装。
- 参数键名抽查通过样例：`save_project_iteration_note` `{input:{versionId,content}}`
  ↔ `IterationNoteInput{version_id,content}`；`assign_task_date` `{taskId,dateValue}`
  ↔ `task_id,date_value`；`submit_practice_answer` `{setId,questionId,answer}`。
- 事件载荷抽查通过样例：`provider.chat_delta` `{requestId,text,reasoning:bool}`
  （providers/mod.rs:1159-1160 ↔ useAgent.ts:140 `=== true`）；
  `agent.run_started/step_started/message_saved` 均含 `{sessionId,runId,requestId}`；
  `agent.artifact_promoted` 含 `{planId,stageId}`；审批 payload 与 AgentCenter.tsx:33
  读取一致。
- 返回形状：所有跨 IPC struct 均带 `#[serde(rename_all = "camelCase")]` 或显式
  rename；缺 rename_all 且 Serialize 的仅 BackendError（单词字段）与内部输入
  结构，无 snake_case 泄漏到前端。
