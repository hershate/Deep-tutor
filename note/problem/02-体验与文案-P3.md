# P3 体验与文案问题（14 项）

不阻断核心使用，但存在刷新缺口、状态残留、契约残留或文案与实际行为不符。

## 事件与刷新

### 1. 知识地图不监听练习/复习证据事件，后台评分完成后掌握度不刷新
- 前端：`desktop/src/pages/KnowledgeMap.tsx:67-76` 仅监听 `plan.adopted` 与 `study.progress_changed`。
- 后端：`practice/mod.rs:1130-1160`、`practice/subjective.rs:474-519`、`review/mod.rs:461-470`
  写入 `learning_node_evidence` 只发 `practice.*`/`review.graded`；掌握度由
  `learning/knowledge.rs:43-51` 从该表计算。
- 影响：主观题评分、中断恢复等后台任务在停留知识地图页期间完成时，掌握度保持旧值，
  需离开再进入页面才更新。

### 2. `agent.approval_expired` 事件无处理路径，过期审批卡片残留
- 前端：`desktop/src/backend/useAgent.ts:119-130`——该事件 payload 无 runId/sessionId，
  落入“不刷新”分支。
- 后端：`agent/tools.rs:780-790`——payload 仅 `{approvalId, artifactId}`，审批置 expired；
  `agent/mod.rs:397` 刷新后才会过滤非 pending 卡片。
- 影响：产物超 24 小时过期后，用户点“批准”收到报错，但卡片与产物状态停留在界面上，
  直到切换会话或其他事件触发刷新。

### 3. `agent.message_saved` 无条件清空流式区，跨会话互相干扰
- 前端：`desktop/src/backend/useAgent.ts:128` 未校验事件属于当前会话即清空 stream。
- 后端：`agent/mod.rs:577-587` 不同会话可并发运行，各自保存消息都发该事件。
- 影响：会话 A 保存消息会清掉会话 B 正在直播的部分输出，B 的流从中断处重新累积。

### 4. `maintenance.*` 事件无任何前端处理，也不在插件订阅白名单
- 前端：`desktop/src/components/MaintenancePanel.tsx:15-47` 只用命令返回值，无事件监听；
  全前端无 `'maintenance.'` 匹配。
- 后端：`maintenance/mod.rs:357-384` 发出 `maintenance.scan_completed/cleanup_completed/
  vacuum_completed/maintenance.failed` 并写 outbox；`plugins/mod.rs:294-309` 插件白名单
  14 个命名空间不含 maintenance。
- 影响：事件仅落库，UI 与插件均不消费；信息性缺口，无直接故障。

### 5. 每条 `sync.completed` 都触发一次远端版本列举请求（弹窗未开也执行）
- 前端：`desktop/src/components/SyncPanel.tsx:35` 无条件 `loadVersions()`；
  `SyncPanel.tsx:27-29` 失败写入面板级错误。
- 后端：`sync/mod.rs:593-605` 所有任务终态（含连接检测、调度器自动上传）均发该事件；
  `sync/versions.rs:147-165` 列举发起真实 S3/WebDAV 请求。
- 影响：任何同步完成都额外打一次远端请求；远端不支持目录列举时弹出与当前操作无关的报错。

### 6. `Reports` 页监听 `learning.` 前缀，后端不存在任何 `learning.*` 事件（死前缀）
- 前端：`desktop/src/pages/Reports.tsx:43` 监听数组含 `'learning.'`。
- 后端：全部事件 kind 中无 `learning.` 开头者（讲义为 `lecture.*`、方案为 `plan.*`）。
- 影响：当前无用户可见后果（刷新已由 `practice.`/`review.`/`focus.` 前缀覆盖），
  属无效契约残留。

## 类型与入口

### 7. `ProviderRequest` TS 类型缺 `toolCalls` 字段（serde/TS 漂移）
- 前端：`desktop/src/backend/client.ts:219-233` 无 `toolCalls`。
- 后端：`providers/mod.rs:807-824` 序列化 `toolCalls: Vec<ToolCall>` 随命令返回。
- 影响：当前路由调用不传 tools，字段恒为 `[]`；属类型漂移，未来接入工具调用时 TS 侧不可见。

### 8. `streamProviderChat` 有前端包装但无调用方，且绕过用量预算防线
- 前端：`desktop/src/backend/client.ts:361` 定义，全前端无调用（ProviderHub 实际走
  `routeProviderChat`）。
- 后端：`providers/commands.rs:80-104` 命令存在；`providers/mod.rs:1026-1045` 直连路径
  全链路无 `ensure_budget`（对比 `routing.rs:911` 路由路径有预算检查）。
- 影响：当前无用户可见后果；与 `UsagePanel.tsx:84`“达到预算后不再发起新请求”文案不符的旁路入口。

### 9. `logout_local_user` 有完整实现但无任何 UI 入口
- 前端：`desktop/src/backend/security.ts:30` 定义 `logout`，全前端无调用；
  `SecurityPanel.tsx` 无退出按钮，仅展示“会话有效期至…”（:93）。
- 后端：`security/commands.rs:22-28`、`security/mod.rs:890-909` 完整实现撤销会话、删密钥库、
  发 `security.session_revoked`。
- 影响：用户无法主动结束 7 天会话；面板宣称“撤销由后端验证”但用户侧无撤销当前会话的操作。

## 文案与行为

### 10. 登录门控页持续弹出原始认证错误 toast
- 前端：`desktop/src/backend/useBackendState.ts:78-83` 认证错误时 `setReady(true)`；
  `App.tsx:100-133` 通知/仪表盘 effect 仅以 `ready` 为门控，失败经 `reportBackendError`
  → toast（`App.tsx:81-85`），门控页也渲染 toast（`App.tsx:260-262`）。
- 后端：`security/guard.rs:156-188` 非白名单命令每条都过会话校验；
  `security/mod.rs:590-599` 会话过期返回 `session_expired`。
- 影响：会话过期进入“选择本地用户”页后，进入时及每 30 秒轮询各弹一条
  `session_expired：…` 原始错误 toast，与门控页文案重复。

### 11. “重试初始化”按钮：ready 时整页 reload、pending 时静默无反馈
- 前端：`desktop/src/components/DataDirectoryPanel.tsx:55-60`——`next.ready` 即
  `window.location.reload()`；无 error 无 ready（pending）时不设任何提示；按钮在设置页常驻（:82）。
- 后端：`startup.rs:431-439`——ready 或 pending 时直接返回 overview，不做任何动作。
- 影响：正常运行时点击“重试初始化”实际效果是整页刷新，界面状态丢失；启动失败已存新目录后
  点击则毫无反应，与按钮文案不符。

### 12. 局部重生成次数前端硬编码 3，后端为可配置（默认 2，范围 1–3）
- 前端：`desktop/src/pages/PlanGenerator.tsx:271`——`plan.version >= 3` 禁用并显示
  “剩余 {3 - version} 次”，regenerate 调用不携带 limit。
- 后端：`learning/actions.rs:147-153` 上限取自用量设置 `regeneration_limit`
  （`providers/usage.rs:23-31` 默认 2，`:171` 允许 1..=3）。
- 影响：设为 1 时 UI 显示“剩余 2 次”且 v2 按钮可点但后端必拒；设为 3 时 v3 被 UI 提前禁用，
  损失一次后端允许的重生成。默认 2 时数值恰好重合，不可见。

### 13. 报告页三处文案与实际数据来源/产物不符
- 掌握证据：`desktop/src/pages/Reports.tsx:80` 称“掌握估计仅来自练习、复习与项目证据”，
  但 `projects/mod.rs` 全流程不写 `learning_node_evidence`（仅 practice/exams/subjective/review 写入，
  `reports/mod.rs:679-696` 也只聚合这些来源）——项目证据永不出现。
- 周报：`desktop/src/pages/Settings.tsx:92` 称“每周日生成一份可编辑的学习报告”，
  后端 `engagement/mod.rs:610-631` 周日仅插入一条通知，不生成任何报告实体；报告仍需进页现算。
- 影响：文案夸大证据来源与产物形态，用户找不到承诺的“项目证据明细”与“可编辑周报”。

### 14. 用量指标文案未标明“今日”范围
- 前端：`desktop/src/components/UsagePanel.tsx:80`——“已上报输入/输出 tokens、取消/异常已计价”
  三格未注明今日（仅首格写“今日已计价成本”）。
- 后端：`providers/usage.rs:351-383` 全部字段仅统计 `today_entries`。
- 影响：用户可能把当天 tokens/成本误解为累计值。
