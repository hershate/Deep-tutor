# 88 号：打包产物与依赖供应链问题集（第三十一轮·横切审计）

审计基线：`f0d7e54a`，产物 dist/DeepTutor_1.1.3_x64-setup.exe。方法：Bandizip 实际解包 NSIS 安装包核对内容（临时目录已彻底清理）、PowerShell 读 exe 版本资源、npm audit --omit=dev 实跑、Cargo.lock 逐 crate 凭知识核查（不确定处标注）。共 8 条：P3×3、信息×5。

## P3

### 88#1 NOTICE 与 LICENSE-REASONIX 未随安装包分发，与自身声明不符

- 位置：仓库根 `NOTICE:3`（「分发本仓库或构建产物时，必须同时保留本文件及适用的许可全文」）↔ `desktop/src-tauri/tauri.conf.json:37-39`（bundle.resources 仅收 `licenses/*`）。
- 传递链条：①collect-licenses.mjs 只收集 Cargo/npm 依赖许可；②解包实测顶层仅 $PLUGINSDIR、deep-tutor-workspace.exe、licenses/、uninstall.exe——NOTICE、根 LICENSE、LICENSE-REASONIX 均不在包内，licenses/ 中亦无 reasonix 条目；③安装包作为唯一交付物单独流通时，上游 Reasonix（MIT）的版权与许可声明缺失，与 NOTICE 自设义务直接矛盾。
- 影响范围：分发合规缺口；与 84#1（README 许可表述错误）叠加后披露链混乱。
- 修复方向：collect-licenses.mjs 或 bundle.resources 一并收录 NOTICE / LICENSE / LICENSE-REASONIX 到包内。

### 88#2 38 个 Rust 依赖许可文本缺失，仅有「以上游仓库为准」的兜底声明

- 位置：包内 `licenses/COLLECTED.md`（「已收录 618 个依赖……另有 38 个 Rust 依赖在本地源码与 .crate 归档中均未找到许可文件，许可以 Cargo.lock 记录的上游仓库为准」）。
- 传递链条：①部分 crate 归档确实不含许可文件；②MIT/Apache-2.0 的分发义务要求随分发附许可文本；③38 个缺口构成批量合规缺口，且未列名单无法事后核验。
- 影响范围：安装包单独流通场景下的批量许可合规缺口；因未附名单，事后无法核验哪些依赖缺文本、适用什么许可。
- 修复方向：collect-licenses.mjs 输出这 38 个包的名单与适用许可类型（可按 crate 元数据 license 字段推断），至少把名单写进 COLLECTED.md 供核验；有条件的从上游 tag 补齐文本。

### 88#3 根 README 直连构建命令缺 `-- -- --locked`，与自称「同一口径」不符

- 位置：`README.md:35-41`（直连路径 `npm run tauri build` 无参数，:35 却称「两条路径同一口径」）↔ Makefile build 目标与 desktop/README.md:35 均带 `-- -- --locked`。
- 传递链条：①按根 README 操作；②Cargo.lock 与 manifest 不匹配时静默更新锁文件而非失败；③可能带漂移依赖出包。
- 影响范围：按根 README 构建的操作路径；lock 漂移出的包可能未经 make check 的锁定验证链，与 Makefile/CI 路径产物不一致。
- 修复方向：根 README:40 补 `-- -- --locked`。

## 信息

### 88#4 WebView2 为在线下载引导模式，全新离线机器安装失败

- 位置：`desktop/src-tauri/tauri.conf.json`（未配置 `webviewInstallMode`，Tauri 2 默认 downloadBootstrapper）。
- 传递链条：①安装包构建时未内嵌 WebView2 引导程序（解包实测 $PLUGINSDIR 无 MicrosoftEdgeWebview2Setup.exe）→ ②目标机无 WebView2 运行时且无网络时，安装器在线下载引导失败 → ③安装中断。
- 影响范围：全新离线机器；Win10/11 绝大多数已预装 Evergreen WebView2，实际影响面小。产品含本地学习场景，若需覆盖离线部署需评估。
- 修复方向：改 `embedBootstrapper`（安装包增重数 MB），或维持现状并在 README 标注联网要求。

### 88#5 主程序 LegalCopyright 元数据为空

- 位置：`desktop/src-tauri/tauri.conf.json`（未设 `bundle.copyright`）；实测解包主程序 VersionInfo 的 LegalCopyright 为空。
- 传递链条：①tauri.conf.json 无 copyright 字段 → ②构建时 exe 版本资源的 LegalCopyright 留空 → ③用户在文件属性/版权页看不到任何版权声明——与 88#1 的许可披露缺口同方向。
- 影响范围：产物元数据缺失；企业环境审计软件可能标记无版权二进制。
- 修复方向：补 `bundle.copyright` 一行配置（如「Copyright © 2026 DeepTutor Contributors」——具体署名由用户定）。

### 88#6 Cargo 传递依赖多版本冗余（非功能重复）

- 位置：Cargo.lock——base64 0.21.7/0.22.1/0.23.1 三版、bitflags 1.3.2/2.13.2、schemars 0.8.22/0.9.0/1.2.3、miniz_oxide 双三版共存。
- 传递链条：①不同直接依赖各自声明同一库的不同 semver 区间 → ②Cargo 允许多版本共存、各用各的 → ③编译时间与二进制体积增加；无符号冲突或功能重复。
- 影响范围：构建效率与体积；无运行时影响，不值得强行收敛（收敛需改上游依赖声明）。
- 修复方向：知悉即可；升级依赖时顺带观察是否自然收敛。

### 88#7 lock 中 openssl 系列版本偏旧，但不进入 Windows 产物

- 位置：Cargo.lock 含 openssl 0.10.66 / openssl-sys 0.9.103（2024-08）。
- 传递链条：①reqwest 配置走 native-tls → ②Windows target 上解析到 schannel（lock 中 schannel 0.1.23 为证），openssl 链仅在其他 target 编译 → ③本 NSIS 安装包不含 openssl 代码，版本新旧无影响。
- 影响范围：当前交付物零影响；未来若出 Linux/macOS 版需复查 openssl 版本是否有未修复 CVE（当前无已知记录，不完全确定）。
- 修复方向：跨平台计划启动时复查；现在不动。

### 88#8 关键 crate 供应链快照

- 位置：Cargo.lock——tauri 2.12.5 / tauri-runtime-wry 2.12.3 / wry 0.57.1、reqwest 0.12.28、rusqlite 0.38.0、serde 1.0.229 / serde_json 1.0.154、hyper 1.12.0 / hyper-util 0.1.21、idna 1.1.0、zip 2.6.1、lopdf 0.35、quick-xml 0.42。

- 影响范围：供应链观察条目；无当前行动项。vite 锁 5.4.21（≥5.4.15 修复线，含 2025 年四个 CVE 修复）且仅构建期使用不入产物。
