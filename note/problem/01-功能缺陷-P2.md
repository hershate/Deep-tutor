# P2 功能缺陷（9 项）

功能不可用、或实际行为与界面承诺相反。均经双侧代码复核确认。
1–3 为首轮域级审计发现；4–9 为第二轮交互闭环审计发现。

## 1. 同步"清除已保存凭据"开关在 S3 与 WebDAV Basic/Bearer 下必然失败，旧凭据被原样回写

- 前端：`desktop/src/components/SyncPanel.tsx:52`——勾选 `clearCredentials` 后把
  `password/accessKey/secretKey` 置空字符串提交；`SyncPanel.tsx:144` 开关文案
  "保存后删除系统密钥库中对应的同步凭据"。
- 后端：`desktop/src-tauri/src/backend/sync/mod.rs:350-367`——S3 分支先按空串删除
  access/secret 两把 key，随后第 367 行 `credentials(service, &config)?` 立即强制要求
  两把 key 均存在（缺失返回 `sync_credentials_missing`）；
  `sync/mod.rs:369-379`——WebDAV 非 `none` 认证同样在删除后强制校验；
  `sync/mod.rs:394-397`——失败路径 `restore_credentials` 把刚删除的旧凭据恢复回密钥库。
- 影响：S3 档案勾选"清除凭据"后保存必报"S3 Access Key 未配置"，WebDAV Basic/Bearer
  报"WebDAV 凭据未配置"，且密钥库旧凭据被恢复、配置未保存——清除功能完全不可用，
  与开关文案相反。仅 WebDAV + 无认证组合不受影响。

## 2. 路由 failover 第二次切换起前端丢失上游请求 id，Agent 直播输出冻结

- 后端：`desktop/src-tauri/src/backend/providers/routing.rs:994-1010`——候选循环中
  第 N 次尝试的上游 id 为 `{request_id}-f{N}`（仅第 0 次等于逻辑 id）；
  `providers/mod.rs:1107-1115`——`provider.chat_delta` 携带的是上游 id，
  而域记录（plan 步骤、practice、lecture、wiki）保存的是逻辑 id。
- 前端：`desktop/src/backend/useAgent.ts:102`——`provider.route_attempt` 仅当
  `payload.requestId === liveRequestRef.current` 时才切换；第一次 failover 后
  `liveRequestRef.current` 已被改为 `-f1` 上游 id，而后续 attempt 事件的 `payload.requestId`
  仍是路由级逻辑 id，条件永假；`useAgent.ts:111` 随后的 `chat_delta`（`-f2` 等）全部被过滤。
- 同根因的更广缺口：除 `desktop/src/pages/StudyRoom.tsx:111-119` 建立了
  route_attempt→upstreamRequestId 映射外，`PlanGenerator.tsx:111-118`、`Practice.tsx:58-61`、
  `components/SubjectivePractice.tsx:66-71`、`components/ExamWorkspace.tsx:60-75`、
  `components/WikiPanel.tsx:38-53` 均直接用逻辑 id 匹配 delta。
- 影响：路由模式配置 failover 且首个供应商失败后，Agent 及上述页面的流式输出停止刷新，
  直到该步终态事件触发重拉才恢复；direct 模式（默认）不受影响。

## 3. 社区预约提醒链路为死代码：UI 承诺的"开始前 15 分钟提醒"永不送达

- 前端：`desktop/src/backend/community.ts:53` 定义 `claimDueReminders`，全前端无任何调用方
  （无按钮、无定时器、无 useEffect）；`desktop/src/pages/Community.tsx:123/127` 文案
  "按后端计算的时间收到应用内提醒""预约后由后端保存开始前 15 分钟的应用内提醒"。
- 后端：`desktop/src-tauri/src/backend/community/mod.rs:832-878`——`claim_due_reminders`
  是唯一将 `delivered_at` 置位并发出 `community.reminder_due`（:861-863）的路径；
  除命令注册（`main.rs:249`）外无任何调用，也无后台定时器。唯一补偿是
  `engagement/mod.rs:586-609` 在通知中心为 24 小时内开始的预约插入一条"即将开始"通知。
- 影响：预约提醒功能整体不可达——`claim_community_reminders` 命令、`community.reminder_due`
  事件、`community_reminders` 表的投递字段全部成为死代码；用户按文案预期收不到 15 分钟前提醒。

## 4. 专注会话暂停后"结束并保存/取消重置"后端不落库，幽灵 paused 会话永久阻塞新专注

- 前端：`desktop/src/App.tsx:301`——"结束并保存"按钮对 `['running','paused']` 均启用；
  `App.tsx:174-184` finishFocus 无异常时直接提示"已完成 X 秒真实专注"；
  `App.tsx:185-189` resetFocus 在 finishFocus 返回非空后清空本地会话状态。
- 后端：`desktop/src-tauri/src/backend/reports/mod.rs:361`——finish_focus 的 UPDATE 带
  `AND status = 'running'`，对 paused 会话匹配 0 行且未检查受影响行数；
  `:362-369` 照常提交、发 `focus.completed/cancelled` 事件并返回仍是 paused 的行；
  `reports/mod.rs:318-328` start_focus 对任何 running/paused 残留返回 `focus_active`；
  测试 `reports/tests.rs:112-120` 只覆盖 pause→resume→complete，未测 paused 直接 complete。
- 影响：暂停后点"结束并保存"或重置：界面谎称已保存，数据库仍为 paused、时长丢失；
  前端清空后幽灵会话仍在，之后所有新专注报 `focus_active`，必须重开弹层"继续专注"再结束才能解锁。

## 5. 全量备份导出/导入后，24 小时自动同步调度器被停止且永不恢复

- 前端：`desktop/src/components/BackupPanel.tsx:23`（导出）、`:41`（确认追加导入）为常规入口；
  `SyncPanel.tsx:143` 文案承诺"每 24 小时自动同步……由原生调度器检查到期任务"。
- 后端：`desktop/src-tauri/src/backend/backup/commands.rs:26`（导出前 `sync::stop`）、
  `:47-52`（导入前同样 stop），两处均无 `start_scheduler`；`sync/mod.rs:819` stop() 内
  终止调度线程。恢复点仅 5 处：重启（startup.rs:384）、重存同步配置（sync/mod.rs:391）、
  运维清理/整理（maintenance/commands.rs:51/68）、重新登录（security/guard.rs:85）。
- 影响：开启自动同步的用户每次导出或导入备份后，自动同步静默失效直到上述事件之一发生；
  无任何提示。

## 6. 同步配置从 S3 切换到 WebDAV 后 region/bucket 残留，保存必败且错误文案误导

- 前端：`desktop/src/components/SyncPanel.tsx:127`——切换"同步方式"只更新 kind/authKind，
  不清空 region/bucket；`:42` 加载已存 S3 配置时两字段合入表单；
  `:131-134` 两输入框仅在 `kind === 's3'` 时渲染（WebDAV 下不可见、不可改）。
- 后端：`desktop/src-tauri/src/backend/sync/mod.rs:219-223`——WebDAV 分支要求 region 与
  bucket 均为空，否则报 `invalid_webdav_config：WebDAV 认证方式无效`。
- 影响：先填（或加载）S3 的 region/bucket 再切 WebDAV 保存必然失败；错误指向"认证方式"
  而真实原因是两个已被隐藏的字段，用户只能切回 S3 清空再切回 WebDAV。

## 8. 报告页"采纳建议"固定按 8 周窗口校验，非默认周期视图勾选必被拒且按提示刷新无效

- 前端：`desktop/src/pages/Reports.tsx:62`——`adopt(ids)` 不携带当前 `period`；
  `desktop/src/backend/reports.ts:57`——命令参数仅 `ids`。
- 后端：`desktop/src-tauri/src/backend/reports/mod.rs:928`——`adopt_recommendations` 用
  `get_report(state, None)`（固定回落 8 周，:812-814）重算建议；`:936-941` 所选 id 不在

- 前端：`desktop/src/pages/Plan.tsx:172`、`PlanGenerator.tsx:274`——`onPreview` 执行
  `window.history.replaceState(null, '', localShareUrl(token))` 后导航到 shared 页；

  URL 残留 `?share=` 令牌。
