## P3

### 131#1 dev-smoke cleanup 无条件强杀占用 43198 的任意进程——端口撞车时误杀无关程序

- 位置：`scripts/dev-smoke.sh:11-16`（`cleanup() { for pid in $(netstat -ano | grep ":$PORT" | grep LISTENING | awk '{print $5}' | sort -u); do taskkill //F //PID "$pid" ...`，116#3 建立）。
- 传递链条：①开发机任意本地服务（另一实例的 dev server、代理工具、任意监听程序）恰占 43198；②dev-smoke 以 strictPort 启动 vite 绑定失败退出（launcher 死），curl 轮询的是**占用者**——返回 200 则冒烟假性通过（见 131#2），不返回则 20s 后冒烟失败；③无论结果如何，trap cleanup 对 netstat 找到的监听 PID 无条件 `taskkill //F`——按端口找 PID「精确」但完全不校验进程归属，杀掉的是从未参与本次冒烟的无害进程；④116#3 的设计目标「不按进程名广杀 node」只避免了名字误杀，引入了端口误杀。
- 影响范围：受影响=端口 43198 被占时跑 `make check`/`make dev-smoke` 的开发者（本地服务被强杀，可能丢数据——如未保存的代理会话）；不受影响=端口空闲的常规路径（杀的就是自己启动的 vite）；损害性质=开发机侧破坏性副作用，随门禁高频触发。
- 修复方向：启动前探测端口空闲（占线即报错退出，不启动、不杀）；cleanup 改为只终止 $launcher 进程树（Windows 可用 `taskkill //F //T //PID` 于 npm 包装进程）或让 vite 收到自身退出信号正常退出。

## 信息

### 131#2 dev-smoke 通过判据仅「GET / 返回 200」——占用者应答即假绿，不校验内容归属

- 位置：`scripts/dev-smoke.sh:18-24`（`curl -fsS http://127.0.0.1:$PORT/` 成功即 echo 通过）。vite 因 strictPort 起不来时，只要 43198 的既有占用者对 GET / 返回 200，冒烟即「通过」——111#2 要防的「dev 工作流坏了但门禁全绿」经此通道重现；判据也不含任何「响应确为本应用 index」的断言。
- 修复方向：断言响应体含应用标记（如 `<div id="root">` 或 vite client 脚本引用）；配合 131#1 的启动前端口探测后本条假绿通道自然关闭。

### 131#3 `make build` 无门禁前置——坏树可直接产出安装包

- 位置：`Makefile:22-26`（`build:` 目标无任何依赖；lint/audit/测试全部只挂在 `check: lint test dev-smoke`）。`make build` 在未过门禁的树上照常打包分发（110#1 特意加的 audit 等门禁对 build 路径零约束）。
- 修复方向：`build: check` 或在 build 前重跑 lint+audit（测试是否前置按耗时权衡并在 Makefile 注释说明）。

### 131#4 package.json 的 allowScripts 字段无任何消费者——死配置

- 位置：`desktop/package.json:39-41`（`"allowScripts": { "esbuild@0.25.12": true }`）。非 npm 标准字段，仅 lavamoat/allow-scripts 类工具读取——全仓 grep 无消费者（仓库未装此类工具）。意图管控 esbuild 安装脚本的配置实为惰性字段，实际是否执行由 npm 默认行为决定。
- 修复方向：删除字段；若确要管控 postinstall，引入真正读取它的机制或在文档说明保留原因。

### 131#5 licenses/README.md 写 `licenses/**` 通配，tauri.conf.json 实为 `licenses/*`

- 位置：`desktop/src-tauri/licenses/README.md:5`（「`bundle.resources` 的 `licenses/**` 通配」）vs `desktop/src-tauri/tauri.conf.json:38-40`（`"resources": ["licenses/*"]`）。当前收录全部平铺单层，`*` 够用，README 描述与配置不符；若未来收录出现子目录（工具改造），`*` 会静默漏收而 README 读者以为 `**` 兜底。
- 修复方向：README 改 `licenses/*`，或配置改 `licenses/**` 与 README 对齐。

### 131#6 COLLECTED.md 指引措辞不通且指向不随包分发的文件

- 位置：`scripts/collect-licenses.mjs:293`（生成文案「完整依赖版本清单见安装包同仓库的 Cargo.lock 与 package-lock.json」）。①「安装包同仓库的」语序不通（疑为「与安装包同一仓库的」）；②`resources` 只有 `licenses/*`（tauri.conf.json:38-40），lockfile 并不随安装包分发——包内读者按指引在本机找不到所指文件。
- 修复方向：改为「见构建本安装包所用仓库的 Cargo.lock 与 package-lock.json」；或将两份 lockfile 一并加入 resources 使指引在包内可达。

### 131#7 嵌套许可输出名丢弃父身份与 scope——同名嵌套包互覆（当前树实测未触发）

- 位置：`scripts/collect-licenses.mjs:159/:169`（嵌套包输出名 `nested_${basename(dir)}`）。①丢父身份：pkgA/node_modules/x 与 pkgB/node_modules/x 输出同名互覆；②丢 scope：嵌套 @scope/pkg 只剩 pkg 名，与另一 scope 同名包互覆。84#2 只修了「顶层 vs 嵌套」一类。主审实测当前 desktop/node_modules 无同名嵌套包（按脚本同款展开规则扫描）——依赖树变化时可触发，无门禁防护。
- 修复方向：嵌套输出名携带父路径（如 `nested_${parent}__${basename}`）；可在脚本内对输出名冲突做去重后缀。

### 131#8 katex override 强制版本超出 rehype-katex 声明范围，@types/katex 与运行时偏差

- 位置：`desktop/package.json:16/:34`（dependencies 与 overrides 均 `katex: ^0.19.1`）vs lockfile `node_modules/rehype-katex` 声明 `katex: ^0.16.0`（7.0.1）。override 压制了 npm 的范围告警装出 0.19.1；rehype-katex 运行时依赖的 `@types/katex` 停在 0.16.8，类型描述与运行时 0.19.1 偏差。110#7 已记录为有意决策并给出退出条件（rehype-katex 发布声明支持 katex ^0.19 的版本后移除 override）。
- 修复方向：跟进 rehype-katex 上游；满足退出条件时按 110#7 移除 override 并同步删 AGENTS.md 记录。

## 待核

### 131#9 dev-smoke 在非 Windows 下 cleanup 失效、vite 成孤儿（条件性）

- 位置：`scripts/dev-smoke.sh:12-15`。netstat 列序/PID 语义（`-ano` 的 $5=PID）与 taskkill 均为 Windows 形态；非 Windows 下 PID 提取落空、taskkill 不存在 → 监听者不会被杀，仅 `kill $launcher` 终止 npm 包装进程，vite 子进程存活继续占用 43198。本仓库开发与 CI 均 Windows（winlibs 工具链、CI windows-latest）——仅当有人在 WSL/Linux/macOS 跑 `make check` 时触发。待核：若引入非 Windows 开发/CI 环境需先补 `pgrep -P`/进程组终止逻辑。
