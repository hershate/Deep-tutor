## P3

### 131#1 dev-smoke cleanup 无条件强杀占用 43198 的任意进程——端口撞车时误杀无关程序

- 位置：`scripts/dev-smoke.sh:11-16`（`cleanup() { for pid in $(netstat -ano | grep ":$PORT" | grep LISTENING | awk '{print $5}' | sort -u); do taskkill //F //PID "$pid" ...`，116#3 建立）。
- 传递链条：①开发机任意本地服务（另一实例的 dev server、代理工具、任意监听程序）恰占 43198；②dev-smoke 以 strictPort 启动 vite 绑定失败退出（launcher 死），curl 轮询的是**占用者**——返回 200 则冒烟假性通过（见 131#2），不返回则 20s 后冒烟失败；③无论结果如何，trap cleanup 对 netstat 找到的监听 PID 无条件 `taskkill //F`——按端口找 PID「精确」但完全不校验进程归属，杀掉的是从未参与本次冒烟的无害进程；④116#3 的设计目标「不按进程名广杀 node」只避免了名字误杀，引入了端口误杀。
- 影响范围：受影响=端口 43198 被占时跑 `make check`/`make dev-smoke` 的开发者（本地服务被强杀，可能丢数据——如未保存的代理会话）；不受影响=端口空闲的常规路径（杀的就是自己启动的 vite）；损害性质=开发机侧破坏性副作用，随门禁高频触发。
- 修复方向：启动前探测端口空闲（占线即报错退出，不启动、不杀）；cleanup 改为只终止 $launcher 进程树（Windows 可用 `taskkill //F //T //PID` 于 npm 包装进程）或让 vite 收到自身退出信号正常退出。

### 131#2 dev-smoke 通过判据仅「GET / 返回 200」——占用者应答即假绿，不校验内容归属

- 位置：`scripts/dev-smoke.sh:18-24`（`curl -fsS http://127.0.0.1:$PORT/` 成功即 echo 通过）。
- 传递链条：①vite 因 strictPort 端口被占启动失败退出（launcher 死）；②43198 的既有占用者（任意本地服务）对 GET / 返回 200；③curl 单判据满足——冒烟输出「通过」而 vite 从未运行；④111#2 要防的「dev 工作流坏了但门禁全绿」经此通道重现；判据也不含「响应确为本应用 index」的任何断言。
- 影响范围：受影响=43198 被占且占用者返回 200 的冒烟运行（假绿，且占用者随后被 131#1 强杀）；不受影响=端口空闲的常规路径；损害性质=门禁假绿通道。
- 修复方向：断言响应体含应用标记（如 `<div id="root">` 或 vite client 脚本引用）；配合 131#1 的启动前端口探测后本条假绿通道自然关闭。

### 131#3 `make build` 无门禁前置——坏树可直接产出安装包

- 位置：`Makefile:22-26`（`build:` 目标无任何依赖；lint/audit/测试全部只挂在 `check: lint test dev-smoke`）。
- 传递链条：①`build:` 目标无依赖；②坏树（fmt 不过/audit 有洞/测试红）上跑 `make build`；③`npm run tauri build` 照常产出安装包——110#1 特意加的 audit 等门禁对 build 路径零约束；④带病安装包可被直接分发。
- 影响范围：受影响=跳过 check 直接 build 的发布流程（人工疏漏时无护栏）；不受影响=走 make check 的常规门禁路径；损害性质=流程约束缺位，非自动触发。
- 修复方向：`build: check` 或在 build 前重跑 lint+audit（测试是否前置按耗时权衡并在 Makefile 注释说明）。

### 131#4 package.json 的 allowScripts 字段无任何消费者——死配置

- 位置：`desktop/package.json:39-41`（`"allowScripts": { "esbuild@0.25.12": true }`）。
- 传递链条：①package.json 写 allowScripts 白名单放行 esbuild 安装脚本；②该字段非 npm 标准语义，仅 lavamoat/allow-scripts 类工具读取——全仓 grep 无消费者（未装此类工具）；③字段永不生效，esbuild postinstall 是否执行由 npm 默认行为决定；④维护者以为安装脚本已被管控——实际防护为零。
- 影响范围：受影响=以为该字段管控了安装脚本的维护者（认知误导）；不受影响=实际安装行为（npm 默认）；损害性质=死配置误导。
- 修复方向：删除字段；若确要管控 postinstall，引入真正读取它的机制或在文档说明保留原因。

### 131#5 licenses/README.md 写 `licenses/**` 通配，tauri.conf.json 实为 `licenses/*`

- 位置：`desktop/src-tauri/licenses/README.md:5`（「`bundle.resources` 的 `licenses/**` 通配」）vs `desktop/src-tauri/tauri.conf.json:38-40`（`"resources": ["licenses/*"]`）。
- 传递链条：①README 声称打包用 `**` 递归通配；②配置实为 `*` 单层——当前收录全部平铺单层、功能等价；③读者以为子目录内容也会随包分发；④未来收录逻辑出现子目录（工具改造）时 `*` 静默漏收，README 读者不会起疑。
- 影响范围：受影响=依赖 README 描述判断打包范围的维护者与未来子目录场景的许可分发完整性；不受影响=当前平铺布局的实际打包结果；损害性质=文档与配置不符+潜伏漏收。
- 修复方向：README 改 `licenses/*`，或配置改 `licenses/**` 与 README 对齐。

### 131#6 COLLECTED.md 指引措辞不通且指向不随包分发的文件

- 位置：`scripts/collect-licenses.mjs:293`（生成文案「完整依赖版本清单见安装包同仓库的 Cargo.lock 与 package-lock.json」）。
- 传递链条：①COLLECTED.md 随安装包分发，指引读者去看「安装包同仓库的」两份 lockfile；②`resources` 只有 `licenses/*`（tauri.conf.json:38-40）——lockfile 并不随包分发；③包内读者（终端用户/合规审阅者）按指引在本机找文件必然落空；④「安装包同仓库的」语序也不通（疑为「与安装包同一仓库的」）。
- 影响范围：受影响=安装包内阅读 COLLECTED.md 的终端用户与审阅者（指引不可达）；不受影响=仓库内构建者（本就有 lockfile）；损害性质=指引失效+措辞缺陷，属许可披露链的体验缺口。
- 修复方向：改为「见构建本安装包所用仓库的 Cargo.lock 与 package-lock.json」；或将两份 lockfile 一并加入 resources 使指引在包内可达。

### 131#7 嵌套许可输出名丢弃父身份与 scope——同名嵌套包互覆（当前树实测未触发）

- 位置：`scripts/collect-licenses.mjs:159/:169`（嵌套包输出名 `nested_${basename(dir)}`）。
- 传递链条：①嵌套包输出名只取叶子名——丢弃父包身份（pkgA/node_modules/x 与 pkgB/node_modules/x 同名）与 scope（嵌套 @scope/pkg 只剩 pkg）；②依赖树出现上述任一同名形态；③二者输出 `npm-nested_x-LICENSE` 同名——后写者静默覆盖先写者；④安装包内许可文件实际缺失一份。主审实测当前 desktop/node_modules 无同名嵌套包（按脚本同款展开规则扫描）——依赖树变化时触发，无门禁防护。
- 影响范围：受影响=未来依赖树出现同名嵌套包时的安装包许可完整性（MIT 等分发义务合规面）；不受影响=当前依赖树；损害性质=潜伏合规缺口，触发条件在依赖升级之外。
- 修复方向：嵌套输出名携带父路径（如 `nested_${parent}__${basename}`）；可在脚本内对输出名冲突做去重后缀。

### 131#8 katex override 强制版本超出 rehype-katex 声明范围，@types/katex 与运行时偏差

- 位置：`desktop/package.json:16/:34`（dependencies 与 overrides 均 `katex: ^0.19.1`）vs lockfile `node_modules/rehype-katex` 声明 `katex: ^0.16.0`（7.0.1）。
- 传递链条：①override 强制 katex 0.19.1——压制 npm 的范围告警装出声明范围（^0.16）之外的版本；②rehype-katex 7.0.1 从未声明支持 0.19——运行时依赖 KaTeX 内部行为，上游小版本破坏即渲染失效；③rehype-katex 运行时依赖的 @types/katex 停在 0.16.8——类型描述与运行时 0.19.1 偏差（构建期类型检查失真）；④110#7 已记录为有意决策并给出退出条件（rehype-katex 发布声明支持 ^0.19 的版本后移除 override）。

### 131#9 dev-smoke 在非 Windows 下 cleanup 失效、vite 成孤儿（条件性）

- 位置：`scripts/dev-smoke.sh:12-15`。
- 传递链条：①cleanup 依赖 Windows netstat -ano 的列序（$5=PID）与 taskkill 命令；②非 Windows 下 netstat 无该列序/PID 语义、taskkill 不存在——监听者不会被杀；③仅 `kill $launcher` 终止 npm 包装进程，vite 子进程不在其进程组终止范围；④vite 成孤儿继续占用 43198——下次 dev-smoke 恒失败（strictPort 撞旧实例）。
- 影响范围：受影响=在 WSL/Linux/macOS 跑 make check 的环境（本仓库开发与 CI 均 Windows——winlibs 工具链、CI windows-latest，条件性）；不受影响=Windows 全路径（当前唯一现实路径）；损害性质=环境特定缺陷，引入非 Windows 环境前需先修。
- 修复方向：若引入非 Windows 环境，cleanup 补 `pgrep -P`/进程组终止逻辑并按平台分流。
