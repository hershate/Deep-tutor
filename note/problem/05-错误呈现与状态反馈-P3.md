# P3 错误呈现与状态反馈问题（8 项）

后端共 402 个去重错误码，前端专门处理的仅 6 个（认证五码 + not_found 四处静默过滤）
及 startup_not_ready 重试；其余一律按"英文码：中文消息"透出。本文件记录呈现层问题。

## 1. 同一"任务终态错误对象"在不同页面有三种呈现格式
- 前端：`PlanGenerator.tsx:269`、`StudyRoom.tsx:212/223`、`Library.tsx:265`、`SyncPanel.tsx:117`、
  `ProviderHub.tsx:365` 渲染 `{code}：{message}`；`AgentCenter.tsx:105`、`TutorPanel.tsx:40`、
  `Projects.tsx:158`、`AgentTaskCenter.tsx:27-29` 只渲染 message（无码）；Practice/Wiki/
  SubjectivePractice 走 `backendErrorMessage`。
- 后端：同一 `BackendError {code,message}`（`error.rs:3-7`）结构。
- 影响：同一语义错误（如 `request_interrupted`）在不同页面格式不一，对照错误码排查时行为不一致。
- 传递链条：触发（任一命令/任务返回错误）→ 根因（统一 `BackendError {code,message}`（`error.rs:3-7`）到达前端后由各页自行选择渲染字段）→ 传导（`PlanGenerator.tsx:269`、`StudyRoom.tsx:212/223`、`Library.tsx:265`、`SyncPanel.tsx:117`、`ProviderHub.tsx:365` 渲染 `{code}：{message}`；`AgentCenter.tsx:105`、`TutorPanel.tsx:40`、`Projects.tsx:158`、`AgentTaskCenter.tsx:27-29` 只渲染 message；Practice/Wiki/SubjectivePractice 走 `backendErrorMessage`）→ 症状（同一错误在不同页面三种格式）。
- 影响范围：全部展示后端错误的页面（9 处以上）；任何错误发生即呈现不一致；视觉与排查效率受损，无数据风险。

## 4. StudyRoom 讲义"取消生成"按钮在 cancelling 期间未禁用（全应用唯一可重复点击的取消入口）
- 前端：`StudyRoom.tsx:223`——按钮无 disabled、不检查 `busy === 'cancel'`；对比其余 10 处
  取消入口均有 `disabled={status === 'cancelling' || busy}`。
- 后端：`learning/lecture.rs:729-763`——cancel 幂等但重复发 `lecture.cancel_requested` 事件；
  worker 退出后返回 `no_active_lecture`。
- 影响：cancelling 期间可连点，worker 结束瞬间点击显示 `no_active_lecture` 原始码横幅。
- 传递链条：触发（讲义 cancelling 期间连点"取消生成"）→ 根因（`StudyRoom.tsx:223` 取消按钮无 disabled、不检查 `busy === 'cancel'`，为全应用唯一未防护的取消入口）→ 传导（`learning/lecture.rs:729-754` cancel 幂等但每次重复发 `lecture.cancel_requested` 事件；worker 退出后 active 标志移除，`:743` 返回 no_active_lecture）→ 症状（worker 结束瞬间的点击弹原始码横幅）。
- 影响范围：学习空间讲义生成弹窗；cancelling 期间连点且恰逢 worker 退出才命中（窄窗口）；视觉/可用性受损，无数据风险（取消本身幂等落库）。

## 5. 错误 toast 以成功样式呈现（绿色对勾 + role=status），且单槽覆盖
- 前端：`App.tsx:65/80-86`——单一 toast state，backend-error 与 notify 共用，后到覆盖先到，
  3.2 秒自动清除；`:302` 渲染固定 `<Check>` 图标 + `role="status"`（`styles.css:200-201`
  图标固定绿色）。
- 影响：任何后端错误都带绿色对勾、按 status 而非 alert 播报，易被当成操作成功；
  两个并发错误只留最后一条。另 `startupError`/`!ready` 分支不渲染 toast，该窗口内错误仅剩 console。
- 传递链条：触发（任何后端命令失败派发 backend-error 事件）→ 根因（`App.tsx:65/80-86` 单一 toast state 由 backend-error 与 notify 共用，后到覆盖先到、3.2 秒清除）→ 传导（`:302` 渲染固定 `<Check>` 图标 + `role="status"`；`styles.css:200-201` 图标固定 lime 绿色；`startupError`/`!ready` 分支（`App.tsx:257-265`）不渲染 toast）→ 症状（错误以成功样式播报、并发错误只留最后一条、启动窗口错误仅剩 console）。
- 影响范围：全局 toast 通道（全部页面共享）；任何错误发生即命中（默认配置）；视觉与可访问性受损（错误被误读为成功），无数据风险。
