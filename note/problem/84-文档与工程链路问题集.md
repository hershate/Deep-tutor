### 84#2 collect-licenses.mjs 嵌套许可覆盖 bug——注释宣称的 nested_ 前缀不存在，已实际造成许可张冠李戴

- 位置：`scripts/collect-licenses.mjs:121-123`（注释「嵌套副本输出名带 nested_ 前缀，与顶层同名包互不覆盖」）与 `:153/:163`（实现取 `entry.name` 作输出名）。
- 传递链条：①非 scope 顶层包（如 parse-entities）的嵌套包（`parse-entities/node_modules/@types/unist`）输出名仍为 `entry.name`（即顶层包名 parse-entities）→ 写出 `npm-parse-entities-license`；②顶层 parse-entities 自己的许可输出同名 → Windows 大小写不敏感文件系统互相覆盖，后写胜出；③实物验证：现存产物 `desktop/src-tauri/licenses/npm-parse-entities-license` 内容为「MIT License Copyright (c) Microsoft Corporation」（嵌套 @types 包的），而 `node_modules/parse-entities/license` 实为「Copyright (c) Titus Wormer」——随安装包分发的 parse-entities 许可文本已被替换。另：`runtimeFilter` 的 `rel` 用 `basename(dir)` 匹配 dev 标记，嵌套运行时包与顶层 dev 包同名时会被误排除。
- 影响范围：违反 NOTICE:23「汇总各依赖的许可/声明文本并随安装包分发」的承诺；`COLLECTED.md` 计数与实际文件不符；随包分发的许可文本存在系统性错配风险（凡有嵌套 node_modules 的顶层包均中招）。
- 修复方向：输出名真正加入嵌套段（如 `nested_` 前缀或以顶层包名为目录段）；dev 匹配改用 lock 中完整相对路径；修复后重跑收集并核对受影响文件。
