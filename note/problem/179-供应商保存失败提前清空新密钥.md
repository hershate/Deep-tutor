# 179：供应商保存失败提前清空新密钥

## 证据

- `desktop/src/pages/ProviderHub.tsx:239-267` `saveProfile` 在调用 `upsertProviderProfile` 前执行 `setForm(current => ({ ...current, key: '' }))`。
- 后端校验、密钥库写入或 IPC 失败时进入 `catch`，仅显示错误，不恢复刚输入的密钥。
- `desktop/src/pages/ProviderHub.tsx:450` 编辑器的保存按钮允许直接重试，用户不会收到“密钥已被清空”的提示。

## 完整传递链条

新手填写供应商档案和 API Key → 点击保存 → 前端在持久化结果未知时清空密钥输入 → 地址校验、密钥库或 IPC 失败 → 表单其余字段保留但密钥丢失 → 用户直接重试时 `apiKey` 变为 `undefined` → 新档案可能以无凭据状态保存，后续检测报缺少凭据；编辑档案时则意外回退为保留旧密钥。

## 影响范围

- 首次配置模型供应商，尤其是地址或权限需要多次修正的新手流程。
- 新建档案、替换现有档案密钥、保存并获取模型、检测前自动保存。
- 密钥不会被写入额外持久存储；问题限于当前编辑表单的内存状态与重试语义。

## 修复验收

- 仅在 `upsertProviderProfile` 成功后清空密钥；失败时保留当前内存输入供修正后重试。
- 成功路径仍不将密钥写入 WebView 长期存储、快照或日志。
- 新建、编辑、保存并获取模型三条调用共享同一修复，前端构建通过。
