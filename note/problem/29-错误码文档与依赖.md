## 错误码对照（P3 × 3）

### 29#1 三个取消竞态码漏进 isCancelRace 名单外，重复操作弹真错误

- 位置：`desktop/src/backend/client.ts:427-439`（名单）；漏网码后端位置：
  `agent/tools.rs:703,713,892`（`approval_resolved`——审批已被另一操作处理）、
  `community/mod.rs:848-849`（`not_reserved`）、`:868-872`（`room_not_available`）
- 证据：主审 grep client.ts 三码均为 0 命中。双击审批按钮/两处面板同时处理同一审批、
  列表滞后时重复点"取消预约"/"取消安排"→ 弹错误 toast，语义上任务已被正常处理——
  与 isCancelRace 注释声明的处理原则（client.ts:422-423）矛盾。前端对应调用点：
  useAgent.ts:219-227（resolveApproval）、Community.tsx:113、:118-120。

- 证据：多数 resume 已幂等（直接返回现状），`*_active` 只在"内存中已在恢复"的窄窗口触发
  且文案自释，严重度低于 29#1，但与名单设计意图不一致。

### 29#3 三处后端错误 message 内嵌技术细节直接透出到用户界面

## 依赖审计（P3 × 1 + 信息性）

### 29#8 Cargo.lock 中 reqwest 0.12.28（直接依赖）与 0.13.5（tauri 带入）双主版本共存

- 位置：`desktop/src-tauri/Cargo.lock`
- 证据：两份各带一套辅助依赖（0.12 走 native-tls/schannel，0.13 无 TLS feature）；
  编译时间与二进制体积无谓增长、安全审计面翻倍。受 tauri 上游约束 0.13 副本必须保留，
  可在升级窗口把直接依赖迁 0.13 去重。

### 29#9 quick-xml 的 `encoding` feature 无任何使用痕迹

- 位置：`desktop/src-tauri/Cargo.toml:18`
- 证据：两个 XML 入口（materials/parse.rs、sync/versions.rs）无任何编码转换 API 调用；
  但 encoding_rs 同时被 lopdf 带入，去掉无体量收益——记录精度问题，不建议动。
