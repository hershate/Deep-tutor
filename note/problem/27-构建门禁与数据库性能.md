# 27 号 · 构建门禁与数据库性能（P1 × 1 + P2 × 2 + P3 × 6）

> 第十二轮：真实执行 `make build` 发现交付物构建损坏；SQLite 索引与热查询静态审计。
> 全部经主审实证（含端到端修复验证）。

## P1

### 27#1 `make build` 与 CI 安装包步骤当前必然失败——1.1.0 发布后从未成功产出过安装包

- 位置：`Makefile:20` 与 `.github/workflows/ci.yml:51`（`npm run tauri build -- --locked`）；引入提交 `42ae01e3`（2026-11-07）
- 证据：实测 `make build` 立即失败：
  ```
  error: unexpected argument '--locked' found
    tip: to pass '--locked' as a value, use '-- --locked'
  ```
  npm 把 `--locked` 直接透传给 `@tauri-apps/cli`（2.12.4），tauri CLI 的 `--locked` 必须放在
  `--` 之后转发给 cargo。**dist/ 只有 1.0.0–1.0.5 安装包、没有 1.1.0**——版本升到 1.1.0
  （3c6b0242）以来无人跑通过安装包构建；最近提交声称"构建全绿"指的是前端 tsc/vite 构建。
  这是"唯一交付物"的主门禁。
- 修复方向（已实证）：Makefile 与 ci.yml 改为 `npm run tauri build -- -- --locked`
  （npm 吞掉第一个 `--`，脚本收到 `build -- --locked`）。主审已用该形式完整构建成功：
  `dist/DeepTutor_1.1.0_x64-setup.exe`（6.21 MiB）产出并通过 tauri.mjs 的 SHA-256 校验
  （本审计只验证、不落修复，产物留在 dist/ 备用）。

## P2

### 27#2 流式期间每 150ms 全表扫描 events 并逐行 json_extract 重建聊天内容

- 位置：`desktop/src-tauri/src/backend/providers/mod.rs:941-943`；events 表仅 `id INTEGER PRIMARY KEY`（store.rs:189-194，kind 无索引）
- 证据：
  ```sql
  SELECT payload FROM events WHERE kind = 'provider.chat_delta'
    AND json_extract(payload, '$.requestId') = ?1 ORDER BY id
  ```
  流式未完成时 `output`/`reasoning` 列为空（终态才 UPDATE），`rebuild_output=true` →
  每次调用全表扫描 + 逐行 JSON 解析。前端所有流式页面（StudyRoom/PlanGenerator/Practice/
  Projects/ExamWorkspace/SubjectivePractice/WikiPanel/useAgent 共 8 处）在流式期间以
  `deltaThrottle()` 150ms 节流轮询 `getProviderChat`。events 保底 2 万行（maintenance 裁剪
  下限），单次长回答自身产生 500–2000 行 delta——轮询成本随累计事件数单调上升（二次增长），
  流式越用越慢。
- 修复方向：events 增设 `(kind, id)` 索引或表达式索引；或在 provider_requests 上增量持久化
  部分输出，消除重放扫描。

### 27#3 每次模型请求前全量读取 provider_requests 全表（ensure_budget 读放大）

- 位置：`desktop/src-tauri/src/backend/providers/usage.rs:297-307`（`entries()` 无 WHERE 全表 + JOIN + 每行 JSON 解析 + 每行费率点查）；调用点 `usage.rs:426-459` ensure_budget，直连 providers/mod.rs:1143 与路由 routing.rs:911 在**每次模型请求开始**时调用
- 证据：provider_requests 无保留策略（仅 reset 清空），每行含 output/tool_calls 全文
  （KB–100KB 级）。重度使用数月后 1 万–5 万行——每次发起聊天/生成方案/出题前都全量扫一遍，
  请求启动延迟随历史线性增长；用量页与 CSV 导出同路径。
- 修复方向：ensure_budget 改按日聚合 SQL（SUM + 费率 JOIN）或维护累计表；为
  provider_requests 增加保留/归档策略。

## P3

### 27#4 agent 域四表（messages/runs/artifacts/approvals）均无 session_id 索引，每个 agent.* 事件触发 4 次全表扫描

- 位置：`desktop/src-tauri/src/backend/agent/mod.rs:352,374,394,417`；表定义 :199-266 仅 PK id
- 证据：每会话消息数无上限（仅 sessions ≤200）；useAgent 对活跃会话每个事件调
  refreshSession → getAgentSession → 4 次全扫。

### 27#5 practice_answers 无 set_id 索引，每次答题提交全表扫描

- 位置：`desktop/src-tauri/src/backend/practice/mod.rs:957,1021,1052,1172-1180`；表仅 PK id + UNIQUE(question_id)
- 证据：practice_sets 无配额上限；累计约 1.5 万行后每次提交答题的 COUNT/列表/求和全表扫。

### 27#6 learning_node_evidence 无 created_at 索引（周报全扫+排序）

- 位置：`desktop/src-tauri/src/backend/reports/mod.rs:609`；表仅 PK + UNIQUE(plan_id,node_id,evidence_key)
- 证据：每次作答/复习/考试 UPSERT 证据行、无上限；万行级后周报打开可感知。

### 27#7 流式 delta 逐条自动提交 + 全库未设 synchronous（默认 FULL）

- 位置：`desktop/src-tauri/src/backend/providers/mod.rs:1156-1164`（每 delta 一条 INSERT+commit）；store.rs:162-168（仅设 WAL/foreign_keys/busy_timeout）
- 证据：WAL + FULL = 每提交 fsync；每秒数十 delta 即每秒数十次 fsync（Windows 上昂贵）。
  决策文档对 synchronous 无成文要求——补 `PRAGMA synchronous=NORMAL`（WAL 常规搭配）
  需先评估断电语义并回写决策。

### 27#8 域命令每次操作 Store::new 全量重算 schema 指纹

- 位置：`desktop/src-tauri/src/backend/store.rs:94-116,118-256`；各域 State 每操作新建连接（providers/mod.rs:260-262 等同构）
- 证据：无条件读全量 sqlite_master（~45 对象）+ SHA256；27#2 的 150ms 轮询路径每轮都付
  该固定成本。核心 kv 命令走共享连接（commands.rs:11-15）不受影响。

### 27#9 事件同步全量重读 app_state（4 集合逐行 JSON 解析）

- 位置：`desktop/src-tauri/src/backend/store.rs:407-467`；前端每事件批次（120ms 合并）eventsSince+getAppState
- 证据：受配额约束（笔记 500×1MB 上限等），数 MB 内可忽略；笔记多且大时流式期间形成持续
  的解析/序列化负载。与 27#2 同源的读放大，改增量快照可一并解决。

## 信息性

1. `sync_jobs` 的 `(id, created_at)` 索引冗余且无效：id 是唯一 PK 前导，列表
   `ORDER BY created_at DESC LIMIT 50`（sync/mod.rs:413）用不上，仍全扫+top-N。
2. 启动恢复 10 个域的 `WHERE status IN (...)` 全扫各一次（startup.rs:377-386），仅启动时；
   provider_requests 无限增长会拖慢启动（与 27#3 同根）。
3. `provider_route_runs` 列表排序、`community_replies.post_id`、`notifications.created_at`、
   `focus_sessions.ended_at` 等缺口在当前配额/增长量级下无感（详见审计索引总表，此略）。
4. kv `data LIKE '%q%'` 全文搜索无法用索引——任务点已自知（13#13 注释），受配额硬上限约束。
