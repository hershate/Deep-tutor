### 30#1 8 个技能的 README/SKILL 声称由不存在的 Python 运行时加载，「修改即生效」与编译期嵌入矛盾

- 位置：`desktop/src-tauri/assets/skills/deep-tutor-*/README.md`（6 个技能的「运行时集成」小节，
  12 处 `loader.py`/「重启后端即生效」表述；含 Python 表述的文件共 14 个）及各 SKILL.md
  frontmatter/Notes
- 证据：
  - README 声称「运行时由 Python Skill 加载器读取 SKILL.md」「`app/skills/loader.py`
    启动扫描并注册到 `skill_registry`」「修改 `SKILL.md` 后重启后端即生效（加载器启动扫描 +
    缓存）」，并引用 `app/agent/loop.py`、`app/tools/understand_intent.py`、pydantic
    `IntentData`/`KnowledgeMapData` 校验等——全仓无任何 `.py` 后端（Python 运行时已删除），
    上述路径 find 零命中。
  - 实际实现：`plugins/mod.rs:129-186` 的 `assets()` 用 `include_str!` 把 8 份 SKILL.md
    **编译期嵌入**二进制，仅作为「legacy-skill（历史 Skill 资产）」静态条目经
    `get_plugin_overview`/`asset` 命令展示；内联第 9 项 `native-operations` 明示「不执行
    Python」。
- 影响：维护者按 README 修改 SKILL.md 后重启应用——内容不变（须重新编译 Rust）；按 README
  理解系统架构会误信存在 Python 加载器、pydantic 校验与缓存回退链。README 是本仓库新写
  文档（「目录结构」小节与历史项目不同），其运行时集成描述与实现不符属事实错误。
- 修复方向：README 的「运行时集成」改为「历史资产，经 `include_str!` 编译期嵌入，修改需
  重新构建；当前应用不执行 Python」。SKILL.md 正文属历史原貌可保留。

### 30#2 许可收集先于任何 Rust 构建，裸跑 `make build` 冷缓存会产出 Rust 许可大面积缺失的安装包

- 位置：`Makefile:18-21`（`collect-licenses.mjs` 在 `tauri build` 之前）；`scripts/collect-licenses.mjs:40-63`
- 证据：
  ```makefile
  build:
  	node scripts/collect-licenses.mjs
  	# npm 吞掉第一个 --，脚本收到 build -- --locked，--locked 才能转发给 cargo
  	cd desktop && $(NPM) run tauri build -- -- --locked
  ```
  Rust 部分经 `cargo metadata` 定位**本地已解包**的 registry src 目录；`cargo metadata` 只解析
  并下载 `.crate` 归档，不解包源码。CI 不受影响（`ci.yml:44` 的 `cargo test --release --locked`
  先于 `:49` 收集步运行，构建已解包源码）；本地已有构建缓存时也不受影响（当前 COLLECTED.md
  = 磁盘 449 cargo + 181 npm，精确一致）。暴露路径是**全新环境单独执行 `make build`**：
  收集时 registry src 为空，Rust 许可成片缺失，安装包内仅剩 COLLECTED.md 兜底行。
- 影响：NOTICE:23 承诺「汇总各依赖的许可/声明文本并随安装包分发」，其「个别源码未解包」
  措辞不能覆盖该场景；属合规弱化风险（非确定性缺陷）。
- 修复方向：`make build` 在收集前先 `cargo fetch`（并在 metadata 阶段触发解包）或直接把
  收集步移到 `tauri build` 之后（构建必解包源码）；NOTICE 措辞同步收敛。

### 30#5 desktop/README.md 构建命令缺 `--locked`，与 Makefile/CI 锁定策略不一致

- 位置：`desktop/README.md:35`（`npm run tauri build`）
- 证据：`Makefile:21` 与 `ci.yml:51` 均为 `npm run tauri build -- -- --locked`；`make test`
  亦全程 `--locked`。
- 影响：照 README 直接构建时，Cargo.lock 与清单不一致会静默更新锁文件而非失败，可能产出
  与 CI 不同的依赖集合。
- 修复方向：补全为 `npm run tauri build -- -- --locked`。
