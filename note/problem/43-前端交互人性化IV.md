### 43#1 全局「快速记录」无 busy 防抖——双击/回车连击创建重复任务或笔记

- 位置：`desktop/src/App.tsx:376`（入口）、`:279-288`（`addQuick`）、`:61-62`（`setTasks`/`setNotes` → `replaceCollection`）；对照 `desktop/src/pages/Plan.tsx:177`（同型 addTask 有 `busy === 'task'` 守卫）
- 证据：
  ```tsx
  <Button onClick={addQuick} disabled={!quickTitle.trim()}>保存{quickType}</Button>
  <input … onKeyDown={e => { if (e.key === 'Enter' && !e.nativeEvent.isComposing) addQuick() }} />
  ```
  `addQuick` 仅有 `if (!quickTitle.trim()) return` 一个守卫；`quickTitle` 直到 IPC 成功后才清空。
- **传递链条**：① 顶栏「快速记录」弹窗输入标题后双击「保存」（或回车后瞬间再点）→ ② 两次 `addQuick` 都通过 trim 检查（清空发生在 `await` 之后）→ ③ 两次 `setTasks(current => [...current, { id: localId(), … }])` → ④ `replaceCollection`（useBackendState.ts:214-232）对同命名空间 inflight 串行化：第二次以第一次回填后的最新集合为基准执行 updater（24#5 语义）→ ⑤ **两条 id 不同的同标题任务都落库**，revision 不冲突、无任何报错 → ⑥ toast 弹两次「任务已保存」。
- **影响范围**：应用最高频入口之一（顶栏常驻按钮）；双击是保存类按钮的本能操作，回车+点击连击同样触发。产出为用户可见的重复数据，需手动删除。对照 Plan 页 addTask、Practice 页 bookmark/mastered 均已有 busy 守卫（32#10 家族），独漏此处。修复方向：`const [quickBusy, setQuickBusy] = useState(false)` 守卫 + 按钮 `disabled={quickBusy || !quickTitle.trim()}` +「正在保存…」文案。

### 43#9 PAT 复制失败无兜底指引——令牌只显示一次，失败后用户不知如何补救

- 位置：`desktop/src/components/SecurityPanel.tsx:83-87`
- 证据：`try { await navigator.clipboard.writeText(…); notify('PAT 已复制…') } catch (error) { reportBackendError(error) }`——WebView 失焦等场景 clipboard API 可用性受限；失败只弹通用后端错误。对照 `ProviderHub.tsx:384` 同类场景有「复制失败，请使用下载」的替代指引。
- **传递链条**：① 创建 PAT 后明文只显示一次（token-once 区）→ ② 用户点「复制令牌」→ ③ WebView 失焦/权限受限时 `navigator.clipboard.writeText` 拒绝 → ④ catch 只弹通用「后端错误」样式 toast——未告诉用户「令牌就在下方 code 里可手动选中复制」→ ⑤ 用户关闭对话框后令牌永久不可再取，只能撤销重建。
- **影响范围**：明文令牌只显示一次，复制失败又不给「请手动选中 `<code>` 复制」指引的用户会直接丢失令牌。修复方向：catch 里明确提示手动复制路径。

### 43#11 拖放监听 effect 依赖不稳定 notify——每次渲染重挂 onDragDropEvent

- 位置：`desktop/src/App.tsx:89`（`notify` 为渲染期箭头函数，非 useCallback）、`:203`（依赖数组 `[ready, loginRequired, notify]`）
- **传递链条**：① 任意状态更新触发 App 渲染（toasts、snapshot、弹层开关等高频）→ ② effect cleanup 先 `unlisten()`（同步）→ ③ 新注册是 promise 异步完成 → ④ 两次渲染之间存在无拖放监听窗口（此刻拖入被 WebView2 吞掉，正是 37#3 修前的现象短暂回归）+ 每次渲染两次无谓 IPC。
- **影响范围**：窗口极短、触发需要恰在渲染间隙拖入，实际命中率低；但属可零成本消除的缺陷（notify 用 useCallback 稳定化，或 effect 内用 ref 引 notify）。

## 本轮排除项（核查过、无问题的类别）

- **打开本地文件/不存在路径/非 https 外链**：`revealInFileManager` 仅用于刚导出的文件与 dataRoot（路径真实存在）；唯一外链 ProviderHub 预设文档 16 条全 https 且 preventDefault 走 opener。
- **浏览器 API 残留**：全仓无 `target="_blank"`、`mailto:`、`file://`、`window.open`、`alert/confirm/prompt`、`location.href/assign/replace`。仅存两个 `<a>`：skip-link（preventDefault + focus）与 ProviderHub 文档链接（已处理）。
- **键盘/焦点**：Modal Esc 分层栈仲裁与焦点圈禁/恢复在位；Review 快捷键已排除弹层与输入焦点场景。
- **主流静默失败**：绝大多数异步提交均有全局 error toast 或页内 form-error + 重试；唯一实质漏网即 43#7。
