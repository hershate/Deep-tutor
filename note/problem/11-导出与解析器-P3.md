# P3 导出生成器与解析器问题（20 项）

第四轮对 export/pdf.rs、anki.rs、其余格式、materials/parse.rs、去重暂存、
notes 导入的审计发现。验证通过未列入：PDF 布局计算/xref/ToUnicode、ICS
转义与 fold、HTML 转义、docx 表格/tab、EPUB 路径防护与 ZIP 预算、
sha256 去重语义、staged→parsed 原地不动、原子写、notes ZIP 三重限制。

## 导出生成器（export/）

### 1. 任一字符缺字形即整份 PDF 失败，且不回退第二字体
- `pdf.rs:281-286`——首轮任一字符无字形即 Err；`:211-231` 字体链回退只发生在"文件读取/解析失败"，字形缺失在内层不触发换字体。内容含 emoji/生僻字/BOM 字符 U+FEFF 时整份失败。

### 2. 无字形子集化：系统字体全量嵌入，一页 PDF 也 ≥约 10MB
- `pdf.rs:42-79`——program 复制源字体全部表（仅重建目录偏移）；msyh.ttc 约 19–21MB，Flate 后仍约 10MB。全仓无"子集化"声明，属体积体验问题。

### 3. SM-2 调度数据整体丢弃：所有卡片按"全新卡"写入 Anki
- `review/mod.rs:53-68` 的 due_at/interval/ease/repetitions/lapses 在 `export/mod.rs:87-92/421-425` 组装时丢弃；`anki.rs:110-113` 固定 type=0/queue=0/due=index/ivl=0——导出后全部回到新卡队列，应用内复习进度清零。

### 4. note guid/id 锚定导出时间戳，再次导出导入 Anki 必产生整套重复笔记
- `anki.rs:51-54/82/90-96`——guid = sha256(本次时间戳 note_id:front)[:10]，非内容锚定；对比 deck/model 用 stable_id。更新内容后重导得到重复卡而非更新。

### 5. [待确认] col/deck 配置 JSON 为最小子集，缺官方索引，csum 算法与 Anki 不同
- `anki.rs:67-79`——dconf 缺 new.order/separate/rev.fuzz 等键；建表无 ix_cards_nid 等官方索引；csum 取 sha256 前 4 字节（Anki 官方为 first-field 自有校验和）。schema 与 ver 11 逐列一致、无媒体正确；新版 Anki（2.1.50+）导入兼容性未实测。

### 6. 学习报告 CSV 缺公式注入防护（三处文件级 CSV 出口唯一未覆盖者）
- `reports/mod.rs:999` escape 仅引号包裹；`:1025/:1033` goal_detail/plan.title 用户可控。对比 `export/formats.rs:81-87` 与 `providers/usage.rs:469-475` 均有 `= + - @` 守卫——计划标题以 = 开头导出后 Excel 打开即按公式执行。

### 7. 用量 CSV 无 UTF-8 BOM，与另两个 CSV 出口不一致
- `providers/usage.rs:479` 表头无 \u{feff}（对比 formats.rs:108、reports/mod.rs:1000）——中文供应商名在 Excel 双击打开时按 GBK 解码乱码。

### 8. OPML text 属性保留原始换行，被 XML 属性规范化吞掉
- `export/formats.rs:197-208`——多行正文进 text="..." 属性未替换换行；处理器按属性规范化折叠为空格（HTML 导出有 \n→&lt;br&gt;，OPML 无对应处理）。

## 材料解析器（materials/parse.rs）

### 9. txt/md 解析与笔记导入均不剥 UTF-8 BOM，U+FEFF 入库并连锁毁掉 PDF 导出
- `parse.rs:43-49`（:73 trim 不移除 U+FEFF）、`materials/mod.rs:470-475`、`notes/mod.rs:148-199` 同样保留——Windows 记事本旧默认保存的文本首字符 FEFF 入库进 Wiki 上下文/摘录，且 msyh 无该字形 → 叠加 01#23 使知识库 PDF 导出失败。

### 10. PDF 单页提取失败即全量失败，无部分文本保留
- `parse.rs:102-112`——2000 页文档仅 1 页内容流损坏，整份解析失败、已累积文本全部丢弃（对比 5MB 截断有 warning）。

### 11. [待确认] 中文 PDF 编码覆盖依赖 ToUnicode/UniGB 两类，其余预定义 CMap 直接失败或乱码
- lopdf 0.35：Identity-H 仅走 ToUnicode，预定义 CMap 仅 UniGB-UCS2/UTF16 可解码（其余 CharacterEncoding 错误→整份失败）；流式 Encoding 无 ToUnicode 回退单字节 StandardEncoding 可能"已解析+乱码"落库。测试无中文 PDF 用例。

### 12. EPUB href 仅解码 %20，其余百分号编码路径整体失败
- `parse.rs:349-377`——中文文件名 href（chapter-%E4%B8%AD.xhtml，规范允许且常见）by_name 找不到 → "压缩包缺少必需文档"，错误文案与真实原因（未解码）不符。

### 13. EPUB 无 spine 时回退顺序随机（HashMap 无序），且仅认 application/xhtml+xml
- `parse.rs:408-415`——旧规范/残缺 EPUB 要么章节顺序不可预测，要么（OEBPS 1.x 常见 text/html）全被跳过 → 空文本失败。

### 14. 解析进度为固定里程碑 10/35/85/100，与真实工作量无关
- `materials/mod.rs:961/724/748/751`——大 PDF 实际提取期间恒停 35%；失败重置 0；前端按百分比展示，属装饰性进度。

## 去重与暂存（materials/mod.rs）

### 15. sha256 去重短路不校验原件存在性，原件丢失后该内容永久无法重新导入恢复
- `mod.rs:492-505`——命中既有行直接返回 deduplicated:true，发生在原件写入之前，不检查 originals/{sha256}.{kind} 是否在盘——外部删除/杀毒隔离后重导永远得到坏记录；若被方案引用则删除也被 material_in_use 阻止（:1119-1128）。

## 笔记导入（notes/mod.rs）

### 16. 单文件 md/txt 路径缺 1MB 预检，且 1MB 上限含 JSON 转义膨胀，临界笔记使整批导入失败
- `notes/mod.rs:179-184` 单文件仅查 64MB；实际约束 store.rs:786-791 记录 ≤1MB（含转义，`\n`→`\\n` 每行膨胀）——接近 1MB 的合法笔记在落库前才失败，错误泛化，同 ZIP 其余笔记一并回滚。

### 17. [待确认] md 元数据仅识别自家导出头格式，不支持通用 frontmatter
- `notes/mod.rs:50-62`——只精确匹配本产品导出头；外部带 YAML frontmatter 的 Markdown 导入后元数据留正文、标题带扩展名、标签固定"复盘"。是否属有意最小实现需产品判定。
